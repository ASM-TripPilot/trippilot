# gen-aidlc-claude-md — aidlc-docs 참조 CLAUDE.md 생성기

대상 디렉토리에 CLAUDE.md를 생성한다. 생성된 CLAUDE.md는 그 디렉토리에서 작업하는
Claude에게 `aidlc/aidlc-docs/`의 인셉션 산출물을 읽고 시작하라고 지시한다.
`aidlc/CLAUDE.md`(AI-DLC 워크플로우 정본)의 "MANDATORY PRE-READ" 스타일을 따른다.

모든 경로는 **저장소 루트(`trippilot/`) 기준**이다.

## 실행 절차

### 1. 대상 디렉토리 결정

- 인자(`$ARGUMENTS`)로 대상 디렉토리를 받는다 (예: `/gen-aidlc-claude-md backend`).
- 인자가 없으면 사용자에게 어느 디렉토리에 생성할지 물어본다.
- **금지 대상**: `aidlc/` 내부(동료 소유 워크스페이스 — 이미 자체 CLAUDE.md 있음),
  저장소 루트(프로젝트 정본 CLAUDE.md가 이미 있음 — 덮어쓰기 금지).

### 2. 문서 인벤토리를 런타임에 수집

문서 목록을 하드코딩하지 말고 실행 시점에 열거한다 (문서는 계속 추가/변경됨):

```bash
find aidlc/aidlc-docs -name '*.md' -type f | sort
```

`aidlc/aidlc-docs/aidlc-state.md`를 읽어 현재 단계(Current Phase/Stage)와
Key User Directives를 확인한다 — 생성할 CLAUDE.md의 "현재 상태" 줄에 반영한다.

### 3. CLAUDE.md 생성

아래 템플릿을 채워 `<대상>/CLAUDE.md`로 쓴다.
`{...}` 자리는 2단계에서 수집한 실제 값으로 치환하고,
문서 목록은 실제 존재하는 파일만 나열한다 (깨진 링크 금지).

- **대상에 CLAUDE.md가 이미 있으면**: 전체를 덮어쓰지 말고,
  `<!-- aidlc-docs:begin -->` ~ `<!-- aidlc-docs:end -->` 마커 블록만 추가/교체한다.
  마커가 없으면 파일 끝에 마커 블록을 추가한다.
- **새로 만들면**: 템플릿 전체를 그대로 쓴다.

### 4. 검증

생성 후 CLAUDE.md 안의 모든 경로가 실제 파일로 해석되는지 확인한다
(대상 디렉토리 기준 상대경로가 맞는지 주의 — 템플릿은 저장소 루트 기준 경로를 쓰므로
파일 상단에 그 사실을 명시한다):

```bash
grep -o 'aidlc/[a-zA-Z0-9./_-]*\.md' <대상>/CLAUDE.md | sort -u | while read f; do
  [ -f "$f" ] || echo "MISSING: $f"
done
```

`MISSING` 출력이 없어야 완료.

## 템플릿

```markdown
# CLAUDE.md

<!-- aidlc-docs:begin (generated by /gen-aidlc-claude-md — 재생성 시 이 블록만 교체) -->

# ⛔ MANDATORY PRE-READ: AI-DLC 인셉션 산출물

이 디렉토리에서 작업을 시작하기 **전에**, 저장소 루트 기준
`aidlc/aidlc-docs/`의 인셉션 산출물을 읽어야 한다.
아래 경로는 모두 **저장소 루트(`trippilot/`) 기준**이다.

**현재 상태**: {aidlc-state.md의 Current Phase/Stage 요약 — 예: INCEPTION 완료(STOP), CONSTRUCTION 자동 진입 금지}

## 읽기 순서

1. `aidlc/aidlc-docs/aidlc-state.md` — 진행 상태·범위·Key User Directives (**항상 먼저**)
2. `aidlc/aidlc-docs/inception/requirements/requirements.md` — 요구사항
3. `aidlc/aidlc-docs/inception/user-stories/stories.md` + `personas.md` — 유저스토리·페르소나
4. `aidlc/aidlc-docs/inception/application-design/` — 앱설계 (application-design.md,
   components.md, component-methods.md, services.md, component-dependency.md)
5. `aidlc/aidlc-docs/inception/application-design/unit-of-work.md`
   + `unit-of-work-dependency.md` + `unit-of-work-story-map.md` — 유닛 분해(U0~U9)
6. `aidlc/aidlc-docs/inception/plans/` — 각 단계 실행 계획 (필요 시)
7. `aidlc/aidlc-docs/audit.md` — 결정 이력 추적이 필요할 때만

## 제약

- `aidlc/` 은 **동료 소유 워크스페이스** — 읽기 전용. 수정하려면 사전 협의 필수.
- `aidlc/aidlc-docs/audit.md` 는 append-only — 절대 덮어쓰지 않는다.
- 문서 간 충돌 시 `docs/planning/` 이 정본("정본")으로 우선한다
  (루트 CLAUDE.md 참조 — docs/planning/ 은 aidlc/docs/PRD/ 를 정제한 상위집합).

<!-- aidlc-docs:end -->
```

## 주의사항 (실제 확인된 것)

- `aidlc/aidlc-docs/` 에는 현재 20개 md 파일이 있다: 루트에 state/audit 2개,
  `inception/` 아래 plans 5개 · requirements 3개 · user-stories 2개 · application-design 8개.
  CONSTRUCTION 단계 산출물은 아직 없다 (인셉션에서 STOP 상태).
- `aidlc-state.md` 의 Workspace Root 는 동료 로컬 경로
  (`/Users/taehyeonpark/...`)라서 이 저장소와 다르다 — 생성물에 복사하지 말 것.
- 루트 `CLAUDE.md` 와 `aidlc/CLAUDE.md` 는 각각 프로젝트 정본·AI-DLC 워크플로우 정본이므로
  이 스킬로 건드리지 않는다.
