# 백엔드 작업 절차

`docs/conventions/workflow-8steps.md` 의 8단계를 백엔드 실무 순서로 편 것이다. **새 절차가 아니다** —
그 문서가 정본이고 여기는 "각 칸에서 실제로 무엇을 하는가"를 담는다.

## 순서

```
1. 정본 확인  →  2. 테스트 시나리오  →  3. 구현  →  4. 역검증
                                                      ↓
        7. PR  ←  6. 전체 빌드  ←  5. 통합 검증(실 DB·E2E·실 AI)
```

각 단계의 상세는 두 스킬이 나눠 갖는다 — **1번은 `backend-canon`, 4~6번은 `backend-verify-gates`**.
여기서는 그 사이를 잇는 것과, 각 단계가 남기는 산출물만 다룬다.

## 1. 정본 확인 — `backend-canon` 을 쓴다

코드를 한 줄이라도 쓰기 전에. 이 단계를 건너뛰면 **구현이 아니라 재작업을 하게 된다.**

## 2. 테스트 시나리오 — 짧아도 먼저 적는다

**우리가 약한 칸이다**(8단계 문서가 그렇게 지목한다). 구현 후에 테스트를 맞추면 "지금 만든 것이 도는지"만
확인하게 되고, "무엇이어야 하는지"는 검증되지 않는다.

세 줄이면 충분하다:

- **정상**: 무엇이 일어나야 하는가
- **경계·예외**: 무엇을 막아야 하는가 — 그리고 **막지 못하면 사용자에게 무엇으로 보이는가**
- **불변식**: 어떤 상태가 절대 생기면 안 되는가(INV-\*)

세 번째 줄이 PBT 대상 후보다. 그리고 두 번째 줄의 "사용자에게 무엇으로 보이는가"가 테스트 이름이 된다 —
`"취소된 세션은 뒤늦은 완료로 되살아나지 않는다"` 같은 이름은 이 질문에서 나온다.

## 3. 구현 — 최소한으로

`backend/CLAUDE.md` 의 규율을 따른다(요청 범위 밖 금지 · 단일 사용처에 추상화 금지 · 인접 코드 개선 금지).

**상태를 다루는 코드에는 한 가지를 더 센다.** 상태를 여는 호출을 잡고, 그 뒤로 갈라지는
**모든 반환·예외 경로에서 그 상태가 닫히는지** 센다. 정상 완료만 닫아 두면 나머지 경로에서 열린 채 남고,
화면은 끝난 적 없는 작업을 영원히 기다린다(실측: 닫히는 경로가 다섯이었는데 처음엔 셋만 닫았다).

## 4~6. 검증 — `backend-verify-gates` 를 쓴다

역검증 → 통합 검증 → 전체 빌드. 순서를 지켜라: 위가 빨간데 아래로 가면 원인이 섞인다.

## 7. PR — 무엇을 적는가

**제목**: `docs/conventions/commit.md` 규약. **본문은 아래 네 절**을 채운다.

| 절 | 내용 |
|---|---|
| **왜** | 이 변경이 없으면 사용자에게 무엇이 잘못되는가. 티켓 번호가 아니라 **증상**을 적는다 |
| **무엇** | 표면(엔드포인트·이벤트·마이그레이션)을 표로. 구현 상세가 아니라 **계약이 어떻게 달라졌는지** |
| **판단** | 갈림길에서 왜 그쪽을 골랐는가. **안 만든 것**도 여기 적는다 — 정본 이탈은 반드시 |
| **검증** | 역검증 결과 · 통합 검증 · 전체 빌드 테스트 수. **건너뛴 검증이 있으면 명시한다** |

리뷰어가 가장 먼저 읽는 것은 "판단"이다. 코드로는 *무엇을 했는지*만 보이고 *왜 다른 길을 안 갔는지*는 안 보인다.

## 규모별 보정

전 단계를 다 밟는 것은 **스토리·모듈 단위**뿐이다.

| 규모 | 단계 |
|---|---|
| 스토리·모듈 | 전체 |
| 버그 수정 | 2(재현 테스트) → 3 → 4(**필수**) → 6 → 7. 정본 확인은 원인이 설계에 있을 때만 |
| chore·문서 | 6 → 7 |

버그 수정에서 4번(역검증)이 필수인 이유 — **재현 테스트가 버그를 못 잡는데 통과만 하는 경우**를
그 단계만이 걸러낸다. 고치기 전에 테스트가 빨간 것을 눈으로 봤어야 한다.

## 끝나고 남기는 것

- **새로 겪은 실패** → `docs/conventions/anti-patterns.md` 에 한 줄. 가설이 아니라 **재현·검증된 것만**
- **정본 이탈** → 코드 주석 + PR 판단 절 + 계약 파일
- **티켓 없이 미룬 것** → 코드에 `TODO`/`미개통` 으로 남기되, **그것이 Jira 에 안 올라간다는 것을 안다**.
  중요한 것은 티켓을 만들어 달라고 요청한다(이 리포에 그렇게 잊힌 구멍이 셋 있었다)

## 하지 않는 것

- **머지** — PR 까지만. 머지는 사용자가 명시적으로 승인한다
- **force push** · 볼륨·데이터 삭제 · 대화형 명령
- **남의 PR 수정**
