# 정본 확인 — 착수 전에

**이 스킬이 존재하는 이유는 한 사건이다.** U4(여행 중 Plan-B) 작업을 `inception/` 과 패키지 설계 문서만 읽고
시작했다가, `construction/u4-in-trip-planb/` 에 있던 엔티티·상태 어휘·불변식(INV-U4-\*)을 통째로 놓쳤다.
모듈 분할·상태 어휘·중복 진입 처리·억제 기록 방식 등 **7군데가 정본과 어긋난 PR 2건**을 만들었고 전부 재작업했다.

**루트 `CLAUDE.md` 의 "Where the authority lives" 목록에는 `construction/` 이 없다.** 본문 다른 곳에
"Construction-stage design docs go under …" 라는 한 줄이 있을 뿐이고, 그 문장은 *산출 위치*를 말하지
*착수 전 필독*을 말하지 않는다. 그래서 이 스킬이 그 자리를 메운다.

## 착수 전 읽는 순서

1. **티켓 본문** — 무엇을 요구하는지, 부모 스토리의 AC(정상·예외)까지
2. **`aidlc/aidlc-docs/construction/<unit>/functional-design/`** — 해당 유닛이 있으면 **여기가 가장 구체적이다**
3. **`backend/docs/design/openapi.yaml`** — 건드릴 표면의 현재 계약
4. **`docs/conventions/anti-patterns.md`** — 손댈 영역과 관련된 절

2번을 건너뛰지 마라. 1·3·4 는 대개 자연스럽게 보게 되지만 2번은 의식하지 않으면 빠진다.

## 유닛 지도

| 유닛 | 범위 | 백엔드 모듈 |
|---|---|---|
| `u0-foundation` | 공통 토대 | common/* |
| `u1-accommodation-trip` | 숙소 등록·저장 · 여행 · 구간 거점 · 커버리지 | saved-accommodation · trip · accommodation-search |
| `u2-itinerary-intelligence` | 경계 계약 · slotKey · 거리 표시 · 문구 제약 | (경계 규약, 코드 없음) |
| `u3-ai-itinerary` | AI 일정 생성 · 편집 재검증 · 리비전 · 확정 | itinerary-generation |
| `u4-in-trip-planb` | 방문 실적 · 트리거 · 재계획 · 날씨 | itinerary-recalculation · planb-detection · weather-context |

각 유닛 폴더의 네 문서는 역할이 다르다. **필요한 것만 읽어라 — 전부 읽으면 착수가 늦어진다.**

| 문서 | 언제 |
|---|---|
| `domain-entities.md` | 필드·상태값·**불변식(INV-\*)** 을 정할 때. 새 테이블·상태 추가는 항상 |
| `business-rules.md` | 판단 규칙(BR-\*)이 필요할 때. "이 경우 어떻게 해야 하나" |
| `business-logic-model.md` | 흐름·경계 계약(F-\*)·외부 호출 매핑 |
| `frontend-components.md` | 화면이 이 표면을 어떻게 쓰는지 — **응답 모양을 정할 때** 읽으면 헛도는 필드를 안 만든다 |

## 정본과 코드가 다를 때

**정본이 항상 이기는 것은 아니다.** 정본은 "무엇이 필요한가"를 정하지 "어떻게 저장·전송하는가"까지 정하지 않는다.
실제로 이 리포에서 셋 다 나왔다.

**정본대로 간다** — 규칙이 업무 판단일 때.
US-TRIP-03 은 "기간 밖이면 확장 여부를 묻는다"고 하고 INV-U1-15 는 "기간 내여야 한다"고 한다.
거부를 유지하고 클라이언트 2단계로 만족시켰다 — 서버가 기간을 늘리면 일정·커버리지·필수 방문지가 모두 흔들린다.

**정본에서 이탈한다** — 정본이 저장 방식을 지정했는데 읽는 곳이 없을 때.
U3 §2.2 의 `partial`(중간 결과 jsonb) 컬럼을 만들지 않았다. day1 은 이미 일정 행에 있고 화면도 그걸 읽어서
사본이 갈라지면 어느 쪽이 사실인지 판단할 근거가 없다.

**정본 모양이 실 계약과 안 맞는다** — 상대가 그 형태를 받지 않을 때.
U4 §3.1 은 `lockedSlotKeys: List<String>` 인데 AI 는 시각 없는 고정 블록을 거부한다(422). 블록 타입으로 바꿨다.

**이탈했으면 세 곳에 남긴다.** 하나라도 빠지면 다음 사람이 "빠뜨렸다"고 오해한다.

- **코드 주석** — 이탈 사유를 그 자리에
- **PR 본문** — 판단 절에 "정본 §X 이탈"로 명시
- **마이그레이션·계약 파일** — 스키마·openapi 를 건드렸으면 거기에도

## Jira 는 코드의 현실이 아니다

**티켓 상태를 믿지 마라.** 이 리포에서 실측으로 둘 다 나왔다.

- **닫히지 않은 완료** — 코드는 다 됐는데 "해야 할 일"인 티켓 2건
- **티켓 없는 미구현** — 코드 주석으로 "다음 스프린트에" 미뤄 둔 구멍 3건. **주석은 Jira 에 안 올라간다**

남은 작업을 물었을 때 Jira 만 세면 둘 다 놓친다. 코드에서 직접 찾아라:

```bash
grep -rnE "TODO|FIXME|미개통|미구현|다음 스프린트|Sprint [0-9]" --include="*.kt" backend/modules/*/src/main
```

**`-i` 를 쓰지 마라.** 대소문자를 무시하면 `TODO` 가 `toDomain` 에 걸려 매퍼 함수가 전부 딸려 온다
(실측 144건 → 7건). `스텁`·`후속` 도 빼라 — 설명 문장에 흔히 쓰여 신호가 묻힌다(각 12건·24건).

이 조합이 실제로 찾아낸 것들 — **셋 다 Jira 에 티켓이 없었다**:

- 재계획이 입구만 있고 결과가 안 나오는 상태(`SOLVING→DRAFT` 전이 부재)
- **Apple 로그인이 비활성** — id_token 서명검증(JWKS)·aud/iss/exp 미구현이라 fail-closed
- **국내강제(INV-U1-12)가 지역명 하드코딩 스텁** — 실제는 지오코딩 후 영역 검증이어야 한다

반대로 티켓이 "해야 할 일"이면 **정말 안 됐는지 코드로 확인**한다. 마이그레이션·응답 필드·테스트가 이미
있으면 상태만 낡은 것이다.

## 정본·문서가 낡았을 때

문서가 실물보다 뒤처지는 일이 있다. 발견하면 **고치기 전에 어느 쪽이 최신인지 근거로 판단**한다 —
요약 문서와 `construction/` 이 다르면 날짜로 확인하고, 대개 `construction/` 이 최신이다.

지금 알려진 낡은 서술: 루트 `CLAUDE.md` 의 "AI/Solver: 초기 스캐폴딩, 서비스 로직 미구현" —
실제로는 `ai/src` 에 파이썬 99개와 api 모듈(app·routes·wiring·schemas)이 있고 실 왕복이 200 으로 확인됐다.
**루트 `CLAUDE.md` 수정은 팀 전체에 영향이 있으니 임의로 고치지 말고 제안한다.**
