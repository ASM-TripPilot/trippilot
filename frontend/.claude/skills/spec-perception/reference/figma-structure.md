# Figma 화면 구조 (밴드 맵)

**어느 밴드를 라이브로 읽을지 판단하는 용도.** 화면 상세(레이아웃·IO·컴포넌트)는 여기 없다 — 라이브 Figma가 유일한 정본이다.

## 파일

- 파일 키: **`1MTF3dtptIrbg8gld5IdO2`**
- 단일 페이지 "화면" = 노드 **`1228:1045`**
- URL 없이 이 키로 바로 읽는다 — 사용자에게 URL을 매번 묻지 않는다.

## 밴드

| 밴드 | 도메인 | 범위 |
|---|---|---|
| `a` | 홈 | first-cut |
| `b` | AI 어시스턴트 | M16 — 밖 |
| `c` | 온보딩·인증 | first-cut (U0) |
| `d` | 탐색 | first-cut |
| `e` | 숙소 | first-cut |
| `g` | 여행 생성 | first-cut |
| `h` | 일정 생성 | first-cut |
| `i` | 여행중·Plan-B | first-cut |
| `j` | 기록·회고 | first-cut |
| `k` | 커뮤니티 | M15 — 밖 |
| `l` | 알림·마이·설정 | first-cut |
| `m` | 공동편집 | M17 — 밖 |

- **`f` 밴드는 없다.** 결번이니 찾지 마라.
- `b`·`k`·`m`은 first-cut 범위 밖 — 해당 밴드 작업 요청이 오면 범위 밖임을 먼저 알린다.
- 화면은 밴드 코드 + 번호로 명명한다(`c01`, `c02`, `d01`…). **정리된 밴드(g·h·i, 2026-09-11)는 `xNN-[갈래] 이름 · 상태`** 형식이고 같은 화면의 상태는 같은 번호를 쓴다(`h08-[완전AI] AI 추천안 · 접힘/펼침/…`). 다른 밴드는 옛 형식(`e02-숙소 검색 결과 · default`)이 남아 있다.
- **번호도 결번이 있다.** 밴드 `e`는 `e00`·`e02`~`e05`로 **`e01`이 없다**. 번호가 비었다고 "못 찾았다"로 판정하지 마라 — 있는 것만 세라. h·i는 재번호돼 결번이 없다(h01~h17·i01~i10).
- **h·i의 옛 코드(h04~h38·i01~i19)는 죽었다.** 코드 라우트·`traps-execution.md`가 쓰는 h/i 코드는 그 옛 체계라(프리뷰 h 키·`traps-itinerary.md`는 새 코드 — TRIP-782·942) 라이브 프레임과 번호가 다르다 — 매핑은 `_workspace/20260908-figma-hnew/figma-build.md` 후속 33·38.

## 읽는 절차

1. `get_metadata(fileKey[, nodeId])` — 프레임 목록
2. `get_design_context` / `get_screenshot` — 대상 화면의 디자인·스크린샷

**토큰 주의**: `get_metadata`로 페이지 전체를 뜨면 1MB를 넘길 수 있다. 대상 노드로 좁히거나, 목록은 최상위 프레임(2칸 들여쓰기)만 추출한다.

### ⚠️ 캔버스는 플랫이다 — 밴드 컨테이너 프레임이 없다

`get_metadata`가 "밴드 → 프레임" 트리를 줄 것으로 기대하지 마라. 캔버스 `1228:1045`는 **플랫 구조**다 — 화면 프레임이 전부 캔버스의 **직계 자식**이고, **밴드는 y좌표 행으로만 구분된다.** 밴드 하나를 통째로 집는 `nodeId`가 존재하지 않으므로, 밴드 단위로 좁히려면 좌표로 걸러야 한다.

### ⚠️ 이름이 같은 프레임이 여러 개일 수 있다 — 왼쪽부터 읽으면 구 세대를 만난다

같은 화면 코드가 **여러 프레임에 붙어 있다**(상태 변형·재디자인 누적). 구·신 세대는 앱바 높이·배경색·카드 방향·FAB 유무가 달라서, 먼저 만난 것을 정본으로 삼으면 **이미 구현된 화면과 어긋난 것을 그리게 된다.**

세대를 한 신호로 단정하지 마라. 나중에 그린 것이 대개 행 오른쪽 끝에 붙지만 `default`가 왼쪽에 있거나 상태 변형보다 낡은 반례가 실측됐고(상세는 하네스 변경이력), 좌표는 사용자가 수시로 옮긴다. 세대 판정 축은 밴드 행(y)·이름 규약이다(`rules/figma-traps.md` — 지도 출처 표기와 `[보관]` 접두는 축이 아니다).

→ 같은 코드의 프레임이 둘 이상이면 행·이름·내용을 함께 보고 **무엇을 정본으로 삼았는지 브리프에 명시**한다. 어느 세대를 따를지는 화면 정본 문서가 정해 뒀을 수 있다(예: U1 `frontend-components.md` 머리말이 "상태 변형은 구 프레임의 동작·문구만 취하고 레이아웃은 신 default 기준 재해석"으로 확정).

**프레임 이름과 내부 노드 이름이 다를 수 있다.** 화면 코드로 프레임을 찾다가 안 나오면, 그 코드가 내부 노드 이름(예: 지도 노드 `h05map`)으로 옮겨 붙었는지 확인한다.

## 이 표가 낡았을 때

밴드 구성이 이 표와 다르면 **라이브가 옳다.** 브리프에 `문서-라이브 드리프트: {요지}`를 **명시만** 한다 — 이 파일을 고치는 것은 [기록]의 scribe다(밴드 수준만, 화면 목록은 여기 두지 않는다). [인지]가 사이클 도중 하네스 파일을 고치면 변경 집합이 오염된다.
