# Figma 화면 구조 (밴드 맵)

**어느 밴드를 라이브로 읽을지 판단하는 용도.** 화면 상세(레이아웃·IO·컴포넌트)는 여기 없다 — 라이브 Figma가 유일한 정본이다.

## 파일

- 파일 키: **`1MTF3dtptIrbg8gld5IdO2`**
- 단일 페이지 "화면" = 노드 **`1228:1045`**
- URL 없이 이 키로 바로 읽는다 — 사용자에게 URL을 매번 묻지 않는다.

## 밴드

| 밴드 | 도메인 | 범위 |
|---|---|---|
| `a` | 홈 | first-cut |
| `b` | AI 어시스턴트 | M16 — 밖 |
| `c` | 온보딩·인증 | first-cut (U0) |
| `d` | 탐색 | first-cut |
| `e` | 숙소 | first-cut |
| `g` | 여행 생성 | first-cut |
| `h` | 일정 생성 | first-cut |
| `i` | 여행중·Plan-B | first-cut |
| `j` | 기록·회고 | first-cut |
| `k` | 커뮤니티 | M15 — 밖 |
| `l` | 알림·마이·설정 | first-cut |
| `m` | 공동편집 | M17 — 밖 |

- **`f` 밴드는 없다.** 결번이니 찾지 마라.
- `b`·`k`·`m`은 first-cut 범위 밖 — 해당 밴드 작업 요청이 오면 범위 밖임을 먼저 알린다.
- 화면은 밴드 코드 + 번호로 명명한다(`c01`, `c02`, `d01`…).
- **번호도 결번이 있다.** 밴드 `e`는 `e00`·`e02`~`e05`로 **`e01`이 없다**. 번호가 비었다고 "못 찾았다"로 판정하지 마라 — 있는 것만 세라.

## 읽는 절차

1. `get_metadata(fileKey[, nodeId])` — 프레임 목록
2. `get_design_context` / `get_screenshot` — 대상 화면의 디자인·스크린샷

**토큰 주의**: `get_metadata`로 페이지 전체를 뜨면 1MB를 넘길 수 있다. 대상 노드로 좁히거나, 목록은 최상위 프레임(2칸 들여쓰기)만 추출한다.

### ⚠️ 캔버스는 플랫이다 — 밴드 컨테이너 프레임이 없다

`get_metadata`가 "밴드 → 프레임" 트리를 줄 것으로 기대하지 마라. 캔버스 `1228:1045`는 **플랫 구조**다 — 화면 프레임이 전부 캔버스의 **직계 자식**이고, **밴드는 y좌표 행으로만 구분된다.** 밴드 하나를 통째로 집는 `nodeId`가 존재하지 않으므로, 밴드 단위로 좁히려면 좌표로 걸러야 한다.

### ⚠️ 이름이 같은 프레임이 여러 개일 수 있다 — 왼쪽부터 읽으면 구 세대를 만난다

같은 화면 코드가 **여러 프레임에 붙어 있다**(상태 변형·재디자인 누적). 밴드 `e`의 `e02`는 **6개**다(상태 5 + default 1).

**세대가 x좌표로 갈린다** — 나중에 그린 것이 행의 **오른쪽 끝**에 추가된다. `e02` default(신 세대)는 `x=6208`로 행 맨 끝에 있어서, **왼쪽부터 읽으면 구 세대를 먼저 만난다.** 구·신 세대는 앱바 높이·배경색·카드 방향·FAB 유무가 다르므로, 먼저 만난 것을 정본으로 삼으면 **이미 구현된 화면과 어긋난 것을 그리게 된다.**

→ 같은 코드의 프레임이 둘 이상이면 **x좌표를 확인하고, 무엇을 정본으로 삼았는지 브리프에 명시**한다. 어느 세대를 따를지는 화면 정본 문서가 정해 뒀을 수 있다(예: U1 `frontend-components.md` 머리말이 "상태 변형은 구 프레임의 동작·문구만 취하고 레이아웃은 신 default 기준 재해석"으로 확정).

**⚠️ 이 x좌표 규칙은 보편적이지 않다 — `default`가 항상 오른쪽 끝은 아니다.** `e05`는 반례다: `default`(`1703:1183`)가 x=3958로 3탭 상태 그룹(`1354`~`1359`, x=4408~5308)보다 **왼쪽**에 있다(`e02`에서는 규칙이 맞는다). 어긋난 것은 밴드 구성이 아니라 **"오른쪽 = 신 세대"라는 판정 규칙 자체의 보편성**이다 — x좌표만으로 세대를 단정하지 말고, 프레임 이름(`default` 여부)과 화면 정본 문서를 함께 확인한다(실측 2건 연속 보고, 상세는 하네스 변경이력).

**⚠️ x좌표·`default` 이름 말고 세대를 가르는 축이 둘 더 있다 — `h05` 조사(TRIP-339)에서 나왔다.**

- **이름의 `[보관]` 접두사.** 구세대 프레임 이름 앞에 붙는다.
- **저작권 표기.** 구세대 지도는 `© OpenStreetMap · CARTO`, 신세대는 `© Kakao` — 지도가 들어간 화면이면 이 표기로도 세대를 가를 수 있다.

**프레임 이름과 내부 노드 이름이 다를 수 있다.** `[보관]` 구세대 프레임의 이름은 `h05`가 아니라 `g03`이었다 — 코드로만 찾으면 놓친다. 반대로 그 프레임 **안**의 지도 노드 이름은 `h05map`이다. 화면 코드로 프레임을 찾다가 안 나오면, 그 코드가 내부 노드 이름으로 옮겨 붙었는지 확인한다.

**`default`가 항상 최신인 것도 아니다.** `h05`의 `default` 프레임이 상태 변형 6개보다 낡은 사례가 나왔다(안내 문구가 1줄 — 변형들은 2줄). §"`default`가 항상 오른쪽 끝은 아니다"에 이어, **"`default` = 최신"도 보편 규칙이 아니다**(실측, 상세는 하네스 변경이력).

## 이 표가 낡았을 때

밴드 구성이 이 표와 다르면 **라이브가 옳다.** 브리프에 `문서-라이브 드리프트: {요지}`를 **명시만** 한다 — 이 파일을 고치는 것은 [기록]의 scribe다(밴드 수준만, 화면 목록은 여기 두지 않는다). [인지]가 사이클 도중 하네스 파일을 고치면 변경 집합이 오염된다.
