# [FE] 지라 서브태스크 작성

## 서식이 왜 규칙인가

이 티켓은 사람만 읽는 문서가 아니다. dev-cycle [인지]의 spec-analyst가 **티켓의 `정본 경로` 절을 1차 판정 경로로 그대로 읽는다**(정본: `<리포 루트>/frontend/.claude/agents/spec-analyst.md` 「정본 경로 판정」 1항). 경로가 틀리면 그 사이클 전체가 틀린 문서 위에서 돈다 — 게이트①까지 가서야 드러난다.

그리고 그 자리 규칙은 이미 **"티켓 설명은 작성 시점의 사본이라 갈라진다"**고 적고 있다(실측 2건, 상세는 하네스 변경이력). 사본이 나중에 갈라지는 것은 막을 수 없다. 막을 수 있는 것은 **쓰는 시점에 이미 틀린 것을 쓰는 일**뿐이다. 그래서 아래 실측 규칙이 서식보다 먼저 온다.

**서식 원문과 절별 규칙은 [reference/template.md](reference/template.md)에 있다** — 본문을 쓰기 직전에 읽는다. 여기(SKILL.md)에 옮겨 적지 마라, 사본은 갈라진다.

## 절차

### 1. 부모·형제 조회 — 항상 먼저

```bash
~/.claude/scripts/jira.sh get <부모키>          # 스토리 본문 + SUBTASKS 줄
~/.claude/scripts/jira.sh get <형제키>          # 이미 있는 칸이 있으면 전부
```

형제를 먼저 읽는 이유는 중복 방지만이 아니다. **선행조건 체인이 이미 서 있으면 새 칸은 그 끝에 붙어야 하고**, 형제가 남긴 "결정 필요"·"반쪽인 곳"이 새 칸의 선행조건인 경우가 많다.

### 2. 정본 읽기

정본 위치 판정은 이 스킬이 정하지 않는다 — **`spec-perception` 스킬의 문서 참조 맵**과 **spec-analyst.md 「정본 경로 판정」 3단계**가 정본이다. 그대로 따른다. 요약하면: 유닛 디렉토리를 이름으로 추측하지 말고 `ls <리포 루트>/aidlc/aidlc-docs/construction/`으로 실존을 확인한 뒤 연다.

[FE] 칸이 최소로 필요로 하는 것:

| 무엇 | 어디 |
|---|---|
| 스토리·AC 원문 | `inception/user-stories/stories.md` (US 코드) |
| 비즈니스 규칙 | `construction/{unit}/functional-design/business-rules.md` (BR-* 코드) |
| 컴포넌트·testID·PBT 대상 | `construction/{unit}/functional-design/frontend-components.md` |
| API 계약 | `backend/docs/design/openapi.yaml` — **브랜치를 확인하라**(아래 실측 표) |
| 프론트 구조·재사용 API | `frontend/README.md` · `frontend/docs/structure.md` |

### 3. 실측 — 이 스킬의 본체

**티켓의 모든 사실 주장은 아래 명령 중 하나의 출력에 근거해야 한다.** 확인하지 못한 것은 지우지 말고 "미확인"으로 남긴다 — 빈칸은 다음 사람이 채우지만, 그럴듯한 추측은 아무도 다시 안 본다.

| 쓰려는 문장 | 실행해서 확인 | 못 하면 |
|---|---|---|
| "Figma: {밴드} · {변형} (라이브 확인 완료)" | 밴드 맵(`frontend/.claude/skills/spec-perception/reference/figma-structure.md`)으로 밴드를 정하고 `mcp__figma__get_metadata`/`get_screenshot`으로 **실제 조회** | "Figma 미확인 — 밴드 {코드} 추정, 확인 필요". **폴백 없음**: 리포에 화면 명세 사본이 없으므로 조회 실패는 곧 근거 부재다 |
| "리포 거리: {파일}이 {상태}" | `ls`·`wc -l`·`grep -rn "^export" src/shared src/features` | 적지 않는다. 실측 없는 "리포 거리"는 이 절의 존재 이유를 무효화한다 |
| "응답 계약 {필드}" · "GET {경로}" | `git show origin/develop:backend/docs/design/openapi.yaml` — **main에는 U0 경로뿐이다.** 프론트 브랜치 사본도 낡았을 수 있다 | "계약 미확인 — {경로}가 openapi에 없음"을 스코프가 아니라 **막힌 이유**로 적는다 |
| "construction {문서} §{절}이 {내용}" | 해당 파일을 열어 절 번호까지 확인 | 절 번호를 지어내지 않는다. 문서명까지만 적는다 |
| "선행조건: {앞 칸}" | 형제 티켓 상태(`jira.sh get`)로 확인 | — |

**문서와 구현이 어긋나면 그것 자체를 티켓에 적는다.** 숨기고 문서 쪽을 따라 쓰면 구현자가 존재하지 않는 API를 호출한다. TRIP-181이 실제로 그랬다 — construction §3은 `GET /stays?region=`과 무한 스크롤을 적었지만 실제 API는 `GET /stays/search`이고 페이지네이션 파라미터가 없다. 티켓은 그 사실을 `문서-구현 드리프트 주의` 절로 적고, 루트 CLAUDE.md 정본 규칙(구현 결정은 소유 패키지 canon이 정본)으로 어느 쪽을 따를지까지 못박았다. **드리프트를 발견하고도 안 적으면 티켓이 그 드리프트를 구현으로 전파한다.**

### 4. 칸 분해

한 스토리를 [FE] 칸 N개로 쪼갠다. 크기 기준은 **게이트②에서 사람이 한 번에 검토할 수 있는 분량**이다.

- **조용히 실패하는 선행은 반드시 독립 칸.** 낡은 openapi 위에서 돌린 codegen은 에러 없이 성공하고 클라이언트만 안 생긴다 — 뒤 칸에 묻으면 그 칸이 두 배가 되고 실패 지점이 가려진다(TRIP-179가 0번 칸인 이유).
- **바깥 의존이 없는 순수 로직은 병렬 칸.** 서버·화면과 무관하면 선행조건이 없다(TRIP-180 formatPrice).
- **default 화면과 상태 변형을 나눈다.** default가 서야 상태를 얹는다. 묶으면 한 게이트에서 볼 것이 6배가 된다(TRIP-181 / 182).
- **막힌 것은 격리한다.** 선행 갭이 있는 부분을 다른 칸에 섞으면 그 칸까지 같이 멈춘다(TRIP-183은 보류 상태로 따로 섰다).
- 각 칸은 **선행조건 한 줄**을 가진다. 체인이 안 그려지면 아직 덜 쪼갠 것이다.

**갭을 스코프로 위장하지 마라.** 선행(백엔드 API·외부 등록·리빌드)이 없어 못 하는 칸은 "상태: 보류 + 막힌 이유 + 필요한 선행 작업"으로 적고, 스토리 AC 중 **무엇이 미충족인지 명시**한다. 안 남기면 다음 사람이 AC 만족으로 오인한다(INV-4 침묵 실패 금지와 같은 취지).

### 5. 승인 게이트 → 생성

**본문을 파일로 쓰고 사용자에게 전문을 보인 뒤, 승인을 받고 생성한다.** 지라 생성은 되돌리기 비싼 외부 쓰기다(삭제 권한이 없으면 빈 티켓이 영구히 남는다).

제시 형식: 칸별 `요약 / 선행조건 / 미확인·결정 필요 개수`를 표로 보이고, **미확인·결정 필요·반쪽인 곳 항목은 전량 펼쳐 적는다.** 본문 전문은 파일 경로로 제시하고 요청이 있을 때만 출력한다 — 사용자가 게이트에서 판단할 것은 서식이 아니라 **무엇이 확인 안 됐고 칸 경계가 맞는가**이고, 전문을 쏟으면 그 항목들이 서식에 묻힌다.

```bash
# 본문은 $CLAUDE_JOB_DIR/tmp 또는 _workspace 아래에 .md 로 쓴다
~/.claude/scripts/jira.sh create-sub <부모키> "[FE] 요약" body.md   # 생성 (자기 자신에게 배정)
~/.claude/scripts/jira.sh describe   <티켓키> body.md               # 기존 본문 교체
```

두 명령은 본문 한 줄을 ADF 문단 하나로 바꾼다 — TRIP-179~183과 **동일한 구조**로 저장된다(왕복 무손실 확인함). 그래서 본문 파일은 **평문 마크다운이 아니라 지라에 그대로 보일 텍스트**로 쓴다: `##` 헤딩이나 `**굵게**`를 쓰면 문자 그대로 렌더된다.

## 유지 판정

*이 스킬이 만든 티켓으로 dev-cycle을 4회 돌린 시점에 판정한다. 세는 것은 **[인지]에서 spec-analyst가 낸 `티켓-리포 드리프트` 보고 건수**다(scribe가 개발로그에 남긴다). 0건이면 실측 절이 값을 하고 있다는 뜻이므로 유지한다. 드리프트가 계속 나오면 원인이 어느 실측 칸인지 특정해 그 줄만 강화한다 — 절 전체를 손대지 않는다.*
