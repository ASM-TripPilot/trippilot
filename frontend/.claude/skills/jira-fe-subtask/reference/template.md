# [FE] 서브태스크 서식

본문은 지라에 **한 줄 = 한 문단**으로 저장된다(`jira.sh create-sub`/`describe`). 마크다운 문법은 문자 그대로 렌더되므로 `##`·`**굵게**`·표를 쓰지 마라. 계층은 `-` 와 들여쓰기로만 만든다.

## 요약(summary)

```
[FE] {밴드코드 있으면} {대상} — {구체} ({근거코드 또는 상태})
```

실물:
- `[FE] e02 숙소 검색 결과 — 목록·카드 default (US-STAY-01)`
- `[FE] e02 상태 변형 5종 — 로딩·무결과·필터0건·부분실패·전체실패`
- `[FE] 가격 표기 순수 함수 formatPrice + PBT (가격 미확인 · INV-3)`
- `[FE] 탐색 진입 — e00 지역 선택 + '내 주변' (백엔드 결정 대기)`

화면 칸이면 밴드코드를 앞에 둔다 — 목록에서 같은 화면의 칸들이 붙어 보인다. 인프라 칸은 밴드가 없으므로 생략한다.

## 본문 절 순서

고정 3절(**스코프 · 근거 · 선행조건**)과 구분선 뒤 2절(**수용 기준 · 정본 경로**)은 항상 있다. 나머지는 그 칸에 해당할 때만 넣는다 — 빈 절을 남기면 다음 칸에서도 습관으로 비워둔다.

```

{증거 절 — 해당하는 것만, 0~3개}

Figma: (화면 칸이면 필수)

선행조건: (필수)

DoD
- (검증 조건이 자명하지 않을 때)

---

- (필수)

정본 경로 (사이클 [인지] 입력)

```

## 절별 규칙

### 스코프

**만들 것을 파일·컴포넌트·규약 단위로 적는다.** "구현한다" 같은 동사만 있는 줄은 스코프가 아니다.

```
스코프
- 라우트 src/app/stays/index.tsx 신설
- StaySearchResult — 헤더 "{지역} · 날짜 미정 · N곳" + 카드 목록
- StayCard — 이름 · 최저가 스냅숏 · 거리 · 하트 토글
- testID 규약: stay-card-{stayId} · stay-card-save-{stayId} · stay-search-filter-{axis}
```

화면·상호작용 칸이면 **testID 규약 줄을 넣는다.** 테스트가 붙잡을 손잡이를 티켓이 미리 못박아야 test-designer와 implementer가 같은 이름을 쓴다. 규약이 `frontend-components.md` §testID에 있으면 그대로 인용하고, 없으면 이 칸에서 정한다는 사실을 적는다.

### 증거 절 (해당할 때만)

| 절 이름 | 넣는 때 | 무엇을 적나 |
|---|---|---|
| `왜 독립 칸인가` | 인프라·선행 칸 | 뒤 칸에 묻으면 **어떻게 조용히 실패하는지**. 정당화가 아니라 실패 시나리오다 |
| `응답 계약 ({확인일})` | 서버 데이터를 그리는 칸 | openapi에서 실제로 읽은 스키마·파라미터. 확인일을 적어 언제 기준인지 남긴다 |
| `속성` | 순수 함수·PBT 칸 | 입력 전체에 대해 참인 명제. `frontend-components.md` PBT 대상 표의 원문을 인용 |
| `문서-구현 드리프트 주의` | **어긋남을 발견하면 항상** | 문서가 뭐라 적었는지 · 실제가 무엇인지 · **어느 쪽을 따르는지와 그 정본 규칙** |
| `막힌 이유` | 보류 칸 | 무엇이 없어서 못 하는지. 대안이 정본에 없으면 "정본에 결정 없음"까지 |
| `결정 필요 N건` | 사람이 정해야 할 때 | 번호를 붙여 답할 수 있는 형태로. 배경 사실을 함께 |
| `반쪽인 곳` | 일부만 되는 때 | 되는 범위와 안 되는 범위의 경계 |

드리프트 절 실물(TRIP-181):

```
문서-구현 드리프트 주의
- construction §3 은 GET /stays?region=&filters= 와 "무한 스크롤"을 적었으나, 실제 API 는 GET /stays/search?region&amenity&stayType 이고 페이지네이션 파라미터가 없다.
- 문서가 아니라 구현 계약(openapi.yaml)을 따른다. 루트 CLAUDE.md 정본 규칙: 구현 결정은 소유 패키지 canon(backend/docs/design/)이 정본.
```

세 줄이 다 필요하다 — 무엇이 다른지만 적으면 읽는 사람이 어느 쪽을 따를지 다시 고민하고, 결론만 적으면 왜 그런지 몰라 다음 드리프트에서 반대로 판단한다.

### 근거

**추적 코드 없는 줄을 넣지 마라.** 코드가 문서 간 링크 그래프이고, 코드 없는 인용은 검증할 수 없다. 코드마다 규칙 요지를 한 조각 붙인다 — 코드만 적으면 읽는 쪽이 매번 문서를 열어야 한다.

```
근거
- BR-U1-14 (스냅숏 없으면 "가격 미확인" 표기. 가격 부재는 카드 제외 사유가 아니다)
- INV-3 (소요시간 미표시 · 거리만). 응답 DTO 에 duration 필드 자체가 없다
- construction frontend-components.md §7 PBT 대상 표에 formatPrice(snapshot?) 명시
```

스토리 근거가 없는 칸(아키텍처 선행 작업 등)은 **"US/FR 코드 근거 없음 (스토리가 아니라 아키텍처 선행 작업)"**이라고 적는다. 비워두면 못 찾은 것인지 없는 것인지 구분되지 않는다.

### 리포 거리 · Figma

둘 다 **실측했을 때만** 쓴다(SKILL.md 실측 표).

```
리포 거리: src/features/stay/index.ts 가 export {} 한 줄짜리 빈 스텁. src/app/stays/ 미존재
Figma: e02-숙소 검색 결과 · default (라이브 확인 완료)
```

"라이브 확인 완료"는 **실제로 Figma를 조회했을 때만** 붙는 도장이다. 못 봤으면 `Figma: e02 추정 · 미확인 — 착수 전 확인 필요`.

### 선행조건

한 줄. 없으면 **없는 이유**까지 적어야 병렬 착수 가능 여부가 읽힌다.

```
선행조건: 앞 두 칸 (계약·서버 상태 계층 / formatPrice)
선행조건: 없음 — 서버·화면과 무관한 가장 안쪽. 1번 칸과 병렬 가능
```

### 수용 기준 (AC)

구분선(`---`) 뒤에 온다. 형식:

```
- {유형}: Given {상태} When {행위} Then {관찰 가능한 결과} ({근거코드} — {규칙 원문 요지})
```

- **유형 라벨**(`정상` · `정렬` · `금지` · `loading` 같은 상태명)을 앞에 붙인다 — test-designer가 케이스를 묶는 단위가 된다.
- **Then은 관찰 가능해야 한다.** "올바르게 표시한다"는 테스트로 못 옮긴다. "헤더에 `{지역} · 날짜 미정 · N곳`을 표기한다"는 옮길 수 있다.
- **INV는 금지 AC로 바꾼다.** 불변식은 "하지 않음"이 관찰 대상이라 긍정문으로 적으면 테스트가 안 나온다.
  `- 금지: Given 어떤 응답에 대해서도 When 카드를 렌더하면 Then 소요 시간 문자열이 화면에 나타나지 않는다 (INV-3)`
- **위반 형태를 아는 AC는 그것도 적는다** — 통과 조건보다 오해를 더 잘 막는다.
  `… 가용 결과를 즉시 함께 노출한다 (BR-U1-17). 결과를 감추고 배너만 띄우면 위반이다`
- PBT 칸이면 속성 AC임을 명시하고 **차단 게이트라는 사실**을 적는다(`PBT 는 리포 CI 의 차단 게이트다. 100% 통과하지 못하면 머지 불가.`).
- 보류 칸이면 마지막 줄에 **착수 불가 조건**을 적어 어디까지가 지금 가능한지 가른다.

### 정본 경로 (사이클 [인지] 입력)

구분선 뒤 마지막 절. **spec-analyst가 1차 판정 경로로 그대로 읽는 절이다**(SKILL.md 「서식이 왜 규칙인가」).

같은 유닛의 형제 티켓이 이미 있으면 **그 티켓에서 가져온다** — 유닛 단위 상수라 5개 티켓이 글자까지 같다. 리포에 사본을 두지 않는 이유도 같다: 형제 티켓이 살아 있는 사본이다.

```bash
~/.claude/scripts/jira.sh get <형제키> | sed -n '/^정본 경로/,$p'
```

가져온 뒤에도 **각 경로의 실존을 확인한다**(`ls`·`git show`). 형제가 쓰인 뒤 문서가 옮겨졌을 수 있다.

새 유닛이라 형제가 없으면 아래 줄들을 채운다:

- 스토리·AC: `inception/user-stories/stories.md` (해당 US 코드 전부)
- 비즈니스 규칙: `construction/{unit}/functional-design/business-rules.md` (BR 접두어)
- 프론트 컴포넌트·testID·PBT 대상: `construction/{unit}/functional-design/frontend-components.md`
- API 계약: `backend/docs/design/openapi.yaml` — **어느 브랜치인지와 읽는 명령까지**
- 프론트 아키텍처: `frontend/README.md` · 구조 지도: `frontend/docs/structure.md`
- Figma 밴드 맵: `frontend/.claude/skills/spec-perception/reference/figma-structure.md` (해당 밴드 표시)
- 주의: **이 유닛에서 실제로 밟은 함정** — 이름이 내용과 다른 문서, 제거된 디렉토리 등

마지막 `주의` 줄이 이 절에서 가장 값나가는 부분이다. U1의 실물:

```
- 주의: aidlc/aidlc-docs/planning/ 은 2026-07-17 제거됨. backend/docs/design/U1-API-설계.md 는 이름과 달리 U0 내용뿐이라 숙소 API 근거가 아니다.
```

함정을 밟을 때마다 이 줄에 누적한다 — 다음 칸이 같은 곳에서 시간을 버리지 않는다.
