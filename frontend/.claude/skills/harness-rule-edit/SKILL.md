# 하네스 규칙 문서 편집·기록 규칙

트리거·목표·장치 판정 규칙·모델 배치는 계속 `frontend/CLAUDE.md`에 있다.

## 규칙 본문 편집 규칙(2026-07-23 신설)

규칙 문서(`frontend/.claude/**`)에는 **규칙과 기제까지만 쓴다.** 기제는 *왜 그래야 하는가*를 시점과 무관하게 설명하는 것이라 규칙의 일부다(빼면 경계 사례에서 적용 판단을 못 한다). **사건 식별자 — 사이클 ID·날짜·"몇 건이었다" — 는 옵시디언 `하네스 변경이력.md` 소관이고, 본문에는 `(실측 n건, 상세는 하네스 변경이력)` 한 조각만 남긴다.** 서사가 준수율을 올리는 효과는 실재하므로 통째로 빼지는 않되, 한 문단이 사건 재연에 3문장을 쓰고 있으면 압축 대상이다. **전수 스윕은 하지 않는다** — 그 문단을 다른 이유로 만질 때 함께 적용해 점진 수렴시킨다(잘 도는 문서를 통째로 흔드는 비용이 이득보다 크다).

> ⚠️ **순서가 규칙의 절반이다 — 원장 확인이 먼저다.** 본문에서 사건을 빼기 전에 **그 사건이 `하네스 변경이력.md`에 실제로 있는지 grep한다.** 없으면 소급 기록 행을 먼저 append하고, 그다음에 본문을 압축한다. 첫 적용에서 실제로 걸렸다 — `20260719-trip161-preview` 소실 사건은 **SKILL.md 본문이 유일한 기록**이었고, 확인 없이 압축했다면 그대로 소실이었다. "원장 소관이니 본문에선 뺀다"는 원장에 있을 때만 참이다. *유지 판정: 6사이클 관찰 — 이 규칙을 적용한 문단이 0건이면(= 만질 일이 없었다는 뜻) 규칙을 떼고 필요할 때 그때 판단한다.*

## 변경 이력

원장은 옵시디언 `TripPilot/하네스 변경이력.md`다 — 하네스(에이전트·스킬·settings·`frontend/CLAUDE.md`)를 변경하면 반드시 그 표에 행을 추가하라(append-only, 날짜·변경 내용·대상·사유). 리포 쪽 diff는 git 히스토리(`frontend/.claude/`)로 추적한다.
