# Figma 화면 빌드 (스펙 → Figma)

## 정본 — 누가 무엇을 읽나

| 파일 | 역할 | 읽는 자리 |

| 라이브 캔버스 `1MTF3dtptIrbg8gld5IdO2` 페이지 `1228:1045` | **무엇이 있나**의 유일 정본 | 오케(`get_metadata`→jq), 빌더, QA |
| `frontend/tailwind.config.js` | **값**(색 25·반경 6·간격 7·폰트 8단)의 정본 | 킷이 미러 |

오케는 킷 전문을 읽지 않는다 — 킷은 빌더·QA 몫. 페이지 메타는 1.4MB라 `get_metadata` 결과를 jq/python으로 걸러 top-level 프레임(id·이름·x·y)만 본다.

## 두 종류의 작업 — 어디에 그리는가가 규칙이다

| 작업 | 어디 | 사람 검토 |
|---|---|---|
| **안 그리기**(대안·신규 화면·수정본) | **새 밴드** — 라이브 max y + 600 아래, 제목 프레임 + x 원점 −122·간격 450 | 그린 뒤 — 사용자가 고르면 정본으로 이식 |
| **정본 이식 / in-place 수정** | 정본 밴드 프레임 | **전** — 사용자가 그 안을 골랐을 때만 |

자율 실행(dictate·야간)은 위 행까지만. 이식은 "통째 교체"가 아니라 **정본을 기준으로 수정본에서 배운 것만 옮기기**(킷 §10) — 정본에만 있던 자산이 회귀한다. QA가 "정본 무변경"(새 밴드 모드)·"원본 자산 회귀"(이식 모드)를 단언한다.

## 절차

1. **컨텍스트** — `whoami`로 SWT pro 연결 확인(starter 팀은 6회/월). 라이브 top-level 프레임 목록에서 대상 화면 node id·자매 화면(같은 밴드 신세대)·max y를 얻는다. 옛 id를 받았으면 `rules/figma-traps.md`의 이동·결번 규칙으로 해독(2026-07 이전 id는 6밴드에서 죽었다 — 라이브 이름·좌표로 다시 찾는다). `get_screenshot`으로 대상·자매를 `<스크래치패드>/{cycle-id}/before-{node}.png`에 저장(QA 입력).
2. **스펙 게이트** — 먼저 `Skill(frontend-design)`을 로드한다(5번의 대조 절차와 카피 규칙). 아래 5줄이 다 있어야 빌더를 부른다. 하나라도 비면 사용자 질문(자율 실행이면 그 화면은 보류로 브리핑에).
   1. 이 화면이 사용자에게 시키는 **한 가지 일**.
   2. **실제 카피**(부산 데이터·실제 상태 문구). 플레이스홀더 금지.
   3. **자매 화면 node id** — 어휘를 물려받을 것.
   4. 라이브에서 확인한 **파운데이션 컴포넌트·Variables id**(킷 §0, 못 찾으면 그 사실) — 컴포넌트·변수를 먼저 찾고, 없을 때만 만든다.
   5. **제네릭 대조 한 줄** — "아무 여행앱에나 붙는 화면"과 무엇이 다른지. (`frontend-design`의 "계획을 기본값과 대조" 절차)
   코드 사이클에서 왔으면 `01_spec-analyst_brief.md`가 1~3의 출처다.
3. **빌드** — `Agent(figma-builder)` **1회 1화면**, 완료 알림을 받은 뒤 다음 화면(단일 파일 트랜잭션, 병렬 금지). 입력: 스펙 5줄·node id·밴드 좌표·**절대 경로**(킷·작업공간). 출력: 생성 node id + 스크린샷 경로.
4. **QA** — `Agent(figma-qa)`. high FAIL → 빌더 재호출 1회, 재실패는 누락 명시(조용한 생략 금지). H(슬롭 의심)는 차단 없이 브리핑으로.
5. **산출** — `<리포 루트>/_workspace/{cycle-id}/`(=옵시디언 볼트 `사이클/`)에 `figma-build.md`(node id·결정·함정)·`figma-qa.md`만. **PNG(before/sibling/after)는 세션 스크래치패드에** 둔다 — 판정이 끝나면 가치가 없고 볼트는 iCloud 동기화라 화면당 500KB가 쌓인다. md에는 PNG 경로 대신 node id를 적는다. 사이클 밖 단독 실행이면 `{cycle-id}` = `{YYYYMMDD}-figma-{화면코드}` 이고 **RESUME.md를 만들어 `상태: 종료`를 적는다**(dev-cycle Phase 0이 미완료 사이클로 오인하지 않게).
6. 검토 결과 이식이 결정되면 3~5를 정본 프레임 대상으로 다시(이식 원칙·QA 이식 절 적용), 그 뒤 코드 반영은 `figma-screen-impl`.

## 사이클 접점
dev-cycle 1단계 [인지]에서 spec-analyst가 "Figma에 이 화면 없음/불충분"을 브리프에 적으면, 오케가 4단계 전에 이 스킬을 돌리고 산출 밴드 node id를 브리프에 되돌려 넣는다. 학습자 톤 주입은 **하지 않는다**(사람이 읽는 산출은 스크린샷과 QA 표뿐).

## 하지 말 것
- 코드 토큰 밖 hex·크기·간격. 대괄호 플레이스홀더, 회색 빈 박스, 가짜 상태바.
- 페이지를 이름으로 잡기. 큰 `use_figma` 한 방(≤10 오퍼레이션, `figma-use`).
- 밴드 중간 삽입(뒤 전부 리플로우). 정본 밴드에 470 간격(정본은 450).
- `ALT-`/`COMBO-`/`DREAM-`/`V-`/`BS-`/`u.`/`v.` 노드 찾기·복원 — 정본 승격·삭제됨(2026-07, 상세는 하네스 변경이력).

## 유지 판정 (검사별)
- **스펙 게이트 5줄**: 3회 실행에서 빌더 질문 반환 0건이면(스펙이 항상 충분했다는 뜻) 1·2·3만 남기고 4·5는 권고로 격하.
- **QA H 슬롭 렌즈**: 3회 실행에서 "슬롭 의심"에 사람이 1건도 동의 안 하면 뗀다.
- **figma-qa 독립 판정**: 3회 실행에서 빌더 스크린샷으로는 안 보이던 high 결함 0건이면 QA를 빌더 첨부 스크린샷 검토로 격하.
- **빌더 재호출 1회 상한**: 재실패 누락이 3회 중 2회 이상이면 상한을 2로.
