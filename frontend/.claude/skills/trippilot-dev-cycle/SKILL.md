# TripPilot Dev Cycle — 오케스트레이터

루프 엔지니어링 개발 사이클: 인지 → 메모리 → 설계 → 테스트(게이트①) → 구현(게이트②) → 검증 → 리팩토링 → 재검증 → 기록.

**실행 모드: 하이브리드** — 오케스트레이터(메인 세션)가 사용자 게이트와 MCP 호출(Ouroboros/Obsidian/Figma)을 직접 관리하고, 단계별 전문 작업은 서브 에이전트(`Agent` 도구, 반드시 `model: "opus"`)에 위임한다. 사용자 검토 게이트가 2개 있어 실시간 팀 통신보다 순차 파이프라인이 적합하다.

## 참조 파일 — 해당 시점에 반드시 읽는다

| 파일 | 읽는 시점 |
|---|---|
| [reference/resume.md](reference/resume.md) | **Phase 0 진입 시** — 사이클 ID 탐지·재개 판별·RESUME.md·데이터 전달 프로토콜 |
| [reference/gate-protocol.md](reference/gate-protocol.md) | **게이트①·② 제시 직전** — 원장 기록 형식·해시 규약·제시 형식·이해부채·학습자 모드 |
| [reference/troubleshooting.md](reference/troubleshooting.md) | **검증 FAIL·에이전트 실패·MCP 불가 시** — 에스컬레이션 상한·분기 처리 |

요약으로 대신하지 마라. 게이트 제시와 재개 판별은 형식이 곧 규칙이라, 원문을 읽지 않으면 원장이 오염된다.

## 서브 에이전트 호출 공통 (1단계부터 적용)

**모든 서브 에이전트(spec-analyst·test-designer·implementer·scribe) 프롬프트에 "학습자 톤" 지시를 명시 주입한다.** 이 사용자는 코드 초심자다:

1. 새 문법·API·패턴은 이름만 쓰지 말고 한 줄 개념 설명 병기
2. 테스트는 "준비(Arrange)→실행(Act)→단언(Assert)" 3동작 뼈대로 서술
3. 코드를 읽을 줄 안다고 가정 금지 — diff보다 "무엇을 보장하나" 동작 서술 우선

주입을 빠뜨리면 산출물 톤이 조용히 어긋난다. 게이트 시점의 학습자 규칙(핵심 개념 선정 등)은 reference/gate-protocol.md "학습자 모드"에 있다.

## 경로 규약 (모든 단계 공통)

- **리포 루트**는 `git rev-parse --show-toplevel`로 확정한다 (예: `~/Desktop/dev/trippilot`).
- 사이클 작업 공간: `<리포 루트>/_workspace/{cycle-id}/` — **항상 리포 루트 기준**. cwd 기준 상대경로 금지.
- 서브 에이전트 프롬프트에는 작업 공간과 산출물 경로를 **절대 경로로** 전달한다 — 서브 에이전트의 cwd(frontend)에서 상대경로를 해석하면 생산자와 소비자가 서로 다른 디렉토리를 보게 된다.

## 사이클 체크리스트

응답에 복사해 진행하면서 체크한다:

```
사이클 {cycle-id} 진행:
- [ ] Phase 0: 컨텍스트 확인 (reference/resume.md 읽기)
- [ ] 1. [인지] spec-analyst → 01_brief
- [ ] 2. [메모리] 옵시디언·devlog 조회 + 미상환 이해부채 재노출
- [ ] 3. [설계] Ouroboros → 01b_seed (폴백 포함 항상 생성)
- [ ] 4. [테스트] test-designer → 02 → 🧑 게이트① 승인·원장 기록
- [ ] 5. [구현] implementer → 03 → 🧑 게이트② 승인·원장 기록
- [ ] 6. [검증] qa-verifier → 04_report_{n}
- [ ] 7. [리팩토링] (선택) → re-green + 게이트② 재제시 판정
- [ ] 8. [기록] scribe → 옵시디언·devlog
- [ ] 9. 종료 — RESUME.md "완료" 마킹
```

**각 단계(1~8) 종료 시 공통**: 다음 단계로 넘어가기 전 RESUME.md를 현재 상태로 덮어쓴다 — 이 한 장이 `/clear` 후 새 세션의 유일한 무맥락 진입점이다. 갱신을 빠뜨리면 재개가 직전 단계를 다시 하거나 건너뛴다.

## 규모 분기 (경량 사이클)

단일 파일 수준 + 기존 테스트 유지 범위의 소규모 작업(오타·한 줄 버그픽스·문구 변경)은 [인지]·[설계]를 오케스트레이터가 직접 축약하고(서브 에이전트·인터뷰 생략, 브리프·01b 즉석 작성) **게이트①·②를 1회 통합 제시**로 병합한다.

**깎는 것은 절차뿐이다** — `00_gates.md` 기록 형식(해시·red 로그)과 **이해 체크의 두 축**은 그대로 유지한다. 통합 제시 시의 역질문 배분 규칙은 reference/gate-protocol.md "경량 사이클의 이해 체크"에 있다.

## Phase 0: 컨텍스트 확인

**reference/resume.md를 읽고 그 절차대로 수행한다.** 요약하면: 사이클 ID 확정(브랜치에서 티켓키 도출) → `_workspace/` 상태로 초기실행·재개·부분재실행 분기 → RESUME.md와 00_gates.md 교차 확인 → **사용자에게 상태 요약 제시 후 진행**.

## 사이클 단계

### 1. [인지] — spec-analyst (서브)
`Agent(spec-analyst, model: "opus")` 호출, 대상 작업 설명 + 작업 공간 **절대 경로** 전달.
산출: `01_spec-analyst_brief.md`. 열린 질문이 있으면 다음 단계 전에 사용자에게 제시한다.

### 2. [메모리] — 오케스트레이터 직접
`obsidian-second-brain` 조회 규칙대로:
1. **`구조/` 최신 1건** — 프론트 디렉토리 구조·파일별 역할·무엇이 스텁인지. 코드를 뒤지기 전에 이 지도를 먼저 본다.
2. 최근 개발로그·문제로그·미해결 항목 + 리포 `frontend/docs/devlog/` 최근 파일.

요약을 이후 단계 프롬프트에 반영한다(읽고 버리면 메모리가 아니다). **스냅샷과 실제 리포가 어긋나면 리포가 옳다** — 어긋남을 기억해 뒀다가 [기록]에서 새 스냅샷에 반영한다.
**미상환 이해부채 1~2건을 사용자에게 재노출한다**(간격 반복) — 이번 작업과 관련된 항목 우선. 사용자가 "이제 이해했다"고 하면 상환 처리(status 갱신)를 [기록] 단계에 포함한다.

**파산 차단**: 미상환 부채가 **10건을 넘으면** 새 사이클 대신 정리 세션(폐기/통합/상환)을 먼저 제안한다 — 적립이 상환을 초과하는 장부는 학습 도구가 아니라 빚 독촉이 된다. 이 판정은 여기서 한다(게이트까지 미루면 이미 늦다).

### 3. [설계] — 오케스트레이터 직접 (Ouroboros MCP)
0. **생략 조건**: 브리프의 열린 질문이 0건이고 정본 인용만으로 AC가 충족되면 인터뷰를 생략하고 곧장 폴백 경로(브리프 AC를 01b로 저장, "인터뷰 생략 — 정본 충족" 명시)를 쓴다 — 정본이 이미 답한 질문을 학습 중인 사용자에게 던지는 것은 부하이자 신뢰 손상이다.
1. `mcp__ouroboros__ouroboros_interview`로 브리프의 모호점을 인터뷰한다(세션 기반 — 위임 영수증이 반환되면 지시대로 처리).
2. 모호성 기준 도달 시 `ouroboros_generate_seed(session_id)`로 Seed를 생성한다. Seed는 인터뷰 대화에서 추출되므로 추적 코드가 빠질 수 있다 — 오케스트레이터가 브리프의 추적 코드(US/ADR/INV)를 병기해 보강한다.
3. 결과를 **`01b_ouroboros_seed.md`로 저장한다 — 폴백 포함 항상 생성**: Ouroboros 불가·모호성 게이트 미달 시 브리프의 AC 초안을 01b로 저장하고 "폴백"을 명시한다. (01b가 항상 존재해야 test-designer 입력 경로가 보장된다.)
4. 01b 요약을 사용자에게 제시한다(설계 방향 확인).

### 4. [테스트 작성] — test-designer (서브) → 🧑 게이트 ①
`Agent(test-designer, model: "opus")`, 입력: 01 + 01b (절대 경로).
산출: 실패 테스트 + `02_test-designer_map.md`.
**제시 전 reference/gate-protocol.md를 읽는다.** 전문(02의 "테스트 설계 설명" + 매핑 표 + 주해 달린 테스트 코드)은 게이트 노트에 수록하고, 채팅은 요약 형식(생략 불가 항목 포함) + 이해 체크 2개 → 승인 → 00_gates.md에 게이트① 기록(승인 발화 인용 + 포맷 후 파일 해시 + red 로그). **승인 전 구현 금지.**

### 5. [구현] — implementer (서브) → 🧑 게이트 ②
`Agent(implementer, model: "opus")`. 승인된 테스트를 green으로.
**제시 전 reference/gate-protocol.md를 읽는다.** 전문(03의 "변경 설명" + 전줄 주해)은 게이트 노트에 수록하고, 채팅은 요약 형식 + 이해 체크 2개 → 승인 → 00_gates.md에 게이트② 기록(승인 발화 인용 + 포맷 후 파일 해시 — 테스트 인프라 파일 포함 변경 전체).

### 6. [검증] — qa-verifier (서브)
`Agent(qa-verifier, model: "opus")`, 입력: 변경 파일 목록 + 00_gates.md **절대 경로**.
산출: `04_qa-verifier_report_{n}_{PASS|FAIL}.md` — n은 사이클 내 검증 차수(채번 = 기존 최대 n+1), **덮어쓰기·삭제 금지**. 판정·차수·시각을 00_gates.md에도 append한다(카운터의 정본은 원장).
FAIL·실행 불가·PASS(해시 불일치)의 분기 처리는 reference/troubleshooting.md "검증 단계의 분기"를 따른다.

### 7. [리팩토링] — implementer (서브, 선택)
동작 변경 없는 구조 개선. **완료 후 qa-verifier 재실행 필수(re-green) + 게이트② 재제시 규칙 적용.** 개선 여지가 없으면 건너뛴다.

### 8. [기록] — scribe (서브)
`Agent(scribe, model: "opus")`, 입력: `_workspace/{cycle-id}/` 절대 경로 + 문제/에러 발생 내역 + **게이트에서 수집한 이해부채 목록(상환된 항목 포함)** + **게이트 노트 경로·차수 목록**(개발로그가 링크 허브가 되기 위한 입력). 최신 04 리포트는 경로로 전달하지 않는다 — scribe가 `04_qa-verifier_report_*`를 직접 나열해 최대 n을 스스로 확정한다(선별 전달 오염 방지).
게이트 통과 현황은 scribe가 **04 리포트의 표를 원문 복사**한다 — 오케스트레이터의 요약 재서술로 대체 금지(심판받는 루프의 자기서술이 기록을 오염시킨다). 이해부채는 `TripPilot/이해부채/`에 건별 기록하고, 상환된 항목은 status를 갱신한다.

### 9. 사이클 종료
결과 요약(완료 내용, 게이트 현황 — 00_gates.md·최신 04 리포트 기준, 기록 위치) + 다음 사이클 후보 제시. **RESUME.md의 종료 필드를 "완료"로 마킹**한다(더는 자동 재개 대상이 아님). 하네스 개선 피드백 기회를 제공한다.

## 금지 사항

- 어떤 단계에서도 `aidlc/` 이하 쓰기 금지 — Edit/Write 도구는 settings deny로 기계 강제, **Bash 경유 쓰기는 규칙 준수 + qa-verifier의 `git status <리포 루트>/aidlc` 검사로 탐지**. atlassian MCP 사용 금지.
- 원장(`00_gates.md`) 기록 없는 게이트를 통과로 취급하지 않는다 — 산출물 파일 존재는 "작성됨"이지 "승인됨"이 아니다.
- 에이전트 실패 시 침묵 진행 금지(reference/troubleshooting.md).
