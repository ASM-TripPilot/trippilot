# TripPilot Dev Cycle — 오케스트레이터

루프 엔지니어링 개발 사이클: 인지 → 메모리 → 설계 → 테스트 → 구현·리뷰·리팩토링 → 검증 → 학습 → 기록.

**중간 승인 게이트는 없다 — 전진 전용이다.** 사람이 개입하는 자리는 3-a 맹점 훑기(시작)와 7 [학습](끝) 둘뿐이고, 둘 다 승인이 아니라 이해 검증이다. 검증(6)에서 판단성 이상이 나오면 이 사이클 안에서 되돌리지 않고 문제로그 + 새 티켓으로 넘긴다. 승인·해시 동결·재제시 기계는 2026-08-25에 제거됐다(상세는 하네스 변경이력) — 자동 그물(5-b 적대적 리뷰 · 6 qa)은 그대로다.

**실행 모드: 하이브리드** — 오케스트레이터(메인 세션)가 사용자 상호작용과 MCP 호출(Ouroboros/Obsidian/Figma)을 직접 관리하고, 단계별 전문 작업은 서브 에이전트(`Agent` 도구)에 위임한다.

**작업 공간은 LLM 위키의 원본층이다** — `<리포 루트>/_workspace`는 옵시디언 볼트 `TripPilot/사이클/`으로의 심볼릭 링크다. 경로는 그대로 쓰고, 산출물은 자동으로 위키에 들어간다(검색 본문·링크 종점 — 정본은 `obsidian-second-brain`).

## 서브 에이전트 호출 공통 (1단계부터 적용)

**호출에 `model`을 쓰지 마라 — 자리별 모델의 정본은 각 에이전트 frontmatter다. 예외는 없다.** (4-b가 유일한 예외였으나 4단계 통합으로 그 자리가 사라졌다.)

**모든 서브 에이전트(spec-analyst·test-designer·implementer·code-critic·scribe) 프롬프트에 "학습자 톤" 지시를 명시 주입한다.** 이 사용자는 코드 초심자다:

1. 새 문법·API·패턴은 이름만 쓰지 말고 한 줄 개념 설명 병기
2. 테스트는 "준비(Arrange)→실행(Act)→단언(Assert)" 3동작 뼈대로 서술
3. 코드를 읽을 줄 안다고 가정 금지 — diff보다 "무엇을 보장하나" 동작 서술 우선

주입을 빠뜨리면 산출물 톤이 조용히 어긋난다. 학습 시점의 학습자 규칙(핵심 개념 선정 등)은 reference/learning-review.md "학습자 모드"에 있다.

**산출물 길이 — 실질은 다 담고 패딩만 뺀다.** 함께 주입한다: *"문서 길이를 작업에 필요한 만큼으로 맞춰라 — 내용은 다 담되 중복 요약·보일러플레이트·빈 섹션으로 늘리지 마라."* Opus 5는 **디스크에 쓰는 파일이 이전 모델보다 길어지는 성향**이 정본(Prompting Claude Opus 5)에 명시돼 있고, 우리 산출물은 02·03·게이트 노트가 전부 파일이라 그 성향을 그대로 받는다. **설계 근거·★장치·개념 설명은 실질이므로 감축 대상이 아니다** — 줄일 것은 같은 말의 재서술이다. (전줄 주해는 애초에 산출물에 들어가지 않는다 — 학습 아티팩트·대화 소관이고, 정본은 reference/learning-review.md.) *유지 판정: 6사이클 관찰 — 분량 과다 지적이 0건이면 성향이 실측되지 않았다는 뜻이므로 이 주입을 뗀다.*

**에이전트 프롬프트에 "검증하라·다시 확인하라"를 넣지 마라.** Opus 5는 지시 없이 자기 작업을 검증하므로, 그 지시는 과검증으로 토큰만 늘리고 품질 이득이 없다(정본: Prompting Claude Opus 5 §Task scope and over-verification — 고쳐 쓰는 게 아니라 **빼는 것**이 권고다). 금지 대상은 **한 에이전트에게 자기 출력을 재확인시키는 문구**다 — **검증 대상이 다른 자리는 해당하지 않는다**: 5-b code-critic이 보는 것은 코드가 아니라 **심판(테스트)과 자기 신고**이고(자체 검증은 green을 더 신뢰하므로 원리적으로 못 본다), 6-a qa-verifier는 결정론적 명령 실행이다. **구현 정확성 재검증은 실제로 뺐다** — 차단 실측 5사이클 0건이 근거이고 정본은 code-critic.md다(실측 상세는 하네스 변경이력). ⚠️ **페이블 5는 정반대**라 정본이 검증 하네스를 명시하라고 한다 — 자리 모델이 페이블로 바뀌면 이 항목을 재검토한다. *유지 판정: 6사이클 관찰 — 이 규칙에 걸려 문구를 뺀 건이 0건이면(= 아무도 넣지 않는다는 뜻) 규칙을 뗀다.*

## 경로 규약 (모든 단계 공통)

- **하네스 파일을 가리킬 때는 `<리포 루트>/frontend/.claude/...`로 쓴다.** `<리포 루트>`는 읽는 쪽이 `git rev-parse --show-toplevel`로 푼다.
  - **서브 에이전트의 cwd는 호출마다 다르다**(`frontend/`일 때도, `frontend/.claude/`일 때도 있다 — 실측 확인). 따라서 `.claude/...`도 `frontend/.claude/...`도 안전하지 않다. 기준점을 문자열에 박아야 어디서 읽어도 열린다.
  - 예외: SKILL.md가 **자기 스킬의** `reference/x.md`를 가리킬 때는 스킬 루트 기준 상대경로가 맞다(Claude Code가 스킬 디렉토리 기준으로 해석한다).
- **리포 루트**는 `git rev-parse --show-toplevel`로 확정한다 (예: `~/Desktop/dev/trippilot`).
- 사이클 작업 공간: `<리포 루트>/_workspace/{cycle-id}/` — **항상 리포 루트 기준**. cwd 기준 상대경로 금지.
- 서브 에이전트 프롬프트에는 작업 공간과 산출물 경로를 **절대 경로로** 전달한다 — 서브 에이전트의 cwd(frontend)에서 상대경로를 해석하면 생산자와 소비자가 서로 다른 디렉토리를 보게 된다.

## 사이클 체크리스트

응답에 복사해 진행하면서 체크한다:

```
사이클 {cycle-id} 진행:
- [ ] Phase 0: 컨텍스트 확인 (reference/resume.md 읽기)
- [ ] 1. [인지] spec-analyst → 01_brief
- [ ] 2. [메모리] 옵시디언 개발로그 조회 + 미상환 이해부채 재노출
- [ ] 3. [설계] 🧑 맹점 훑기 제시 → Ouroboros 인터뷰 → 01b_seed (폴백 포함 항상 생성)
- [ ] 4. [테스트] test-designer → 02a 명세 + 02 테스트·red
- [ ] 5. [구현] implementer → 03 → code-critic → 03b(차단 0건) → [리팩토링](5-c, 조건부)
- [ ] 6. [검증] 6-a qa-verifier → 04_report_{n} · 6-b 실기 스모크(조건부) → 04b_smoke_{n} · 판단성 이상 → 새 티켓 후보
- [ ] 7. [학습] 🧑 아티팩트 + 퀴즈 5문항 → 학습노트(이해부채 즉시 영속) — reference/learning-review.md
- [ ] 8. [기록] scribe → 옵시디언(개발로그·개념 병합·린트·로그.md)
- [ ] 9. 종료 — RESUME.md "완료" 마킹
```

**각 단계(1~8) 종료 시 공통**: 다음 단계로 넘어가기 전 RESUME.md를 현재 상태로 덮어쓴다 — 이 한 장이 `/clear` 후 새 세션의 유일한 무맥락 진입점이다. 갱신을 빠뜨리면 재개가 직전 단계를 다시 하거나 건너뛴다.

## 규모 분기 (경량 사이클)

경량 사이클은 [인지]·[설계]·[구현]을 오케스트레이터가 직접 축약한다(서브 에이전트·인터뷰 생략, 브리프·01b·구현 즉석 작성). [학습]은 기본과 같다 — 이미 사이클당 1회다.

**판정은 기본 아니면 경량, 둘 중 하나다 — 중간(하이브리드) 실행은 금지한다.** "오케가 직접 구현하면서 5-b·학습·심판 보강을 임의로 생략"하는 형태가 하이브리드다. 이건 경량이 아니라 **경량보다도 얕은 실행**이고, 실제로 기본 판정 작업에 그걸 씌워 심판 사각지대를 무더기로 낳았다(실측, 상세는 하네스 변경이력). 판정 결과가 밟을 단계를 지배하고, 그 결과를 원장에 남긴다.

**경량도 5-b(적대적 리뷰)를 돌린다 — 이것이 완화를 안전하게 만드는 조건이다.** 5-b를 버리면 "경량 오판"이 비대칭으로 비싸진다(적대적 그물이 없어 사각지대가 커밋된 뒤에야 드러난다). 유지하면 경량으로 잘못 판정해도 그물이 남으므로, 아래처럼 기준을 넓혀도 안전해진다. 승인 동결 테스트를 열면 **뮤테이션 실측도 유지**한다.

**판정은 Phase 0에서 하고 제시 후 승인받는다**(자동 진행 금지). **①·④를 어기면 기본이고, ②·③은 완화된 경계다**:

1. **판단이 하나다 (유지 — 어기면 기본)** — 무엇을 만들지가 티켓·직전 사이클·리뷰 지적으로 이미 확정돼 설계 선택지가 없다. 설계 선택이 열려 있으면 기본이다.
2. **새 계약은 작고 자명한 것까지 허용 (완화)** — testID 몇 개·옵셔널 prop 추가처럼 판단이 안 드는 계약은 경량 OK. **새 컴포넌트·새 순수 모듈·새 API**가 생기면 기본이다.
3. **기존 테스트를 고쳐도 경량 OK (완화)** — 단 뮤테이션 실측을 유지한다(위 5-b 문단). 심판이 실제로 무는지 뮤테이션으로 증명하면 절차를 축약 못 할 이유가 없다.
4. **Figma 화면 표면 신규 없음 (유지 — 어기면 기본)** — `figma-screen-impl`이 필요하면 [인지]를 축약할 수 없다.

⚠️ **파일 개수는 조건이 아니다.** 참조 0인 배럴 14개를 지운 사이클은 파일이 14개여도 판단은 하나였고 정당한 경량이었다(실측, 상세는 하네스 변경이력). 반대로 파일 1개여도 설계 선택지가 열려 있으면 기본이다. **세는 것은 파일이 아니라 판단이다.**

**애매하면 기본이다.** 5-b를 경량에 남겨 비대칭을 줄였지만 0으로 만들진 못한다 — ①·④(설계 선택·Figma 표면)는 5-b가 **사후에 메울 수 없는** 자리라 여전히 기본으로 붙잡는다.

**자율/야간 세션 조항.** 사용자가 잠들었거나 자리를 비운 자율 세션에서 생략 가능한 것은 **사람이 있어야 하는 것뿐**이다 — 3-a 응답·7 [학습]의 퀴즈(→ 아티팩트만 게시하고 학습노트에 "퀴즈 대기"로 기록해 다음 세션에서 사용자가 치르게 한다). **헤드리스로 도는 것은 자율 세션이어도 생략 불가**: 5-b·판정별 서브에이전트·뮤테이션 실측·6 검증·[기록]. 정당한 생략(사람 필요)을 부당한 생략(기계인데 뺌)의 면허로 삼지 마라 — 이 이탈이 실측으로 발생했다(상세는 하네스 변경이력).

**깎는 것은 절차뿐이다** — **주해 전수(아티팩트)**와 **퀴즈 5문항**은 그대로다(경량이면 파일이 1~2개라 아티팩트도 자연히 짧다). 정본은 reference/learning-review.md.

**[기록]은 생략 대상이 아니다.** 경량 사이클도 전 단계를 밟는다 — [기록](8단계)에서 개발로그를 남긴다. 규모 분기가 축약하는 것은 [인지]·[설계]·[구현]의 서브에이전트 위임뿐이다. **빠뜨리면 백필이 불가능하다** — `_workspace/`에 02/03 원문이 없으면 사후에 복구할 재료 자체가 없다.

*유지 판정: 6사이클 관찰 — 완화된 경량(②·③을 열고 돈 사이클)에서 5-b가 잡은 결함이 0건이면 완화가 안전했다는 뜻이므로 유지한다. 경량으로 판정했다가 5-b 차단·6 판단성 이상으로 새 티켓이 난 건이 1건이라도 나오면 그 조건(②·③)을 다시 좁힌다. 실적은 scribe가 개발로그에 남긴다.*

## Phase 0: 컨텍스트 확인

**reference/resume.md를 읽고 그 절차대로 수행한다.** 요약하면: 사이클 ID 확정(브랜치에서 티켓키 도출) → `_workspace/` 상태로 초기실행·재개·부분재실행 분기 → RESUME.md와 산출물 파일 존재 교차 확인 → **사용자에게 상태 요약 제시 후 진행**.

## 사이클 단계

### 1. [인지] — spec-analyst (서브)
`Agent(spec-analyst)` 호출, 대상 작업 설명 + 작업 공간 **절대 경로** 전달.
산출: `01_spec-analyst_brief.md`. 열린 질문이 있으면 다음 단계 전에 사용자에게 제시한다.

**티켓이 있으면 설명 전문(+ 상위 스토리 요약)을 프롬프트에 실어 보낸다** — 서브태스크 설명 끝의 `정본 경로` 절이 spec-analyst 「정본 경로 판정」의 1차 근거인데, 그 자리는 atlassian MCP를 쓰지 않으므로 **전달하지 않으면 1차가 통째로 없는 것이 된다**(2차 story-map 폴백으로 조용히 내려간다). 요약하지 말고 원문을 넘긴다 — 경로가 요약에서 제일 먼저 떨어진다.

**화면·컴포넌트 비주얼이 이번 범위에 있으면 프롬프트에 `figma-screen-impl` 스킬 사용을 명시 지시한다** — 1~2단계(추출·토큰 스냅)로 화면 요구·토큰·에셋 목록이 브리프에 들어온다. 이 분기 판단은 오케 몫이다(에이전트 정의에도 규칙이 있지만, **태울지 말지를 정하는 건 여기다**). Figma 접근 실패는 폴백이 없다 — 리포에 화면 사본이 없으므로 열린 질문으로 올라온다.

### 2. [메모리] — 오케스트레이터 직접
`obsidian-second-brain` 조회 규칙대로. **최근 N건을 훑는 게 아니라 그래프를 탄다** — 그래프가 못 잡는 축이 둘(3·4번) 있다:
1. **`<리포 루트>/frontend/docs/structure.md` — 통독하지 않는다.** 층 무관 절만 남아 작아졌다(~2만자). 매번 읽는 것은 **「한눈에」**. **층별 파일 표는 `.claude/rules/layer-*.md`로 이관돼 만지는 폴더에서 자동 로드**되므로 structure.md에서 따로 열지 않는다(경고도 `.claude/rules/repo-traps.md`가 무조건 로드). 재구현 방지 색인 **「재사용 공개 API」는 새 export를 만들기 전 확인**한다. **리포 추적 파일이라 옵시디언 조회가 아니라 Read다** — 볼트에서 구조 노트를 찾지 마라. *유지 판정: 6사이클 관찰 — path-scoped 층 규칙이 서브에이전트에 안 실려 재구현 사고가 1건이라도 나면 무조건 로드(또는 structure.md 복귀)로 되돌린다.*
2. **건드릴 파일 경로를 그대로 `obsidian_simple_search`에 넣는다** → `설명하는코드`에 그 경로를 선언한 개념 노트가 잡힌다 → **본문**을 읽고 → 대괄호 두 개로 감싼 개념 이름으로 **역링크 검색**. 그 개념을 다룬 과거 사이클·게이트·**미상환 부채**가 나온다 — 걸려 나온 부채가 이번 작업의 위험 지점이다.
   - **코드→개념 진입점은 `설명하는코드` 하나뿐이다.** `structure.md`에는 개념 열이 없다(사본 분기를 막으려고 일부러 뺐다) — 거기서 개념을 찾지 마라.
   - **절차 정본은 `obsidian-second-brain`의 "조회 규칙"이다.** 위 요약과 어긋나면 그쪽이 옳다.
3. **직전 사이클 개발로그 1건 — 인수인계 전용.** `다음에 이어서 할 일`·`⚠️ 실기 미검증`·미커밋 상태는 코드가 아니라 **시간**에 매달려 있어 역링크에 안 걸린다. 최근 N건이 아니라 **직전 1건**이다.
4. **문제로그를 작업 키워드로 검색한다** — 도구·API·파일 이름(`Metro`·`jest.mock`·`eslint` 등). 개념 링크 없는 문제로그는 역링크로 못 잡고, 여긴 최근성이 아니라 **반복**이 관건이라 오래된 것도 걸려야 한다. (실측 근거는 하네스 변경이력)

**개발로그는 옵시디언에만 있다 — 리포 devlog는 폐지됐다.** 볼트 없는 팀원용 사본으로 뒀으나 실제 독자 0(팀 확인 — 존재조차 미인지)이라 지웠다. 옵시디언 MCP 실패 시에는 `_workspace/{cycle-id}/`에 "옵시디언 미기록" 센티넬만 남기고, 그 구멍은 scribe의 백필 점검이 다음 사이클에 메운다(리포에는 아무것도 쓰지 않는다).

요약을 이후 단계 프롬프트에 반영한다(읽고 버리면 메모리가 아니다). **구조 지도와 실제 리포가 어긋나면 리포가 옳다** — 어긋남을 기억해 뒀다가 [기록]에서 `docs/structure.md` 갱신에 반영한다.
**미상환 이해부채 1~2건을 사용자에게 재노출한다**(간격 반복) — 이번 작업과 관련된 항목 우선. 사용자가 "이제 이해했다"고 하면 상환 처리(status 갱신)를 [기록] 단계에 포함한다.

**파산 차단**: 미상환 부채가 **10건을 넘으면** 새 사이클 대신 정리 세션(폐기/통합/상환)을 먼저 제안한다 — 적립이 상환을 초과하는 장부는 학습 도구가 아니라 빚 독촉이 된다. 이 판정은 여기서 한다([학습]까지 미루면 이미 늦다).

### 3. [설계] — 오케스트레이터 직접 (맹점 훑기 → Ouroboros MCP)

#### 3-a. 맹점 훑기 🧑 — **채팅에 직접 제시한다**

구현 전에 사용자가 **못 볼 것**을 짚어 준다. 사용자는 자기가 모르는 것을 질문할 수 없으므로, 질문 목록 자체를 하네스가 만들어야 한다.

**문서에만 적으면 도달하지 않는다** — 브리프에 적힌 경고는 브리프에 머무르고, 그 개념을 [학습]에서 처음 만나면 그대로 이해부채가 된다(실측 1건, 상세는 하네스 변경이력). 이 단계의 산출물은 파일이 아니라 **채팅 메시지**다.

재료: 01 브리프 + [메모리]에서 걸린 개념·부채 + `.claude/rules/repo-traps.md`. 형식은 **3~5줄, 각 줄 "무엇 + 왜 물리나"**:

- 이 리포에서만 걸리는 함정 (일반론 금지 — "OAuth는 보안이 중요합니다" 류는 쓰지 마라)
- 시작 전에 알아둘 개념 이름 — **처음 등장하는 것 위주**
- 이번 범위에서 **못 하는 것** (자격증명·외부 등록·네이티브 리빌드 등 선행조건)
- **참조한 정본의 공백·드리프트** (브리프 맹점 후보 ④)

**맹점 앞에 브리프의 「읽은 정본 경로」 목록을 그대로 낸다** — 사용자가 그 자리에서 직접 열어 보고 판단하기 위한 것이다. 요약하지 말고 경로를 낸다(요약하면 열 수 없다).

제시 후 사용자 응답을 받는다. "이건 안다/모른다"가 곧 3-b의 입력이고, **모른다고 한 개념은 학습노트 §1 "지금 배울 핵심 개념"의 1순위**가 된다.

**정본 반영 선택 🧑** — 공백·드리프트 항목이 있으면 **건별로 반영 여부를 묻는다**(묶어서 한 번에 묻지 마라 — 성격이 다르면 행선지도 다르다). 사용자가 고른 것만 [기록]의 scribe에게 넘긴다. 고르지 않은 것은 개발로그에 관측으로만 남는다.

- **여기서 정본을 고치지 않는다.** 반영은 [기록](8)에서 한다 — 이 시점에 고치면 같은 사이클의 test-designer가 **방금 우리가 쓴 문서**를 AC 근거로 인용하게 된다(요구를 코드에 맞추는 역류).
- 선택 결과는 3-b 인터뷰 입력이 아니라 **[기록] 입력**이다. 오케스트레이터가 사이클 요약에 `정본 반영 선택: {항목} → {행선지}`로 실어 나른다.

*유지 판정: 6사이클 관찰 — ④ 축이 제시한 항목이 0건이면(= 관측할 드리프트가 없다는 뜻) 축을 뗀다. 제시는 되는데 **사용자 선택이 6사이클 연속 0건**이면 반영 배선(scribe (B)·settings deny 완화)만 떼고 축은 관측용으로 남긴다. 실적은 scribe가 개발로그에 `정본 반영 — 제시 n / 선택 n`으로 남긴다.*

#### 3-b. 인터뷰

0. **실행 조건**: 3-a에서 **사용자가 처음 만나는 개념이 하나라도 나오면 인터뷰를 실행한다.** 판정 근거는 `TripPilot/개념/`의 노트 존재 여부 + 미상환 부채 목록이다.
   - **"열린 질문이 없으니 생략"은 생략 근거가 아니다**(구 조건이 실제로 인터뷰를 0회로 만들었다 — 실측, 상세는 하네스 변경이력). 정본이 답하는 것은 *무엇을 만드나*고, 인터뷰가 캐야 하는 것은 *어떤 경우에 어떻게 동작하나*다.
   - 생략은 **신규 개념이 0건일 때만**. 생략 시 01b에 "인터뷰 생략 — 신규 개념 0"을 명시한다.
1. `mcp__ouroboros__ouroboros_interview`로 브리프의 모호점을 인터뷰한다(세션 기반 — 위임 영수증이 반환되면 지시대로 처리). **한 번에 1~2개씩** 묻는다 — 목록으로 쏟으면 사용자가 대충 넘긴다.
2. 모호성 기준 도달 시 `ouroboros_generate_seed(session_id)`로 Seed를 생성한다. Seed는 인터뷰 대화에서 추출되므로 추적 코드가 빠질 수 있다 — 오케스트레이터가 브리프의 추적 코드(US/ADR/INV)를 병기해 보강한다.
3. 결과를 **`01b_ouroboros_seed.md`로 저장한다 — 폴백 포함 항상 생성**: Ouroboros 불가·모호성 게이트 미달 시 브리프의 AC 초안을 01b로 저장하고 "폴백"을 명시한다. (01b가 항상 존재해야 test-designer 입력 경로가 보장된다.)
4. 01b 요약을 사용자에게 제시한다(설계 방향 확인).

### 4. [테스트 작성] — test-designer 1회

`Agent(test-designer)`, 입력: 01 + 01b (절대 경로). `model` 미지정 = frontmatter 값.
산출 둘을 **한 자리에서** 낸다:

1. `02a_test-design_spec.md` — 파일 목록 · 케이스별 AAA 뼈대 · **단언 목록**(무엇을 어떤 매처로) · 신규 testID/prop 계약 · red/선제 green 판정+사유 · **★장치·함정 목록(강제 항목)** — 확장 타입 재대입·목 호이스팅 규칙·press 버블링·queryBy+루트존재 짝처럼 코드 수준에서 갈리는 판단 전부를 여기 박는다. ★가 비면 재호출 사유다(주해·퀴즈 재료가 여기서 나온다 — 정본: reference/learning-review.md "주해 내용 규칙").
2. 실패 테스트 + red 실행 확인 + `02_test-designer_map.md`(매핑 표 + 설계 설명). **전줄 주해는 여기 쓰지 않는다** — [학습] 아티팩트에서 낸다.

**02a를 먼저 쓰고 그것을 번역해 테스트를 쓴다** — 한 자리라도 순서는 유지한다. 명세 없이 코드부터 쓰면 ★장치가 사후 정당화가 된다.

**실검증 의무 — 단일 매처와 조합 둘 다.**

- *조합*: **전처리와 탐지기를 함께 태워 본다.** 소스를 가공한 뒤(`stripComments` 등) 정규식으로 훑는 형태면, **가공 결과에 탐지 대상이 살아남는지**를 실제 문자열로 1회 확인한다. 각 요소가 개별로 옳아도 조합이 서로를 지울 수 있다 — 주석 제거가 `//`를 지워 `https://…`를 찾는 단언이 **어떤 구현으로도 통과 불가**가 되고, 같은 원인으로 URL로 적힌 위반이 **조용히 스캔에서 사라진** 사례가 있다(실측 2건, 상세는 하네스 변경이력).

*유지 판정: 6사이클 관찰 — 매처·조합 오기로 인한 test-designer 재호출 0건 유지면 존치, 02a 분량 부담 지적 2회면 "신규 매처만"으로 축소.*

- **심판 결함이 뒤늦게(5-b·6·7에서) 드러나면** 테스트를 고치되 **뮤테이션 실측**(일부러 위반을 심어 red 확인 → 원복 → green 재확인)을 03b 또는 04에 남긴다. 구현이 이미 있어 red 단계가 원리적으로 없으므로, 고친 심판이 실제로 잡는지를 그것으로 증명한다.
- **분할은 시도했다가 되돌렸다** — 4-a(설계)/4-b(작성) 2자리로 나눴던 구조를 트립와이어 재발동으로 통합 복귀시켰다(사용자 결정, 실측 상세는 하네스 변경이력). **다시 나누자는 제안이 나오면 그 원장 행부터 읽어라** — 실제 근본 원인은 위 *조합* 실검증 공백이었다.

- **범위는 심판·자기신고 감사다** — 구현 정확성 재검증은 격하했다(정본은 code-critic.md, 상세는 하네스 변경이력). *조정 조건: 3사이클 관찰 — 경고에서도 실제 조치가 0건이면 5-b 자체를 뗀다.*
- 프롬프트에 **입력 순서를 명시 주입한다**: ① diff + 테스트만 보고 지적 확정 → ② 그 다음 03을 열어 대조. 03을 먼저 주면 구현자 프레임에 갇힌다.
- **차단 0건이어야 5-c로 간다.** 차단이 있으면 5-a 수정 루프(implementer 재호출 → code-critic 재호출).
- **경고·참고는 여기서 고치지 않는다 — 바로 다음 5-c의 입력이 된다.** 여기서 끊기면 지적이 숫자로만 남고 증발한다.
- **경량 사이클에서도 돌린다** — 경량이 5-b를 버리면 오판이 비대칭으로 비싸진다(상세는 하네스 변경이력). 자율 세션이어도 헤드리스라 생략 불가.

#### 5-c. [리팩토링] — implementer 재호출 (조건부)

**[검증] 전인 것이 요점이다 — 5-b와 같은 이유다.** 검증 뒤에 고치면 검증을 다시 돌려야 하고, 그 비용이 실제로 이 단계를 거의 안 돌게 만들었다(실측, 상세는 하네스 변경이력).

**범위 = 테스트가 볼 수 없는 개선.** 기계적 기준은 **4단계 테스트 파일의 diff가 0**인 것이다 — 테스트가 곧 공개 계약이고, 이 단계는 그 선 *아래*만 다룬다.

| | |
|---|---|
| **여기서 한다** | 내부 함수 추출 · 조건 단순화 · 지역 변수명 · 중복 제거 · 파일 내부 구조 |
| **여기가 아니다** | export 이름 · 파일 위치 · prop·testID · 모듈 경계 |

"여기가 아니다"는 **막혔다는 뜻이 아니라 문이 다르다는 뜻이다** — 테스트의 import·`jest.mock` 경로가 그것들을 물고 있어(실측: import 53줄 · `jest.mock` 23파일) 손대면 심판이 바뀐다. **4단계부터 다시 타는 새 티켓**이므로 여기서 시도하지 말고 [기록]에 후속 티켓 후보로 남긴다. implementer의 **테스트 수정 금지는 이 단계에서도 그대로다.**

**입력은 `03b`의 경고·참고다. 목록이 비면 건너뛴다** — 판단 근거는 오케의 느낌이 아니라 이 목록이다.

**처리할지 미룰지는 오케가 가른다**: 위 표의 "여기서 한다"에 들어가고 03b의 재현 시나리오가 구체적이면 처리, 범위·계약을 건드리거나 값 판단이 필요하면 미룬다(후속 티켓 후보). **가른 결과는 양쪽 다 [학습] 아티팩트 요약 ⑤에 올린다** — 사용자가 "미룬 걸 지금 고쳐"라고 하면 **새 티켓 후보**로 기록한다(이 사이클로 되돌아가지 않는다 — 전진 전용).

**완료 후 테스트가 여전히 green인지 확인**하고 6으로 간다. 전체 검증은 6단계가 한 번에 한다.

### 6. [검증] — qa-verifier (서브) → 실기 스모크 (오케, 조건부)

#### 6-a. jest 층
`Agent(qa-verifier)`, 입력: 변경 파일 목록(implementer·test-designer 신고) **절대 경로**.
산출: `04_qa-verifier_report_{n}_{PASS|FAIL}.md` — n은 사이클 내 검증 차수(채번 = 기존 최대 n+1), **덮어쓰기·삭제 금지**. FAIL 카운터의 정본은 `04_*` 파일 개수다.

**FAIL은 두 갈래다** (정본: reference/troubleshooting.md "검증 단계의 분기"):
- **기계적 FAIL**(포맷·lint·tsc·jest red·미신고 변경) → implementer 수정 루프. 상한 도달 시 에스컬레이션.
- **판단성 이상**(설계 의심·code-critic 사각·범위 밖 결함) → **고치지 않는다.** 문제로그 + 새 티켓 후보로 [학습] 요약 ⑥과 [기록]에 넘긴다. 이 사이클 안에서 되돌아가면 그게 곧 재제시 루프다.

#### 6-b. 실기 스모크 🎯
**절차 정본은 `<리포 루트>/frontend/.claude/skills/verify-gates/SKILL.md`의 `## 실기 스모크`** — 발동 조건(diff 판정 5종)·명령·판정 4항목을 그대로 따른다. 산출: `04b_smoke_{n}_{PASS|FAIL|SKIP|실행불가}.md`. 실기 결함은 대부분 **판단성**이다 — 재현 가능한 코드 결함이면 수정 루프, 아니면 새 티켓 후보.

**오케 직영인 이유**: 시뮬레이터·dev build·Metro 기동 여부에 따라 실패 원인이 "코드가 틀림"인지 "환경이 안 됨"인지 갈리는데, 그 구분에는 사용자와의 대화가 필요하다("시뮬레이터 띄워줄래?"). 사용자가 **"qa-verifier는 jest만 돌린다"**로 확정한 바 있고(상세는 하네스 변경이력), 이 배치는 그 결정을 따른다.

**이 단계가 없던 12사이클 동안, 발견된 유일한 실제 동작 결함이 여기서 나왔다** — jest 전부 통과 후 시뮬레이터 레드박스. 발동 조건에 걸리면 건너뛰지 마라.

### 7. [학습] 🧑 — 오케스트레이터 직접 (전용 세션)

**진입 전 reference/learning-review.md를 읽는다.** 코드는 끝났다 — 이 단계는 사용자가 이번 사이클의 테스트·구현을 **한 번에** 읽고 이해를 검증하는 자리다. 승인이 아니다.

요약하면: 핵심 개념 선정 → 학습 아티팩트(HTML) 게시 → 채팅 퀴즈 5문항(테스트축·구현축) → 틀린 함수만 줄 단위 승격 → 학습노트(`TripPilot/학습/`) 작성 + **이해부채 즉시 영속** → RESUME.md `학습: 완료`.

- **`/clear` 후 전용 세션에서 한다**(비용 규약). 본 세션은 이 시점에 산출물이 다 쌓여 있다.
- **되돌아가지 않는다.** 코드가 이상하면 학습노트 결과 절에 `새 티켓 후보`로 적는다. 이해가 안 되면 이해부채다.
- **[기록]보다 앞이다** — 부채·퀴즈 결과·새 티켓 후보가 여기서 생기고, scribe가 그것을 받아 정리한다. 순서를 바꾸면 scribe가 받을 것이 없다.
- 자율 세션이면 아티팩트만 게시하고 학습노트에 "퀴즈 대기"로 남긴다(규모 분기 「자율/야간 세션 조항」).

### 8. [기록] — scribe (서브)
`Agent(scribe)`, 입력: `_workspace/{cycle-id}/` 절대 경로 + 문제/에러 발생 내역 + **학습노트 경로**(이해부채·퀴즈 결과·새 티켓 후보의 원본) + 6단계 판단성 이상 목록. 최신 04 리포트는 경로로 전달하지 않는다 — scribe가 `04_qa-verifier_report_*`를 직접 나열해 최대 n을 스스로 확정한다(선별 전달 오염 방지).
검증 현황은 04 리포트를 `[[사이클/…]]`으로 **링크**하고 판정 한 줄만 쓴다(복사 금지 — 같은 볼트에 있다). 이해부채는 `TripPilot/이해부채/`에 건별 기록하고, 상환된 항목은 status를 갱신한다.

**scribe는 위키 컴파일러다** — 개발로그(원본 요약 페이지) + 개념 노트 병합 + 린트 패스 + `로그.md` 한 줄. 정본은 scribe.md와 `obsidian-second-brain`.

**하네스 규칙 후보는 종료 보고에 싣는다**: scribe가 개발로그에 올린 "하네스 규칙 후보" 목록을 **오케가 9단계 종료 보고에 그대로 옮긴다.** 문제로그가 값을 내는 경로는 [메모리] 조회가 아니라 **하네스 규칙으로 승화되는 것**인데(실측, 상세는 하네스 변경이력), 그 승화는 누가 알아채야만 일어난다 — 보고를 강제해 우연을 없앤다. **판정 형식의 정본은 `obsidian-second-brain`의 문제로그 규칙이다**(여기 옮겨 적지 마라). *유지 판정: 카운터와 조건도 그 정본에 있다 — 거기서 판정이 서면 이 보고 항목도 함께 뗀다.*

### 9. 사이클 종료
결과 요약(완료 내용, 검증 현황 — 최신 04 리포트 기준, 학습노트·기록 위치, **새 티켓 후보**) + 다음 사이클 후보 제시. **RESUME.md의 종료 필드를 "완료"로 마킹**한다(더는 자동 재개 대상이 아님). 하네스 개선 피드백 기회를 제공한다.

**aidlc 반영 대조 (오케 몫)**: `git status <리포 루트>/aidlc`를 직접 돌려 실제 변경 파일을 **스스로 도출**하고 3-a 정본 반영 선택 목록과 대조한다. 목록 밖 변경이 있으면 종료하지 말고 보고한다. 이 대조가 필요한 이유는 순서다 — qa-verifier는 6단계라 8단계 scribe의 쓰기를 못 보고, [기록] 이후 재검증은 조건부라 항상 돌지 않는다. **scribe의 자기 신고를 그대로 믿지 마라**(자기 신고만 믿으면 안 된다는 것은 이 리포에서 이미 실측됐다 — 상세는 하네스 변경이력).

## 금지 사항

- **`aidlc/` 이하 쓰기는 [기록]의 정본 반영에서, 3-a에서 사용자가 고른 항목에만.** 그 외 어떤 단계에서도 금지 — 특히 사이클 도중 수정은 test-designer가 *방금 우리가 쓴 문서*를 AC 근거로 인용하는 역류를 만든다.
  - ⚠️ **기계 강제는 없다.** settings의 aidlc deny는 그 정본 반영 배선을 열기 위해 전량 제거됐다(상세는 하네스 변경이력). **도구가 막아 주리라 기대하지 마라** — 지금 이 금지를 지키는 것은 규칙 준수뿐이고, 위반은 **사후에** qa-verifier의 `git status <리포 루트>/aidlc` 검사와 9단계 오케 대조로만 드러난다.
  - atlassian MCP 사용 금지.
- **검증(6) 뒤에 이 사이클의 코드를 고치지 않는다** — 판단성 이상은 새 티켓이다. 고치면 검증이 무효가 되고, 다시 돌리는 순간 제거한 재제시 루프가 돌아온다.
- 에이전트 실패 시 침묵 진행 금지(reference/troubleshooting.md).
- **미완료 사이클을 두고 하네스 파일(`frontend/.claude/**`)을 고치지 않는다.** 고치면 작업트리에 섞여 qa-verifier의 **미신고 변경 검사에 FAIL로 걸린다** — `20260718-trip161-login` #1 FAIL이 정확히 이것이었고, 리포트가 *"이 FAIL은 implementer 코드 수정 대상이 아니다 — 하네스 파일의 미신고 변경"*이라고 라우팅을 따로 적어야 했다.
  - 원칙은 **미완료 사이클이 없을 때 고치는 것**이다.
  - 불가피하면 **즉시 별도 커밋으로 분리**해 작업트리에서 뺀다(qa는 `git diff --name-only`로 HEAD와 대조하므로 커밋되면 변경 집합에서 사라진다).
  - 사이클 도중 [인지]가 밴드 맵 드리프트를 발견해도 **고치지 않고 보고만 하는 규칙**(spec-perception)이 같은 이유에서 나왔다.
