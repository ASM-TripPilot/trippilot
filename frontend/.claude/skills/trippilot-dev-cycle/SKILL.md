# TripPilot Dev Cycle — 오케스트레이터

루프 엔지니어링 개발 사이클: 인지 → 메모리 → 설계 → 테스트(게이트①) → 구현(게이트②) → 검증 → 리팩토링 → 재검증 → 기록.

**실행 모드: 하이브리드** — 메인 세션이 오케스트레이터로서 사용자 게이트와 MCP 호출(Ouroboros/Obsidian/Figma)을 직접 관리하고, 단계별 전문 작업은 서브 에이전트(`Agent` 도구, 반드시 `model: "opus"`)에 위임한다. 사용자 검토 게이트가 2개 있어 실시간 팀 통신보다 순차 파이프라인이 적합하다.

## 경로 규약 (모든 단계 공통)

- **리포 루트**는 `git rev-parse --show-toplevel`로 확정한다 (예: `~/Desktop/dev/trippilot`).
- 사이클 작업 공간: `<리포 루트>/_workspace/{cycle-id}/` — **항상 리포 루트 기준**. cwd 기준 상대경로 금지.
- 서브 에이전트 프롬프트에는 작업 공간과 산출물 경로를 **절대 경로로** 전달한다 — 서브 에이전트의 cwd(frontend)에서 상대경로를 해석하면 생산자와 소비자가 서로 다른 디렉토리를 보게 된다.

## 게이트 원장 (00_gates.md)

게이트 승인은 `_workspace/{cycle-id}/00_gates.md`에 즉시 영속한다. **이 파일에 기록 없는 게이트는 산출물 파일이 있어도 미통과다** — 파일 존재는 "작성됨"이지 "승인됨"이 아니다.

```
## 게이트① — {승인 시각}
- 승인 테스트 파일: {경로}: {shasum 해시} ...
- red 실행 로그: (원문, 또는 "미실행 — 사유")
## 게이트② — {승인 시각}
- 승인 구현 파일: {경로}: {shasum 해시} ...
```

- 게이트① 제시 전에 오케스트레이터가 테스트를 직접 1회 실행해 red 로그를 첨부한다. 환경 부재 시 "미실행 — 사유"를 기록하고, 이 경우 [검증]에서 qa-verifier가 red 소급 확인을 수행한다.
- 수정 루프·리팩토링으로 코드가 게이트② 승인 해시와 달라진 채 검증을 PASS하면, 기록으로 가기 전에 **게이트②를 재제시**한다(변경 diff와 사유 포함).

## 게이트 제시 규칙 (게이트①·② 공통 — 이해가 병목이다)

사용자의 이해 속도가 사이클의 실제 병목이다. 게이트가 "읽지 않은 승인"으로 변질되면 인지 부채가 쌓인다. 제시 형식으로 이를 방어한다:

- **서술형 우선**: 게이트 제시의 본문은 diff·코드 나열이 아니라 **개념 순서의 서술형 설명**이다 — 왜 이 설계인가 → 데이터/화면 흐름 → 의심해야 할 지점·트레이드오프 순. 원시 diff·코드는 첨부로 제공한다(diff는 코드 순서지 개념 순서가 아니라서 이해 비용이 높다).
- **이해 체크**: 제시 끝에 역질문 2개를 던진다(예: "이 테스트가 커버하지 **않는** 경계는?", "이 구현이 깨진다면 어디부터 깨질까?"). 사용자가 답이 막히면 승인 보류가 아니라 **해당 부분을 더 설명하는 트리거**로 쓴다 — 압박 장치가 아니다.
- **이해부채 수집**: 사용자가 "동작은 믿고 승인하지만 아직 이해 못 함"을 표한 항목은 그 자리에서 목록화한다 → [기록] 단계에서 scribe가 옵시디언 `TripPilot/이해부채/`에 기록하고, 이후 사이클의 [메모리] 단계에서 재노출한다. 숨겨진 인지 부채가 가장 비싸다 — 부채는 숨기지 말고 장부에 올린다.

## Phase 0: 컨텍스트 확인

1. 사이클 ID 결정: `{YYYYMMDD}-{작업슬러그}` (예: `20260717-trip160-scaffold`)
2. `<리포 루트>/_workspace/` 확인:
   - 해당 사이클 폴더 존재 + 부분 수정 요청 → **부분 재실행** (해당 단계만 재호출)
   - 해당 사이클 폴더 존재 + 새 작업 → **새 사이클** (새 폴더)
   - 미존재 → **초기 실행**
3. 재개 시 진행 단계 판별: 산출물 파일 존재 **+ 00_gates.md의 승인 기록**을 함께 본다. 승인 기록 없는 게이트는 그 게이트부터 재개한다.

## 사이클 단계

### 1. [인지] — spec-analyst (서브)
`Agent(spec-analyst, model: "opus")` 호출, 대상 작업 설명 + 작업 공간 **절대 경로** 전달.
산출: `01_spec-analyst_brief.md`. 열린 질문이 있으면 다음 단계 전에 사용자에게 제시한다.

### 2. [메모리] — 메인 직접
`obsidian-second-brain` 조회 규칙대로 최근 개발로그·문제로그·미해결 항목 확인 + 리포 `frontend/docs/devlog/` 최근 파일 확인. 요약을 이후 단계 프롬프트에 반영한다(읽고 버리면 메모리가 아니다).
**미상환 이해부채 1~2건을 사용자에게 재노출한다**(간격 반복) — 이번 작업과 관련된 항목 우선. 사용자가 "이제 이해했다"고 하면 상환 처리(status 갱신)를 [기록] 단계에 포함한다.

### 3. [설계] — 메인 직접 (Ouroboros MCP)
1. `mcp__ouroboros__ouroboros_interview`로 브리프의 모호점을 인터뷰한다(세션 기반 — 위임 영수증이 반환되면 지시대로 처리).
2. 모호성 기준 도달 시 `ouroboros_generate_seed(session_id)`로 Seed를 생성한다. Seed는 인터뷰 대화에서 추출되므로 추적 코드가 빠질 수 있다 — 오케스트레이터가 브리프의 추적 코드(BR/US/INV)를 병기해 보강한다.
3. 결과를 **`01b_ouroboros_seed.md`로 저장한다 — 폴백 포함 항상 생성**: Ouroboros 불가·모호성 게이트 미달 시 브리프의 AC 초안을 01b로 저장하고 "폴백"을 명시한다. (01b가 항상 존재해야 test-designer 입력 경로가 보장된다.)
4. 01b 요약을 사용자에게 제시한다(설계 방향 확인).

### 4. [테스트 작성] — test-designer (서브) → 🧑 게이트 ①
`Agent(test-designer, model: "opus")`, 입력: 01 + 01b (절대 경로).
산출: 실패 테스트 + `02_test-designer_map.md`.
**게이트 제시 규칙에 따라 서술형 설명(무엇을 보장하는 테스트인가, 커버 경계) + 매핑 표 + 테스트 코드(첨부) 제시, 이해 체크 질문 2개 → 승인 → 00_gates.md에 게이트① 기록(파일 해시 + red 로그) + 이해부채 수집. 승인 전 구현 금지.**

### 5. [구현] — implementer (서브) → 🧑 게이트 ②
`Agent(implementer, model: "opus")`. 승인된 테스트를 green으로.
**게이트 제시 규칙에 따라 `03_implementer_notes.md`의 "변경 설명"(개념 순서 서술) 기반으로 제시하고 원시 diff는 첨부, 이해 체크 질문 2개 → 승인 → 00_gates.md에 게이트② 기록(파일 해시) + 이해부채 수집.**

### 6. [검증] — qa-verifier (서브)
`Agent(qa-verifier, model: "opus")`, 입력: 변경 파일 목록 + 00_gates.md **절대 경로**.
산출: `04_qa-verifier_report_{n}.md` — n은 사이클 내 검증 차수, **덮어쓰기 금지**(n이 누적 실패 카운터를 겸한다).
- FAIL → implementer 재호출(수정 루프). **같은 게이트 3회 연속 또는 사이클 누적 FAIL 5회(n 기준) 시 사용자 에스컬레이션 + 에러로그 기록.** 실패 게이트가 번갈아 나와도 누적 상한에 걸린다.
- 실행 불가(도구/설정 부재) → 수정 루프로 보내지 말고 필요한 설정을 사용자에게 보고한다.
- PASS → 게이트② 승인 해시와 현재 코드가 다르면 게이트② 재제시, 같으면 다음 단계.

### 7. [리팩토링] — implementer (서브, 선택)
동작 변경 없는 구조 개선. **완료 후 qa-verifier 재실행 필수(re-green) + 게이트② 재제시 규칙 적용.** 개선 여지가 없으면 건너뛴다.

### 8. [기록] — scribe (서브)
`Agent(scribe, model: "opus")`, 입력: `_workspace/{cycle-id}/` 절대 경로 + **최신 04 리포트 경로** + 문제/에러 발생 내역 + **게이트에서 수집한 이해부채 목록(상환된 항목 포함)**.
게이트 통과 현황은 scribe가 **04 리포트의 표를 원문 복사**한다 — 오케스트레이터의 요약 재서술로 대체 금지(심판받는 루프의 자기서술이 기록을 오염시킨다). 이해부채는 `TripPilot/이해부채/`에 건별 기록하고, 상환된 항목은 status를 갱신한다.

### 9. 사이클 종료
결과 요약(완료 내용, 게이트 현황 — 00_gates.md·최신 04 리포트 기준, 기록 위치) + 다음 사이클 후보 제시. 하네스 개선 피드백 기회를 제공한다.

## 데이터 전달 프로토콜

- 파일 기반, 모두 `<리포 루트>/_workspace/{cycle-id}/`: `00_gates.md`(게이트 원장) / `01_spec-analyst_brief.md` / `01b_ouroboros_seed.md` / `02_test-designer_map.md` / `03_implementer_notes.md` / `04_qa-verifier_report_{n}.md`
- 서브 에이전트 반환값: 경로 + 판정만(대용량 내용은 파일로)
- 최종 산출물(코드·테스트)만 리포 정위치에 두고, 중간 산출물은 `_workspace/`에 보존한다(감사 추적용, git 미추적)

## 에러 핸들링

- 에이전트 실패: 1회 재시도 → 재실패 시 해당 단계 결과 없이 사용자에게 보고한다(침묵 진행 금지)
- 검증 실패 상한: 같은 게이트 3연속 또는 누적 5회 → 중단, 실패 로그 원문 제시, 에러로그 기록
- MCP(Ouroboros/Obsidian/Figma) 불가: 각 스킬의 폴백 사용, 기록에 누락 명시
- 어떤 단계에서도 `aidlc/` 이하 쓰기 금지(`frontend/.claude/settings.json`의 deny로 기계 강제됨), atlassian MCP 사용 금지

## 테스트 시나리오

- **정상**: "TRIP-160 스캐폴딩 사이클 돌려줘" → 1~9 순차, 게이트 2회 승인(00_gates.md 기록), PASS 후 옵시디언·devlog 기록 생성
- **에러**: 검증에서 lint 3연속 실패 → 루프 중단, 실패 로그 원문 제시, 에러로그 노트 생성 후 대기
- **후속**: "어제 사이클 테스트만 다시 봐줘" → Phase 0에서 00_gates.md 확인 → 게이트① 승인 기록 없으면 test-designer 재호출 후 게이트①부터 재개
- **게이밍 방어**: 검증 PASS인데 테스트 파일 해시가 게이트① 기록과 다름 → qa-verifier가 FAIL + 즉시 에스컬레이션(심판 변조)
