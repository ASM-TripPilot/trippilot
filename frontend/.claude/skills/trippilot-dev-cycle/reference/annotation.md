# 대화 주해 규칙

게이트 제시 순서 **6번(대화 주해)** 직전에 읽는다. 어디서 어떻게 진행하는지 · 무엇을 담는지 · 어떤 입자로 · 언제 줄 단위로 내려가는지 · 대화 비용을 어떻게 관리하는지가 여기 있다.

게이트 전체 절차(제시 순서·원장·해시·게이트 노트·퀴즈·이해부채)는 `gate-protocol.md`에 있다. **이 문서는 그 6번 한 칸을 펼친 것이다.**

## 목차

- **진행 방식** — 파일 하나씩·건너뛰기 권한·중간 확인은 승인이 아님 (먼저 읽어라)
- 주해 내용 규칙 — 전수 커버리지·문서 내부 식별자 금지·학습용 사본
- 기본 입자 — 함수 — 배경→직관→흐름 네 절 · 문답형 · 일상어 재서술
- 줄 단위 승격 — 퀴즈가 발동시킨다
- 주해 형식 — 인라인 — `// ▸` 마커
- 비용 규약 — 히스토리 재전송이 비용이다

## 진행 방식 (제시 순서 6)

**주해는 문서가 아니라 대화로 전달한다**(사용자 판정: 문서 한 덩어리로 받으면 이해가 어렵다 — 상세는 하네스 변경이력). 근거는 3-a 맹점 훑기와 같다 — **문서에만 적으면 도달하지 않는다.** 노트에 적어 둔 주해가 실제로 다 읽히는지는 확인할 수 없고, 대화는 막힌 지점이 **즉시** 드러난다.

- **파일마다 배경 → 직관 → 흐름 순으로 가고, 파일을 다 돈 뒤 퀴즈 1회다.** 절별 내용과 비용은 아래 「기본 입자 — 함수」. 퀴즈는 파일마다가 아니라 **게이트당 1회**다 — 파일별로 내면 문항 수가 두 자릿수가 되어 받는 쪽이 접는다.
- **건너뛰기 권한은 사용자에게 있다.** "이 함수는 안다"고 하면 확인 없이 넘어간다. 이것은 전수 원칙의 예외가 아니라 그 원칙의 실행 형태다 — **무엇을 건너뛸지 판단하는 주체는 읽는 사람**이고, 기본값이 전수일 때만 그 권한이 성립한다.
- **한 메시지에 파일 하나다**(사용자 선택). 비슷한 파일이라도 여러 개를 한 번에 담지 않는다 — 묶어 내면 한 화면에서 읽을 양이 임계를 넘고, **그때 접히는 것은 뒤쪽 파일 통째**다. 왕복이 느는 대가는 아래 비용 규약이 진다.
- **반복 함수는 묶어 제안한다**(파일 **안**에서) — `이 3함수는 앞과 같은 형태입니다, 한꺼번에 넘어갈까요?` 오케가 임의로 접지 말고 **묶음 여부를 물어본다.** 파일 사이를 묶는 것은 위 규칙이 막는다.
- **앞을 재인용하지 않는다.** 되돌아보기는 사용자가 요청할 때만.
- **막히면 그 자리에서 재설명한다.** 해소되면 계속, 안 되면 이해부채 등재 후보다(등재 기본값은 `gate-protocol.md` 「이해부채 수집」 그대로 — 넘겨짚기 금지).
- **중간 확인은 승인이 아니다.** `ㄱㄱ`가 20번 나와도 승인은 대화를 다 돈 뒤 **1회**이며, 대상은 제시 순서 3에서 계산한 해시다. 원장 규약("*그 해시의 파일*에 대한 승인", `gate-protocol.md`)이 그대로 적용된다.

## 주해 내용 규칙

주해를 **어디서 어떻게** 진행하는지는 위 「진행 방식」에 있다. 이 절은 **무엇을 담는가**만 규정한다.

- **이번 사이클에서 사람이 작성한 코드는 빠짐없이 전부 대상이다.** 빈 줄·닫는 괄호처럼 설명할 것이 없는 줄을 제외하면 **어느 함수에도 안 속한 코드가 남아서는 안 된다** — 전수인 것은 **커버리지**이고, 갈리는 것은 **입자**다(아래 "기본 입자 — 함수"). 건너뛰기는 사용자가 명시할 때만이다(위 「진행 방식」의 건너뛰기 권한).
- **기본 입자는 함수다.** 함수 하나를 통째로 놓고 *무엇을 받아 무엇을 돌려주나 · 왜 이 분기가 있나 · 누가 부르나* 셋을 답한다. **줄 단위로 내려가지 않는다** — 줄 단위는 퀴즈에서 막힌 자리에만 사후로 붙는다(아래 "줄 단위 승격").
- 처음 볼 가능성이 있는 개념(RN/Expo API·TanStack 패턴·fast-check 문법 등)은 이름만 쓰지 말고 **한 줄 개념 설명을 병기**한다.
- ⚠️ **대화에서는 문서 내부 식별자를 아예 쓰지 않는다.** 괄호 병기도 아니고 **부재**다. 대상은 종류가 아니라 **패턴**이다 — `N4`·`N3-6`(파일·케이스) · `★12`(장치) · `AC-10`(수용 기준) · `D3`(결정) · `I-5`(문구) · 문제로그 날짜, 그 밖에 산출물 문서 안에서만 뜻이 통하는 모든 기호. **받는 쪽은 그 문서를 읽지 않는다** — 대화 서두에 경로를 제시해도 마찬가지다(사용자 판정). 기호는 02a·03·원장이 갖는다. 그쪽이 감사 추적이고, 대화의 목적은 *그때 이해되는 것*이다.
  - **파일은 「역할 이름 + 파일명」으로 부른다**(사용자 선택): `지배인(TripNewStep2Page)` · `계산기(baseGate)`. **괄호는 그 파일이 처음 나올 때만 달고 이후로는 역할 이름만 쓴다**(사용자 선택 — 매번 붙으면 거슬린다). 역할 이름은 3-a의 일상어 재서술에서 정한 비유를 사이클 내내 유지한다(아래 「일상어 재서술」).
    - 괄호에 들어가는 것은 **실재하는 파일 이름**이지 기호 설명이 아니다. `N4(배선 테스트)`는 여전히 위반이다 — 문서 번호는 바깥에서 아무 뜻이 없고, 파일 이름은 사용자가 실제로 찾을 수 있다.
  - **케이스·장치·AC는 하는 일로 부른다**: `★12에 걸린다` → **`핀만 찍고 확인은 안 눌렀을 때 저장이 여전히 막히는지 보는 케이스`**.
  - **제목·표 머리·퀴즈 문항에도 그대로 걸린다.** 실제로 뚫린 자리가 거기다 — 1차 반려는 퀴즈였고 규칙이 퀴즈를 명시하자 2차는 **주해 제목과 표**로 옮겨 갔다. 역할 이름을 곁들였다고 지킨 것이 아니다: **손잡이가 기호면 위반**이다.
  - 내보내기 직전 훑는다 — 주해·퀴즈 본문에 `N\d` · `★` · `AC-\d` · `\bD\d` 가 하나라도 있으면 위반이다(실측 2건, 상세는 하네스 변경이력).

  *유지 판정: 존치 — 실적 2건(2026-08-06 퀴즈 전문 반려 · 2026-08-07 주해 전반 반려)으로 "0건이면 뗀다"는 반대 방향이 확정됐다. 다음 판정은 **강화가 먹었는가**로 바꾼다: 6사이클 관찰 — 위 패턴이 주해·퀴즈에 등장한 건이 0이면 규칙이 물린 것이므로 이 조항을 「일상어 재서술」 어휘 규칙 한 줄로 격하한다. 다시 반려가 나오면 처방이 문면이 아니라 **생성 시점**에 있다는 뜻이므로(오케가 산출물을 옮겨 적는 순간) 그 자리를 손본다.*
- import·타입 선언·설정 객체처럼 "당연해 보이는" 코드도 **목록에서 빠지지 않는다** — 한 덩어리로 묶어 한 줄로 지나갈 수는 있어도 없는 것처럼 다루지는 않는다. 초심자에게 당연한 줄은 없고, **무엇을 자세히 볼지 판단하는 주체는 읽는 사람이어야 한다.**
- **02/03 산출물 문서에는 전줄 주해를 쓰지 않는다.** 같은 주해를 문서·노트·대화 세 번 생산하던 것을 대화 1회 + 막힌 줄 저장 1회로 줄인 것이다(2026-07-26 전환, 상세는 하네스 변경이력). 02/03은 파이프라인 정본으로 남되 담는 것은 매핑·설계 근거·변경 설명이다.
- **그래서 주해 재료는 02a의 설계 근거와 02/03의 매핑·변경 설명이다.** 산출자가 주해 본문을 미리 쓰지 않으므로 *"쓴 사람이 이유를 안다"*는 이점이 사라지고, **근거가 02a에 없으면 대화에서 오케가 추정하게 된다.** 02a의 ★장치·함정 목록이 비면 반려 사유인 이유가 여기서 하나 더 늘어난다.
- **리포의 실제 소스 파일에는 학습 주해를 넣지 않는다.** 리포 주석은 "주변 밀도 준수 + 코드가 말할 수 없는 제약만" 규칙 그대로.
  - 주해가 들어가는 곳은 **02/03 문서와 게이트 노트의 코드블록**이다. 이 코드블록은 읽으라고 만든 **학습용 사본**이라 주석을 달아도 리포 파일은 변하지 않는다.
  - 이 둘을 헷갈려 실제 `.ts`/`.tsx` 파일에 학습 주석을 커밋하면 **게이트② 해시가 달라져 재제시 사유가 된다.** 사본에만 단다.
- **유일한 예외 — 도구 생성 파일**: 스캐폴딩 템플릿·orval 생성물 등 사람이 쓰지 않은 코드는 생성 명령·설정만 주해·해시 대상으로 하고 생성물 자체는 목록+건수만 기재한다. 사람이 그 생성물을 손댔다면 손댄 줄은 주해 대상으로 복귀한다.

## 기본 입자 — 함수

**커버리지는 전수 그대로 두고 입자를 함수로 올린다.** 줄 단위 주해는 조각을 다 설명하고도 *이 함수가 무엇을 하는 물건인지*는 남기지 않는다 — 머리에 남는 것이 줄의 목록이지 동작이 아니기 때문이다(사용자 판정, 상세는 하네스 변경이력).

파일마다 네 절을 순서대로 낸다. **순서가 규칙의 절반이다** — 배경 없이 직관을 내면 비유가 걸릴 데가 없고, 직관 없이 흐름을 걸으면 함수 목록이 된다.

| 절 | 무엇을 내나 | 대화 비용 |
|---|---|---|
| **배경** | 2단 — ① 초심자 배경(이미 아는 것은 `[[개념 노트]]` 링크 한 줄로 대체·건너뛰기 가능) ② 이 변경에 직결된 좁은 배경 | 파일당 2~5줄 |
| **직관** | 이 파일이 무엇의 해답인가 — **본질만, 세부 금지** | 파일당 1~3줄 |
| **흐름** | **문답으로** — 함수마다 셋(무엇을 받아 무엇을 돌려주나 · 왜 이 분기가 있나 · 누가 부르나)을 질문 → 답으로 낸다(아래 「흐름은 문답으로 쓴다」) | 함수당 2~5줄 |
| **퀴즈** | 객관식 5문항 (`gate-protocol.md` 「이해 체크와 이해부채」) | 게이트당 1회 |

**세부를 직관에 섞지 마라.** 직관 절이 구현 세부를 물면 배경도 직관도 아닌 요약이 되고, 그 요약이 "읽지 않은 승인"의 새 대상이 된다.

#### 흐름은 문답으로 쓴다

**흐름 절은 불릿 나열이 아니라 질문 → 답이다.** 같은 내용을 산문형·압축형·문답형 셋으로 나란히 제시했을 때 사용자가 고른 형태다(실측 1건, 상세는 하네스 변경이력).

기제: **불릿은 결론만 늘어놓아** 읽는 사람이 *"왜 이걸 지금 듣고 있나"*를 스스로 복원해야 한다. 질문이 앞에 서면 **읽는 순서가 생각의 순서와 같아지고**, 답이 짧아도 걸릴 데가 생긴다. 그래서 이 전환은 분량을 깎는 장치가 **아니다** — 분량은 그대로 두고 순서만 바꾼다.

- 질문은 **사용자가 그 자리에서 실제로 떠올릴 만한 것**이어야 한다. *"이 함수의 시그니처는?"*은 문답의 탈을 쓴 나열이다.
- 한 함수에 **질문 2~3개가 상한**이다. 넘으면 그 함수가 실은 여러 개다.
- **★장치·함정에 걸린 함수는 "이게 없으면 어떤 가짜가 통과하나"를 질문으로 낸다** — 그 답이 곧 퀴즈 출제 지점이다.

*유지 판정: 3사이클 관찰 — 읽기 어려움 판정이 또 나오면 다음 후보는 **분량**이다(문답형에서도 안 읽히면 남은 변수가 그것뿐이다). 반대로 3사이클 동안 그 판정이 0건이고 퀴즈 오답도 사이클당 1건 이하면 형식이 안정된 것이므로 이 절을 위 표의 한 줄로 접는다.*

#### 일상어 재서술 — 네 절보다 앞선다

**절 구조를 지켜도 어휘가 리포 내부어면 도달하지 않는다.** 함수 단위 전환 첫 적용에서, 절 순서·분량을 규칙대로 지킨 주해가 *"모든 설명이 사실 이해가 안 간다"*로 통째로 반려됐고, 어휘만 걷어낸 재서술로 같은 5파일을 완주했다(사용자 판정: *"이해 된다"*, 이후 *"지금처럼 진행하면 딱 좋겠다"*로 형식 확정 — 실측 1건, 상세는 하네스 변경이력).

파일을 열기 전에 **세 가지를 먼저 낸다.** 이것이 배경 절 ①단의 자리를 겸한다:

1. **화면에서 보이는 그대로** — 사용자가 무엇을 보고 무엇을 누르나. 약어 0개
2. **사고가 날 수 있는 자리 2~4개** — *"`x`를 눌렀는데 원래 하트까지 풀리면 탐색 화면 찜 목록이 날아간다"* 처럼 **피해를 사용자 언어로**
3. **파일이 각각 무엇을 감시하나** — 한 줄 비유 + 표. 파일 이름이 아니라 **역할**로 부른다

그다음 파일별로 배경 → 직관 → 흐름을 돈다. **어휘 규칙**:

- 영어 API·패턴 이름은 **한 줄 개념 설명 없이는 등장 금지**(위 「주해 내용 규칙」과 같은 규칙)
- 기제를 먼저, 이름은 나중에 — *"`Promise.allSettled`를 쓴다"*가 아니라 *"성공이든 실패든 전부 기다렸다 세는 방식을 쓴다(`Promise.allSettled`)"*
- **비유를 하나 정해 사이클 내내 유지한다**(감시자·계산기·메모장·가운데 사람 등). 중간에 갈아타면 앞에서 쌓은 것이 무효가 된다

*유지 판정: 6사이클 관찰 — 재서술 반려가 0건이고 사용자 확인 발화도 0건이면(= 어느 쪽인지 관측이 안 된다는 뜻) 이 절을 「주해 내용 규칙」 한 줄로 격하한다. ⚠️ **"이 형식으로도 반려가 나오면 분량을 의심하라"는 예고는 한 번 시험됐고 빗나갔다** — 실제로 나온 판정에서 사용자가 고른 것은 압축이 아니라 **문답형 + 파일 단위 끊기**였다(실측 1건, 상세는 하네스 변경이력). 분량은 그다음 후보로 내려간다(위 「흐름은 문답으로 쓴다」의 유지 판정).*

**코드블록은 기본적으로 펼치지 않는다.** 함수 이름과 시그니처만 인용하고 본문은 말로 설명한다 — 펼치는 순간 줄 단위로 되돌아간다.

**연속한 함수가 3개를 넘거나 갈래가 지면 문장 대신 흐름도 한 장**을 그린다. 줄줄이 나열한 문장보다 그림 하나가 짧고, 흐름 절의 목적은 "이 함수들이 어떻게 이어지나"다.

- **게이트 노트 §0 자리 지도와 겹치지 않는다** — §0은 **파일 사이**(어느 파일이 무엇을 부르나), 흐름 그림은 **파일 안**(이 파일의 함수들이 어떻게 이어지나)이다. 형식은 §0의 매체 규칙 그대로(`gate-protocol.md`) — 채팅은 ASCII, 게이트 노트는 `mermaid`.
- 그림에 **02a ★장치·함정에 걸린 함수를 표시**한다(`★`). 퀴즈 출제가 그 표시에서 나온다.

## 줄 단위 승격

**줄 단위는 퀴즈가 발동시킨다.** 항상 하는 것이 아니라 **측정된 실패에 대한 응답**이다 — 그래야 퀴즈가 장식이 아니라 예산 배분 장치가 된다.

- **승격 단위는 함수다.** 틀리거나 막힌 문항이 가리키는 **그 함수 하나만** 코드블록을 펼쳐 `// ▸` 주해로 한 줄씩 걷는다. 파일 전체를 다시 펼치지 않는다 — 막힌 것은 그 함수이지 파일이 아니다.
- **사용자 요청도 승격 사유다.** "여기 자세히"라고 하면 퀴즈 전이라도 그 자리에서 펼친다.
- **계획된 노출이 하나 더 있다 — 「앞으로 또 나올 모양」 1~2개**(사용자 결정). 퀴즈 발동은 *실패*에 붙는 사후 예산이라, 그것만으로는 **코드를 아예 안 보는 게이트**가 계속 나올 수 있다. 게이트마다 재활용될 형태를 1~2개 골라 미리 펼친다 — 테스트 코드는 종류가 적어 같은 모양이 계속 돌아오므로 이 적립이 다음 게이트의 비용을 깎는다. 고르는 기준은 **재등장 빈도**이지 난이도가 아니다(첫 적용에서 고른 것은 "준비→누르기→확인" 화면 테스트 한 덩어리였고, 그것 하나로 두 파일 20케이스가 같은 모양으로 넘어갔다). 무엇을 고를지는 **사용자에게 후보를 제시하고 고르게 한다** — 무엇이 또 나올지는 오케가 알고, 무엇이 필요한지는 사용자가 안다.
  *유지 판정: 6사이클 관찰 — 이 노출로 연 코드가 뒤 사이클에서 "이건 안다"로 건너뛰어지는 건이 0건이면(= 적립이 안 된다는 뜻) 뗀다.*
- **승격되지 않은 코드도 승인 대상이다.** 게이트 해시는 파일 전체에 걸리므로 **줄로 보지 않은 코드도 승인에 포함된다** — 이것이 입자를 올린 대가다. 완충은 셋이다: 퀴즈가 이해 구멍을 짚고, code-critic(5-b)·qa-verifier(6-a)가 코드를 따로 보고, 사용자가 언제든 승격한다. **셋 다 못 잡는 결함이 나오면**(계약·경계면처럼 테스트도 리뷰도 통과하는데 사람 눈에만 걸리는 것) 그것이 퀴즈 출제 기준(`gate-protocol.md` 「이해 체크」)을 넓히라는 신호다.

*유지 판정: 3사이클 관찰 — 양쪽으로 센다. **퀴즈 발동 승격이 0건이면** 문항이 변별을 못 하는 것이므로 출제 기준(아래 "이해 체크")을 조인다. 반대로 **사용자 자발 승격이 사이클당 3건 이상이면** 함수 단위가 얕은 것이므로 흐름 절의 밀도를 올린다. 실적은 게이트 노트 §2에 `함수 n · 퀴즈승격 n · 자발승격 n`으로 남긴다(§2 형식은 `gate-protocol.md`).*

## 주해 형식 — 인라인 (승격된 함수·게이트 노트 §3 공통)

**이 형식은 승격된 함수에서만 쓴다** — 기본 흐름 절은 코드를 펼치지 않는다(위 "줄 단위 승격").

**코드 바로 아래에 설명을 붙인다.** 표로 빼거나 뒤에 몰아쓰지 않는다 — 코드와 설명 사이 거리가 벌어지면 눈이 왕복한다. 대화에서 승격된 함수를 펼칠 때와 게이트 노트 §3에 막힌 줄을 남길 때 같은 형태를 쓴다.

- 주해 주석은 **`// ▸` 마커**로 시작한다. 원본 코드에 없는 줄임을 한눈에 구분하기 위해서다.
- 설명이 길면 이어지는 줄은 `//` 들여쓰기로 잇는다.
- "준비(Arrange)→실행(Act)→단언(Assert)" 3동작이 어디인지 보이게 쓴다(학습자 모드).
- 파일 제목 줄에 그 파일이 무엇을 하는지 한 줄을 먼저 단다.

대화에서는 **승격된 함수 안을 한 줄씩** 이 형태로 내고, 게이트 노트 §3에는 그중 **막힌 줄만** 남긴다(아래는 파일 전체를 펼친 예시 — 실제로는 퀴즈가 가리킨 함수 하나만 이렇게 열린다):

````markdown
**`hooks/useAuthBootstrap.test.ts`** — 앱 시작 시 저장된 토큰으로 로그인 상태를 복원하는지 검증
> 아래 코드블록은 학습용 사본이다(`// ▸`는 설명용 추가 줄). 해시 대상은 주석 없는 원본 파일.

```ts
import { renderHook, waitFor } from '@testing-library/react-native'
// ▸ RNTL(React Native Testing Library)에서 도구 두 개를 가져온다.
//   renderHook = 화면을 그리지 않고 훅만 따로 실행해 보는 도구
//   waitFor = 비동기 결과가 나올 때까지 기다려 주는 도구

import { useAuthBootstrap } from './useAuthBootstrap'
// ▸ 검증 대상 훅을 가져온다 — 이 테스트가 무엇을 겨냥하는지 선언하는 줄

it('저장된 토큰이 있으면 인증 상태로 복원된다', async () => {
// ▸ 테스트 1건을 연다. 따옴표 안 문장이 곧 이 테스트가 보장하는 내용이다.
//   async = 이 안에서 "기다림(await)"을 쓰겠다는 표시. 토큰 읽기가 비동기라 필요하다.

  const store = makeTokenStore({ accessToken: 'tok_1' })
  // ▸ 준비(Arrange) — 토큰이 들어 있는 가짜 저장소를 만든다.
  //   실제 SecureStore를 쓰면 기기에 뭐가 저장돼 있느냐에 따라 결과가 흔들린다.

  const { result } = renderHook(() => useAuthBootstrap(store))
  // ▸ 실행(Act) — 가짜 저장소를 넣어 훅을 돌린다.
  //   DI(의존성 주입) = 훅이 저장소를 스스로 만들지 않고 인자로 받게 해서,
  //   테스트에서 가짜로 갈아끼울 수 있게 한 구조.

  await waitFor(() => expect(result.current.settled).toBe(true))
  // ▸ 부트스트랩이 끝났다는 신호(settled)가 true가 될 때까지 기다린다.
  //   기다리지 않으면 아직 로딩 중인 상태를 단언하게 된다.

  expect(result.current.isAuthed).toBe(true)
  // ▸ 단언(Assert) — 인증된 상태로 복원됐는지 확인한다. 이 테스트의 결론.
})
```
````

원본 코드는 한 줄도 바꾸지 않는다 — **주석 줄만 사이에 끼워 넣는다.** 원본과 대조하면 `// ▸` 줄만 빼면 실제 파일과 정확히 같아야 한다.

## 비용 규약

대화형의 비용은 내가 보내는 줄이 아니라 **매 턴 재전송되는 대화 히스토리**다(N번째 턴이 앞의 N-1턴을 다시 읽는다). 그래서 절약은 전부 히스토리를 짧게 유지하는 데서 나온다:

- **전용 세션에서 한다.** 사이클 본 세션은 게이트 시점에 브리프·설계·구현 노트·툴 결과가 쌓여 있고, 그 프리픽스가 왕복마다 곱해진다. `/clear` 후 RESUME.md + 대상 파일만 들고 시작한다.
- **게이트 하나 = 대화 1회차다.** 파일별로 끊지 않는다 — **퀴즈가 게이트당 1회라** 파일마다 `/clear`하면 마지막 세션이 앞 파일 맥락을 잃어 출제가 불가능해진다. 함수 단위로 파일당 산출이 줄어 여러 파일이 한 세션에 들어간다. **길어지면 파일이 아니라 차수로 쪼갠다**(`게이트①-1`·`①-2`, 차수 분할 장치 재사용) — 퀴즈는 **마지막 차수**에 붙이고 앞 차수는 그 차수의 게이트 노트로 넘긴다.
- **한 파일은 끊지 않고 끝낸다.** 중간에 오래 쉬면 캐시가 식어 그때까지의 히스토리 전체를 정가로 다시 낸다.
- **파일 하나씩 끊는 대가는 왕복 수다.** 파일 8개면 왕복도 8회고 그만큼 앞부분이 다시 실린다. 그래도 이쪽을 택한다 — **읽히지 않은 주해는 비용이 싼 것이 아니라 전부 손실**이고, 게이트의 목적은 승인이 아니라 이해다. 절약은 여전히 **승격 여부를 퀴즈에 맡기는 데서** 얻는다.
- **사용자 응답은 짧을수록 싸다** — `ㄱㄱ` 한 글자가 최적이고, 긴 문장은 이후 모든 턴에서 재과금된다. 막힘도 `막힘` + 한 단어.
- **주해 길이는 위 「기본 입자 — 함수」 표 그대로**(함수당 2~5줄, 승격된 함수 안에서만 줄당 1~3줄). 대화형에서 주해 길이는 곧 히스토리 누적 속도이고, **절약은 함수 설명을 깎아서가 아니라 승격 여부를 퀴즈에 맡겨서 얻는다.**
- **02/03에 전줄 주해를 쓰지 않는다**(위 「주해 내용 규칙」) — 3중 생산 제거가 가장 큰 절약이다.
