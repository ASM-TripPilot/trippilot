# 게이트 프로토콜

게이트①·② 제시 직전에 읽는다. 제시 순서, 원장 기록 형식, 해시 규약, 노트·요약 형식, 이해부채 수집이 여기 있다.

## 목차

- **게이트 제시 순서** — 복사해 체크하는 8단계 (먼저 읽어라)
- 게이트 원장 (00_gates.md) — 기록 형식·해시 규약·red 로그·무효화·재제시
- 게이트 노트 — 3계층 구조 + 주해 예시
- 채팅 요약 — 생략 불가 항목 + 형식 예시
- 이해 체크와 이해부채 — 역질문·등재 기준·개념 노트
- 학습자 모드 — 학습자 프로필 주입·핵심 개념 선정
- 경량 사이클의 이해 체크 — 통합 제시 시 두 축 유지

## 게이트 제시 순서

응답에 복사해 체크하며 진행한다. **순서를 바꾸면 원장이 오염된다** — 특히 3(해시 계산)과 7·8(원장 먼저, 노트 나중).

```
게이트{①|②}-{n} 제시:
- [ ] 1. 산출자(test-designer/implementer)가 prettier 통과 — 해시 박제의 전제
- [ ] 2. [게이트①만] verify-gates 사전 점검 → **환경 지문 기록** → red 1회 실행 → 로그 확보
- [ ] 3. shasum으로 파일 해시 계산 — 이 시점 값이 곧 승인 대상
- [ ] 4. 등장 개념 선정 → "지금 배울 핵심 개념 5~7개"
- [ ] 5. 게이트 노트 작성 (옵시디언, 3계층 구조)
- [ ] 6. 채팅에 요약 제시 (생략 불가 항목 + 이해 체크 2개 + 승인 요청)
- [ ] 7. 승인 수령 → 00_gates.md 기록 (발화 인용 + 3에서 계산한 해시 전사)
- [ ] 8. 게이트 노트 결과 섹션 갱신 (승인/반려 · 이해 체크 답변 · 이해부채)
```

- **3 → 7의 해시는 같은 값이어야 한다.** 승인 후 재계산 금지 — 승인은 "그 해시의 파일"에 대한 승인으로 정의된다.
- **7이 8보다 먼저다.** 둘이 갈라지면 원장이 단독 권위다.
- 반려되면 6으로 돌아가지 않고 산출 단계([테스트 작성]/[구현])로 복귀한 뒤 1부터 새 차수로 다시 탄다.

## 게이트 원장 (00_gates.md)

게이트 승인은 `_workspace/{cycle-id}/00_gates.md`에 즉시 영속한다. **이 파일에 기록 없는 게이트는 산출물 파일이 있어도 미통과다** — 파일 존재는 "작성됨"이지 "승인됨"이 아니다.

### 기록 형식

```
## 게이트① — {승인 시각}
- 승인 발화: "{사용자 원문 인용}"
- 승인 테스트 파일: {경로}: {shasum 해시} ...
- red 실행 로그: (원문, 또는 "미실행 — 사유")
- 환경 지문: {있는 설정 파일 목록 + node/pnpm 버전}
## 게이트② — {승인 시각}
- 승인 발화: "{사용자 원문 인용}"
- 승인 구현 파일: {경로}: {shasum 해시} ...
```

필수 필드는 셋이다:
- **사용자 승인 발화 원문 인용**
- **제시 시점 해시의 전사** — 제시 시점에 계산해 채팅 요약에 명시하고(채팅이 사후 수정 불가능한 유일한 채널이다), 원장에는 그 값을 옮겨 적는다
- **환경 지문**(게이트①만) — 제시 시점에 존재한 검증 설정의 목록. verify-gates §0 사전 점검을 돌면서 확인한 것을 그대로 적는다:

  ```bash
  ls package.json jest.config.js jest.integration.config.js eslint.config.js tsconfig.json 2>/dev/null
  node -v; pnpm -v
  ```

  **이 필드가 없으면 "도구를 부숴 FAIL을 판정 불능으로 세탁하는 경로"가 열린다** — qa-verifier가 검증 시점에 이 목록과 대조해, 게이트① 때 있던 설정이 사라졌으면 실행 불가가 아니라 **FAIL + 변조 에스컬레이션**으로 판정한다(verify-gates "0. 사전 점검").

### 해시 규약

- **포맷 후 상태로 박제한다.** 산출자가 게이트 제시 전 prettier를 통과시키는 것이 의무다.
- 검증 단계의 포매터는 멱등이므로 승인 해시를 바꾸지 않는다 — **해시 대조 불일치는 전부 진짜 변조다.**

### red 로그 (게이트①)

- 제시 전에 오케스트레이터가 테스트를 직접 1회 실행해 첨부한다. **verify-gates §0 사전 점검을 선행**한다.
- 설정 부재로 인한 전멸은 red가 아니라 `"미실행 — 사유"`로 기록한다.
- 로그에는 실행 시점 테스트 파일 해시를 병기한다.
- [검증]에서 qa-verifier가 red 소급 확인을 **로그 유무와 무관하게 상시** 수행한다.

### 검증 판정 append

- 판정·차수·시각을 원장에 append한다(qa-verifier 수행). **FAIL 카운터의 정본은 원장이다.**

### 무효화와 재제시

- **부분 재실행 시 하류 무효화**: 특정 게이트를 다시 열면 그 이후 게이트의 원장 항목에 `무효화(사유·시각)` 행을 append한다. **기존 행 수정 금지.** 해시 대조·재개 판별은 항상 각 게이트의 **최신 유효 섹션** 기준이다.
- **게이트② 재제시 조건**: 수정 루프·리팩토링으로 코드가 게이트② 승인 해시와 달라진 채 검증을 PASS하면, [기록]으로 가기 전에 게이트②를 재제시한다(변경 diff와 사유 포함).
  - 이 해시 대조는 **qa-verifier의 04 필수 항목**이다 — 오케스트레이터 자체 판단 금지.
  - 재제시가 반려되면 [구현] 수정 루프로 복귀한다.

## 게이트 노트

게이트 제시 전문은 옵시디언에 저장한다 — **옵시디언에서 읽고, 채팅에서 승인한다.**

- 경로: `TripPilot/게이트/{YYYY-MM-DD} {cycle-id} 게이트{①|②}-{n}.md` (`게이트 템플릿` 구조)
- `n`은 제시 차수. **재제시는 새 차수로, 덮어쓰기 금지.** 무효가 된 구 노트에는 `무효(재제시됨)`를 표기한다.
- 승인/반려 결과는 노트의 결과 섹션에 갱신한다(순서 8).
- Obsidian MCP 불가 시 채팅에 전문을 제시하고 폴백을 명시한다.
- `_workspace/`의 02/03은 파이프라인 정본으로 그대로 유지된다 — 게이트 노트는 열람·학습용 스냅샷이다.

### 3계층 구조 (위에서부터 읽다가 멈출 수 있게)

전줄 주해는 분량을 늘리므로, 통제는 **빼는 방식이 아니라 읽는 순서를 만드는 방식**으로 한다.

**세 계층은 게이트 노트 한 파일 안의 세 섹션이다** — 노트를 쪼개지 않는다. 사용자는 노트 하나만 열면 개념부터 전줄 주해까지 다 있다.

| 계층 | 내용 | 분량 | 반복 단위 |
|---|---|---|---|
| §1. 지금 배울 핵심 개념 | 이번 게이트의 신규/미소화 개념만 | 5~7개 | 노트당 1회 |
| §2. 파일별 요약 | 이 파일이 무엇을 하는가 | 파일당 3~5줄 | **변경 파일마다** |
| §3. 전줄 주해 (부록) | 아래 규칙대로 | 전 줄 | **변경 파일마다** |

"파일별"은 노트가 파일마다 쪼개진다는 뜻이 아니라, 변경된 소스 파일 수만큼 §2·§3 안에서 덩어리가 반복된다는 뜻이다(파일 4개 → 한 노트 안에 §2 4덩어리, §3 4덩어리).

- §1 본문은 **개념 순서의 서술형**이다 — 왜 이 설계인가 → 데이터/화면 흐름 → 의심해야 할 지점·트레이드오프 순. 원시 diff는 코드 순서지 개념 순서가 아니라서 이해 비용이 높다.
- **노트가 둘 이상이 되는 경우는 분할 제시뿐이다**: 30분 초과로 차수를 나누면 `게이트①-1`·`게이트①-2`가 되고 **각 노트가 다시 3계층을 갖는다**.
- 예상 열람 30분 초과면 차수 장치를 재사용해 분할 제시한다.
- 분량이 이해를 이기게 두지 마라 — 다만 **이기지 못하게 하는 수단은 요약의 질이지 주해의 누락이 아니다.**

### 전줄 주해 규칙

- **이번 사이클에서 사람이 작성한 코드는 빠짐없이 전 줄에 주해를 단다.** 빈 줄·닫는 괄호처럼 설명할 것이 없는 줄을 제외하면 **주해 없는 줄이 남아서는 안 된다.**
- 각 줄에 "무엇을 하는가 + 왜 필요한가"를 단다.
- 처음 볼 가능성이 있는 개념(RN/Expo API·TanStack 패턴·fast-check 문법 등)은 이름만 쓰지 말고 **한 줄 개념 설명을 병기**한다.
- import·타입 선언·설정 객체처럼 "당연해 보이는" 줄도 생략 금지 — 초심자에게 당연한 줄은 없고, **무엇을 건너뛸지 판단하는 주체는 읽는 사람이어야 한다.**
- 주해는 산출자(test-designer/implementer)가 산출물 문서(02/03)에 작성한다 — 쓴 사람이 이유를 안다.
- **리포의 실제 소스 파일에는 학습 주해를 넣지 않는다.** 리포 주석은 "주변 밀도 준수 + 코드가 말할 수 없는 제약만" 규칙 그대로.
  - 주해가 들어가는 곳은 **02/03 문서와 게이트 노트의 코드블록**이다. 이 코드블록은 읽으라고 만든 **학습용 사본**이라 주석을 달아도 리포 파일은 변하지 않는다.
  - 이 둘을 헷갈려 실제 `.ts`/`.tsx` 파일에 학습 주석을 커밋하면 **게이트② 해시가 달라져 재제시 사유가 된다.** 사본에만 단다.
- **유일한 예외 — 도구 생성 파일**: 스캐폴딩 템플릿·orval 생성물 등 사람이 쓰지 않은 코드는 생성 명령·설정만 주해·해시 대상으로 하고 생성물 자체는 목록+건수만 기재한다. 사람이 그 생성물을 손댔다면 손댄 줄은 전줄 주해 대상으로 복귀한다.

### 주해 형식 — 인라인 주석

**각 줄 바로 아래에 주석으로 설명을 단다.** 표로 빼거나 코드 뒤에 몰아쓰지 않는다 — 코드와 설명 사이 거리가 벌어지면 눈이 왕복하고, 파일이 길어질수록 그 비용이 커진다.

- 주해 주석은 **`// ▸` 마커**로 시작한다. 원본 코드에 없는 줄임을 한눈에 구분하기 위해서다.
- 설명이 길면 이어지는 줄은 `//` 들여쓰기로 잇는다.
- "준비(Arrange)→실행(Act)→단언(Assert)" 3동작이 어디인지 보이게 쓴다(학습자 모드).
- 파일 제목 줄에 그 파일이 무엇을 하는지 한 줄을 먼저 단다.

게이트 노트 §3에 이 형태로 들어간다:

````markdown
**`hooks/useAuthBootstrap.test.ts`** — 앱 시작 시 저장된 토큰으로 로그인 상태를 복원하는지 검증
> 아래 코드블록은 학습용 사본이다(`// ▸`는 설명용 추가 줄). 해시 대상은 주석 없는 원본 파일.

```ts
import { renderHook, waitFor } from '@testing-library/react-native'
// ▸ RNTL(React Native Testing Library)에서 도구 두 개를 가져온다.
//   renderHook = 화면을 그리지 않고 훅만 따로 실행해 보는 도구
//   waitFor = 비동기 결과가 나올 때까지 기다려 주는 도구

import { useAuthBootstrap } from './useAuthBootstrap'
// ▸ 검증 대상 훅을 가져온다 — 이 테스트가 무엇을 겨냥하는지 선언하는 줄

it('저장된 토큰이 있으면 인증 상태로 복원된다', async () => {
// ▸ 테스트 1건을 연다. 따옴표 안 문장이 곧 이 테스트가 보장하는 내용이다.
//   async = 이 안에서 "기다림(await)"을 쓰겠다는 표시. 토큰 읽기가 비동기라 필요하다.

  const store = makeTokenStore({ accessToken: 'tok_1' })
  // ▸ 준비(Arrange) — 토큰이 들어 있는 가짜 저장소를 만든다.
  //   실제 SecureStore를 쓰면 기기에 뭐가 저장돼 있느냐에 따라 결과가 흔들린다.

  const { result } = renderHook(() => useAuthBootstrap(store))
  // ▸ 실행(Act) — 가짜 저장소를 넣어 훅을 돌린다.
  //   DI(의존성 주입) = 훅이 저장소를 스스로 만들지 않고 인자로 받게 해서,
  //   테스트에서 가짜로 갈아끼울 수 있게 한 구조.

  await waitFor(() => expect(result.current.settled).toBe(true))
  // ▸ 부트스트랩이 끝났다는 신호(settled)가 true가 될 때까지 기다린다.
  //   기다리지 않으면 아직 로딩 중인 상태를 단언하게 된다.

  expect(result.current.isAuthed).toBe(true)
  // ▸ 단언(Assert) — 인증된 상태로 복원됐는지 확인한다. 이 테스트의 결론.
})
```
````

원본 코드는 한 줄도 바꾸지 않는다 — **주석 줄만 사이에 끼워 넣는다.** 원본과 대조하면 `// ▸` 줄만 빼면 실제 파일과 정확히 같아야 한다.

## 채팅 요약

채팅에는 **핵심 요약 + 게이트 노트 위치 + 이해 체크 2개 + 승인 요청**만 제시한다.

### 생략 불가 항목

① 변경/테스트 파일 전체 목록 + 각 해시 ② 커버되지 않는 AC·경계 **전부** ③ 의심 지점·트레이드오프

요약에서 불리한 내용이 빠지면 **"읽지 않은 승인"의 대상이 요약이 된다.** scribe가 [기록]에서 채팅 요약 ↔ 게이트 노트의 이 항목들 일치 여부를 대조·기록한다.

### 형식 예시

```markdown
## 게이트① — 20260721-trip162-archive (1차)

**무엇을 보장하는 테스트인가**: 여행 종료 후 아카이브 생성이 …(2~3줄)

**파일 · 해시**
- `hooks/useAuthBootstrap.test.ts` : a1b2c3d4…
- `test/factories/tokenStore.ts`   : e5f6a7b8…

**커버되지 않는 AC·경계**
- AC-3(오프라인 재시도)는 이번 범위 밖 — 별도 티켓
- 토큰 만료 경계(정확히 0초)는 미검증

**의심 지점·트레이드오프**
- 가짜 저장소가 실제 SecureStore의 예외 형태를 흉내내지 않음
```

## 이해 체크와 이해부채

사용자의 이해 속도가 사이클의 실제 병목이다. 게이트가 "읽지 않은 승인"으로 변질되면 인지 부채가 쌓인다.

### 이해 체크

- 제시 끝에 **역질문 2개**를 던진다.
- **출제 기준**: 채팅 요약만으로는 답할 수 없고 **게이트 노트의 주해 본문을 읽어야 답할 수 있는 지점**에서 낸다 — 노트 열람이 답변의 전제 조건이 되게.
- 사용자가 막히면 승인 보류가 아니라 **해당 부분을 더 설명하는 트리거**로 쓴다.
- **막힌 항목은 이해부채 후보로 자동 등재**한다(사용자 확인 후 장부화 — 막힌 답이 가장 확실한 부채 신호다).
- 답변 요지는 게이트 노트 결과 섹션에 기록한다 — 기록 없는 체크는 형해화를 관찰할 수 없다.

### 이해부채 수집 (즉시 영속)

사용자가 "동작은 믿고 승인하지만 아직 이해 못 함"을 표한 항목 + 이해 체크에서 막힌 항목은 **게이트 기록 시점에 즉시** 게이트 노트 결과 섹션과 00_gates.md에 쓴다 — [기록]까지 세션 메모리에만 두면 에스컬레이션 중단·세션 사망 시 부채가 증발한다([기록]의 scribe는 건별 노트화·정리만 담당).

- **기본값은 등재 (넘겨짚기 금지)**: 사용자가 개념 몰이해를 표하면(질문·"모르겠다"·이해 체크 막힘 포함), 명시적 "이해했다" 발화가 없는 한 **기본값은 부채 등재**다. 재설명 후 "이해했겠지"로 넘겨짚어 부채를 소멸시키는 것을 금지한다(넘겨짚기 = "읽지 않은 승인"의 재생산). 애매하면 되묻고, 되물을 수 없는 상태(세션 종료 등)면 등재 쪽으로 판정한다.
- **개념 노트 링크 (재방문 학습)**: 부채 등재 시 그 개념의 설명을 담은 개념 노트(`TripPilot/개념/{개념명}.md`)를 생성·링크한다(obsidian-second-brain 개념 규칙). 부채 노트는 장부일 뿐이라, 재방문 시 배울 설명이 없으면 상환이 구조적으로 불가능하다. 설명이 가장 신선한 등재 시점에 오케스트레이터가 담고, [기록]에서 scribe가 정리·확정한다.
- **장부화 필터**: 다음 작업을 막을 항목만 부채로 올리고, 나머지는 개발로그의 "참고 개념" 목록으로 격하한다.
- **파산 차단**(미상환 10건 초과 시 정리 세션 선행)은 **[메모리] 단계 규칙이라 SKILL.md에 있다** — 이 파일은 게이트 시점에 읽히므로 여기 두면 판정 시점을 이미 지나쳤다.

## 학습자 모드

이 사용자는 코드 초심자다(TS/Jest/RN 테스트 코드를 아직 유창하게 못 읽음). "이해가 병목" 원칙을 이 수준에 맞춰 구체화한다.

- **학습자 톤**: 게이트 노트·주해도 서브 에이전트와 같은 학습자 톤을 쓴다. 톤 3원칙과 주입 시점은 SKILL.md "서브 에이전트 호출 공통"에 있다(1단계부터 적용되므로 이 파일에 두면 늦다). 프로필 근거: [[user-learner-profile]].
- **"지금 배울 핵심 개념 5~7개" 선정**: 이번 게이트에 등장하는 개념 중 **처음 등장하거나 사용자가 아직 이해를 표명하지 않은 것**을 오케스트레이터가 판단해 채운다. 이미 설명했고 사용자가 이해를 표명한 개념은 재설명하지 않고 한 줄 리마인드 + `[[개념 노트]]` 링크만 단다.
  - 판단 근거: 미상환 이해부채 목록(`TripPilot/이해부채/`)과 기존 개념 노트의 존재 여부 — 부채로 남아 있으면 아직 모르는 것이고, 개념 노트가 이미 있으면 최소한 한 번은 설명한 것이다.
- **분할 제시는 기본 강제 아님**: 필요 시 차수 분할을 재사용하되 기본값은 아니다.

## 경량 사이클의 이해 체크

규모 분기로 게이트①·②를 1회 통합 제시할 때에도 **깎는 것은 절차뿐이다**. 원장 기록 형식(해시·red 로그)과 이해 체크의 두 축은 그대로 유지한다:

- 역질문은 **게이트①축**(이 테스트가 무엇을 보장하나)과 **게이트②축**(구현이 그 테스트를 어떻게 통과시키나)에서 **각각 최소 1개씩** 낸다. 총량은 2개 — 문항을 늘리지 않되 축을 비우지 않는다.
- 답변·막힘을 축별로 구분해 기록해, 한 축만 막혀도 그 축을 부채로 등재한다.

<summary>왜 이 규칙들이 이 형태인가 (사고 이력 — 규칙 적용에는 불필요)</summary>

- **경량 사이클에서도 두 축을 유지하는 이유**: 규모와 무관한 중량 사이클은 사용자의 하네스 우회를 부르고, 우회는 전 장부에 구멍을 낸다. 그러나 반대로 제시만 합치고 검토 축까지 비우면 경량화가 이해부채로 되돌아온다 — `20260718-token-mirroring` 사이클의 이해부채 2건이 **모두** 통합 이해 체크에서 발생했다.
- **원장이 노트보다 먼저인 이유**: 노트는 열람용 스냅샷이고 원장은 감사 대상이다. 둘이 갈라진 상태로 세션이 죽으면 살아남아야 하는 쪽은 원장이다.
- **해시를 승인 후 재계산하지 않는 이유**: 재계산을 허용하면 "승인된 것"의 정의가 사후에 움직인다. 심판이 경기 후 규칙을 바꾸는 것과 같다.
- **주해를 코드 파일이 아니라 02/03에 쓰는 이유**: 학습 주해가 코드에 남으면 리포 주석 밀도 규칙과 충돌하고, 다음 사람에게는 소음이 된다. 학습은 사이클 산출물의 몫이다.
