# 사이클 진입·재개 규칙

Phase 0(컨텍스트 확인) 진입 시 읽는다. 사이클 ID 결정, 재개 판별, 산출물 전달 프로토콜이 여기 있다.

## 목차

- Phase 0: 컨텍스트 확인 — 사이클 ID 자동 탐지·진입 분기·재개 판별·상태 요약
- 데이터 전달 프로토콜 — 산출물 파일 규약·RESUME.md 형식·서브 에이전트 반환값

## Phase 0: 컨텍스트 확인

1. **사이클 ID 자동 탐지 (`/clear` 후 단절 대비)**: 사용자가 cycle-id를 명시하지 않고 "이어서/재실행/다시" 류로 진입하면, `<리포 루트>/_workspace/`에서 **`RESUME.md`에 종료 미기록인 폴더 중 가장 최근 수정본**을 찾아 그 `RESUME.md`를 읽고 "이 사이클(`{cycle-id}`, 다음 할 일: `{...}`)을 이어갈까요?"를 제시한다. 미완료 폴더가 없으면 새 작업으로 취급한다. 새 작업이면 사이클 ID 결정: `{YYYYMMDD}-{티켓키}-{작업슬러그}` — **같은 날 같은 슬러그의 새 작업은 순번 접미사**(`-2`, `-3`…), 산출물이 있는 기존 폴더 재사용 금지.
   - **티켓키는 소속 브랜치에서 도출한다**(`git rev-parse --abbrev-ref HEAD` → `feature/TRIP-161-login` → `trip161`, 소문자). 티켓 키가 없는 브랜치면 생략해 `{YYYYMMDD}-{작업슬러그}`.
   - **티켓(브랜치) 1 : 사이클 N이다.** 한 티켓 안에서 사이클이 여러 번 돌므로(예: `trip161` = login·wiring·screens), 티켓 키만으로는 사이클을 지목할 수 없다 — 사용자가 티켓 코드만 말하면 어느 사이클인지 되묻거나, `_workspace/`에서 같은 티켓키 폴더를 나열해 제시한다.
2. `<리포 루트>/_workspace/` 확인:
   - 해당 사이클 폴더 존재 + 부분 수정 요청 → **부분 재실행** (해당 단계만 재호출)
   - 해당 사이클 폴더 존재 + 새 작업 → **새 사이클** (순번 접미사 새 폴더)
   - 미존재 → **초기 실행**. 단, 옵시디언 문제로그에 동일 슬러그의 에스컬레이션 기록이 있으면 FAIL 잔고를 승계 보고한다(폴더 삭제로 상한 카운터를 세탁할 수 없다).
3. 재개 시 진행 단계 판별: **`RESUME.md`(다음 할 일)를 1차 근거**로, 산출물 파일 존재로 교차 확인한다. RESUME.md가 가리키는 단계의 산출물이 없으면 그 단계부터 재개한다. 코드가 최신 04 리포트 이후 바뀌었으면(`git diff --name-only` 변경 집합이 04의 검사 대상과 다름) 기존 04를 stale로 간주하고 [검증]부터 재개한다(미검증 반쪽 코드가 낡은 PASS를 증거로 기록되는 것을 막는다).
4. **재개·부분 재실행 진입 시 사용자에게 상태 요약을 먼저 제시한다**: 완료 단계 · 현재 단계 · 다음 할 일 · 최신 04 판정 → 확인 후 진행. `_workspace/`는 사용자 열람 채널 밖의 파일이므로, 상태는 하네스가 보여줘야 한다.

5. **초기 실행 진입 시 규모 판정을 제시한다.** 형식은 `규모: {경량|기본} — 근거 {한 줄} · 뒤집으려면 말씀만`이고, 판정 조건은 SKILL 「규모 분기」의 넷이다(**전부 만족할 때만 경량**). 판정 재료는 **지라 티켓 본문(스코프·AC)·브랜치·직전 사이클 개발로그**이므로, 사용자가 티켓 키만 말하고 들어오면 티켓을 먼저 조회한다. **재개 경로에는 4번의 상태 요약이 있지만 초기 실행에는 제시 지점이 없어 규모가 조용히 정해진다** — 경량 오판은 5-b가 얕아진 뒤에야 드러나므로, 한 줄을 보여 사용자가 뒤집을 수 있게 하는 것이 여기서 유일한 방어다. *유지 판정: 6사이클 관찰 — 제시한 판정을 사용자가 뒤집은 건수와 경량으로 시작했다가 기본으로 돌린 건수가 둘 다 0이면, 판정이 자명하다는 뜻이므로 제시를 떼고 자동 진행으로 격하한다.*

## 데이터 전달 프로토콜

- 파일 기반, 모두 `<리포 루트>/_workspace/{cycle-id}/`: `01_spec-analyst_brief.md` / `01b_ouroboros_seed.md` / `02_test-designer_map.md` / `03_implementer_notes.md` / `03b_code-critic_findings.md`(적대적 리뷰 — 차단 0건이어야 6 [검증]) / `04_qa-verifier_report_{n}_{PASS|FAIL}.md` / `04b_smoke_{n}_{PASS|FAIL|SKIP|실행불가}.md`(실기 스모크 — 조건부) / `RESUME.md`(이어하기 인덱스)
  - `<리포 루트>/_workspace`는 옵시디언 볼트 `TripPilot/사이클/`으로의 심볼릭 링크다 — 경로는 그대로 쓰고, 볼트에서 같은 파일을 `[[사이클/{cycle-id}/…]]`로 링크할 수 있다.
- **RESUME.md — `/clear` 후 무맥락 재개용 지시서**. **매 단계 종료 시 오케스트레이터가 갱신**한다(append 아닌 덮어쓰기 — 항상 "현재 상태" 1장). 고정 형식:
  ```
  cycle-id: {id}   작업: {한 줄}   갱신: {YYYY-MM-DD 단계명}
  완료: [인지·메모리·설계·테스트…]   현재: {단계}   다음 할 일: {구체 행동}
  학습: {대기|완료}   검증: 최신 n={n} {PASS|FAIL}
  종료: {미완료 | 완료 YYYY-MM-DD}   블로킹: {사용자 응답 대기 | 없음}
  ```
  종료 필드가 "미완료"인 폴더만 Phase 0 자동 탐지 대상이다. 사이클 종료([기록] 후) 시 `완료 YYYY-MM-DD`로 마킹한다.

  **⚠️ 판정은 "값이 `미완료`와 정확히 같은가"로 한다 — `완료`가 포함되는지로 판정하지 마라.** `미완료`는 문자열 `완료`를 **포함한다**(미+완료). 포함 검사로 구현하면 **미완료 사이클이 통째로 자동 탐지에서 빠져** 재개가 조용히 실패한다.

  값에 볼드·수식어를 붙이지 마라 — 실제로 `**완료`처럼 마크다운이 섞여 기록된 사례가 12건 중 4건이다. 정확 비교를 깨뜨리는 형태다.
- 서브 에이전트 반환값: 경로 + 판정만(대용량 내용은 파일로)
- 최종 산출물(코드·테스트)만 리포 정위치에 두고, 중간 산출물은 `_workspace/`에 보존한다(감사 추적용, git 미추적)
