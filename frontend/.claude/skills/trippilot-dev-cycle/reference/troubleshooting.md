# 에러 핸들링·에스컬레이션

에이전트 실패, 검증 FAIL 누적, MCP 불가 상황에서 읽는다.

## 에러 핸들링

- 에이전트 실패: 1회 재시도 → 재실패 시 해당 단계 결과 없이 사용자에게 보고한다(침묵 진행 금지)
- 검증 실패 상한 도달 시(임계값 정본은 verify-gates 판정 규칙 — 원장 기준, PASS 미산입) → 중단, 서술형 실패 요약+선택지 제시(로그는 첨부), 문제로그 기록. **중단 시에도 scribe를 이해부채·문제로그 기록 한정으로 호출한다** — 가장 배울 게 많은 실패 사이클의 부채가 장부에서 빠지면 안 된다.
- MCP 불가 — **서버마다 다르다. "폴백을 찾아라"가 아니라 아래를 따른다**:
  - **Ouroboros**: 브리프의 AC 초안을 `01b`로 저장하고 "폴백 — 인터뷰 불가" 명시.
  - **Obsidian**: 리포 devlog에만 기록하고 "옵시디언 미기록" 표식. 게이트 전문은 채팅에 제시. **동기화 책임** — 다음 [기록] 시작 시 scribe가 직전 devlog의 "옵시디언 미기록" 표식과 이번 사이클 게이트 노트 존재 여부를 점검하고, 02/03 원문 기반으로 백필한다.
  - **Figma**: **폴백 없음.** 화면 명세의 리포 사본이 없으므로 접근 실패는 곧 근거 부재다. 추측으로 메우지 말고 "Figma 접근 실패 — 화면 근거 없음"을 브리프에 명시하고 **열린 질문으로 올린다**(spec-perception "Figma" 절과 동일).
- **`aidlc/` 이하 쓰기는 [기록]의 정본 반영에서, 3-a에서 사용자가 고른 항목에만** — 그 외 단계는 금지. ⚠️ **기계 강제 없음**(settings deny는 그 배선을 열려고 전량 제거됐다 — 상세는 하네스 변경이력): 규칙 준수뿐이고 위반은 사후 `git status <리포 루트>/aidlc` 대조로만 드러난다. atlassian MCP 사용 금지

## 검증 단계의 분기 (6단계 상세)

- FAIL → implementer 재호출(수정 루프). **상한 도달 시(임계값 정본은 verify-gates 판정 규칙 — 원장 기준, PASS 미산입) 사용자 에스컬레이션 + 문제로그 기록.** 실패 게이트가 번갈아 나와도 누적 상한에 걸린다. 에스컬레이션 본문은 서술형 실패 요약 + 선택지 2~3개, 로그 원문은 첨부.
- 실행 불가(도구/설정 부재) → 수정 루프로 보내지 말고 필요한 설정을 사용자에게 보고한다. 단 **부재 원인이 이번 사이클 AC면 FAIL로 취급해 수정 루프로**(verify-gates §0 예외). 실행 불가 상태로 [기록]에 가면 "미검증" 플래그를 강제 명기한다.
- PASS → qa-verifier가 04에 기록한 게이트② 해시 대조 결과에 따라: 불일치("PASS(재제시 필요)")면 게이트② 재제시, 일치면 6-b로.
- **6-b 실기 스모크**(발동 조건은 verify-gates `## 실기 스모크`): FAIL → implementer 수정 루프(04와 같은 누적 상한 적용). **실행 불가**(시뮬레이터 미부팅·dev build 미설치) → 수정 루프로 보내지 말고 사용자에게 보고, [기록]에 **"실기 미검증"** 강제 명기. 발동 조건 미해당 → SKIP을 04b에 남긴다(빈칸은 "안 걸림"과 "안 함"을 구별하지 못한다).

## 테스트 시나리오

- **정상**: "TRIP-160 스캐폴딩 사이클 돌려줘" → 1~9 순차, 게이트 2회 승인(00_gates.md 기록), PASS 후 옵시디언·devlog 기록 생성
- **에러**: 검증에서 lint 3연속 실패 → 루프 중단, 실패 로그 원문 제시, 문제로그 노트 생성 후 대기
- **후속**: "어제 사이클 테스트만 다시 봐줘" → Phase 0에서 00_gates.md 확인 → 게이트① 승인 기록 없으면 test-designer 재호출 후 게이트①부터 재개
- **게이밍 방어**: 검증 PASS인데 테스트 파일 해시가 게이트① 기록과 다름 → qa-verifier가 FAIL + 즉시 에스컬레이션(심판 변조)
