# Obsidian Second Brain

볼트 워크스페이스: `TripPilot/` (`🗂️ 전체 Index.md`의 ✈️ TripPilot 섹션에서 링크됨)

## 구조

| 위치 | 용도 | 파일명 규칙 |
|---|---|---|
| `TripPilot/✈️ TripPilot Index.md` | MOC — 모든 로그의 입구 | 고정 |
| `TripPilot/대화로그/` | 세션별 대화 요약·결정 사항 | `YYYY-MM-DD 주제.md` |
| `TripPilot/개발일지/` | 하루 단위 요약(그날 사이클들 링크) | `YYYY-MM-DD.md` |
| `TripPilot/개발로그/` | 사이클 단위 상세 기록 | `YYYY-MM-DD cycle-id.md` |
| `TripPilot/문제로그/` | 막힌 문제 + 해결 과정 | `YYYY-MM-DD 문제요약.md` |
| `TripPilot/에러로그/` | 에러 + 원인 + 수정 | `YYYY-MM-DD 에러요약.md` |
| `TripPilot/이해부채/` | 승인했지만 이해 못 한 것 + 상환 추적 | `YYYY-MM-DD 주제.md` |
| `TripPilot/_templates/` | 각 로그 템플릿 | `{로그종류} 템플릿.md` |

## 기록 규칙

- `_templates/`의 해당 템플릿 섹션 구조를 그대로 따른다 — 섹션 임의 변경 금지(구조가 흔들리면 다음 사이클의 조회가 깨진다).
- 관련 노트를 [[링크]]로 연결한다: 개발로그 ↔ 문제로그/에러로그 ↔ 개발일지. 링크가 제2의 뇌를 그래프로 만든다.
- 학습 자료 성격의 내용은 기존 스터디 노트(`개발 공부/TripPilot/`)와 교차 링크한다.
- 도구: `mcp__obsidian__obsidian_append_content`(새 노트 생성/추가), `obsidian_patch_content`(기존 노트의 특정 섹션 수정).
- 새 노트 생성 후 `✈️ TripPilot Index.md`의 해당 로그 섹션에 링크를 추가한다(섹션당 최근 5개 유지, 오래된 것은 제거해도 노트는 남는다).
- 코드 사이클 외 작업(문서 편집, 환경 구축, 하네스 변경)도 개발일지에 최소 한 줄 남긴다 — 기록 없는 작업일을 만들지 않는다.

## 조회 규칙 ([메모리] 단계)

- `obsidian_simple_search`로 작업 키워드 검색 + 최근 개발로그·문제로그 2~3개를 읽는다.
- 확인할 것: 미해결 문제, 이번 작업과 충돌하는 과거 결정, 반복되는 에러 패턴.
- **이해부채 재노출(간격 반복)**: `이해부채/`에서 status가 "미상환"인 노트 중 이번 작업과 관련된 것 1~2건을 사용자에게 다시 보여준다. 사용자가 이해를 확인하면 status를 "상환"으로 갱신하고 상환 기록 섹션에 한 줄 남긴다 — 재노출 없는 부채 장부는 장부가 아니다.
- 조회 결과 요약을 이후 단계(설계·테스트·구현) 프롬프트에 포함시킨다 — 읽고 버리면 메모리가 아니다.

## 기록 내용 우선순위

1. 왜 그렇게 결정했는가(검토한 대안과 기각 이유)
2. 예상과 달랐던 것
3. 다음에 이어서 할 일
4. 무엇을 했는가 — 마지막(코드·git이 이미 말해주는 것은 짧게)
