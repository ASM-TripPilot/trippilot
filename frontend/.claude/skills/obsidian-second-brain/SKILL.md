# Obsidian Second Brain

볼트 워크스페이스: `TripPilot/` (`🗂️ 전체 Index.md`의 ✈️ TripPilot 섹션에서 링크됨)

## 구조

**볼트는 독자로 갈린다.** 사람은 `개념/`과 `게이트/`만 읽으면 되고, 나머지는 AI가 읽어 필요분만 꺼내 보인다. 이 구분을 지키는 것이 사용자의 읽기 부담을 일정하게 유지하는 장치다 — AI용 문서를 사람이 읽어야 하는 상태가 되면 구분이 무너진 것이다.

## 기록 규칙

- `_templates/`의 해당 템플릿 섹션 구조를 그대로 따른다 — 섹션 임의 변경 금지(구조가 흔들리면 다음 사이클의 조회가 깨진다).
- 관련 노트를 [[링크]]로 연결한다: 개발로그 ↔ 문제로그/에러로그 ↔ 개발일지. 링크가 제2의 뇌를 그래프로 만든다.
- **온톨로지 속성**([[온톨로지]] 정본). 프론트매터에 딱 둘만 쓴다 — 나머지 관계는 백링크가 이미 하므로 중복 저장 금지:
  - **개념 노트를 만들거나 보강하면 `설명하는코드`를 채운다** — 그 개념이 설명하는 리포 파일들(`frontend/` 기준 상대경로 문자열 리스트). 이것이 `[메모리]`의 코드→개념 진입점 **정본**이다. 실재하지 않는 경로를 쓰면 역인덱스가 거짓이 된다 — 경로는 반드시 리포에서 확인하고 쓴다. 코드에 매이지 않는 개념(테스트 규율·하네스 규약 등)은 `[]`로 비운다.
  - **이해부채를 등재하면 `학습자료`를 채운다** — 그 부채를 갚을 개념 노트 이름 리스트. 부채→개념→코드 2단 조인이 여기서 성립한다.
  - 새 속성이 필요해 보이면 노트에서 즉흥적으로 만들지 말고 [[온톨로지]]를 먼저 고친다. 규약에 없는 속성은 조회가 못 본다.
- 학습 자료 성격의 내용은 기존 스터디 노트(`개발 공부/TripPilot/`)와 교차 링크한다.
- **이해부채 ↔ 개념 노트**: 이해부채를 등재하면 그 개념의 실제 설명을 담은 **개념 노트**(`개념/{개념명}.md`, 날짜 없는 영구 노트)를 생성하거나 기존 노트에 보강하고, 부채 노트 `## 관련`에서 `[[개념명]]`으로 링크한다. **부채 노트 = 장부(상환 기준·status), 개념 노트 = 학습 자료(설명 본문).** 부채 노트만 있으면 재방문해도 "못 이해함"만 재확인하고 정작 배울 설명이 없다 — 개념 노트가 그 공백을 메운다. 같은 개념의 다음 부채도 **같은 개념 노트를 공유**한다(중복 생성 금지, 설명만 보강). 개념 노트는 상환돼도 남는다(영구).
- **상환 기준에는 코드 축을 반드시 포함한다 (2026-07-21 신설)**: 개념 설명만으로 상환 조건을 쓰면 **위키백과로 갚을 수 있는 장부**가 된다(`PKCE` 부채의 기존 기준엔 우리 코드가 한 줄도 없었다). 마지막 항으로 이걸 넣는다:

  > **이 개념이 우리 코드 어느 파일에 어떻게 나타나는지 짚을 수 있으면**

  게이트 역질문이 코드에 앵커돼 있어도 부채를 개념으로 일반화해 등재하면 코드 이해는 장부에서 사라진다 — 이 한 줄이 그 누수를 막는다.
- 도구: `mcp__obsidian__obsidian_append_content`(새 노트 생성/추가), `obsidian_patch_content`(기존 노트의 특정 섹션 수정).
- 새 노트 생성 후 `✈️ TripPilot Index.md`의 해당 로그 섹션에 링크를 추가한다(섹션당 최근 5개 유지, 오래된 것은 제거해도 노트는 남는다). **예외: `게이트/` 노트는 Index에 개별 링크하지 않는다** — 사이클당 여러 개라 도배가 된다. 해당 사이클 개발로그가 게이트 노트들의 [[링크]] 허브다.
- **개발일지는 하루 3~5줄로 끝낸다.** 섹션은 둘뿐 — `진행한 사이클`(개발로그 [[링크]] + 각 한 줄)과 `사이클 밖 작업`(코드 사이클 외 작업: 문서 편집·환경 구축·하네스 변경 등, 한 줄 + 원장 [[링크]]). 사이클 외 작업은 **반드시 남긴다** — 기록 없는 작업일을 만들지 않으며, 개발로그는 사이클 키라 이걸 받을 수 없다(개발일지만 담을 수 있는 유일한 것).
  - **사이클 상세를 옮겨 적지 마라** — 결정 이유·예상과 달랐던 것·다음에 할 일은 전부 개발로그 소관이다. 개발일지에 `오늘 목표`·`배운 것`·`내일 할 일` 절을 만들지 않는다(2026-07-20 폐지: 개발로그와 중복).
  - 이유: **개발일지는 자동 조회 경로가 없다.** [메모리] 조회 규칙 어디에도 개발일지를 읽으라는 항목이 없고 사용자도 평소 읽지 않는다 — `"어제 뭐 했지"` 류의 사용자 질의에만 쓰인다. 그 용도에 3~5줄이면 충분하고, 더 쓰면 아무도 안 읽는 글만 쌓인다.
- **하네스 변경 시** `하네스 변경이력.md`의 표에 행을 추가한다(append-only, 날짜·변경 내용·대상·사유) — frontend/CLAUDE.md에는 이 원장을 가리키는 포인터만 있다.
- **구조 지도**([기록] 단계) — 정본은 **리포의 `frontend/docs/structure.md`**다.

  **왜 옮겼나**: 볼트 스냅샷은 매 사이클 12,000자를 복사해 오는 비용 때문에 이틀 만에 델타 메모로 퇴화했다(6,628 → 12,746 → 2,252 → 1,967자). 리포에 두면 복사 왕복이 사라지고, **갱신 누락이 사이클 diff에 드러나** qa-verifier의 변경 집합 검사에 자동으로 걸린다.

  - **기계 몫과 사람 몫을 가른다.** 파일 목록·export 심볼은 스크립트가 만든다:
    ```bash
    node <리포 루트>/frontend/.claude/skills/trippilot-dev-cycle/scripts/structure-index.cjs
    ```
    scribe가 쓰는 것은 기계가 못 주는 것뿐 — **용도 한 줄 · 스텁 여부 · "지금 작업하려면" 경고**.
  - **이번 사이클이 만진 행만** 고친다(전면 재작성 금지). 파일 추가·삭제·이동이나 스텁을 채운 경우가 대상이다.
  - **경로는 리포 상대 전체 경로를 백틱으로** 적는다(`src/features/auth/lib/makeAuthorize.ts`) — 대조 검사가 이 형태만 인식한다.
  - **반환 전 대조를 돌린다**: `structure-index.cjs --check` → *파일은 있는데 행이 없다*(새 파일 누락) · *행은 있는데 파일이 없다*(삭제·이동 미반영 — 이게 가장 흔한 실패였다). 불일치면 고치고 다시 돌린다.
  - **가장 중요한 항목은 여전히 "무엇이 빈 스텁인가"**다. 디렉토리 존재를 구현으로 오인하는 것이 이 문서가 막아야 할 1순위 오류이고, 기계가 못 갈라 주는 유일한 지도 정보다.
  - **개념 링크는 넣지 않는다** — 리포 마크다운에서 `[[ ]]`는 죽은 링크이고, 코드→개념 진입점의 정본은 개념 노트의 `설명하는코드` 속성이다(경로 문자열을 `obsidian_simple_search`에 넣으면 잡힌다). 사본을 두 곳에 두면 또 갈라진다.
  - 구조 변화가 없는 사이클이면 건드리지 않는다.

## 조회 규칙 ([메모리] 단계)

- **`frontend/docs/structure.md`를 먼저 읽는다** — 파일별 역할, 무엇이 빈 스텁인지, "지금 작업하려면" 경고의 지도다. **옵시디언이 아니라 리포 파일이므로 Read로 연다.** 실제와 어긋나면 리포가 옳다 — 다만 `--check` 대조가 붙어 있어 조용히 어긋나지는 않는다(아래 "구조 지도").
- **그다음은 시간순이 아니라 그래프로 판다.** 볼트는 이미 링크 그래프다(개념 28노트·110링크) — "최근 N건"은 이번 작업과 무관한 것을 읽고 정작 관련된 과거를 놓친다.
  1. **건드릴 파일 경로를 그대로 `obsidian_simple_search`에 넣는다** — 예 `src/features/auth/hooks/useBootstrapGate.ts`. `설명하는코드`에 그 경로를 선언한 개념 노트가 잡힌다. **이것이 코드→개념 진입점의 유일한 정본이다** — 구조 지도(`docs/structure.md`)는 개념 링크를 두지 않으므로 사본 분기가 없다.
  2. 그 **개념 노트 본문**을 읽는다 — 사용자가 이 개념을 어느 수준까지 설명받았는지가 거기 있다(존재 여부만 보면 판단이 얕다).
  3. **역링크로 이력을 판다**: `obsidian_simple_search`에 대괄호 두 개로 감싼 개념 이름을 넣으면 그 개념을 참조하는 노트가 전부 나온다 — 개발로그·게이트 노트·이해부채. MCP에 백링크 전용 도구는 없지만 이 검색이 같은 일을 한다.
  4. 걸려 나온 **미상환 이해부채가 이번 작업의 위험 지점**이다. 우선 재노출 대상으로 삼는다. (부채의 `학습자료` 속성이 곧장 읽을 개념 노트를 가리킨다.)
  - **`.base` 파일을 조회 수단으로 쓰지 마라** — MCP는 Bases를 실행하지 못하고 YAML 원문만 돌려준다. 결과 표를 봤다고 착각하기 쉬운 지점이다.
- 그래프로 잡히지 않는 축은 시간순으로 보완한다: 최근 개발로그·문제로그 2~3개 + `obsidian_simple_search` 키워드 검색.
- **에러로그도 확인한다**(최근 2건 또는 작업 키워드 검색) — 확인 항목에 "반복되는 에러 패턴"이 있는데 에러로그를 안 읽으면 판단 근거가 없다.
- 확인할 것: 미해결 문제, 이번 작업과 충돌하는 과거 결정, 반복되는 에러 패턴.
- **이해부채 재노출(간격 반복)**: `이해부채/`에서 status가 "미상환"인 노트 중 이번 작업과 관련된 것 1~2건을 사용자에게 다시 보여준다. 사용자가 이해를 확인하면 status를 "상환"으로 갱신하고 상환 기록 섹션에 한 줄 남긴다 — 재노출 없는 부채 장부는 장부가 아니다.
- 조회 결과 요약을 이후 단계(설계·테스트·구현) 프롬프트에 포함시킨다 — 읽고 버리면 메모리가 아니다.

## 기록 내용 우선순위

1. 왜 그렇게 결정했는가(검토한 대안과 기각 이유)
2. 예상과 달랐던 것
3. 다음에 이어서 할 일
4. 무엇을 했는가 — 마지막(코드·git이 이미 말해주는 것은 짧게)
