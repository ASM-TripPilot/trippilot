## 지도 구현 (`shared/map`)

- **`viewOnly` 4토글은 jest가 prop 전달까지 심판하지만, 실제 제스처 차단은 실기 전용** → `MapView`가 `viewOnly`를 `isScrollGesturesEnabled`·`isZoomGesturesEnabled`·`isRotateGesturesEnabled`·`isTiltGesturesEnabled` 4개로 펼치고 prop-기록형 목이 그 값을 노출해 `MapView.test.tsx` AC2가 4토글 개별로 잠근다. **네이티브가 그 prop으로 실제로 제스처를 막는지**는 jest가 못 본다 — 시뮬레이터에서 손으로 확인.
- **네이버 커스텀 뷰 마커는 `collapsable={false}` 없으면 New Architecture(iOS)에서 기본 마커로 보인다** → `NaverMapMarkerOverlay`의 children(마커 자리에 얹는 커스텀 React 뷰)은 최상위 자식에 `collapsable={false}`(RN에게 "레이아웃에만 쓰는 뷰라도 지우지 마라"고 알리는 prop — 없으면 view flattening 최적화로 네이티브 트리에서 사라진다)가 없으면 네이티브가 자식을 못 찾아 기본 초록 심볼/흰 실루엣이 뜬다(6-b 실측, 라이브러리 소스 "Custom React View" 항 대조). 생김새가 바뀌는 자식은 `key`도 함께 준다.
- **마커 번호·글자를 RN `<Text>`로 그리면 iOS 마커 스냅샷에 안 잡힌다** → 네이버 SDK는 커스텀 마커 뷰를 `UIImage`(정지 이미지)로 한 번 찍어 지도 위에 얹는데, 그 시점엔 배경 `View`(레이어 속성)는 찍히지만 `<Text>` 글리프는 아직 안 그려진 상태다(6-b 실측 — 원은 뜨는데 번호만 빔). `react-native-svg`의 `Text`(벡터로 한 레이어에 동기 렌더)로 바꿔야 찍힌다. jest 쪽도 갈라진다 — RNTL `toHaveTextContent`는 이 SVG 문자열을 못 읽고, 목이 문자열을 `RNSVGTSpan.props.content`에 넣으므로 `within().UNSAFE_queryAllByProps({content})`로 검증한다.
- **`camera`와 `region`을 같이 넘기면 SDK가 `region`을 버린다 — 한쪽만 간다** → 네이버 SDK 구현이 `region={!camera && !initialCamera ? region : undefined}`라, `camera`(또는 `initialCamera`)가 있으면 `region`은 무조건 무시된다. `fitPins`(핀 전체를 담는 영역 맞춤)처럼 `region`으로 카메라를 옮기려면 `camera` 자체를 스프레드에서 빼야 한다(`{...(region !== null ? { region } : { camera })}` 형태로 택일).
- **영역 맞춤(fit-to-bounds) 결과가 실제로 화면에 다 들어오는지는 jest 원리적 사각** → `MapView.test.tsx`류 목은 `region`·`camera` prop 값만 기록하고, 네이버 SDK가 그 `region`으로 실제 카메라를 움직여 모든 핀을 뷰포트 안에 넣는지는 재현하지 않는다. 순수 함수(`buildFitRegion`)의 여백 비율(예 1.4배)이 물방울 핀처럼 anchor가 중심이 아닌 마커(머리가 좌표 위로 솟음)의 실제 잘림을 막는지는 실기 확인 전용(6-b) — jest는 전부 green이어도 카드 위쪽에서 핀 머리가 잘릴 수 있다.
- **region은 레이아웃 전 임시 프레임으로 맞춰진다 — `onLayout` 재맞춤이 없으면 카드가 작을수록 잘린다**(TRIP-1043 실측). 네이버 SDK(`RNCNaverMapViewImpl.mm` `setRegion`)는 `region` prop을 받는 **즉시** `fitBounds`로 줌을 정하는데, 그 순간 뷰는 아직 RN 레이아웃이 끝나기 전(카드 실제 크기가 아닌 임시 프레임)이라 한 축(가로 또는 세로)으로만 맞고 반대 축은 잘린다. SDK는 같은 값의 `region`이 다시 오면 무시하므로(`isRegionEqual`) 재전달로는 못 고친다 — `onLayout`(레이아웃 확정 콜백)에서 `ref.animateRegionTo`(easing: 'None' = 순간이동)로 같은 영역을 한 번 더 맞춰야 한다. **jest 가짜 지도는 `onLayout`을 호출하지 않는다** — 이 재맞춤 코드를 통째로 지워도 jest 전부 green이라 실기 캡처만 그물이다. `radiusCircle`을 새로 받는 화면·`fitPins`를 쓰는 기존 화면 전부(`MapView.tsx`가 공용이라 h02·h10·h15 등) 이 축을 공유한다.
- **`logoMargin`(지도 로고 위치)은 jest 가 prop 전달·기본값 불변까지만 보고, 로고가 실제로 바 위로 올라가는지는 실기 전용이다**(TRIP-1522) → 허브가 하단 바에 NAVER 로고가 가리지 않게 `{bottom: 바 점유(70)+안전영역}` 을 넘긴다. iOS 시뮬레이터에서는 시트를 끝까지 내려도 로고가 바 위에 보이는 것을 확인했지만(2026-10-21) **안드로이드 SDK 에서의 효과는 미검증**이다. 값을 바꾸면 효과가 jest 로 안 잡히니 허브(`live-hub-closed` 프리뷰 키 또는 실허브)에서 시트를 −1 로 내려 눈으로 본다. `MapView` 는 `memo` 라 호출부가 객체를 `useMemo` 로 고정하지 않으면 시트 이동마다 지도가 다시 그려진다(허브 테스트의 로고 마진 동일 객체 단언이 그 그물).
- **내 위치(`showMyLocation`)는 prop 이 아니라 ref 호출(`setLocationTrackingMode`)이라 jest 는 지도 목이 남긴 호출 기록(`globalThis.__naverTrackingModes`)으로만 본다**(TRIP-1535) → 실제 파란 점이 뜨는지·방향 표시·권한 `whenInUse` 에서 SDK 가 따로 권한 창을 띄우지 않는지는 실기 전용(6-b). 기록을 모듈 export 로 두면 `jest.requireMock` 이 다른 인스턴스를 돌려줘 기록이 안 보인다(실측) — 전역 배열을 쓴다. 맞춤↔카메라 전환으로 지도가 다시 마운트되면(`key` 변경) 효과가 새 지도에 다시 건다(`regionMode` 의존). 권한은 조회만 하고 묻지 않는다 — 여기서 `request*` 를 부르면 허브를 여는 순간 OS 창이 뜬다.

## 웹 지도 (`MapView.web.tsx`, TRIP-1651)

- **jest 는 `./MapView` 를 항상 네이티브로 푼다 — 웹 테스트는 `./MapView.web` 을 확장자까지 써서 직접 import 해야 한다** → 안 그러면 네이티브를 심판하고 green 이다. 성공 경로(로더가 풀려 컨트롤러가 지도를 만드는 것)는 `render(ui, { createNodeMock: () => 가짜요소 })` 로 `<div ref>` 를 채워야 보인다 — 옵션 없이는 ref 가 `null` 이라 컨트롤러가 조용히 안 만들어지고 `Map` 0개로 모든 단언이 침묵한다(02 의 "jest 불가"는 틀린 전제였다, 03b B1). 매 케이스 앞에 "로더가 풀리기 전엔 `Map` 0개" 앵커를 둔다.
- **네이버 인증 실패(URL 미등록·키 불일치) 뒤엔 네이버 내부 객체가 망가져 `marker.setMap(null)`·`circle.setMap(null)`·`map.destroy()` 가 throw 한다** → 실패 표면으로 바꾸며 `destroy()` 를 부르면 effect cleanup 에서 새어 레드박스가 난다(04b_1 실측, `Cannot read properties of null (reading 'capitalize')`). `destroy()` 는 항목별 try/catch(`attempt`), 실패 상태면 `update`·`refit` 을 건너뛴다. jest 가짜는 **throw 만 흉내**낼 뿐 원인(네이버 내부 상태)은 못 본다 — 실물은 헤드리스 Chrome 스모크만. 삼킨 오류는 로그를 안 남긴다(`console.warn` 여부는 미결).
- **웹 지도 실타일은 NCP 콘솔 Web 서비스 URL(`localhost` 포함)이 등록돼야 뜬다** → 미등록이면 `navermap_authFailure` → `map-failure`(정상 동작, 스모크 2). 스모크 3 에서 실타일이 떴으나 등록 시점은 미확인(사람 몫 TRIP-1645). `?ncpKeyId=` 파라미터명은 테스트가 못 박지 않는다 — URL 등록 뒤에도 안 뜨면 `naverMapsLoader.ts` 의 이 줄부터 본다.
- **웹 시트(`MapSheetShell`, gorhom)는 정상 동작한다 — 시트가 안 올라온 것처럼 보이면 측정 방법을 의심하라** → `--virtual-time-budget` 헤드리스 측정에선 reanimated 웹이 `requestAnimationFrame` 위에서 돌아 애니메이션이 한 번도 안 돌고, 시트가 초기값(화면 높이)에 머문 것처럼 나온다(W5 04b_3·W6 01c 가 이 인공물을 시트 결함 (B)로 오판). 실시간 대기(CDP `--remote-debugging-pipe`, 9초+)로 재면 첫 칸(h14 top 464·허브 top 380)으로 정상 이동한다. 합성 터치로 지도 드래그(시트 불변)·손잡이 드래그(시트 이동)도 보였으나 **CDP 합성 터치라 실기기(갤럭시 크롬·iOS Safari) 증거는 아니다** — 시트 안 스크롤(가장 높은 칸 규칙)은 미확인.
- **웹 h14 에서 `fitPins` 핀 맞춤이 보이는 띠와 어긋난다(미해결 — 새 티켓 후보)** → 마커 5개 중 2·4·5 가 화면 밖·시트 아래로 실측됐는데 단독 실험 페이지의 naver `fitBounds` 는 점 4개를 모두 담는다. 원인 미확정(`fitBand` 입력·핀 묶음·맞춤 시점). 웹 h14·허브에서 "핀이 안 보임"은 시트 탓이 아니다.
- **경로선(`buildPathLines`)은 네이티브·웹 공유 규칙이고 그리기만 갈린다** → 규칙을 바꾸면 양쪽이 같이 움직이고(네이티브 `MapView*.test.tsx` 무수정 green 이 지킨다), 선 굵기·점선 간격·케이싱 순서(흰 선이 primary 아래)는 jest 가 못 본다 — 실화면 육안. 웹 내 위치는 **권한 조회만** 한다(요청 안 함): 권한이 `granted` 가 아니면 점이 영영 안 뜨는 것이 정상이며, 확인하려면 브라우저에서 위치를 미리 허용해야 한다.
