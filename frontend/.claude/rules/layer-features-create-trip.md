# `src/features/create-trip/`

| 파일 | 역할 |
|---|---|
| `src/features/create-trip/model/wizardOrigin.ts` | (TRIP-1155로 features/explore에서 이사) 위저드 진입 출처 꼬리표 철자의 단일 출처. `wizardOriginParams()`(보내는 쪽) · `isWizardOrigin(params)`(받는 쪽, expo-router가 같은 키 반복 시 주는 배열도 처리). `features/explore`에 있는 이유는 d04 표면의 `@/features/trip` import를 `tripWizardStore` 하나로 묶어 두려는 것이다(옛 소스 스캔 결정, TRIP-1145에서 스캔 삭제). `router.dismissTo`로 같은 d04에 복귀하면 params가 통째 교체돼 `from`이 떨어진다(`traps-explore.md`). |
| `src/features/create-trip/model/tripDraft.ts` | (TRIP-1155로 features/trip에서 이사) 위저드 드래프트 검증. `validateTripDraft`는 위반 코드 **집합**(`NO_DESTINATION`·`END_BEFORE_START`·`NIGHTS_EXCEED_PERIOD`·`PARTY_BELOW_ONE`, 계약에 없는 판정은 발명하지 않음)을 돌려주고 **페일클로즈**다(판독 불가 날짜·`NaN` nights는 통과가 아니다). `nightsSum`(Σ박수)·`toCompanionType`(온보딩 5값→서버 4값, `부모님→null`)·`tripLength`(박수 초과 문구의 분모 — 컨테이너가 재계산하지 않고 재사용). `NaN` 페일클로즈는 PBT 생성기가 못 만드는 입력이라 동결 예제 테스트가 지킨다. |
| `src/features/create-trip/model/tripSummary.ts` | (TRIP-1155로 features/trip에서 이사) 위저드 진행 모델(`wizardProgress`·`formatWizardStep`, [1,4] 클램프)과 g01 요약 5행 셀렉터. `summaryDestinations`·`summaryPeriod`·`summaryBudget`은 `SummaryLine({main; sub?})\|null`, `summaryCompanion`은 `{main}`(sub 키 자체 없음 — `toEqual` 여분키), `summaryPreferences`는 `PreferenceSummary({main; onboarding})\|null`. 취향·예산 tier는 스토어에 없어 **인자로만** 받는다(라벨 불가지). 미선택은 빈 문자열이 아니라 `null`. |
| `src/features/create-trip/model/tripWizardStep1.ts` | (TRIP-1155로 features/trip에서 이사) 순수 함수 계층 — `PERIOD_PRESETS`·`COMPANION_OPTIONS`·`presetRange(code, baseDate)`·`deriveEndDate(startDate, nights)`(`fromEpochDay(toEpochDay(start)+nights)`)·`fromEpochDay`·`dayOfWeek`. 시계를 읽지 않는다(기준일은 인자). |
| `src/features/create-trip/model/tripWizardStore.ts` | (TRIP-1155로 features/trip에서 이사) 위저드 드래프트 **Zustand 스토어**(`useTripWizardStore`, persist 없음 — 모듈 싱글턴이라 재진입 보존이 저절로 성립). 판정은 하지 않는다. `touched`는 오류 문구 표시 게이팅. **제거는 자리 기준**(`removeDestination`·`removeMustVisit` 모두 `findIndex`+슬라이스 — `filter`면 같은 값을 둘 담고 하나 지울 때 둘 다 사라진다). `budgetText`는 사람이 친 원문만 저장하고 프리필은 스토어에 쓰지 않는 파생값이다("프리필 쓰기 ≠ 사용자 입력"). `initMustVisits`는 첫 호출만 반영, `addMustVisits`는 결과가 같은 참조면 `{}`를 돌려 상태를 안 바꾼다(렌더 루프 차단, 개념 [[참조 동일성과 렌더 루프]]). ⚠️ **`resetMustVisits()`는 시드 3필드(`mustVisits`·`mustVisitsInitialized`·`excludedMustVisitPoiIds`)의 손으로 적은 키 목록**이라 새 시드 필드를 추가하면 여기에도 손으로 넣어야 한다(테스트·tsc 모두 못 잡는다). `prefStyleOverride`·`prefActivityOverride`(여행 로컬 취향 두 축 — 같은 라벨 자연·쇼핑이 두 축에 있어 필드가 따로다, TRIP-1092. `undefined`=프리필 사용, `[]`=다 끔)는 사용자 편집값이라 `resetMustVisits`에 넣지 않는다(넣으면 remount마다 삭제). 새 축 필드를 더하면 `INITIAL_DRAFT`(`reset()`) 키와 `src/test-support/wizardDraftFixture.ts`의 채우기에도 손으로 넣어야 한다(픽스처를 빼먹으면 SF-1 자기검사가 red). 종료일은 파생값이다 — `setStartDate`·`addDestination`·`removeDestination`·`setNights`가 비export `endAfter`로 `deriveEndDate(시작, nightsSum)`을 다시 계산한다(`setPeriod`는 파생하지 않는 테스트용 문). ⚠️ 같은 파생이 `TripNewStep1Page.tsx`의 시트 미리보기에도 있다 — 한쪽만 고치면 "시트에 보인 끝 ≠ 적용 뒤 끝". `createdTripId`는 재진입 시 step1 「다음」을 PATCH로 가르는 근거이고, 셸이 마운트마다 지우되 꼭 갈 곳 고르기 완료만 1회성 표식 `preserveCreatedTripIdOnce`(액션 `keepCreatedTripIdOnce`, `INITIAL_DRAFT`에 `false`라 `reset()`이 함께 끔)로 보존한다(TRIP-1113 — 새 진입이 표식을 켜면 `SavedPlacesPage` C1이 red). `INITIAL_DRAFT.companionType`은 `'혼자'`가 기본(TRIP-1045 — `touched`는 안 켜짐, 기본값은 사용자 입력이 아니다). **(TRIP-1042)** `addDestination(name, nights, regionCode?)` — 3번째 인자로 지역 코드를 받아 목적지 객체에 담는다(옵션이라 안 주면 `regionCode: undefined` 키가 생기고 `toEqual`은 무시함, 생성 요청 직렬화에서도 빠짐). `removeDestination`·`setNights`는 `{...one}` 펼치기 복사라 코드가 자동 보존됨(고치지 않음). |
