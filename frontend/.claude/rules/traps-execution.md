이 파일은 repo-traps.md에서 경로별로 쪼갠 함정이다 — 해당 경로 만질 때만 로드된다.
(전역 불변식 INV-3 "소요시간 비표시, 거리만"은 코어 `repo-traps.md`에 남아 무조건 로드된다.)

- **react-query 캐시 알림을 읽는 통합테스트는 `act` 직후 곧바로 `result.current`를 읽지 마라 — flush 헬퍼로 순서를 기다린다.** `notifyManager`가 알림을 `setTimeout(cb, 0)`으로 예약해서 보내므로, `act` 직후 즉시 읽으면 재렌더 전(구값)을 관측할 확률적 flake가 난다(`useVisitCheck.integration.test.tsx` 11/20 재현 — 개념 [[테스트 워커 강제종료 flake (원인 미상)]]). 의심되면 `beforeAll`에 `notifyManager.setScheduler((cb) => setTimeout(cb, 5))`로 재현해 확인한다.
- **동기 제출을 비동기(await 뒤 mutate)로 바꾸면 "대기 중 언마운트" 창이 새로 생긴다 — `mountedRef`류 가드 없이는 화면이 사라져도 POST가 나간다.** 실제 TanStack에서는 언마운트 뒤 호출별 `onSuccess`/`onError`가 안 불리므로(`mutationObserver.js`) 이동도 오류 안내도 없이 조용히 서버 세션만 하나 더 생긴다(`ReplanSessionService.start`가 기존 열린 세션을 취소하고 새 세션을 연다). jest 목은 언마운트와 무관하게 콜백을 부르므로 이 창을 원리적으로 못 잡는다 — 재현하려면 대기 중 언마운트 → 콜백 미호출을 단언하는 통합 테스트를 따로 심는다. 이 도메인 밖에서도 "누름→await→mutate" 패턴을 새로 들이면 같은 사각이 반복된다.
- **측위는 `shared/location/readDevicePosition.ts` 하나로 부른다** → expo-location의 Android 기본값은 `mayShowUserSettingsDialog:true`라, 옵션 없이 `getCurrentPositionAsync()`를 직접 부르면 기기 위치가 꺼져 있을 때 시스템 "위치 사용" 대화상자가 뜬다. 떠 있는 채로 5초 타임아웃 POST가 나가면 사용자가 뒤늦게 "사용"을 눌러도 좌표는 버려진다. 인자를 잠그는 테스트는 `readDevicePosition.test.ts`뿐이라 다른 자리에서 직접 부르면 무심판이다(iOS는 옵션 자체가 없어 무해, 확인은 Android 실기).

## 여행 중 실행 (execution, i01~i05)
⚠️ 이 절의 `i01`·`i05` 등은 **코드 라우트·프리뷰 키가 쓰는 옛 Figma 코드**다. 라이브 Figma i 밴드는 i01~i10으로 재번호됐다(옛 i05 현재 장소 상세 = 새 i10) — 대조는 `spec-perception/reference/figma-structure.md`의 매핑 포인터로.

- **i01 active 카드의 진입로는 수동 [도착]이다 — 관람 중 슬롯이 있어도 그 뒤 예정 카드의 [도착]은 "앞 장소 완료 → 도착" 사슬을 보낸다(TRIP-1561)** → `LiveItineraryPage.tsx`가 `GET /visits/days/{day}` → `deriveVisitProgress` → `projectSlotProgress(activeSlots, {completedPoiIds, activePoiId})`로 방문 기록을 주입하고, `SlotProgressCard`의 upcoming 얼굴이 세 겹 게이트(페이지 `activeDate===today && visits.data!==undefined` → 뷰 `canArriveAt`[관람 중 없음, 또는 관람 중 칸 뒤의 예정이고 `skippedPoiIds`에 없음] → 카드 upcoming 얼굴) 뒤에서 `POST /trips/{tripId}/visits`를 `source:'MANUAL'`로 부른다. 지오펜스(`shared/location/geofence.ts`)는 `armed:false` degrade 스텁이라 실발화하지 않는다. 건너뛰기는 없다(도착 전 슬롯엔 서버 레코드가 없어 `/skip`을 못 부름). **[방문 완료]는 `automationArmed || 뒤에 [도착]이 설 카드 없음`일 때만 그려진다**(수동 허브의 마지막 장소·무장 여행 — 카드는 `onPressComplete` 가 있을 때만 버튼을 그린다). 서버는 두 도착이 동시에 열려도 받으므로 순서를 지키는 책임은 전부 클라(`useVisitCheck.completeThenArrive` ref 잠금 + 페이지 `arriveBusy`·`completeBusy`)다. 무장 여행의 첫 프레임은 `automation.state==='MANUAL'` 이라 [방문 완료]가 잠깐 숨을 수 있다(미확인·6-b 아침 판단). `nextNav.ts`(딥링크 폴백 사다리)는 `LiveItineraryPage.tsx`가 `resolveSlotDests`·`openNextNav`로 쓴다(슬롯별 [길찾기], TRIP-1189) — 데드코드가 아니다. 딥링크 스킴 미등록 문제(`kakaomap`, 개념 [[딥링크 스킴 미등록 — canOpenURL이 항상 false]])는 이 호출 경로에 그대로 걸린다.
- **`geofence.ts` 4함수(shared/location)는 호출자가 0이다** → (`dwellMinutes.ts`는 서버가 체류를 스스로 도출해 클라→서버 dwell 필드가 계약에 없어 TRIP-1191 로 삭제됐다.) `geofence.ts`는 실 네이티브 발화(`startGeofencingAsync`)가 없어 `armed:false`만 반환한다 — expo-task-manager 미설치·"항상 허용" background 권한·네이티브 리빌드가 선행돼야 한다. PBT/유닛 테스트로 정확성만 잠겨 있다.
- **지오펜스 태스크 재무장 루프는 TRIP-1511 로 해결됐다 — 단 해결책이 남긴 사각이 둘 있다** → `native.armGeofences` 가 직전에 등록한 리전 집합(slotKey·lat·lng·radiusM 순서 무관 키, 모듈 변수 `armedKey`)과 같으면 `startGeofencingAsync` 를 부르지 않는다(등록 성공 뒤에만 기억, `disarmGeofences` 가 지움). 기억을 비우는 `forgetArmedRegions` 는 `useLocationAutomation` 의 **포그라운드 복귀 refresh 에서만** 부른다 — 태스크 경로에서 부르면 루프가 되살아난다(시뮬 실측 분당 5천~1만 → 4~5회, 복귀 뒤 60초 0회). **남은 사각**: (1) 실기기에서 OS 가 등록을 잃는 경우(Android 위치 서비스 끔/켬·Play 서비스 비움) 포그라운드 복귀 전까지 복구되지 않고, 앱 프로세스가 죽으면 기억이 비어 콜드 wake 마다 1회 재등록한다 — 6-b 미확인. (2) 재등록이 throw 하면 옛 키가 남는데 expo 가 실패 시 이전 등록을 유지하는지 미확인이라 `handleGeofence`·`handleLocations` 경로(반환값을 버림)에서 옛 등록이 비었을 가능성이 있다. 둘 다 jest 가 원리적으로 못 본다 — 근거: TRIP-1511 구현 결정(03·03b).
- **포그라운드 wake 는 i01 허브(`useLocationAutomation` 마운트)에서만 들어간다 — 홈 등 허브 밖에선 자동 도착이 안 뜬다** → 진입 후 정지한 채 앱을 홈에 둬도 확정은 다음 경로 표본·지오펜스 이벤트·i01 진입 때까지 미뤄진다(TRIP-1517, `handleWake`). 앱 루트로 올리는 건 설계 선택지로만 남아 있다. 6-b 에서 "4분 정지했는데 안 뜬다" 하면 화면부터 확인한다. 근거: TRIP-1517 구현 결정(03·04b, 요구사항 근거로 인용 금지)

- **허브(`LiveHubView`)의 시트 칸 번호는 허브만 새 체계다: −1 완전 내림 · 0 중간 · 1 펼침** → 다른 `MapSheetShell` 소비처는 3칸 기본 배열(`[28,'45%','88%']`)이라 `initialIndex={2}`·`to === 2` 가 정상이다(ReplanDraftView·EditorView·ItineraryPlanPage). 칸 번호는 `number` 라 `tsc` 가 못 잡는다 — 허브 칸 번호를 건드리거나 옮길 때는 `initialSnapIndex`·`onAnimate(from,to)`·`expandedSnapIndex`·`snapToIndex`·프리뷰 호출(`app/_dev/preview.tsx` 약 30곳)·통합 테스트의 `hubSnapIndices()` 까지 형제 전수 스윕이 필수다(테스트 설계 때 첫 grep(`snapPoints\|initialSnap`)이 통합 4곳을 놓쳤다). 잘못 옮기면 "다른 이벤트"를 쏘면서 green 으로 남는다.
- **시트가 −1(완전 내림)에 닿는 전이는 알약 숨김 가드(`from !== expandedSnapIndex`, 펼침 출발이면 건너뜀)를 우회해야 팝업·카드가 닫힌다** → 펼침에서 곧장 −1 로 끌어내리면 가드가 "펼침 출발"로 보고 건너뛰어 시트가 사라진 화면에 `floating` 이 남는다. 그래서 `onSheetAnimate` 에 `to === -1` 을 가드와 별개 줄로 둔 것이고, 테스트의 `1→-1` 행이 이 줄의 유일한 그물이다(지우면 그 두 건만 red). 같은 −1 도착인데 **트리거 알약은 출발 칸에 따라 갈린다**(중간 출발 숨김 · 펼침 출발 유지) — 제품 판단이 안 난 상태라 어느 쪽도 단언하지 않는다. `sheetClosed`(−1 도착 여부)는 일정 칸이 "올릴지 정리만 할지"만 가른다 — 시뮬레이터에서 −1 → 일정 칸으로 올림 → 펼침으로 끌어올림 → 일정 칸을 눌러도 시트가 안 내려오는 것을 확인했다(2026-10-21 실측).
- **"시트 열린 동안 바 없음"(BR-U8-53)·팝업/카드 "닫힘" 단언은 기본 상태가 이미 닫힘·있음이라 공허 통과하기 쉽다** → 팝업·카드는 기본이 닫혀 있어 `queryByTestId(...) == null` 만 보면 안 열었어도 통과한다. 그물은 늘 "열었다(긍정 앵커) → 사건 → 닫힘 + 바·기회 칸은 살아 있음" 쌍이어야 하고, 시트 −1 은 −1 직전에 팝업·카드를 열어 둔 상태에서 단언한다. 바 쪽도 같다 — 시트 4종(메모·위험·변경 반영·위치 설명) 각각 "바 없음" + 닫은 뒤 "바 복귀" 짝과 대조군이 있어야 `barHidden` 을 늘 false 로 만든 구현이 red 가 된다. 긍정 앵커를 정리하다 지우면 나머지가 green 인 채로 그물이 풀린다.

- **간격·크기를 `className` 과 `style` 두 곳에서 내면 jest 는 한쪽만 읽는다** → 사이클 3 구현은 바 루트 `gap-sm`(className)과 캡슐 `marginLeft`(style)로 뒤로–캡슐 간격이 16 이 됐는데(캡슐 256·칸 59·수정 팝업 5pt 어긋남) 렌더 트리엔 `style` 이 없어 어느 테스트도 못 잡았고 code-critic 이 계산으로 잡았다. 지금은 간격이 캡슐 `marginLeft` 한 곳이고, 유리 바깥 노드 className 에 가로 간격 클래스가 없다는 것과 style 허용 키 밖 값이 없다는 것을 BS1~BS4·HD3 이 읽는다. `editPopupPlacement`(수정 칸 중심 197.5)와 실제 칸 중심을 교차하는 테스트는 없다(jest 에 flex 엔진이 없다) — 간격 하나가 바뀌면 팝업 위치가 조용히 어긋난다.
