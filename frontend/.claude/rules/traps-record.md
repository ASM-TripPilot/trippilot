이 파일은 repo-traps.md에서 경로별로 쪼갠 함정이다 — 해당 경로 만질 때만 로드된다.

- **react-query 캐시 알림을 읽는 통합테스트는 `act` 직후 곧바로 `result.current`를 읽지 마라 — flush 헬퍼로 순서를 기다린다.** `notifyManager`가 알림을 `setTimeout(cb, 0)`으로 예약해서 보내므로, `act` 직후 즉시 읽으면 재렌더 전(구값)을 관측할 확률적 flake가 난다(`useVisitCheck.integration.test.tsx` 11/20 재현 — 개념 [[테스트 워커 강제종료 flake (원인 미상)]]). 의심되면 `beforeAll`에 `notifyManager.setScheduler((cb) => setTimeout(cb, 5))`로 재현해 확인한다. 같은 모양인 `savedStays`(stay)·`savedPlaces`(explore)·`useToggles`(notification)·`useAdjustVisitTimes`(record, 이 파일)에 처방이 들어가 있고, 헬퍼는 공용 `src/test-support/flushNotifications.ts`다(스케줄러 잠금은 각 파일 인라인 유지 — 공용 setup으로 옮기면 100여 파일에 번진다). ⚠️ **롤백 단언(기대값=호출 전 값) 앞의 flush는 지워도 파일이 green으로 남는다** — 그 flush가 없으면 잠금 아래서 롤백 심판이 조용히 공허해지는데 기계가 못 잡아, "필요 없어 보이는 줄"로 정리하면 사고가 난다. ⚠️ **`waitFor(() => expect(hitCount).toBe(1))`은 "정확히 1회"를 보장하지 않는다** — 문(gate)은 응답만 막고 요청 카운트는 막지 않으므로, `waitFor`가 첫 시도에 1을 보고 끝난 뒤 지연된 두 번째 요청이 카운트를 올려도 못 잡는다.
- **월 그리드 순수 함수는 `shared/lib/monthGrid.ts`가 유일한 정본이다**(`daysInMonth`·`firstWeekdayOfMonth`·`shiftMonth`·`isDateInRange`·`buildMonthGrid`) — stay·trip의 옛 사본은 삭제돼 한 벌로 통합됐다. 새 record 파일을 만들 때는 이 파일부터 확인한다. record 안에서 이 산술을 다시 짜면 다시 두 벌째가 된다.
- **`recordsCalendar.ts`의 `formatTripDateRange`·`nightsLabel` 정본은 `entities/trip/lib/{formatTripPeriod,formatNights}.ts`다** → 이 파일이 `buildPastTripCards` 내부에서도 그 함수를 쓰므로 옛 자리는 `import`+로컬 재수출이다(순수 `export … from`으로 바꾸면 내부 호출이 깨진다 — `layer-entities.md` entities/trip 절). `PastTripList.tsx`는 `entities/trip/ui/PastTripRow`에 위임하며 완성 `testID` 리터럴(`record-calendar-past-trip-{id}`)을 조립해 넘긴다.
- **`GET /trips/{tripId}/change-log`는 미개통이다(생산자 없음, 항상 빈 목록) — 변경 이력은 `GET /trips/{tripId}/records` 응답의 `TripRecord.changes[]`에 임베드돼 내려온다.** `openapi.yaml`도 "생산자 없어 항상 빈 목록, 붙이지 말 것"이라 적는다. 티켓 설명이나 aidlc 원문(BR-U5-29)이 `/change-log` 개통을 전제해도, 변경 이력을 조회하는 화면은 `/records.changes[]`를 쓴다.
- **`shared/photo`는 `expo-image-picker`·`expo-media-library` 네이티브 모듈을 입는다(TRIP-1070) — 코드만 머지하고 재빌드를 안 하면 기존 dev build에선 [사진]이 조용히 "사진을 불러올 수 없어요"(failed)로 접힌다.** 에러 팝업·크래시가 없어 버그처럼 안 보인다(이 자체는 `pickPhotoAssets`의 전체 try/catch가 의도한 정상 폴백). 재빌드는 `pnpm expo prebuild && pnpm expo run:ios`(`LANG=en_US.UTF-8` 필요, `traps-map.md`와 같은 패턴). Android 사진 권한은 `expo-media-library` config plugin 기본값이 `granularPermissions: ['photo','video','audio']`라 인자 없는 `requestPermissionsAsync()`도 세 종류를 다 묻는다 — "사진만"으로 좁히려면 `app.config.ts`의 플러그인 옵션과 `shared/photo`의 요청 인자를 **함께** 바꿔야 한다(한쪽만 바꾸면 Android throw).
- **"선택한 사진만"(limited)에서 피커는 번호를 주지만 앨범 조회는 허용 목록 밖 사진에 null 이다 — 앱이 허용 목록에 넣는 API 는 없다** → "limited 면 번호가 null" 이 아니다(런타임 측정). 그래서 고를 때 피커 파일을 문서 폴더 사본으로 옮긴다(`src/shared/photo/localCopy.ts`). 앱은 "허용 목록 밖"과 "원본 삭제"를 구별 못 한다(둘 다 nil) — limited 에선 지운 사진도 사본으로 보이고, 이 사실을 고치려고 사본을 끄면 limited 사진 전부가 안 보인다. 전체 허용 시뮬에서는 이 경로가 아예 안 돈다 — 6-b 는 limited 로 허용 목록 **밖** 사진을 고른다. 사진 주소 쿼리는 `photoUriQueryOptions` 만 쓴다.
- **iOS 설정 앱에서 사진 권한 수준(전체·제한·안 함)을 바꾸면 OS 가 앱을 죽인다 — 앱 복귀가 아니라 재실행이다** → 코드로 못 바꾼다. 재시작 없는 경로는 허용 목록 추가(「선택된 사진 편집」)와 앱 안 프롬프트뿐이다. "복귀하면 풀린다" 류 6-b 는 복귀 전후 pid 를 함께 본다 — 앱이 재시작되면 캐시가 비어 코드와 무관하게 통과한다(시뮬 iOS 26.5 측정, 실기기 미측정, 상세는 하네스 변경이력).
- **`xcrun simctl privacy booted grant photos <번들>` 은 전체 허용이 아니다 — 앱을 죽이고 권한을 `undetermined` 로 만든다** → 시뮬에서 권한 상태를 만들 때 쓰지 않는다. 전체 허용은 설정 앱으로 만들고, 상태는 앱 안 `getPermissionsAsync`(CDP)로 읽어 확인한다(iOS 26.5 측정, 상세는 하네스 변경이력).
- **msw `response:mocked` 이벤트는 `HttpResponse.error()`(네트워크 실패)에서 발화하지 않는다 → "응답 N개를 기다린다"류 헬퍼는 네트워크 실패 케이스에서 영원히 대기한다**(TRIP-1078 실측). 실패 뒤 안내를 보는 통합테스트는 요청 수신을 기다린 뒤 고정 여유(`settleMemoResponses`)를 주고 본다. 또 `pnpm test:node -- --no-watchman <경로>`는 `--` 뒤를 jest가 경로 패턴으로 먹는다 — `pnpm test:node --no-watchman <경로>`로 돌린다.
- **j01 시트에서 키보드가 떠 있는 채 일차 칩을 누르면 입력 중이던 메모가 blur 없이 사라질 수 있다** → 시트가 `keyboardShouldPersistTaps="handled"`라 시트 안 버튼(일차 칩 포함) 탭이 입력칸 포커스를 빼지 않고, 메모 저장 경로는 `MemoInline`의 `onBlur` 하나다(j01 한정 — 허브 메모 시트는 TRIP-1426부터 [저장] 버튼 하나이고 blur 저장은 꺼져 있다). jest는 포커스·키보드를 흉내 못 내 원리적 사각 — 6-b에서 "메모 입력 → 다른 카드 [완료] → 일차 칩" 순서로만 확인된다.
- **j01 하단 바(`widgets/bottom-nav-bar`)의 위치·닫힘 칸·푸터 여백은 jest 가 하나도 못 지킨다(TRIP-1557)** → 시트 닫힘 칸 98(`NAV_BAR_RESERVE 70 + 핸들 28` — TRIP-1593 이후 가장 낮은 칸이 아니다, 그 아래 완전 내림 -1 이 있고 `enablePanDownToClose`·`mapLogoMargin` 을 지워도 jest 는 green 이라 6-b 전용)·`initialIndex={1}`·푸터 86·바 `bottom 12`·좌우 30 을 각각 0 으로 바꿔도 전 스위트 green 이다(통과형 gorhom 목 + 레이아웃 미측정). 바가 높아지거나 셸 기본 칸이 바뀌면 핸들이 바 뒤로 조용히 숨는다 — 소스(`TripRecordsView.tsx` 의 `SNAP_POINTS`)와 6-b 가 유일한 그물. 같은 뜻으로 시각 수정 결과 토스트는 `absolute` 라 바와 겹칠 수 있어 `bottom: NAV_BAR_RESERVE` 로 올려 두었으나 겹침 해소는 실기 미확인이다. **요약 칸 켜짐은 "서버가 준비됐다고 말했다"일 때만**(`envelope !== undefined && shareEnabled` — TRIP-1584 부터 `features/reflection` 의 `useRecordBarNav` 안) — 조회 중·실패를 "준비됨"으로 접으면 눌러도 요약이 없는 화면으로 간다(BR-U5-48, 뮤테이션 4종이 red 로 지킨다).
- **reanimated 애니메이션 스타일은 jest에서 `props.style`로 읽으면 첫 렌더 값에 굳어 있다** → 허브 FAB 앵커가 시트를 안 따라가도 첫 값만 맞으면 green이 된다(TRIP-1083 때 처음 밟았고 허브 FAB 앵커는 TRIP-1522, j01 FAB 앵커는 TRIP-1557 에서 걷혔다 — 지금 소비처는 허브 하단 바 변신 모션(`LiveBottomBar` — 헬퍼 `src/test-support/barMotionProbe.ts`) 하나다. `fabAnchorProbe` 의 앵커 읽기 함수들은 고아가 됐다). 관측은 `getAnimatedStyle(node)`(reanimated export)로만 하고, **가짜 타이머**가 있어야 갱신된다(매퍼 등록이 타이머로 미뤄짐). **원인 act 안에서 타이머를 흘리면 무효**다 — onLayout처럼 React 상태를 바꾸는 원인은 리렌더 끝(act 종료)에 매퍼를 다시 등록하므로, 타이머 흘림(`flushFrames`)은 **별도 `act`** 로 부른다(올바른 구현도 red로 오판, 실측). 시트 위치 상자는 통과형 gorhom 목이 `...props`를 host View에 펼치는 덕에 `snapPoints` 가진 노드의 `props.animatedPosition`으로 꺼내 `.value`를 써서 흉내 낸다. `Animated.View`의 `className`은 NativeWind 인터롭이 RN 코어만 등록해 기기에서 무시될 수 있으나 jest는 raw prop으로 남겨 통과시킨다 — 그래서 앵커는 className 부재를 단언한다. 앵커의 첫 프레임·리렌더 튐과 실제 터치는 jest 사각이다(gorhom이 처음 쓰는 값은 `창 높이+topInset`이라 초기값과 한 프레임 다를 수 있다).
