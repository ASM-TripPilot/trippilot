- **`GET /trips/{id}/itinerary` 캐시 키의 `retry` 옵션은 한 화면에만 걸어선 안 된다** → 홈(`PlanningHome`)·카드(`TripCardContainer`)·목록·방식 선택(`ItineraryMethodPage`)이 전부 같은 캐시 키를 구독한다. react-query는 `retry` 규칙을 **그 요청을 시작한 관찰자**에 고정한다 — 페이지 로컬로만 "404는 재시도 안 함"을 걸면, 다른 관찰자가 기본 옵션(3회)으로 그 키를 건드리는 순간 무력화된다. 이 키를 만지는 새 화면·훅은 `shared/api/isNotFound.ts`의 `retryUnlessNotFound`(전역 `QueryClient` 기본값으로도 배선됨)를 재사용한다. 개념 [[react-query retry 옵션 고정 — 요청 시작한 관찰자가 이긴다]].
- **`PlaceAddPage`의 `insertAfter`는 페이지가 열려 있는 동안 고정된 URL 파라미터라, 연달아 담기 자리는 `addedPoiIds.length`(저장 성공 수)를 더해 민다(TRIP-1640)** → `insertAt = Number(insertAfter)+1+addedPoiIds.length` 한 값을 PUT 삽입·시각 시트 기본값의 앞 슬롯(`insertAt-1`)·dirty 초안 삽입 셋이 공유한다. **`addedPoiIds`는 "추가됨" 행 표시와 오프셋을 겸하므로** 담은 장소를 빼거나 중복을 거르는 변경이 들어오면 다음 담기가 방금 담은 곳 앞에 끼고 시각이 다시 겹치는데, 빼기 경로 심판이 없다. 마지막 카드 뒤·2일차 이상 연달아 담기도 심판 없음(코드상 안전). 초안 좌표≠서버 좌표(개념 「삽입 좌표계」)는 그대로다.
- **`GeneratingPage`의 POST 성공 캐시 쓰기는 훅 옵션 `mutation.onSuccess`(4번째 인자 `context.client`)에 둔다 — `mutate(vars, { onSuccess })` 두 번째 인자는 화면이 언마운트되면 안 불린다** → 생성 대기 중 뒤로(=홈) 나가면 호출별 콜백은 건너뛰고, 홈이 들고 있던 404 캐시가 남아 "일정 만들기"로 보인다. 이 창은 **1일차가 서버에 도착하기 전**에도 남는다 — 그 전엔 홈 히어로가 여전히 "일정 만들기"라 다시 생성을 고르면 도는 생성이 취소된다. 개념 [[useMutation (뮤테이션)]] "호출별 vs 훅 레벨" 절 참고. **TRIP-1690 이후 이 `onSuccess` 는 async 다**(`await cancelQueries` 뒤 `setQueryData`) — react-query 는 훅 옵션 `onSuccess` 를 기다린 뒤 호출별 `onSuccess`(`router.replace`)를 부르므로 이동은 캐시 쓰기 뒤다. **`GeneratingPage.hookMock` 의 'state' 목은 훅 옵션 `onSettled` 를 흉내 내지 않는다** → `inFlightRef` 를 `onSettled` 로 푸는 구현은 목에서만 영원히 잠긴다. 실패로 끝나는 it 은 `mockHookOptions?.mutation?.onSettled?.()` 한 줄로 직접 정산한다(T-7).
- **`resolveDraftView` 는 슬롯이 있으면 `loading` 보다 `listed` 를 먼저 고른다** → "재생성 중이라 로딩 얼굴로 덮기"는 순수 함수가 아니라 `DraftPage` 가 `view` 를 덮어야 한다(`regenLoading`, TRIP-1690). 이 덮기에는 탈출구가 둘 있다(`pollExhausted` 의 `|| regenerating` · `!itinerary.isError`) — 하나가 빠지면 상한·서버 장애에도 로딩이 안 끝난다(`DraftPage.integration` C8·C9 가 각각 잠근다). 폴백 인터스티셜 판정(`resolveFallbackNotice`)은 `view` 를 안 보므로 `!regenLoading` 을 따로 걸어야 한다(C7).
- **h08 폴백·일부 실패 안내 문구 상수(`FALLBACK_REASON_TITLE` 등 — `STALE_FAILED_NOTE`·`REASON_SUBTITLE` 사본은 TRIP-1352 에서 `DraftScreen` 목록 분기와 함께 지웠다)가 `DraftScreen.tsx`와 `DraftFallbackBanner.tsx`(TRIP-1150부터 둘 다 `pages/itinerary/itinerary-draft/ui`)에 사본으로 있다**(TRIP-1039) → `ALT_LABEL` 이중화와 같은 계열의 드리프트 함정이다. 값은 현재 일치하지만 한쪽만 고쳐도 각 파일의 테스트가 자기 값만 exact-match해 화면 간 문구가 갈라져도 어느 심판도 안 잡는다. 두 사본이 같은 page 슬라이스 안에 들어와 이제 슬라이스 안(예: `pages/itinerary/itinerary-draft/config/`)에서 합칠 수 있다 — 아직 안 합친 상태, 새 티켓 후보.
