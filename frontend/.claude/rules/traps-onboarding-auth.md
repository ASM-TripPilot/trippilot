## auth · onboarding

- **세션 만료·로그아웃 UX** → 토큰 clear가 게이트 목적지를 LOGIN으로 바꾸면 `app-shell/model/useAccountBoundaryReset.ts`가 `dismissAll`→`replace('/login')`→캐시·취향 비우기를 한다(TRIP-1077, 옛 "즉시 리다이렉트 없음(FW2)"은 폐기). 단 세션 만료 실기는 재현 수단이 없어 jest 체인으로만 확인됐고(6-b 미검증), 같은 계정의 HOME→FORCE_UPDATE/RECONSENT 전이는 정리 대상이 아니다.
- **apple 소셜 로그인** → `oauthConfig.ts`의 apple 슬롯은 여전히 빈 값이지만 이제 **안 쓰인다** — `makeAuthorize.ts`(TRIP-932, 2026-09-28 TRIP-1035로 재확인)가 apple을 브라우저 OAuth가 아니라 **네이티브 SDK 어댑터(`appleAuthorize`)로 항상** 라우팅해 `oauthConfig`를 거치지 않는다(env 게이트 없음). "범위 밖" 서술은 낡았다 — 옛 코드 주석·`oauthConfig.ts` 파일 주석에는 아직 남아 있다. kakao·naver는 채워졌고, naver는 `usePKCE:false`+`state` 필수인 비표준 갈래라 다시 만질 땐 `realAuthorize.ts` 조건부 분기부터 본다.
- **약관 라벨(`TERMS_LABELS`)은 신규 타입에 자동 대응 안 한다** → `features/onboarding`의 `ONBOARDING_TERMS_TYPES`(순회 대상 — TRIP-1421이 이사)와 `TERMS_LABELS`(라벨 맵)는 **두 상수를 손으로 맞추는 관례일 뿐 구조적 강제가 아니다**(옛 커밋 메시지의 "구조적 불가"는 부정확). 폴백 `TERMS_LABELS[type] ?? term.termsType`이 있어 라벨을 안 채우면 원시 코드가 그대로 화면에 노출된다.
- **c08 위치 화면의 마운트 시 기존 denied 감지 전이는 TRIP-1427에서 심판이 생겼다(M1·M2 — 조건 삭제·`!canAskAgain` 제거가 red, 뮤테이션 실측)** — 아래는 조건의 의미다 → `pages/onboarding/onboarding-location/ui/LocationPage.tsx`의 `useEffect`(`getForegroundPermissionsAsync` 조회)를 통째로 지우거나 조건을 뒤집어도 `LocationPage.integration.test.tsx`가 green이다. 조건은 `status==='denied' && !canAskAgain`이다 — 안드로이드 `canAskAgain=true`(재요청 가능)를 설정-강제 화면으로 보내면 오분류다. 이 파일을 다시 만질 때 회귀가 소리 없이 날 수 있다. 설정 복귀 재조회 이동의 중복 방지는 400ms 가드 + 언마운트 `alive` 두 장치가 겹쳐 지킨다(가드 창 안에 granted가 오면 재조회 이동은 무시되지만 [계속]으로 빠져나와 갇히진 않는다). `sub.remove()`(구독 해제) 줄은 심판이 없다 — 지워도 green이다. 설정 앱 왕복 자체는 jest 사각이라 6-b 실기(사람 몫).
- **`SocialLoginScreen.tsx`의 앱아이콘 `LinearGradient`는 반경을 `className`이 아니라 `style borderRadius`로 준다** → `rounded-*` 같은 NativeWind 반경 토큰은 그라디언트를 실제로 클립하지 않아 값이 있어도 각져 보인다. 대조군은 `SplashScreen.tsx`(style borderRadius로 라운드 정상). 이 클립 여부·확대 후 픽셀 크기는 jest 무심판 — `_dev/preview` 로그인 실기 육안이 유일한 그물(지도 `viewOnly`·바텀시트 딤과 동형 층 한계). 반경 재조정 시 반경/박스(0.223)·글리프/박스(0.6) 두 비율을 함께 옮긴다.
- **온보딩 카드끼리 하단 버튼이 같은 자리라, 앞 카드의 이동 경로 하나라도 가드 창을 못 열면 연타의 두 번째 탭이 다음 카드 버튼을 대신 누른다** → 위치→푸시 사이에서 실제로 재현됐다(TRIP-1108 5-b): 위치 권한이 **이미 허용된** 기기(같은 기기 두 번째 계정)는 OS 창 없이 곧장 granted가 돌아와, `계속` 연타가 푸시 카드 `계속`을 눌러 카드를 못 본 채 OS 알림 창이 뜬다. `LocationPage.tsx` granted 분기의 `openPressGuardWindow()`가 막고, `pressGuardOnboardingPush.test.tsx` X1(나중에→나중에)·X2(거부 계속→계속)·X3(granted 계속→계속)·X4(설정 복귀 재조회 이동 → 푸시 `계속`) **네 쌍만** 잰다. 온보딩 카드를 하나 더 잇거나 이동 분기를 추가하면 그 쌍은 무심판이다 — `guardPress`가 감싼 버튼을 눌러야만 창이 열리므로, 응답이 빠른 비동기 분기는 감싸거나 창을 직접 열어야 한다. X3은 시계를 멈추고 첫 탭 뒤 `resetPressGuard()`를 부르지 않는다(넣으면 사고가 사라져 red가 안 난다).
- **푸시 카드 `계속` 뒤 OS 알림 창은 취향 1/2 화면 위에 뜬다** → `void promptAndRegisterPush()`를 기다리지 않고 `replace`하기 때문이다(권한 결과·토큰 등록 실패는 이 화면이 모른다, 실패는 `register.ts`가 삼키고 재등록은 다음 콜드 스타트 `SplashGate` HOME 진입뿐). 창이 실제로 취향 화면 위에 어색하지 않게 뜨는지·`(onboarding)/push` 실제 진입·동심원 링 픽셀(위치 카드 추정값)은 jest 사각이고 6-b 미검증이다. 카드 문구는 Figma 채택본 c08-push(`4976:3306`)이고 위치 카드 주 버튼 `위치 사용 허용`(Figma) vs `계속`(코드) 드리프트는 미결이다.
- **`fireEvent.press`는 안쪽 노드에서 올라가다 조상 *컴포넌트*가 받은 `onPress` prop까지 직접 부른다 — `Pressable` 배선이 끊겨도 green** → 애플 버튼(`lib/appleAuthorize.tsx`의 `AppleSignInButton({ onPress })`)에서 실측됐다(TRIP-1124 5-b C1): `onPress={onPress}`를 `onLongPress={onPress}`로 바꿔도 245/245 green이었고 실기에선 짧은 탭이 무반응이다. 그래서 `LoginPage.apple.test.tsx`는 **이 리포 첫 `userEvent`**(`await userEvent.setup().press(...)`, responder 경로·실타이머 약 130ms)로 누르고, 누를 곳을 글자(A10~A12)와 로고(A13) 두 군데로 둔다 — 글자만 누르면 `Text`에만 `onPress`가 달린 구현도 통과한다. 로고 모양은 `FIGMA_APPLE_LOGO_D` 바이트 대조(A14). **이 파일에 `jest.useFakeTimers()`를 넣으면 누르기 4케이스가 5s 시간 초과로 죽는다**(`userEvent.setup()`에 `advanceTimers` 없음 — 시끄럽게 실패하는 방향이라 조용한 통과는 아님). 받은 prop이 `onPress`인 다른 커스텀 버튼(`SkipVisitDialog` 류)의 테스트도 같은 사각을 가질 수 있다 — 아직 훑지 않았다.
- **`expo-apple-authentication` 목(`src/test-support/expoAppleAuthenticationMock.tsx`)에서 시스템 버튼 대역이 사라졌다** → `AppleAuthenticationButton`이 없어서 구현이 시스템 버튼을 되쓰면 렌더가 undefined 엘리먼트로 터진다(`LoginPage.apple` 9건 red — 목 제거가 그물이다). 다만 실패 메시지는 "시스템 버튼이 있다"가 아니라 `Unable to find node on an unmounted component`이고, 누가 목에 대역을 되살리면 혼합형(커스텀+시스템 버튼 병기)은 존재 단언만으로 못 잡는다. 애플 버튼 제목은 22px(`text-hero`)라 iOS "더 큰 텍스트" AX 크기(약 1.8배~)에서 고정 높이 52 안에 잘릴 수 있다 — 리포 전체에 `allowFontScaling`·`maxFontSizeMultiplier` 0건, jest 사각이고 6-b 미검증(4버튼 공통).
- **기능 안내 6장(`pages/onboarding/onboarding-tour`)의 아래는 jest 가 원리적으로 못 본다** → `pagingEnabled` 실제 스냅·스와이프, 무대 래퍼 `pointerEvents="none"` 이 실제 터치를 막는지, 안전영역, `✦`(U+2726)의 Noto Sans KR Bold 폰트 대체(안드로이드 미확인), 안드로이드 하드웨어 뒤로 실제 키, `initialPage` 의 `contentOffset`(안드로이드 미확인 — 프리뷰 전용), 가드 전환 직후 홈 번쩍임. 단언은 testID 트리·콜백 횟수·`replace` 인자까지다. 취향 3출구 → 투어 → 홈 완주는 신규 계정으로 사람이 6-b 에서 봐야 한다(TRIP-1595 은 시뮬 렌더 캡처만 했다). **투어 모션(TRIP-1596)이 얹힌 지금은 사각이 더 있다** → 실제 60fps 재생, 클립 상자가 점선을 실제로 자르는 모양(`overflow:'hidden'` 의 존재는 A17 이 보지만 시각 결과는 아니다), 이징 체감, `다음` 슬라이드와 재생이 겹치는 느낌, 동작 줄이기 ON 첫 1~2프레임의 빈 무대, 안드로이드 `width` 애니메이션 매끄러움, 2~6장 중간 프레임(끝 프레임만 iOS 로 S1 과 픽셀 동일 확인). 단언은 순수 함수 값표와 가짜 시계 위 `getAnimatedStyle` 까지다.
- **`router.replace('/')` 는 홈이 아니다 — `app/` 에 `'/'` 로 풀리는 화면이 둘이다** → `(onboarding)/index` 와 `(tabs)/index`(괄호 그룹은 주소에서 지워진다). 라우터는 가드(`Stack.Protected`)가 잠갔는지 안 보고 하나를 고르고, 온보딩 완료 계정은 `(onboarding)` 이 잠겨 있어 이동이 **에러 없이 무시**된다(TRIP-1597: 투어 `건너뛰기`·`시작하기` 무반응). HOME 으로 가는 이동은 `'/(tabs)'`. 로그인·재동의의 `'/'` 는 "게이트가 다시 판정"하며 가드 전환이 화면을 옮겨 줘서 동작하는 예외다(투어는 게이트가 이미 HOME 이라 그 전환이 없다). 재동의 중 `replace('/')` 는 throw 없이 무시되고 화면은 게이트 전환(`Stack.Protected`)이 옮긴다 — `replace('/')` 자체는 장식이다(실측, TRIP-1628). **가드에 막힌 이동은 throw 가 아니라 조용한 무시라 `not.toThrow` 만으론 빈 통과** — 이동 단언은 pathname·스택·화면 testID 로 한다. 공유 `ROUTES`(`SplashGate.integration`)는 이제 `(onboarding)/index` 를 둘 다 두고, TRIP-1628 카나리가 그 줄을 지킨다(빼면 red). 로그인의 `'/'` 는 아직 진짜 라우터로 고정한 케이스가 없다.
- **기존 계정 권한 안내(TRIP-1601)의 "봤음" 표식은 사용자가 카드를 봤을 때가 아니라 `replace` 를 보내기로 한 순간에 쓰인다** → 어긋나는 자리가 셋이고 사용자 배포 우선으로 **고치지 않고 나갔다**(03b 경고 1~3): ① 신규 가입 마운트는 `sawOnboarding` 으로 이동 0·표식 0 이라, 온보딩 위치 카드에서 iOS "한 번만 허용"을 고른 사람은 **다음 콜드 스타트에 위치 카드를 한 번 더** 본다(OS 상태가 다시 미결정). ② 3초 뒤 잠정 HOME 이 서버 판정으로 LOGIN 등으로 교정되거나 `replace` 가 실패하면 표식만 소진돼 그 사용자는 안내를 영영 못 본다(훅은 `isProvisional` 을 모른다) — **6-b 에서 실측**: 낡은 Metro 번들(`Requiring unknown module`)로 카드가 안 떴는데 표식 파일은 써져 있었다. 6-b 를 다시 돌릴 땐 시뮬 앱 문서 폴더의 `install-flag-permission-catchup` 을 지운다. ③ 위치 카드에서 앱을 종료하면 뒤의 알림 카드는 안 뜬다. 또 `installFlag` 의 "읽기 실패 → reject" 분기는 iOS 에서 도달하지 않는다(`File.exists` 가 `false` 를 돌려줌 — 테스트 대역만 던진다). 이 계약들은 jest 가 보지 않는다(G1 은 같은 마운트만, 잠정→교정 전이 케이스 없음).
