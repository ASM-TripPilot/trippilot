# 숙소 일반 그림

숙소 사진 칸(검색 카드·탐색 숙소 줄·상세 큰 사진·저장한 숙소·추천 카드)을 채우는 수묵담채(K6) 일러스트 6장. 장소 카테고리 그림(`../place-categories/`)과 같은 스타일이다.

> **아직 앱에 연결돼 있지 않다.** 이 폴더는 에셋과 생성 기록만 담는다. 연결 작업은 `docs/handoff/2026-10-22/root-3280e9e7-stay-generic-covers.md` 를 따른다.

## 구성 (6파일 · 약 300KB)

`stay-1.webp` ~ `stay-6.webp` — 가로 3:2, 738×492 WebP q75.

| 파일 | 장면 |
|---|---|
| `stay-1` | 침실(더블 침대·창밖 초록) |
| `stay-2` | 트윈룸(창가 둥근 테이블) |
| `stay-3` | 방 입구에서 본 객실 |
| `stay-4` | 중립적인 저층 건물 외관(발코니·가로수) |
| `stay-5` | 라운지 코너(안락의자 둘·큰 창) |
| `stay-6` | 객실 발코니(저녁빛) |

## 왜 유형별이 아니라 일반 한 세트인가

숙소 유형(`stayType`) 값은 시드 12,936곳 기준 `생활숙박` 6,901 · `호텔` 4,178 · `기타` 1,676 · `리조트` 181 인데, 유형과 그림이 의미 있게 대응되지 않고(생활숙박이 어떤 모습인지 정하기 어렵다) 저장한 숙소(`SavedStay`)는 유형 필드 자체가 없다. 그래서 사용자가 **유형과 무관한 일반 그림 한 세트**로 정했다(2026-10-22). 객실 내부 장면을 중심으로, 풀·고층 타워·기와처럼 특정 유형·양식을 암시하는 요소는 뺐다.

버려진 것(이 폴더엔 없다): 유형별 12장(호텔·리조트·생활숙박·기타 각 3) — 가능하나 쓰지 않기로 했다. 처음 만든 '기타' 세트는 세 장 모두 한옥으로 읽혀 폐기했고, 중립 가드(`NEUTRAL`)를 붙여 다시 만들었다.

## 쓸 때 (설계 제안 — 확정 아님)

- **랜덤 = 결정적 선택**: `Math.random` 이 아니라 숙소 키의 해시로 6장 중 한 장을 고른다(`fnv1a32(key) % 6`). 같은 숙소는 어느 화면에서나 같은 그림이고(목록→상세 일관), 재렌더에도 안 바뀌며, 테스트가 결정적이다.
- **위치·방식**: `shared/lib/placeCover.ts` 의 맵에 '숙소' 키를 더하고 `PlacePhoto` 를 그대로 쓴다(자세한 안은 handoff 문서).

## 다시 만들 때 (`_tools/gen_stays.py`)

```bash
python3 -I frontend/assets/stay-covers/_tools/gen_stays.py gen      # 없는 PNG 만 생성
python3 -I frontend/assets/stay-covers/_tools/gen_stays.py export   # PNG → 738px WebP q75
```

스타일 문구·API 사정은 `../region-covers/README.md` 와 같다(레포 루트 `.env` Azure 키, 한 장 ~45초, 동시 3개). 원본 PNG(1536×1024)는 `../region-covers/_tools/out/`(커밋 안 함)에 쌓인다.

⚠️ 지금 6장의 **원본 PNG 는 만든 머신의 `out/` 에만 있다.** 다시 뽑으면 같은 프롬프트로 새 그림이 나온다(프롬프트는 `gen_stays.py` 의 `SUBJECTS`).
