# 여행 스타일 분석 (j05)

계정 단위(여행 id 없음)로 사용자의 여행 스타일을 보여 주는 화면이다. 기록이 충분해 서버가 정식 분석을 내면 카테고리 비중 막대(상위 3 + 기타)와 하루 평균 방문·평균 체류 시간을 보여 주고, 부족하면 "현재 N곳 / 필요 M곳" 진행 게이지와 온보딩 취향 기반 임시 미리보기 칩을 보여 준다. 화면 아래엔 마이 탭이 활성인 하단 탭 바가 있다.

## Sub-features

- `st-official` 서버 `official:true` + 본문 있음: `분석에 사용된 여행 N회 · 마지막 갱신 M.D`, 카테고리 막대(라벨 + `N%`, 1위 막대만 코랄), `하루 평균 방문`(N.N`곳`), `평균 체류 시간`(N`분`, 0·미측정이면 칸을 비운다).
- `st-label` 카테고리 라벨은 서버 코드 그대로이되 `맛집` 은 `미식`, 기타 묶음은 `기타`.
- `st-insufficient` 그 외: `분석에 필요한 기록이 부족해요 (현재 N곳 / 필요 M곳)`, 게이지, `N / M`·`K곳 더 필요`, `아직 정식 분석이 아니에요`, 미리보기 칩(`#` 이 없으면 붙인다). 진행값 결측이면 0 / 10.
- `st-loading` 조회 중 `불러오는 중…`.
- `st-error` 조회 실패 `불러오지 못했어요`(다시 시도·뒤로 버튼 없음).
- `st-back` 앱바 뒤로 — 이전 화면이 있으면 뒤로, 없으면(딥링크) 마이 탭으로 교체.
- `st-tabbar` 하단 탭 바(마이 활성) — 누른 탭으로 `dismissTo`.

## How to get to it (user POV)

- 마이 탭 `내 여행 스타일` 카드의 `상세 분석 ›` 를 누른다.
- 마이 탭 메뉴의 `여행 스타일 분석` 행을 누른다.
- 도우미 다음 행동 `OPEN_STYLE`.
- 딥링크 `trippilot://records/style`. 시뮬레이터에선 `com.trippilot.travel://records/style` 로 연다.

## Driving it with agent-device

Preconditions:

- 로그인된 계정.
  - `st-insufficient`: 방문 기록이 적은 계정(새 계정이면 거의 늘 이 얼굴). 미리보기 칩은 온보딩 취향을 고른 계정이어야 생긴다(취향 없으면 칩 0개).
  - `st-official`: 서버가 정식 분석을 낼 만큼 기록이 쌓인 계정(필요 수는 서버 `progress.required`, 클라 기본 10곳). 확인 필요 — 개발 서버에서 이 상태의 계정을 만드는 방법(방문 완료 누적 외 시드 여부).
- 조작 절차·셀렉터 함정은 `trippilot-sim-qa` 스킬 §2·§4.

- **카드 진입.** 하단 탭 testID: `shell-tabbar-tab-{my}` → 카드 testID: `my-style-card` 의 testID: `my-style-detail`(`상세 분석 ›`)를 누른다. 앱바 `여행 스타일 분석` 이 보인다.
- **메뉴 진입.** 마이 탭으로 돌아와 testID: `my-style-analysis-row`(`여행 스타일 분석`)를 누른다. 같은 화면이 열린다.
- **부족 얼굴.** testID: `reflection-style-progress` 문장이 `분석에 필요한 기록이 부족해요 (현재 N곳 / 필요 M곳)`, 게이지 testID: `reflection-style-progress-gauge`, `K곳 더 필요`, `아직 정식 분석이 아니에요` 가 보인다. 취향이 있는 계정이면 칩 testID: `reflection-style-preview-chip` 이 `#…` 로 1개 이상.
- **정식 얼굴.** `분석에 사용된 여행 N회 · 마지막 갱신 M.D`, 막대 testID: `reflection-style-bar` 가 카테고리 수만큼(라벨·`N%`), 타일 testID: `reflection-style-stat-places`(`하루 평균 방문`), 평균 체류가 있으면 testID: `reflection-style-stat-dwell`(`평균 체류 시간`).
- **마이 카드와 대조.** 마이 카드(`my-style-card`)의 요약과 j05 의 얼굴(정식/부족)이 같은 서버 봉투에서 왔는지 한 번 더 읽어 맞춰 본다.
- **뒤로.** testID: `reflection-style-back` 을 누르면 마이 탭으로 돌아간다. 딥링크로 바로 연 경우에도 마이 탭으로 교체된다.
- **하단 탭.** 화면 안 탭 바 testID: `shell-tabbar-tab-{home}` 을 누르면 홈 탭으로 간다(마이 칸이 활성 표시).
- **오류.** 네트워크를 끊고 연다. 화면 가운데 `불러오지 못했어요` 만 보인다. 앱바·탭 바가 없으니 복구는 가장자리 스와이프 뒤로뿐이다.

## Gotchas

- 오류·조회 중 얼굴엔 앱바·탭 바·다시 시도가 없다 — 딥링크로 열면 스와이프 외에 나갈 길이 없다(아래 결함 의심). 이 얼굴에서 `reflection-style-back` 을 찾지 않는다.
- 이 화면의 탭 바는 셸 탭 바의 사본이다(같은 testID `shell-tabbar-tab-*`). 셸 탭 바와 구분하려면 앱바 `여행 스타일 분석` 이 같이 보이는지 확인한다.
- 과거 QA 에서 이 화면의 홈 탭 무반응(059)·평균 체류 0분(Q-21)이 있었다. 지금은 홈 탭이 동작하고 체류 0·미측정은 칸을 비운다 — 재현되면 회귀로 적는다.
- 뒤로는 기록 탭이 아니라 마이 탭으로 간다. 이것이 기대 동작이다.
- 서버가 `official:false` 인데 `current ≥ required` 를 주면 `K곳 더 필요` 가 0 이하로 보인다(확인 필요 — 서버가 그런 봉투를 주는지).
- 막대 색(1위만 코랄)은 실화면으로만 확인된다. **[실화면 전용]**
- testID 표기: `a-{x}` 는 `a-` 뒤에 실행 값 x 가 붙은 것이고, `a{-b}` 는 실제 testID `a-b` 다(하단 바·헤더·행 카드). 접근성 트리에서는 합친 값으로 찾는다.
- [실화면] 2026-10-31 이 계정은 정식 얼굴이다 — `분석에 사용된 여행 5회 · 마지막 갱신 10.30`, 막대 `미식 38%`·`명소 27%`·`자연 19%`·`기타 15%`, `하루 평균 방문 3.3곳`, `평균 체류 시간 441분`(7시간 넘는 값이 그대로 보인다 — 서버 값 문제인지 확인 필요).
- [실화면] 2026-10-31 코드 대조 의심 확인 — 앱 종료 후 딥링크 콜드 진입에서도 `reflection-style-back` 은 마이 탭으로 교체돼 정상으로 나간다(무반응 아님). 무반응 우려는 오류·조회 중 얼굴(앱바 없음)에만 해당한다.
- [실화면] 2026-10-31 마이 카드(`my-style-card`)는 정식 분석의 카테고리 비중이 아니라 취향 칩(`#맛집`·`#명소`·`#느긋`)과 게이지 3줄(`여유로움`·`미식 취향`·`활동성`)을 보인다 — 카드와 j05 를 숫자로 대조할 수 있는 항목은 없다.
- [실화면] 2026-10-31 도달 불가 — `st-insufficient`(정식 분석 계정), `st-loading`(순간이라 못 잡음), `st-error`(네트워크 차단 수단 없음), 도우미 `OPEN_STYLE`(재현 수단 없음).
