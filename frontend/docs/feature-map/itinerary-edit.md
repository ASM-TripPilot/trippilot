# 일정 편집

사용자는 이미 있는 일정을 하루 단위로 고친다(Figma h12 일정 편집, 여행 중이면 i07 같은 화면). 전면 지도 위 시트에 그 날 장소 카드가 순서대로 있고, 카드를 길게 눌러 끌어 순서를 바꾸거나 시트 아래 삭제 영역으로 끌어 빼고, 카드 시각 칩을 눌러 시작·종료 시각을 고치고, 카드 사이 [+]·점선 [장소 추가]로 장소를 더한다. 순서·삭제·시각은 화면 안에서만 바뀌다가 [일정 저장하기]를 눌러야 서버에 전체 교체로 저장되고, 장소 추가는 추가 화면에서 곧장 저장된다. 저장 응답에 시간 위반이 있으면 요약 확인창이 먼저 뜬다. 이 화면에는 거리 커넥터도 소요시간도 없다(INV-3).

## Sub-features

- `edit-open` 진입 일자(`date`)의 칸으로 열린다 — 일정에 없는 날짜·미지정이면 1일차.
- `edit-day-switch` 일차 칩(2일 이상일 때만)으로 날 바꾸기 — 편집 중 초안은 날을 바꿔도 유지된다.
- `edit-reorder` 카드 길게 눌러 끌어 순서 바꾸기(로컬, 저장 전).
- `edit-delete-drag` 카드를 끌면 하단에 `여기에 놓으면 삭제돼요` 영역이 뜨고, 그 위에 놓으면 빠진다(로컬, 저장 전). 삭제 버튼은 따로 없다.
- `edit-time` 카드 시각 칩(⌄) → `시간대 조정` 시트(시작·종료 휠) → [적용](로컬, 저장 전). 종료가 시작보다 이르면 `종료 시각은 시작보다 늦어야 해요` + [적용] 비활성.
- `edit-add-end` 점선 [장소 추가] → 장소 추가 화면(그 날에 말미 추가, 추가 즉시 서버 저장).
- `edit-add-between` 카드 사이 [+] → 장소 추가 화면(그 자리에 삽입, 즉시 저장).
- `edit-fixed-lock` 고정(숙소 등 `isFixed`) 카드 — 끌기·시각 편집 불가, `고정` 알약. 다른 카드를 그 위로 끄는 것은 된다(고정은 시각만 지킨다).
- `edit-visited-lock` 방문 완료 카드 — 회색 시각 알약, 끌기·삭제·시각 편집 불가, 다른 카드를 끌어도 제자리. 여행 중(i07)이면 완료 카드 바로 앞의 [+]가 빈 줄로 바뀐다.
- `edit-overlap` 앞 카드와 시각이 겹치면 `‘앞 장소 이름’ 시각과 겹쳐요` 배지(로컬 판정), 서버 위반은 위반 문구 배지.
- `edit-save` [일정 저장하기] → 토스트 `일정을 저장했어요` 후 이전 화면으로.
- `edit-save-conflict` 저장 응답에 위반이 있으면 토스트 없이 `N곳에서 시간이 안 맞아요` 확인창 — [고치기](토스트 + 머묾) / [그대로 저장](토스트 + 떠남). 이미 저장된 뒤다.
- `edit-save-error` 저장 실패 인라인 안내 3종 — `확정된 일정은 수정할 수 없어요` / `일정을 만드는 중이에요. 잠시 후 다시 시도해 주세요` / `일정을 저장하지 못했어요. 잠시 후 다시 시도해 주세요`.
- `edit-save-guard` 저장 연타·장소 추가 저장이 도는 동안의 저장 누름은 무반응. 0곳인 날은 [일정 저장하기] 비활성.
- `edit-unspecified` 시각 미지정 카드(`시간대 설정` 칩)는 저장에서 빠지고, 빠진 수를 성공 토스트(`… · 시간 미정 N곳은 빠졌어요`) 또는 실패 배너로 알린다.
- `edit-guide` 안내줄 — h12 `길게 눌러 순서를 바꾸거나, 아래로 끌어 삭제해요`, 여행 중 `방문한 곳은 그대로 두고, 길게 눌러 순서를 바꾸거나 아래로 끌어 삭제해요`, 그리고 `장소를 추가하면 바로 저장돼요`.
- `edit-loading` 로딩 — 빈 화면(뒤로 버튼 없음).
- `edit-notfound` 일정 없음 — `아직 편집할 일정이 없어요`.
- `edit-failed` 조회 실패 — `일정을 불러오지 못했어요`.
- `edit-in-trip` 여행 중 진입(i07, 라우트 `planb/manual`) — 같은 화면, 안내 문구·완료 카드 앞 [+]만 다르고, 히스토리 없을 때 저장 뒤 목적지가 허브.

## How to get to it (user POV)

- **확정 일정 보기(h16)**: 확정 얼굴 CTA [일정 수정] → `/trips/<id>/itinerary/edit?date=<보던 날>`(push). `itinerary-view.md` 참고. 미확정(h14) 얼굴에는 편집 진입이 없다.
- **여행 중 허브 편집**: 허브 하단 바 [수정](`execution-live-bar-edit`) → 팝업 [직접 수정](`execution-live-edit-popup-manual`) → `/trips/<id>/planb/manual?date=<보던 날>`. 이 라우트는 Plan-B 묶음 소속이지만 같은 편집 페이지를 여행 중 모드로 연다 — 허브 쪽은 `live-hub.md`, 라우트 소속은 `planb.md`. Plan-B 초안 화면에서도 이 라우트로 온다(`planb.md`).
- **도우미(AI 시트)**: 서버 다음 행동 `OPEN_ITINERARY_EDIT` → `/trips/<id>/itinerary/edit`(시트 자리를 replace, `date` 없음 → 1일차).
- **딥링크**: `trippilot:///trips/<tripId>/itinerary/edit?date=YYYY-MM-DD`.
- **일정 생성 완료 뒤·일정 탭·홈에서는 직접 오지 않는다** — 생성 흐름은 초안 → 완성 일정 보기 → (확정 후) [일정 수정] 순이고, 직접 짜기의 편집기(`itinerary/manual`)는 같은 편집 뷰를 쓰지만 다른 화면(다른 레인)이다.

## Driving it with agent-device

Preconditions:

- 로그인 + 일정이 있는 여행. h16 에서 들어오려면 확정된 일정이 필요하다. 일차 전환은 2일 이상 일정, 끌기·삭제는 그 날 카드 2곳 이상.
- **여행 상태가 저장 결과를 가른다**: PUT 계약 요약은 `여행 시작 전 확정·생성 중 일정은 409` 다 — 확정 + 시작 전이면 저장이 `확정된 일정은 수정할 수 없어요` 로 막힌다(2026-10-31 실화면 확인, 장소 추가도 실패). 여행 중 확정 일정은 허브 → 직접 수정 경로로 저장을 검증한다. 생성 중(PARTIAL)이면 `일정을 만드는 중이에요…`.
- 방문 완료 잠금은 그 날 방문 기록이 있어야 보인다 — 여행 중 허브에서 도착·완료를 한 카드가 필요하다.
- 시간 위반 확인창은 저장 응답에 `hasViolation` 슬롯이 있어야 뜬다 — 시각을 앞 카드와 겹치게 고치거나 촘촘히 붙여 저장해 만든다.

- **진입.** h16 에서 `2일차` 칩을 고르고 [일정 수정] 탭. 좌상단 testID: `itinerary-edit-back`, 칩 testID: `itinerary-edit-day-${dayIndex}`(1부터, 2일 이상일 때만 — 접근성 트리에는 testID 대신 라벨 `1일차`·`2일차` 로 잡힌다) 중 2일차가 선택 상태, 시트 머리 testID: `sheet-header-title` = `일정 편집`, testID: `sheet-header-day` = `2일차`, testID: `sheet-header-meta` = `N곳`, 하단 testID: `sheet-cta-button-${index}`(index 0) = `일정 저장하기`.
- **INV-3.** 편집기 카드에는 시각 칩 `HH:mm–HH:mm` 만 있고 카드 사이 거리 커넥터·소요시간이 없다. 위반·겹침 배지 문구에도 숫자(분)가 없어야 한다.
- **일차 전환.** testID: `itinerary-edit-day-${dayIndex}` 의 `1일차` 탭. 카드·핀·머리 `1일차` 로 바뀐다. 2일차에서 바꾼 순서는 2일차로 돌아오면 그대로 남아 있다.
- **순서 바꾸기.** 목록 testID: `itinerary-edit-list` 안의 카드 testID: `slot-stopcard-${slotKey}` 하나를 길게 눌러 다른 카드 아래로 끌어 놓는다. 끄는 동안 하단 CTA 가 사라지고 testID: `itinerary-edit-dropzone-bar` 안에 testID: `itinerary-edit-dropzone`(`여기에 놓으면 삭제돼요`)가 뜬다. 놓으면 카드 번호 순서가 바뀌고 CTA 가 돌아온다. 아직 서버에는 안 갔다.
- **끌어 삭제.** 카드를 길게 눌러 하단 삭제 영역 위까지 끌어 놓는다. 그 카드가 목록에서 빠지고 `sheet-header-meta` 곳 수가 하나 준다.
- **고정 카드.** `고정` 알약(role `fixed`) 카드는 길게 눌러도 끌리지 않고 시각 칩에 ⌄ 가 없다(눌러도 시트가 안 열림).
- **방문 완료 카드.** 여행 중 방문 완료한 카드는 회색 시각 알약 testID: `slot-stopcard-${role}-${slotKey}`(role `locked`) — 끌리지 않고, 다른 카드를 끌어 놓아도 완료 카드는 원래 자리에 남는다. 여행 중 진입이면 완료 카드 바로 앞에 [+]가 없다.
- **시각 고치기.** 비고정 카드의 시각 칩(role `timechip`) 탭. testID: `itinerary-edit-time-${part}` 계열 시트(part = `sheet`·`close`·`seg-start`·`seg-end`·`wheel-h`·`wheel-m`·`readout`·`apply`·`error`)가 제목 `시간대 조정`·부제 `시작·종료를 돌려서 맞춰요` 로 열린다. `종료` 탭(`seg-end`)에서 휠을 시작보다 이른 시각으로 돌리면 part `error` = `종료 시각은 시작보다 늦어야 해요` 와 [적용] 비활성. 정상 값으로 [적용](part `apply`) → 시트가 닫히고 그 카드 시각 칩이 바뀐다(서버는 아직).
- **겹침 배지.** 시각을 앞 카드와 겹치게 적용하면 그 카드에 role `violation` = `‘<앞 장소 이름>’ 시각과 겹쳐요` 배지가 저장 전에 바로 뜬다.
- **장소 추가(말미).** testID: `itinerary-edit-add-place`(`장소 추가`) 탭 → 장소 추가 화면(`/trips/<id>/itinerary/manual/add?date=<그날>`, 다른 레인 소관). 장소를 담고 돌아오면 그 날 말미에 카드가 있다. 이 추가는 [일정 저장하기]와 별개로 이미 서버에 저장됐다(testID: `itinerary-edit-add-saved-hint` = `장소를 추가하면 바로 저장돼요`).
- **장소 추가(사이).** 카드 사이 testID: `itinerary-edit-insert-${index}`(앞 카드 0부터 index) 탭 → 같은 추가 화면이 `insertAfter=<index>` 로 열리고, 담으면 그 두 카드 사이에 들어간다.
- **안내줄.** 카드가 1곳 이상이면 testID: `itinerary-edit-guide` = `길게 눌러 순서를 바꾸거나, 아래로 끌어 삭제해요`(여행 중이면 `방문한 곳은 그대로 두고, …`). 0곳이면 안내줄이 없고 [일정 저장하기]가 회색이다.
- **저장 성공.** 순서·시각을 바꾼 뒤 [일정 저장하기]. 토스트 testID: `itinerary-edit-saved` = `일정을 저장했어요` 후 이전 화면(h16 또는 허브)으로 돌아간다. 다른 화면에서 한 번 더 읽기: h16(또는 허브)의 같은 일차 카드 순서·시각이 저장한 대로 바뀌어 있어야 한다. 히스토리가 없으면(딥링크) h12 는 `/trips/<id>/itinerary`, 여행 중은 `/trips/<id>/live` 로 replace.
- **저장 후 위반 확인창.** 위반이 남는 편집으로 저장. 토스트 없이 testID: `itinerary-edit-save-conflict`(카드 testID: `itinerary-edit-save-conflict-card`) = `N곳에서 시간이 안 맞아요` + testID: `itinerary-edit-save-back`(`고치기`)·testID: `itinerary-edit-save-asis`(`그대로 저장`). [고치기] → `일정을 저장했어요` 토스트 + 편집기에 머묾(위반 배지가 보이고 다시 저장할 수 있다). [그대로 저장] → 토스트 + 이전 화면으로.
- **저장 실패.** 저장이 실패하면 지도 위(상단 96px 아래) testID: `itinerary-edit-save-error` 에 사유별 문구 — 409 이고 재조회한 일정이 확정이면 `확정된 일정은 수정할 수 없어요`, 생성 중이면 `일정을 만드는 중이에요. 잠시 후 다시 시도해 주세요`, 그 밖(5xx·오프라인·재조회 실패)은 `일정을 저장하지 못했어요. 잠시 후 다시 시도해 주세요`. 편집 내용은 화면에 남고 다시 누를 수 있다.
- **저장 연타.** [일정 저장하기]를 빠르게 두 번 탭. 요청·토스트·뒤로 이동이 한 번만 일어난다. 장소 추가 직후 그 저장 응답이 오기 전 누른 저장도 무반응이다.
- **미지정 시각 제외.** `시간대 설정` 칩(role `unspecified`) 카드가 있는 채로 저장하면 성공 토스트가 `일정을 저장했어요 · 시간 미정 N곳은 빠졌어요`, 실패면 testID: `itinerary-edit-unspecified-notice` = `시간대를 정하지 않은 N곳은 저장에서 빠졌어요`.
- **일정 없음·조회 실패.** 일정이 없는 여행 id 로 딥링크 → testID: `itinerary-edit-notfound` = `아직 편집할 일정이 없어요` / `일정을 만들면 여기에서 수정할 수 있어요`. 오프라인 진입 → 자동 재시도 뒤 testID: `itinerary-edit-failed` = `일정을 불러오지 못했어요` / `네트워크를 확인하고 다시 시도해주세요`. 두 얼굴 모두 화면 안 버튼이 없다.
- **뒤로(저장 안 함).** testID: `itinerary-edit-back` 탭 → 이전 화면. 저장 안 한 순서·시각 변경은 확인창 없이 버려진다 — 이전 화면 카드가 원래대로인지 확인한다.
- **증거.** 끌기 전·후 접근성 트리(카드 번호·이름 순서), 저장 토스트, 복귀 화면 카드 순서 스크린샷을 남긴다.

## Gotchas

- **[실화면 전용]** 길게 누르기 → 끌기 → 놓을 자리 계산, 끄는 카드가 떠 있는 얼굴, 삭제 영역 활성(`itinerary-edit-dropzone-active`)·놓을 때 영역 위 판정, 카드가 화면보다 많을 때 끝 끌기 자동 스크롤 — jest 목은 손가락 이동이 없다(`traps-draglist.md`). 개발 콘솔의 `measureLayout` 오류는 알려진 라이브러리 경고다(2026-10-21 N-108).
- **[실화면 전용]** 시각 조정 시트의 실제 열림·휠 드래그가 시트를 끌지 않는지·딤 탭/스와이프 닫힘(`repo-traps.md` 바텀시트 절), 저장 위반 확인창의 딤 덮임·터치 차단(조건부 오버레이 계열).

- **삭제 버튼이 없다** — 빼기는 끌어 삭제뿐이다. agent-device 로 끌기 제스처가 안 되면 삭제·순서 바꾸기는 `live-unreachable` 로 남기고, 다른 조작(시각 시트 [적용])으로 대신 통과시키지 마라.

- **칩 testID 번호가 다르다** — 편집기 `itinerary-edit-day-${dayIndex}` 는 1부터(일정 days 기준), 보기 화면 `sheet-daychip-${index}` 는 0부터(여행 기간 기준). 1일 일정이면 편집기 칩이 아예 없다.
