## 기술 발견 2건

### 1. RN `ScrollView`는 자기 자신에게 `flexGrow: 1`을 기본 부여한다

토글 줄이 화면 높이의 40%를 차지했다(D-2). 높이를 키우라고 시킨 코드는 없었다.

```
react-native/Libraries/Components/ScrollView/ScrollView.js
  :1861 baseVertical   { flexGrow: 1, flexShrink: 1, ... }
  :1867 baseHorizontal { flexGrow: 1, flexShrink: 1, ... }
  :1752 const baseStyle = horizontal ? styles.baseHorizontal : styles.baseVertical;
```

세로 부모 안의 자식 둘(토글 `ScrollView` 기본값 1, 화면 영역 `flex-1`)이 남은 높이를 **반씩 나눠 가졌다.**
해법: `style={{ flexGrow: 0 }}`(원인 제거) + `contentContainerStyle`에 `alignItems: 'center'`(재발 방지).
**교훈**: 레이아웃이 이상하면 내 코드가 아니라 **그 컴포넌트의 기본 스타일**을 의심하고, 추측 대신 `node_modules` 소스를 열어라.

### 2. 이 앱에는 `SafeAreaProvider`가 아예 없다 (앱 전역의 구조적 공백)

토글 줄이 상태바·다이나믹 아일랜드에 가려졌다(D-1). `grep` 결과 **패키지는 설치돼 있는데 앱 어디에서도 쓰이지 않았다.**

| 방법 | 인셋을 어디서 얻나 | `SafeAreaProvider` 필요 |
|---|---|---|
| `useSafeAreaInsets()` 훅 | React 컨텍스트에서 읽는다 | **필요** — 없으면 조용히 **0** |
| `<SafeAreaView>` 컴포넌트 | **네이티브가 스스로 측정** | **불필요** |

`_layout.tsx`가 해시 동결이라 프로바이더를 심을 수 없었고, 훅은 0을 돌려줄 것이 확실했다 → **`SafeAreaView edges={['top']}`**로 프리뷰 안에서만 국소 해결.

⚠️ **앱 전역 공백은 그대로다.** 지금 어느 화면도 기기별 노치 인셋을 자동으로 못 받는다(`SplashScreen`이 `pt-[64px]` 같은 고정 픽셀을 쓰는 이유). **후속 티켓 후보** — `20260719-trip161-screens`의 "SafeArea 인셋배선" 후속과 **동일 건**.

## 설계 판단으로 남길 것

1. **테스트 단언을 뒤집었다.** "목 파일이 삭제됐다"가 아니라 **"목 토글을 켠 채로도 앱이 첫 렌더에 `SplashGate`를 그린다"**를 단언했다. 부재를 단언하면 **앱 전체가 부서져도 통과**한다 — 스위트 전멸과 제거 성공을 구분하지 못한다. → *제거를 검증할 때는 "사라진 것"이 아니라 **"사라지고도 여전히 작동하는 것"**을 단언하라.*
2. **프리뷰의 네트워크 격리를 런타임 지뢰 목으로 잡았다.** 부르면 폭발하는 `@/shared/api` 목. 소스 grep과 달리 **전이 의존까지** 잡힌다(직전 사이클이 배럴 grep 미추적으로 데인 것에 대한 직접 대응). 판별력 실측: 올바른 스텁 11/11 green, 각 오매핑마다 정확히 1건씩만 실패, 금지 모듈 로드 시 스위트 즉시 폭발 — 부수 피해 0.
3. **시나리오 스위처는 애초에 도달 불가능했다.** 삭제한 `_dev/scenarios.tsx`는 라우트 등록은 됐으나 앱 어디에도 링크가 **0건**이었다 — 아무도 열어 본 적 없는 화면이고, 목이 안 먹는 걸 오래 못 알아챈 구조적 이유이기도 하다. 그래서 이번 최대 위험은 "프리뷰도 같은 함정"이었고, **딥링크 도달을 실기로 확인**한 것이 최대의 위험 해소다.
