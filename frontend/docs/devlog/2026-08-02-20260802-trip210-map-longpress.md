# 2026-08-02 20260802-trip210-map-longpress (경량 사이클)

## 왜 여기서 하나

TRIP-199가 머지된 뒤 실기에서 "지도를 길게 눌러도 핀이 안 찍힌다"가 드러났다. TRIP-210 칸이 dev build 재빌드와 실기 확인을 공유하므로 같은 브랜치에서 처리했다(사용자 지시).

## 원인이 세 겹이었다

증상은 하나였는데 원인이 셋이고, **하나씩 벗겨야 다음 겹이 보였다.**

| # | 층 | 수정 |
|---|---|---|
| 1 | iOS 텍스트 선택이 롱프레스를 가로챈다(선택 핸들 + Copy·Translate 메뉴) | `<style>`에 `-webkit-user-select`·`user-select`·`-webkit-touch-callout: none` |
| 2 | `kakao.maps.load` **콜백 안** 예외를 통째로 삼킨다 | 콜백 안에도 try/catch → 실패를 `MAP_LOAD_FAILED_MESSAGE`로 밖에 알린다 |
| 3 | 카카오 합성 마우스 이벤트가 우리 리스너까지 안 온다 | `kakao.maps.event.addListener(map,'mousedown')` 폐기 → 지도 컨테이너에 **DOM 터치/마우스 이벤트를 capture 단계로** 직접 등록 + `getProjection().coordsFromContainerPoint()` 좌표 변환 |

**2번이 없었으면 3번을 못 좁혔다.** 바깥 `try`는 `load()` 호출만 감싸고 콜백은 비동기라, 콜백 안 예외가 바깥 catch에 절대 안 온다 — 실패 사실이 밖으로 나올 통로 자체가 없었다. 진단 도구가 아니라 INV-4(침묵 실패 금지) 구멍이었고, 그걸 메우자 "예외가 아니라 이벤트가 안 온다"가 확정됐다.

## 배운 것

- **문자열로 만드는 코드는 tsc도 eslint도 안 본다.** 대본이 8줄에서 50줄 넘게 커지면서 파싱 실패 위험이 실질을 가졌고, 파싱 실패는 **안쪽 try/catch도 못 잡는다**(스크립트가 아예 실행되지 않으므로). → M-8이 `new Function(src)`로 파싱만 해 그 층을 잠근다.
- **등록 API 이름을 문자열로 못박으면 구현 전환이 막힌다.** M-2가 `kakao.maps.event.addListener`를 못박고 있어 층 3 전환이 "어떤 구현으로도 통과 불가"가 될 뻔했다 — TRIP-199 02a ★13-a가 이벤트 *이름*에 대해 경계했던 것과 같은 함정이 **API 이름**에서 재발했다. `/addListener|addEventListener/`로 완화.
- **세 층 전부 jest가 볼 수 있는 층이었다.** TRIP-199의 N-9("심판이 못 보는 층")가 아니라 **심판을 안 세운 층**이다.

## 실기 결과 — ⭐ TRIP-199 최대 미검증 전제 해소
