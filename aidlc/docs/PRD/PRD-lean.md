## Problem Statement

자유여행객은 숙소를 정한 뒤에도 여행의 나머지 전 과정을 직접 떠안는다. 기존 OTA는 숙소·항공·액티비티를 '예약'하는 데서 멈추고, 일정 앱은 '계획을 한 번 만드는' 데서 멈춘다. 그 사이의 연결과 여행 중·후의 운영은 모두 사용자 몫이다.

- **탐색과 일정이 단절된다.** 어느 숙소를 고르느냐가 매일의 동선·이동시간·방문 가능한 장소를 어떻게 바꾸는지 보여주지 않아, 사용자는 숙소 위치와 날짜를 머릿속에 넣고 일정을 수작업으로 짠다.
- **계획 생성에서 멈춘다.** 일정 앱은 장소를 나열할 뿐, 영업시간·이동시간·하루 시간 예산을 함께 풀어 '실행 가능한 순서'로 정렬해 주지 않는다.
- **여행 중 변수에 무방비다.** 비·휴무·지연·취소가 생기면 사용자가 직접 대안을 찾아 남은 일정을 다시 짜야 한다.
- **여행 후 기록이 흩어진다.** 사진은 갤러리에, 메모는 메모앱에, 방문·경로는 어디에도 남지 않는다.

핵심은 '예약 다음'이 비어 있다는 것이다.

## Solution

TripPilot은 여행자가 직접 쓰는 앱이다. 여행지·날짜로 숙소를 **탐색·저장**하되 실제 예약·결제는 외부 OTA 제휴 링크로 위임하고, 앱은 '예약 다음' — AI 일정 생성, 여행 중 Plan-B 재계획, 여행 기록/회고 — 을 잇는다.

- **두 진입을 모두 1급 지원.** 숙소 우선(Case B — 등록 숙소=출발점)과 장소 우선(Case A — 저장 POI=필수 방문지 시드)이 "등록된 숙소 = 출발점" 상태로 수렴한다. (ADR-0002·0004)
- **AI가 실행 가능한 일정을 짠다.** 등록 숙소 위치·체류 기간을 기준으로 취향을 반영해 방문지를 고르고 영업시간·이동시간·시간 예산 제약을 풀어 날짜별 동선으로 정렬한다. (LLM=취향 해석·설명 / 결정론적 솔버=순서·시간·실현가능성 — ADR-0008)
- **여행 중 Plan-B.** 날씨·휴무·지연·취소를 감지해 대안을 제시하고 남은 동선을 재정렬한다.
- **여행 중 기록·여행 후 회고를 자동으로.** 방문 체크·사진·메모를 일정 위에 남기고, 종료 후 기록·경로·회고를 자동 정리한다.
- **막히면 AI 어시스턴트가 돕는다.** 대화로 기존 모듈을 호출·설명·재질의하되 실현가능성은 솔버가 소유한다. (ADR-0015)
- **검증된 동선을 발견·공유(커뮤니티).** 공개 일정을 둘러보고 '내 여행으로 가져오기'로 복제·편집한다(기본 비공개·옵트인, 좋아요·댓글 포함, 소셜 그래프 없음). (ADR-0014)
- **동행자와 함께 짠다(공동 편집).** 한 여행을 동행자와 실시간 공동 편집하며 모든 편집은 솔버 재검증·변경 이력을 거친다. (ADR-0016)

앱은 자체 예약·인앱 결제·내부 객실 재고를 두지 않는다. 초기 출시는 **국내(대한민국)·한국어** 한정.

## User Stories

> 한 줄 스토리(형식 정본). 상세 수용기준·예외는 `stories.md`. 페르소나는 `personas.md`.

### A. 앱 셸 (01)
1. 여행자로서, 앱 시작 시 세션·약관 상태에 따라 스플래시에서 적절한 진입점(로그인/온보딩/홈)으로 분기되고 싶다 — 내 상태에 맞는 화면으로 바로 들어가기 위해.
2. 여행자로서, 홈 대시보드에서 내 여행 상태·다음 행동·인기 장소·취향 맞춤 공개 기록을 한눈에 보고 싶다 — 다음에 뭘 할지 바로 알기 위해.
3. 여행자로서, 하단 5탭(홈·탐색·일정·기록·마이)으로 주요 기능에 바로 도달하고 싶다 — 헤매지 않기 위해.
4. 여행자로서, 몰입이 필요한 화면에서는 탭바가 숨겨져 '단 하나의 다음 행동'에 집중하고 싶다 — 산만함을 줄이기 위해.
5. 여행자로서, 가고 싶은 장소(POI)를 먼저 저장해 두고 여행 만들 때 '꼭 갈 곳'으로 가져오고 싶다 — 장소 우선으로 시작하기 위해(Case A).

### B. 계정 및 온보딩 (03)
1. 여행자로서, 소셜(카카오·네이버·Google·Apple)이나 이메일로 가입·로그인하고 싶다 — 익숙한 방법으로 빠르게 진입하기 위해.
2. 여행자로서, 최초 1회 약관에 동의하고 싶다 — 필수 절차를 한 번에 끝내기 위해.
3. 여행자로서, 자동 생성된 닉네임을 쓰거나 수정하고 싶다 — 가입 직후 막히지 않기 위해.
4. 여행자로서, 위치 권한의 목적을 이해하고 거부도 할 수 있고 싶다 — 이유를 알고 결정하기 위해.
5. 여행자로서, 여행 스타일을 설정하고 싶다 — 맞춤 추천을 받기 위해.
6. 여행자로서, 예산 수준(전체 여행 예산)을 설정하고 싶다 — 가격대·비용 가중치에 반영하기 위해.
7. 여행자로서, 동행 유형을 설정하고 싶다 — 동행에 맞는 추천을 받기 위해.
8. 여행자로서, 선호 활동을 설정하고 싶다 — 장소 추천 우선순위에 반영하기 위해.
9. 여행자로서, 이동 방식을 설정하고 싶다 — 동선·이동시간 계산 기본값에 반영하기 위해.
10. 여행자로서, 음식 취향을 설정하고 싶다 — 맛집 추천에 반영하기 위해.
11. 여행자로서, 온보딩 각 단계를 건너뛰거나 이전으로 돌아가고 싶다 — 첫 가치를 늦추지 않기 위해.
12. 여행자로서, 설정에서 닉네임·모든 취향을 언제든 수정하고 싶다 — 취향이 바뀌어도 반영하기 위해.
13. 여행자로서, 수집된 취향이 탐색·일정·추천·스타일 분석에 활용되길 원한다 — 개인화된 결과를 받기 위해.
14. 여행자로서, 미설정 취향은 중립 기본값으로 동작하길 원한다 — 미설정만으로 실패하지 않기 위해.
15. 여행자로서, 여행 페이스(일정 밀도)를 설정하고 싶다 — 하루 방문 수·체류 시간 기본값에 반영하기 위해.

### C. 숙소 탐색 / 저장 / 외부 예약 연동 (04)
1. 여행자로서, 여행지만으로(날짜·인원 없이) 숙소를 탐색하고 싶다 — 부담 없이 둘러보기 위해.
2. 여행자로서, 결과를 가격대·숙소 유형·편의시설·거리로 필터·정렬하고 싶다 — 원하는 조건을 좁히기 위해.
3. 여행자로서, 숙소 상세(위치·사진·가격대·편의시설·체크인/아웃)를 보고 싶다 — 예약 전에 확인하기 위해.
4. 여행자로서, 마음에 드는 숙소를 위시리스트에 저장하고 다시 꺼내 쓰고 싶다 — 비교·등록으로 잇기 위해.
5. 여행자로서, [외부 OTA에서 예약하기]로 딥링크 이동해 실제 예약·결제를 하고 싶다 — 익숙한 OTA에서 끝내기 위해.
6. 여행자로서, 이미 예약한 숙소를 앱에 '등록'(위치+체크인/아웃)하고 싶다 — 일정의 출발점으로 삼기 위해.
7. 여행자로서, 일자별로 거점 숙소를 다르게 등록하고 싶다 — 다도시 이동 여행을 표현하기 위해.
8. 여행자로서, 지도 검색·링크 붙여넣기·핀 지정으로 숙소를 직접 등록하고 싶다 — OTA 결과에 없어도 빠르게 등록하기 위해.
9. 여행자로서, 등록·저장한 숙소 목록과 거점 사용 여부를 확인하고 싶다 — 내 숙소 상태를 파악하기 위해.
10. 여행자로서, 조건에 맞는 숙소가 없으면 다음 행동(완화·직접 등록)을 안내받고 싶다 — 빈 화면에 막히지 않기 위해.
11. 여행자로서, 숙소를 모으는 동안 로딩을 보고 일부 OTA 실패에도 나머지 결과를 받고 싶다 — 침묵 실패를 겪지 않기 위해.

### D. 여행 생성 (05)
1. 여행자로서, 여행지·날짜·인원·예산으로 새 여행을 생성하고 싶다 — 계획을 시작하기 위해.
2. 여행자로서, 숙소를 등록하지 않은 상태로도 여행지·날짜만으로 여행을 먼저 만들고 싶다 — 예약 없이 일정부터 받기 위해.
3. 여행자로서, 예약·저장한 숙소를 여행에 등록해 일정 기준점으로 지정하고 싶다 — 등록 숙소=출발점으로 삼기 위해.
4. 여행자로서, 저장한 숙소를 목록에서 골라 여행에 등록하고 싶다 — 빠르게 거점을 잡기 위해.
5. 여행자로서, 등록 숙소의 날짜·인원을 여행 입력값으로 자동 불러오고 싶다 — 재입력을 줄이기 위해.
6. 여행자로서, 한 여행에 여러 숙소를 등록해 구간별 거점을 표현하고 싶다 — 도시 이동을 나타내기 위해.
7. 여행자로서, 같은 숙소 다박을 하나의 등록으로 지정하고 싶다 — 반복 입력을 피하기 위해.
8. 여행자로서, AI 일정 생성 전에 '꼭 갈 곳(필수 방문지)'을 지정하고 싶다 — 일정의 기준에 포함시키기 위해.
9. 여행자로서, 등록 숙소·필수 방문지가 고정/필수 블록으로 유지되길 원한다 — 생성·재생성 후에도 누락되지 않기 위해.

### E. AI 일정 생성 (06)
1. 여행자로서, 등록 숙소 위치·체크인/아웃을 기준으로 날짜별 AI 일정을 생성하고 싶다 — 실행 가능한 동선을 받기 위해.
2. 여행자로서, 취향(스타일·예산·동행·활동·이동·음식)을 반영해 장소가 선별되길 원한다 — 내게 맞는 곳을 받기 위해.
3. 여행자로서, 영업시간·체류·이동시간이 하드 제약으로 지켜진 시간표를 원한다 — 현장에서 못 가는 일이 없도록.
4. 여행자로서, 등록 숙소·필수 방문지가 고정/우선 기준으로 반영되길 원한다 — 앵커 중심 동선을 받기 위해.
5. 여행자로서, 각 장소의 추천 이유·배치 이유를 함께 보고 싶다 — 일정을 납득하기 위해.
6. 여행자로서, 일정을 시간표·지도 2뷰로 전환하며 구간 이동 정보를 보고 싶다 — 동선을 이해하기 위해.
7. 여행자로서, 장소를 추가·삭제·재정렬·시간 조정하면 제약이 재검증되길 원한다 — 바뀐 일정의 현실성을 확인하기 위해.
8. 여행자로서, 수정한 일정을 저장해 여행 중 실행 화면에서 그대로 쓰고 싶다 — 계획을 이어가기 위해.
9. 여행자로서, 생성이 실패·지연돼도 관찰 가능한 폴백(결정론적 솔버·부분 결과)을 받고 싶다 — 빈손이 되지 않기 위해.
10. 여행자로서, 생성 방식을 완전 AI/같이 고르기/직접 만들기 중에 고르고 싶다 — 내 방식으로 만들기 위해.
11. 여행자로서, 숙소 없이 장소 기준 일정을 먼저 짠 뒤 동선 기준 숙소를 추천받고 싶다 — 숙소를 나중에 정하기 위해.
12. 여행자로서, 완성 일정을 '확정'해 최종본으로 잠그고 읽기전용으로 확인하고 싶다 — 여행 시작 전 신뢰성을 확보하기 위해.

### F. 여행 중 일정 재계획 · Plan-B (07)
1. 여행자로서, 재계획 사유(날씨·휴무·지연·취소·체력)를 골라 수동 재계획을 요청하고 싶다 — 상황에 맞게 바꾸기 위해.
2. 여행자로서, 영향 주는 변수는 자동 트리거로 선제 제안받고 싶다 — 무너지기 전에 대응하기 위해.
3. 여행자로서, 재계획이 현재 위치·시각·고정 제약을 입력으로 삼길 원한다 — 현실적인 대안을 받기 위해.
4. 여행자로서, 고정 제약과 충돌하지 않는 대안 후보 2~3개를 받고 싶다 — 골라서 복구하기 위해.
5. 여행자로서, 각 대안의 이유·이동 거리·체류·여유 시간을 함께 보고 싶다 — 근거로 고르기 위해.
6. 여행자로서, 대안 선택/기존 유지/휴식 전환 중에 고르고 싶다 — 내 결정권을 지키기 위해.
7. 여행자로서, 대안을 고르면 남은 일정이 자동 재정렬되길 원한다 — 손쉽게 정리하기 위해.
8. 여행자로서, 확정 전 변경 전/후를 나란히 비교하고 싶다 — 무엇이 바뀌는지 알기 위해.
9. 여행자로서, 확정된 변경이 이력(사유·전후·시각)으로 남길 원한다 — 나중에 되짚기 위해.
10. 여행자로서, GPS를 못 쓸 때 현재 위치를 수동 입력해 재계획을 잇고 싶다 — 권한 없이도 대응하기 위해.
11. 여행자로서, 외부 API 오류 시 수동 일정 수정 화면으로 전환되길 원한다 — 침묵 실패를 겪지 않기 위해.
12. 여행자로서, 대안을 AI에 맡기기/직접 수정 중에 고르고 싶다 — 내 방식으로 바꾸기 위해.
13. 여행자로서, 계획 동선과 실제 이동 경로(GPS 발자취)를 지도에서 토글 비교하고 싶다 — 실제와 계획을 견주기 위해.

### G. 여행 중 현장 이용 (08)
1. 여행자로서, 장소 도착 시 방문 시작·완료를 체크하고 싶다 — 진행 상태·체류 시간을 남기기 위해.
2. 여행자로서, 현재 장소의 상세(영업시간·체류·혼잡도·주변)를 현장에서 보고 싶다 — 지금 판단에 쓰기 위해.
3. 여행자로서, 다음 예정지까지 거리를 보고 외부 지도앱으로 길찾기를 잇고 싶다 — 실제 길안내를 받기 위해.

### H. 여행 기록 / 회고 (09)
1. 여행자로서, 각 장소를 방문 완료/취소로 체크하고 실제 방문 시각을 남기고 싶다 — plan/actual을 구분하기 위해.
2. 여행자로서, 방문 장소에 사진·메모를 첨부하고 싶다 — 기억을 남기기 위해.
3. 여행자로서, 위치 동의 시 GPS 방문 기록이 자동 저장되게 하고 싶다 — 동선을 자동으로 남기기 위해.
4. 여행자로서, plan·actual·change-log 3종을 구분해 보고 싶다 — 계획과 실제를 비교하기 위해.
5. 여행자로서, 그날의 방문 기록이 등록 숙소·날짜에 귀속되길 원한다 — 날짜별로 정리하기 위해.
6. 여행자로서, 방문·사진·메모·변경 이력 기반 당일 회고 초안을 자동으로 받고 싶다 — 손쉽게 하루를 정리하기 위해.
7. 여행자로서, 당일 회고 초안을 직접 수정·삭제·추가하고 싶다 — 내 말로 다듬기 위해.
8. 여행자로서, 여행 종료 후 날짜별 기록·지도 경로·전체 요약을 받고 싶다 — 여행을 돌아보기 위해.
9. 여행자로서, 방문 패턴 기반 여행 스타일 분석을 받고 싶다 — 내 취향을 이해하기 위해.
10. 여행자로서, 누적 기록이 다음 여행 개인화 입력으로 쓰이길 원한다 — 갈수록 맞춤화되기 위해.
11. 여행자로서, 지난 여행별 기록·회고를 다시 확인하고 싶다 — 추억을 다시 보기 위해.
12. 여행자로서, 오프라인에서도 방문 체크·사진·메모를 로컬 저장하고 싶다 — 연결이 없어도 남기기 위해.
13. 여행자로서, 여행 요약·회고를 SNS 공유 카드로 만들고 싶다 — 외부에 자랑하기 위해.
14. 여행자로서, 지난 여행을 캘린더로 보고 특정 날짜 여행으로 진입하고 싶다 — 시간순으로 찾기 위해.

### I. 알림 / 마이페이지 / 설정 (12)
1. 여행자로서, 숙소 등록/저장 완료 알림을 받고 싶다 — 출발점 설정을 확인하기 위해.
2. 여행자로서, 여행 일정과 연동된 단계별 리마인드 알림을 받고 싶다 — 일정을 놓치지 않기 위해.
3. 여행자로서, 여행 중 Plan-B 알림을 받고 싶다 — 변수에 대응하기 위해.
4. 여행자로서, 여행 종료 후 회고 완료 알림을 받고 싶다 — 결과물을 바로 열기 위해.
5. 여행자로서, 알림을 채널(푸시/인앱)·종류별로 켜고 끄고 싶다 — 원하는 알림만 받기 위해.
6. 여행자로서, 마이페이지에서 등록 숙소·외부 예약 기록을 한곳에서 보고 싶다 — 내 숙소를 관리하기 위해.
7. 여행자로서, 예정/진행중/종료 여행을 구분해 보고 싶다 — 상태별로 파악하기 위해.
8. 여행자로서, 마이페이지에서 내 여행 스타일 분석을 보고 싶다 — 내 취향을 한눈에 보기 위해.
9. 여행자로서, 설정에서 개인정보·계정(내보내기·삭제)을 관리하고 싶다 — 내 데이터를 통제하기 위해.
10. 여행자로서, 설정에서 여행 취향을 직접 입력·수정하고 싶다 — 자동 분석보다 내 값을 우선하기 위해.
11. 여행자로서, 설정에서 위치정보 동의를 부여·철회하고 싶다 — 위치 사용을 통제하기 위해.
12. 여행자로서, 외부 OTA 링크 이동 전 제휴(수익) 링크 여부를 안내받고 싶다 — 투명하게 알고 이동하기 위해.

### J. 앱 전반 AI 어시스턴트 (02) · *후속 게이트*
1. 앱 전반에서 어시스턴트를 모달/바텀시트로 열어 자연어로 도움받기. 2. 대화로 조건을 바꿔 탐색·추천 재요청(티키타카). 3. "지금까지 한 거 검토해줘"로 진행 상태·문제 진단. 4. 제안 수락 시 실제 변경은 솔버가 재검증(단독 확정 금지). 5. 대화 맥락 유지·이력 재열람. 6. 오·남용 가드레일(프롬프트 주입·타 사용자 데이터 비노출). 7. 범위 한계 안내·외부 위임. 8. LLM·솔버·데이터 실패 시 관찰 가능한 폴백.

### K. 여행자 커뮤니티 (10) · *후속 게이트*
1. 공개 일정 둘러보기(탐색 랜딩 '여행자 일정'). 2. 공개 일정 상세 읽기전용(시간표·지도 2뷰). 3. 작성자 공개 프로필 보기. 4. 부적절 콘텐츠 신고·숨김(양방향 차단). 5. 내 일정 공개/공유(기본 비공개·마스킹·캡션·해시태그). 6. '내 여행으로 가져오기'(원본 분리 사본 복제·출처 전파). 7. 내가 공유한 일정 관리·공개 해제. 8. 좋아요(토글·집계). 9. 댓글(평면·작성/본인삭제/신고).

### L. 동행 공동 편집 (11) · *후속 게이트*
1. 동행자 초대(링크/계정·편집자/뷰어). 2. 권한별 동작·변경/회수. 3. 항목 단위 잠금 교대 편집·동기화. 4. 편집 충돌 해소(침묵 덮어쓰기 금지). 5. 공동 편집 변경도 솔버 재검증. 6. 오프라인 편집·재연결 동기화. 7. 변경 이력 기록·되돌리기. 8. 참여 종료·이탈·소유권 처리.

## Implementation Decisions

### 모듈 (17개)
1. **Auth** — 여행자 단일 유형 가입/로그인/세션/삭제. 2. **User Profile** — 취향·기본정보 저장, 개인화 입력. 3. **Accommodation Search** — 외부 OTA 숙소 탐색·저장(링크 노출 UI). 4. **Saved Accommodation** — 등록 숙소(위치+체크인/아웃) 보관, 일정 출발점 제공. 5. **Affiliate Link** — OTA 딥링크 생성·추적·전환. 6. **Trip Creation** — 여행 단위 생성·숙소 연결. 7. **Place Data** — 장소 메타데이터 수집·표준화(단일 API 비종속). 8. **Itinerary Generation** — day별 일정 생성(LLM 점수·설명 + 결정론적 TOPTW/제약). 9. **Plan-B Detection** — 재계획 트리거 감지. 10. **Itinerary Recalculation** — 잔여 일정 재최적화. 11. **Weather & Context** — 날씨·맥락 데이터 공급. 12. **Travel Archive** — 방문·동선·사진·메모 보관. 13. **AI Reflection/Summary** — 회고·요약·다음 여행 제안. 14. **Notification** — 푸시·인앱 이중 경로·catch-up. 15. **Community** — 공개·복제·프로필·좋아요·댓글·모더레이션(후속). 16. **Conversational Assistant** — 대화형 오케스트레이션, 솔버에 위임(후속). 17. **Collaborative Editing** — 항목 단위 잠금 공동 편집·솔버 재검증(후속·MVP).

**테스트 대상 핵심 8모듈**: Auth(1) · Accommodation Search(3) · Affiliate Link(5) · Saved Accommodation(4) · Itinerary Generation(8) · Plan-B Detection(9) · Itinerary Recalculation(10) · AI Reflection/Summary(13).

### AI 솔버 전략 (FR-SOLVER · 사용자 지시 2026-07-12)
- **Phase 1 (구현·출시)**: 결정론적 AI 솔버(OPTW/TOPTW, ADR-0008/0009 계승)로 일정 지능 구현. 솔버가 실현가능성 소유·보장.
- **향후 (조건부)**: 솔버 산출물 품질이 부적절하면 엔진을 Bedrock AgentCore 에이전트로 **교체**(옵션 B: 엔진 교체 + 일부 PRD 규칙 완화). 실현가능성은 에이전트가 호출하는 결정론적 검증 도구가 소유. 사용자 노출 시각 = 항상 검증값(환각 금지). '별로' 판정 기준은 Application Design/운영에서 정의.

### 핵심 아키텍처 결정 (ADR-0001 ~ ADR-0017)
- **ADR-0001**: 최종 구조 = **B2C 여행자 전용**. 호스트(숙박업주) 사이드 제품 없음.
- **ADR-0002**: 일정 출발점 = **등록된 숙소**(외부 예약 또는 앱 저장 후 등록)의 위치·체크인/아웃.
- **ADR-0003**: 숙소 예약 경로 = **외부 OTA 제휴 링크**. 앱은 탐색·저장만.
- **ADR-0004**: 등록 숙소 위치 = 일정의 **공간적 앵커**.
- **ADR-0005**: **액티비티(투어·체험) 탐색·예약·고정 입력 제외**. 고정 블록 = 등록 숙소 + 필수 방문지.
- **ADR-0006**: Plan-B = **여행 중 일정 실행 보조**(예약 변경 아님).
- **ADR-0007**: 여행 기록 = 방문 체크·사진·메모·위치 기반. 종료 시점이 회고 자동 생성 트리거.
- **ADR-0008**: 일정 생성은 **LLM 단독 아님** — 지도·장소·날씨 API + 규칙 로직 하이브리드.
- **ADR-0009**: 장소 데이터 = Place Data 모듈 표준화(단일 API 비종속). **이동시간은 거리 기반 추정**(도로 거리 우선·수단별 안전계수), 실시간 대중교통·턴바이턴 미제공. 사용자에겐 거리만 표시(소요시간 미표시), 솔버는 내부 버퍼 사용. 국내 지도 API(카카오·네이버·TMap) 우선·약관 준수.
- **ADR-0010**: 위치정보는 **동의 시에만** 수집·사용, 없으면 수동 폴백.
- **ADR-0011**: 외부 API·AI 실패 시 **수동 폴백**(침묵 실패 금지).
- **ADR-0012**: **외부 제휴 링크화 = 숙소 공급 단일 모델**(길안내·예약 등 외부 위임 상위 원칙).
- **ADR-0013**: 여행 기록 = **plan·actual·change-log 3종 구분 저장**.
- **ADR-0014**: **여행자 커뮤니티** = 공유·발견·좋아요·댓글까지(소셜 그래프 제외, 실시간 공동 편집은 별도).
- **ADR-0015**: **AI 어시스턴트 = 대화형 오케스트레이션**, 실현가능성 결정은 솔버 위임. 타 사용자 비공개 데이터·내부 지표는 컨텍스트 주입 단계 권한 경계로 차단.
- **ADR-0016**: **동행 공동 편집 포함**(소유자/편집자/뷰어, 솔버 재검증·변경 이력). MVP = 항목 단위 잠금, 핵심 여정과 분리된 출시 게이트.
- **ADR-0017**: **위치기반서비스사업 신고(위치정보법 제9조) = 출시 선결**(국내). 지도 국내 API 우선으로 국외반출 규제 회피, 약관 준수.

> 비고: 외부 제휴 링크 클릭/전환·수수료는 **내부 운영 지표로만** 수집, 사용자에게 비노출.

## Testing Decisions

**좋은 테스트의 기준**: LLM 문장 품질이 아니라 **사용자 결과의 필수 조건 충족**을 검증 — 등록 숙소 위치·날짜가 일정 기준점으로 반영, '숙소 저장→등록→AI 일정→Plan-B' 흐름 연결, 재계획이 고정 항목·이동시간과 무충돌, 추천 POI가 RAG 그라운딩(환각·폐업 제외), 계정 중복/미인증 방지, 외부 API 실패 시 fallback 복구(빈 화면·오류만 남지 않음).

**테스트 대상 모듈**: Saved Accommodation · Accommodation Search · Itinerary Generation · Itinerary Recalculation · Plan-B Detection · Affiliate Link · Travel Archive · AI Reflection/Summary · Place Data(RAG) · Notification · Trip Creation/User Profile.

**테스트 불포함**: 항공권 검색·예약·발권 / 액티비티 탐색·예약 / 자체 예약·인앱 결제·내부 재고 / 호스트 사이드 일체 / OTA 실시간 재고 동기화·정산·환불·분쟁 자동화 / 전 세계 일정 정확도 / LLM 문장 품질 절대 평가 / AI 자동 예약 변경·취소.

- OTA 제휴 파트너 선정 · 딥링크/수수료 트래킹 방식.
- 지도·장소 API(카카오/네이버/TMap) · 날씨 API(공공데이터포털/OpenWeather) 최종 선택.
- LLM/어시스턴트 rate-limit·가드레일 임계·대화 이력 보관 정책.
- 커뮤니티 모더레이션 조정값(SLA·필터 민감도·스팸 임계·알림 묶기) — 인프라 4종(신고 큐·검토 보류·금칙어 사전·양방향 차단)은 출시 선결.
- 솔버 '별로' 판정 기준(Bedrock 교체 트리거) — Application Design/운영.

### 법적·규제 선결 (🔴 출시 선결)
- **위치기반서비스사업 신고**(위치정보법 제9조, 사업자등록 전제) — '내 위치만 사용'·'외부 API 위임'으로 면제 안 됨. 이용약관·동의·철회/일시중지·목적달성 후 파기·로그 보존(제16·18·19·23·24조) 반영(ADR-0010·0017).
- **국내 지도 API 약관**(카카오·네이버·TMap) — 응답 데이터 영구 캐싱 금지·실시간 호출·출처 표기를 데이터 모델에 반영.

### 데이터/신선도 게이트
- 초기 지역 실제 데이터 커버리지(POI 영업시간 채움률·좌표 확보율) 정량 게이트 후 출시. 미커버 POI는 자동 감지 대신 수동 트리거·미확인 분리.

### 빌드 전략 메모
- **핵심 여정 우선**: 온보딩→탐색→등록→AI 일정→Plan-B→기록/회고(1차). 어시스턴트·커뮤니티·공동 편집은 **분리된 출시 게이트**(후속).
- **공통 원칙**: "침묵 실패 금지"를 전 파이프라인 불변식으로 — 모든 외부 의존 단계에 fallback + 사용자 안내.
- **초기 출시**: 국내(대한민국)·한국어 한정, 이후 단계적 확장.
