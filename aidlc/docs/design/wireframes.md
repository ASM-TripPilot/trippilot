## Figma 접근 방법

Figma **원격 MCP 서버**가 연결되어 있다 (`figma` MCP). 아래 파일을 MCP 툴로 직접 읽어 참고한다.

- `mcp__figma__get_metadata` — 프레임/레이어 구조 (nodeId 없이 호출 시 페이지 목록)
- `mcp__figma__get_screenshot` — 화면 시각 확인 (nodeId 필수, URL 반환 → curl 다운로드)
- `mcp__figma__get_design_context` — 디자인→코드 컨텍스트 (프론트 구현 시)
- `mcp__figma__get_variable_defs` — 색상·간격 등 디자인 토큰
- `mcp__figma__get_libraries` / `search_design_system` — 디자인 시스템 컴포넌트

> ⚠️ 전체 페이지 메타데이터는 매우 큼(~1.1M자). `get_metadata`는 **특정 프레임 nodeId**로 좁혀 호출한다. 전체 훑기는 서브에이전트로 파싱.

## 워크플로우 단계별 활용 지침

- **Requirements Analysis** — PRD 각 기능 영역에 대응하는 와이어프레임 화면·상태가 존재하는지 확인. 화면에만 있고 PRD에 없는 요소(또는 반대)를 갭으로 식별.
- **User Stories** — 수용 기준을 작성할 때 해당 화면의 실제 요소·상태(빈 상태·에러·로딩·충돌)를 근거로 구체화.
- **Application Design** — 화면 구조·5탭 내비게이션에서 프론트엔드 컴포넌트 경계·내비게이션 그래프를 도출. `59:2` DS-Catalog에서 공통 컴포넌트 파악.
- **Construction · Functional Design (frontend-components)** — 유닛별 대표 nodeId부터 `get_metadata`/`get_design_context`로 읽어 컴포넌트 목록·props·상태를 실제 디자인과 정합.
- **Construction · Code Generation** — `get_design_context`로 디자인→코드, `get_variable_defs`로 디자인 토큰 추출해 구현.
