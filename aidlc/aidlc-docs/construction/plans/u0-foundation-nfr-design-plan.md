### 설계 패턴

**Q1. 복원력 — 재시도 전략** — 추천: **대화형 경로는 재시도 없음**(소셜 IdP 호출 실패 = 즉시 사용자 피드백 + 수동 재시도, UX-01·RES-01). 자동 재시도는 **비대화형 경로만**(아웃박스 릴레이 = 지수 백오프 + 지터, 최대 시도 후 DLQ 상태 전이). 이유: 로그인에 자동 재시도를 걸면 3초 타임아웃(PERF-02) 안에 못 들어오고 IdP 장애 시 부하만 증폭.

**Q2. 확장성 — 스케일링 메커니즘** — 추천: 무상태 앱 컨테이너 **수평 오토스케일(CPU/요청 수 기준, min 2 = 다중 AZ 최소)**, DB는 **단일 프라이머리만**(U0 읽기 부하 ~50 RPS — 읽기 복제본 미도입, 과설계 회피). 10x 스파이크(SCALE-02)는 오토스케일 + 레이트리밋 429 저하로 흡수.

**Q3. 성능 — 캐시 전략** — 추천: **인메모리(프로세스 로컬) 캐시만, 분산 캐시 미도입**. 대상 = JWKS·제공자 메타(TTL 10분, RES-03) · 약관 현행 버전·금칙어 사전(TTL 5분, 부트스트랩 p95 예산 확보). 인스턴스 간 최대 TTL만큼의 불일치는 허용(약관 버전은 즉시성 요구 없음). Redis는 U0 미도입 — 세션/레이트리밋도 DB 카운터(SEC-03 기확정).

**Q4. 보안 — 키 롤오버 절차** — 추천: JWK 셋 **2키 중첩 운용**(현행 서명키 + 직전 검증키). 롤오버 = 신규 kid 추가 → 검증 전파 대기 → 서명키 전환 → 액세스 토큰 TTL(1h) 경과 후 구키 제거. 정기 주기는 운영 정책(Infra Design)이되 **절차와 무중단 불변식은 U0에서 고정**.

**Q7. 롤백 메커니즘** — A) 이전 버전 재배포(버전 핀) / B) 블루/그린 스왑백 / C) 카나리 자동 롤백 / D) DB 인지 롤백(스키마 되돌리기) / E) 조직 기존 절차 / X) 기타
