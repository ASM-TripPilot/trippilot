### A. 모바일 기기 · 배터리

#### Q1. 배터리 예산과 기록 파라미터 ★ (MOBILE-U4-05 철회의 후속 · BR-U10-34)

FD는 "저전력 연속 기록"까지만 정하고 값을 NFR로 넘겼다. 예산이 없으면 6-b #10(배터리 측정)이 판정 기준 없이 끝난다.

A) **무장 하루(10시간) 추가 소모 ≤ 10%p**, 기록 = `Accuracy.Balanced`(≈100m 등급 · 셀/와이파이 위주) · `distanceInterval 50m` · 지연 일괄 전달(`deferredUpdatesInterval 120s`·`deferredUpdatesDistance 250m`) · iOS `pausesUpdatesAutomatically: true`(멈추면 OS가 끊고, **다음 지오펜스 wake가 다시 켠다**) · Android 같은 값 + 포그라운드 서비스 알림. 기준 기기·측정법은 요구에 명시
B) **≤ 5%p 엄격** — 연속 갱신 대신 iOS significant-change(약 500m 해상도)만. 배터리는 좋지만 "실제 경로"가 직선 몇 개가 된다
C) 수치 없이 실측만 하고 나중에 정한다

> 추천 근거: 50m 거리 필터는 U4 DATA-U4-01 초기 제안을 승계한 값이고, Balanced 등급은 판정 정확도 임계(100m 초과 표본 폐기 · BR-U10-12)와 맞물린다 — 더 낮은 등급은 표본 대부분이 버려진다. 자동 정지(`pausesUpdatesAutomatically`)는 머무는 동안 GPS를 끄는 가장 큰 절약원이고, 재개 수단(지오펜스 이탈 wake)이 이 유닛에 이미 있다. B는 Q3=B(사용자 선택 — 연속 경로)의 취지를 무너뜨린다. C는 6-b를 판정 불가로 만든다.

[Answer]: A *(권고 적용 — 2026-10-12 사용자 일괄 지시 "그럼 권고로 ㄱㄱ")*

#### Q2. 기기 로컬 저장소 라이브러리 (G-U10-5)

원시 표본(하루 수천 점)·판정 상태·자동 결과 큐·열린 구간 id를 **백그라운드 태스크에서** 읽고 써야 한다. `expo-secure-store`는 소용량 키값용이고 기본 접근성이 `WHEN_UNLOCKED`라 잠금 상태 wake에서 못 읽는다.

A) **`expo-file-system`(이미 전이 설치 · 자동 링크) — 날짜별 JSONL(원시 표본) + 작은 JSON(상태·큐), 쓰기는 임시 파일 → 원자적 교체** · `package.json`에 직접 의존으로 명시
B) `expo-sqlite` — 트랜잭션·질의가 되지만 신규 네이티브 모듈
C) `react-native-mmkv` — 빠른 키값, 신규 네이티브 모듈(New Arch 대응 버전 필요)

> 추천 근거: 접근 패턴이 "추가(append) → 하루 끝에 통째로 읽고 지움"과 "작은 상태 덮어쓰기" 둘뿐이라 질의가 필요 없다. 새 네이티브 코드 0이고, 크기 상한(MOBILE-U10)을 걸면 파일로 충분하다. 강제 종료 중 쓰기 손상은 원자적 교체로 막는다.

[Answer]: A *(권고 적용 — 2026-10-12 사용자 일괄 지시 "그럼 권고로 ㄱㄱ")*

#### Q3. 기기 안 원시 좌표 보호 (SECURITY-01 · BR-U10-35)

A) **OS 데이터 보호에 맡기고 앱 수준 암호화는 하지 않는다 + 클라우드 백업 제외 경로에 둔다** — iOS 기본 파일 보호(`CompleteUntilFirstUserAuthentication` — 부팅 후 첫 잠금 해제 뒤엔 잠긴 상태에서도 백그라운드 접근 가능) · Android 자격 증명 암호화 저장소. 저장 위치 = 캐시 디렉토리(iOS `Caches`는 iCloud 백업 제외 · Android `cacheDir`는 자동 백업 제외). OS가 저장 공간 압박에서 지우면 그날은 근사(`VISIT_LINE`) — 업로드 실패와 같은 폴백
B) 앱 수준 암호화(AES) + 키는 Keychain `AFTER_FIRST_UNLOCK` — 신규 암호 라이브러리
C) 원시 표본을 메모리에만 — 태스크가 끝나면 사라져 성립 불가

> 추천 근거: 앱 수준 암호화의 키도 결국 같은 기기 Keychain에 같은 잠금 등급으로 있어야 백그라운드에서 쓸 수 있으므로, 위협 모델(기기 탈취)에서 OS 파일 보호 대비 이득이 없다. 실질 위험은 **백업으로 기기 밖에 나가는 것**이라 그것만 막는다. 원시 표본 수명이 당일(+재시도 기한)이라 캐시 퍼지 손실도 감당 가능하다.

[Answer]: A *(권고 적용 — 2026-10-12 사용자 일괄 지시 "그럼 권고로 ㄱㄱ")*

#### Q4. 잠금 상태 wake에서 서버 전송 ★ (실측에서 새로 나온 제약)

토큰은 `WHEN_UNLOCKED` Keychain에 있다. 주머니 속 잠긴 폰에서 지오펜스가 앱을 깨우면 **판정·적재는 되지만(파일) 토큰을 읽지 못해 전송이 안 된다.** 또 토큰 갱신은 재사용 감지가 있어 백그라운드·포그라운드가 동시에 갱신하면 체인이 통째로 무효화된다(SEC-02).

A) **잠금 중엔 보내지 않고 큐에 둔다 · 백그라운드에서는 토큰을 갱신하지 않는다**(401이면 큐 유지 → 포그라운드가 갱신 후 flush). 토큰 저장 등급(SEC-09)은 그대로
B) 토큰 접근성을 `AFTER_FIRST_UNLOCK_THIS_DEVICE_ONLY`로 완화(기존 토큰 재저장 마이그레이션 필요) — 잠금 중 전송 가능
C) 백그라운드 전용 범위 토큰 신설(자동 결과·구간 보고만 허용)

> 추천 근거: 큐는 당일 한정이고(BR-U10-22), 하루 중 기기가 잠금 해제된 상태로 깨어나는 순간(경로 일괄 전달 wake는 2분 간격)과 포그라운드 복귀가 충분히 많다 — 자동 도착 시각은 소급되므로(BR-U10-14) 전송이 늦어도 기록은 정확하다. B·C는 인증 정본(U0)을 건드린다. **당일 유실률이 목표를 넘으면 B로 간다**(재평가 트리거).

[Answer]: A *(권고 적용 — 2026-10-12 사용자 일괄 지시 "그럼 권고로 ㄱㄱ")*

### B. 출시 · 스토어 심사

#### Q5. 기능 플래그 장치 (G-U10-6 · BR-U10-07)

A) **빌드 환경 변수 1개(이름 제안 `TRIPPILOT_LOCATION_AUTOMATION`)를 `app.config.ts`가 읽어 네이티브 권한 표면 + `extra.locationAutomation`을 함께 정하고, `eas.json`에 프로파일을 하나 더 둔다**(`production`은 OFF 그대로, 새 프로파일이 ON). JS는 `expo-constants`로만 읽는다
B) `EXPO_PUBLIC_*` 변수 — FD가 이미 거절(네이티브 표면과 JS 값이 갈라질 수 있다)
C) 별도 번들 ID의 베타 앱

> 추천 근거: OTA가 없으므로 빌드 = JS+네이티브 한 묶음이고, 플래그를 빌드 값 하나로 두면 "권한 표면과 동작이 같은 값"이 구조적으로 보장된다. 프로파일 분리로 심사 반려 시 OFF 빌드 재제출이 명령 하나다. C는 계정·스토어 등록·로그인 키를 전부 복제해야 한다.

[Answer]: A *(권고 적용 — 2026-10-12 사용자 일괄 지시 "그럼 권고로 ㄱㄱ")*

#### Q6. 원격 킬 스위치 (O-U10-7 · RESILIENCY-04 롤백)

빌드 플래그만으로는 출시 후 배터리·오탐 문제가 터져도 **새 빌드 심사 + 사용자 업데이트** 전까지 끌 수 없다.

A) 두지 않는다 — 빌드 플래그만(FD 기본)
B) **서버 설정값 1개(백엔드 env, 기본 ON)를 구간 START 응답(꺼짐 = 409 `AUTOMATION_DISABLED`)과 자동 결과 배치 응답(`automationEnabled`)에 싣고, 꺼짐을 받으면 기기는 강등 경로(BR-U10-46)로 해제한다.** 받지 못하면(오프라인) 직전 상태 유지
C) 원격 설정 SaaS(Firebase Remote Config 등) 도입

> 추천 근거: 이 기능의 실패 모드(배터리 과소모·오탐)는 **사용자 기기 전체에 동시에** 나타나고, 모바일 롤백(OFF 빌드)은 며칠이 걸린다. B는 무장 시점·wake마다 이미 나가는 두 호출에 필드 하나를 얹을 뿐이라 신규 엔드포인트·SaaS가 없다. `/me/settings`는 사용자가 PATCH하는 설정이라 섞지 않는다. 오프라인에서 직전 상태 유지 = 산속에서 회선이 끊겼다고 자동 기록이 꺼지지 않게. **FD 계약(§12.1·§12.4)에 필드 2곳 추가가 필요**하다 — 구현 PR에서 FD 개정 블록으로 남긴다.

## NFR Design 권고

**권고 = 진행(얇게, 3주제)** — Q14=A.

- **U3·U6가 스킵한 이유가 여기엔 성립하지 않는다.** 그 둘은 "패턴이 될 것이 이미 요구 안에 배치까지 들어갔다"가 스킵 사유였다. U10은 패턴의 본체가 **기기 백그라운드 실행**이고, 그 실패 모드(잠금 상태 Keychain · 갱신 경합 · 태스크가 렌더 트리 밖에서 정의돼야 함 · 자동 정지 후 재개 · 강제 종료 중 쓰기)는 **jest가 원리적으로 못 본다**(G-U10-14). 테스트가 못 잡는 것은 설계 문서가 순서·상태 전이로 고정해 두지 않으면 구현 PR마다 다시 발명된다.
- **FD가 이미 NFR Design에 넘긴 미결이 있다** — O-U10-8(다운샘플 허용 오차·점 상한과 "정지 지점 재구성 불가" 판정 기준). 값 하나가 아니라 **판정 방법**을 정해야 해서 요구 문서에 넣으면 요구가 설계를 대신하게 된다.
- **U5처럼 NFR Req를 스킵한 것도 아니고 U4처럼 열린 설계 질문이 남았다**(U4는 NFR Design에서 지오펜스 창 정책을 닫았다 — 같은 계열).
- **범위를 좁히는 이유**: 서버 쪽(배치 엔드포인트 멱등 · 스케줄러 · 스위퍼 · 법정 로그)은 기존 패턴(`OfflineReplayPropertyTest`·`TripEndSweeper`·ShedLock·파사드 트랜잭션 참여)의 재사용이라 새로 설계할 것이 없다. 그래서 **클라 3주제**만 돈다. G-U10-5·6은 `tech-stack-decisions.md`에서 결론을 냈으니 NFR Design이 다시 열지 않는다.
- **스킵해도 되는 조건(참고)**: 위 3주제를 구현 착수 티켓의 설계 절로 대신하겠다는 팀 결정이 있으면 스킵하고 `aidlc-state.md`에 재개 조건(6-b에서 백그라운드 실패 실측)을 남긴다.
