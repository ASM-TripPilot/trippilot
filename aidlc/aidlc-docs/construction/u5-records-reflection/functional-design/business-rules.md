# U5 Records & Reflection — Business Rules

> **상속**: U0(보안·동의·삭제 유예) · U1(장소·숙소) · U2(경계 계약 `BR-U2-*`) · U3(일정 `BR-U3-*`) · U4(여행 중 `BR-U4-*`)는 **재서술하지 않는다.** 아래는 U5 고유 규칙이다.
> 충돌 시 정본 순위: 리포 실물 > 계약 정본 > 라이브 Figma > aidlc 산출물 > 인셉션.

---

## 1. 방문 실적 (US-REC-01 · 승계분)

| ID | 규칙 |
|---|---|
| **BR-U5-01** | 방문 체크는 **plan을 덮어쓰지 않는다.** `visit_slot`은 그대로 두고 `visit_check`에만 쌓는다 — 계획과 실제가 달라도 그 자체가 사실이다(openapi 실장 문구 그대로) |
| **BR-U5-02** | 같은 슬롯을 두 번 체크하면 **409**다. 지오펜스가 한 번 이동에 두 리전을 깨워도 하나만 확정된다(실장 계약) |
| **BR-U5-03** | `slotKey`를 비우면 **즉석 방문**이다. 즉석 방문은 유니크 제약 밖이라 여러 건일 수 있다 |
| **BR-U5-04** | 실제 방문 시각은 **기기 시각으로 자동 기록하되 사용자가 수정할 수 있다**(`PATCH /visits/{id}`). 보내지 않은 필드는 그대로 두는 뜻이지 지우는 뜻이 아니다 |
| **BR-U5-05** | 도착 없이 완료만 남길 수 없다. 순서가 뒤집히면 **409** — 파생 체류가 음수가 된다 |
| **BR-U5-06** | 완료와 건너뜀은 **동시에 참일 수 없다**. 둘 다 있으면 '갔나 안 갔나'가 갈린다 |
| **BR-U5-07** | 방문 상태는 세 timestamp에서 **파생**한다(INV-U5-01). `status` 컬럼을 만들지 않는다 |
| **BR-U5-08** | 실제 체류(`completed_at − arrived_at`)는 산출하되 **개별 방문의 체류 시간으로는 화면에 표시하지 않는다**(BR-U4-37 승계 — U4·U5 화면 공통) |
| **BR-U5-08a** | 반면 **누적 통계의 평균 체류 시간은 표시한다**(`j05` `평균 체류 72분` · DEC-U5-13). INV-3이 막는 것은 솔버 미검증 *예측 소요시간*이고, 사후 실적 통계는 **U5 기록 소관**이다(INV-U4-03이 명시) |
| **BR-U5-09** | 방문 완료는 `VisitChecked`를 발행한다. 이관 후 **발행 주체는 U5 `archive`**이며 페이로드·구독자는 U4 때와 같다 |
| **BR-U5-10** | U4 재계획의 잠금 판정(INV-U4-04)은 `ArchiveFacade.getCompletedSlots`로 읽는다. **U5는 U4를 호출하지 않는다**(순환 금지) |

## 2. 사진·메모 (US-REC-02)

| ID | 규칙 |
|---|---|
| **BR-U5-11** | 사진 **바이너리를 서버에 올리지 않는다.** 저장하는 것은 로컬 자산 식별자·기기 ID·촬영 시각·EXIF 위치(동의 시)·연결 방문뿐이다 |
| **BR-U5-12** | 위치 동의(V1.3 `gps_recording_opt_in`)가 없으면 EXIF 좌표를 **받지도 저장하지도 않는다** |
| **BR-U5-13** | 한 방문에 사진은 **여러 장**, 메모는 **한 개**다(`j01` 카드 구조) |
| **BR-U5-14** | 원본 자산 접근 실패 시 **"사진을 불러올 수 없어요"를 표기**하고, 메모·방문 체크는 사진과 무관하게 저장·표시된다. 빈 자리를 조용히 두지 않는다(INV-4) |
| **BR-U5-15** | 기기 변경·재설치 시 사진은 이관되지 않는다. **메타데이터만 남는다** — 화면은 이 사실을 "다른 기기에서 찍은 사진" 으로 표기하고 깨진 썸네일을 그리지 않는다 |
| **BR-U5-16** | 커뮤니티 공개 업로드(`uploadForCommunity`)는 **U7 게이트까지 미개통**이다. 인터페이스만 두고 호출 경로를 만들지 않는다 |

## 3. 오프라인·동기화 (US-REC-12)

| ID | 규칙 |
|---|---|
| **BR-U5-17** | 오프라인 입력은 **기기 로컬 큐**에 쌓고 화면에 '동기화 대기'를 표기한다. 서버에 큐 테이블을 두지 않는다 |
| **BR-U5-18** | 큐는 **입력 순서대로** 재생한다. 도착→완료 순서가 뒤집히면 BR-U5-05로 거부된다 |
| **BR-U5-19** | 동기화 상태는 `LOCAL → PENDING → SYNCED` \| `CONFLICT` 4종이다(클라이언트 소유) |
| **BR-U5-20** | 재생 중 **409는 실패가 아니다** — 이미 서버에 있는 상태라면 `SYNCED`로 수렴시킨다(멱등) |
| **BR-U5-21** | 충돌이면 **사용자가 고른다** — 조용히 한쪽을 이기게 하지 않는다. ⚠️ **단위는 방문(레코드)별이다**(2026-08-24 `j01 sync-conflict` 시각 확인으로 정정) — 화면 문구가 *"항목마다 어느 버전을 유지할지 선택하세요"*이고 충돌 카드가 방문마다 하나씩 뜬다(`동기화 충돌 2건`). 전역 일괄 선택이 아니다. 선택 후 **`[선택한 버전으로 동기화]`** 로 한 번에 적용한다 |
| **BR-U5-21a** | 충돌 카드는 **`내 기기(오프라인)` vs `서버` 2열**로 **방문 시각 · 방문 상태 · 메모 · 사진 수**를 나란히 보인다. 각 열에 라디오 1개 — 필드별 선택이 아니라 **버전 단위 선택**이다 |
| **BR-U5-22** | 충돌 판정 기준은 `visit_check.updated_at`이다. 로컬 편집 시각이 서버 `updated_at`보다 이르면 충돌로 본다 |
| ~~**BR-U5-23**~~ | ~~사진 메타는 충돌 대상이 아니다 — 합집합 병합~~ → **폐기(2026-08-24 시각 확인)**. `j01 sync-conflict`는 사진을 **버전 비교 항목으로 그린다**(`사진 2장 (대기)` vs `사진 1장`). 합집합으로 병합하면 화면이 보여준 선택이 거짓말이 된다 |
| **BR-U5-23a** | 사진 메타도 **선택한 버전을 따른다**. 다만 버린 쪽 사진의 **로컬 자산은 지우지 않는다** — 서버 메타만 선택 버전으로 맞추고, 기기 사진은 사용자 앨범 소유라 앱이 삭제할 권한도 이유도 없다 |
| **BR-U5-24** | 오프라인 구간의 회고는 **생성하지 않는다.** 복구 후 생성하거나 기본 카드로 대체한다 |

## 4. 귀속·비교 (US-REC-04·05)

| ID | 규칙 |
|---|---|
| **BR-U5-25** | 숙소·날짜 귀속은 **조회 시점 파생**이다. 저장하지 않는다 — 숙소가 나중에 바뀌어도 기록이 따라 움직여야 한다 |
| **BR-U5-26** | 이동 숙박이면 **날짜별 기준 숙소**를 따로 잡는다. 등록 숙소가 없는 날(당일치기·이동일)은 **날짜만**으로 묶는다 |
| **BR-U5-27** | 날짜 경계는 **여행지 기준 날짜**다(U4 승계). 즉석 방문은 슬롯 키가 없어 `arrived_at`으로 묶인다(실장 계약) |
| **BR-U5-28** | 3종 비교(`j02`)에서 **미방문**은 "계획엔 있는데 `visit_check`가 없는 슬롯"으로 판정한다. 별도 저장 없음 |
| **BR-U5-29** | 변경 이력은 `change_log_entry`를 **읽기만** 한다. U5는 이 테이블에 쓰지 않는다. ⚠ **읽을 진입점이 아직 없다** — `ChangeLogFacade`는 `append` 하나뿐이라 **조회 메서드 추가가 선행**돼야 이 규칙이 성립한다(G-U5-12) |
| **BR-U5-30** | 변경 행은 **전후 장소·사유·시각**을 함께 보인다(`△△카페 → ◇◇실내카페 · 휴무로 대체 방문`). `before/after_snapshot`이 근거다 |

## 5. 회고 생성 (US-REC-06·07)

| ID | 규칙 |
|---|---|
| **BR-U5-31** | 생성물은 **근거 데이터 안에서만** 쓴다. 입력에 없는 장소·수치를 서술에 넣지 않는다(환각 금지) |
| **BR-U5-32** | 폴백은 **3단**이다: AI 카드 → **규칙 카드** → 기본 카드. 어느 단에서 멈춰도 **빈 화면을 그리지 않는다**(PBT-U5-1). *(2026-09-01 개정 — 가운데 단이 '규칙 문장'이었다. 산출물이 카드로 확정되면서 규칙 단도 카드를 내야 한다: 문장을 내면 AI 가 죽는 날 **화면 모양 자체가 달라져** 폴백의 뜻이 성립하지 않는다.)* |
| **BR-U5-33** | 응답은 `source: AI \| RULE \| BASIC`을 **항상** 싣는다. 화면이 구분해 그리지 않더라도 계약에는 남긴다(DEC-U5-5a) |
| **BR-U5-34** | 부분 데이터면 **없는 항목을 명시적으로 누락 표기**한다 — 사진 0장이면 하이라이트 생략, 위치 없음이면 지도 자리에 사유. 조용히 칸을 지우지 않는다 |
| **BR-U5-35** | 수정본은 **초안과 별도로 저장**하고 표시본은 `edited ?? draft`다(INV-U5-06). *(2026-09-01 — 단위가 문장에서 **카드 통째**로 바뀐다. 장면·캡션 단위 편집은 화면이 정해진 뒤에 정한다.)* |
| **BR-U5-36** | 생성이 실패한 경우에도 **직접 회고를 쓸 수 있다** — 기본 카드 위에 입력을 연다 |
| **BR-U5-37** | 회고 생성 완료는 `ReflectionReady`를 발행한다. **알림 발송은 U6 소관**이며 U5는 이벤트까지다 |
| **BR-U5-38** | `AI_REFLECTION_MODE`가 `http`인데 `ai/` 표면이 없으면 **기동 시점에 드러낸다**(부팅 로그·헬스체크). 첫 사용자 요청에서 조용히 폴백하지 않는다 |

## 6. 요약·스타일·개인화 (US-REC-08·09·10)

| ID | 규칙 |
|---|---|
| **BR-U5-39** | 여행 요약은 `TripEnded` 수신으로 생성한다. 위치 데이터가 전혀 없으면 **지도 대신 방문 목록**으로 대체한다 |
| **BR-U5-40** | 스타일 분석 임계는 **누적 방문 ≥ 10곳**이다. 미만이면 정식 분석을 만들지 않고 `현재 N곳/필요 10곳` + 진행 게이지 + **"정식 아님"을 명시한** 임시 미리보기를 보인다 |
| **BR-U5-41** | 임시 미리보기는 **저장하지 않는다**(INV-U5-09) |
| **BR-U5-42** | 스타일 분석은 **구체 수치와 근거 데이터**를 함께 낸다 — `카페 40%`·`하루 평균 4곳` + `근거가 된 방문 데이터` 진입 |
| **BR-U5-43** | 이동 거리는 `distanceSource: ROUTE \| VISIT_LINE`을 함께 낸다. 1차 기본은 **방문점 연결선 근사**(DEC-U5-12) |
| **BR-U5-44** | 개인화 활용에 **동의하지 않으면 과거 기록을 추천 입력에서 제외**하고 기본 추천만 제공한다 |
| **BR-U5-45** | 개인화에 **사용된 항목·목적을 설정에서 안내**한다 — 화면은 U6(`l05`) 소관, U5는 "무엇을 넘겼는가" 목록을 계약으로 제공한다 |

## 7. 공유·캘린더 (US-REC-13·14)

| ID | 규칙 |
|---|---|
| **BR-U5-46** | 공유 카드는 **온디바이스 렌더**다. 서버에 이미지를 만들지 않는다(사진이 기기에만 있으므로 서버가 그릴 수 없다) |
| **BR-U5-47** | 대표 사진이 없으면 **지도 경로·통계 기반 '사진 없는 카드'**로 대체한다(`j06 no-photo`) |
| **BR-U5-48** | **종료·요약 전이면 공유 진입점을 비활성화**한다 |
| **BR-U5-49** | 캘린더는 여행 기간을 월 단위로 마킹하고 **복수 여행을 모두** 표시한다. 저장 여행이 없으면 빈 캘린더 대신 안내 + 새 여행 생성 진입 |

## 8. 이관·경계 (설계 위생)

| ID | 규칙 |
|---|---|
| **BR-U5-50** | 이관은 **코드 이동만**이다. 테이블·openapi 경로·`tags`·스키마를 바꾸지 않는다 — 클라이언트 계약을 흔들지 않는다 |
| **BR-U5-51** | `archive`는 `reflection`을 의존하지 않는다. 역방향(`reflection` → `ArchiveFacade`)만 허용 |
| **BR-U5-52** | U5 신규 테이블 5종은 **append-only가 아니다.** 전부 여행·계정 파기 대상이라 앱 롤에 DELETE가 있어야 한다 |

## 9. GPS 기록·재열람 (US-REC-03·11) — 셀프 검수에서 추가된 절

> **왜 뒤늦게 붙었나**: Q5=B로 `actual_route_point` 소유가 U4에 남으면서 **US-REC-03의 규칙이 통째로 빠졌다**(2026-08-22 셀프 검수 발견). 소유가 U4라도 **기록 화면의 동작 규칙은 U5가 정해야 한다** — 안 정하면 "동의했는데 동선이 안 그려진다"가 아무 문서에도 안 걸린다.

| ID | 규칙 |
|---|---|
| **BR-U5-53** | 실제 동선 레이어는 **위치 동의(`location_consent_state.gps_recording_opt_in`)가 있을 때만** 그린다. 없으면 레이어를 **비활성 + 사유 표기**하고 계획 동선만 보인다(U4 INV-U4-07·BR-U4-42 승계 — U5 화면에도 그대로 적용) |
| **BR-U5-54** | 위치 권한이 없거나 거부면 **수동 체크인이 기본 수단**이다. 설정에서 OFF 전환 시 **즉시 수집을 중단**한다(US-REC-03 예외). 수집 중단이 기존 기록을 지우지는 않는다 |
| **BR-U5-55** | **`actual_route_point`가 실장되기 전까지 U5 화면은 실제 동선을 "없음"으로 정직하게 degrade한다** — 방문점 연결선을 실제 동선인 것처럼 그리지 않는다. 연결선은 **거리 근사에만** 쓰고(BR-U5-43 `VISIT_LINE`) 지도에서는 실제 경로로 표시하지 않는다 |
| **BR-U5-56** | 지난 여행 재열람(US-REC-11)은 **여행 단위 목록**을 주고 각 여행에서 plan/actual/changelog 3종으로 진입시킨다. 저장 기록이 하나도 없으면 **빈 화면 대신** '아직 기록된 여행이 없습니다' + 새 여행 생성 진입(`j07` 빈 상태) |

## PBT (property-based · 블로킹 게이트)

| ID | 성질 |
|---|---|
| **PBT-U5-1** ★ | **입력이 무엇이든 회고 결과는 비어 있지 않다.** 방문 0·사진 0·메모 0·변경 0이어도 `stats`가 채워진 기본 카드가 나온다(C13 인셉션 PBT 그대로) |
| **PBT-U5-2** | 방문 실적의 시간 불변식: 임의의 `(arrived, completed, skipped)` 조합에 대해 **완료<도착 또는 완료·건너뜀 동시 참**이면 항상 거부된다 |
| **PBT-U5-3** | 오프라인 큐 재생은 **멱등**이다 — 같은 큐를 두 번 재생해도 서버 상태가 같다(409를 `SYNCED`로 수렴, BR-U5-20) |
