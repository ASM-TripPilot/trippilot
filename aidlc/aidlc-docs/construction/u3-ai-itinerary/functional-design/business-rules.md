# U3 AI Itinerary Generation — Business Rules

> 규칙 우선순위는 U2 `business-rules.md` §0과 동일: **실장 우선 → 양쪽 실장이 다르면 문서가 결정 → 불변식은 개정 대상 아님.**
> 솔버 내부 규칙(HC1~HC4·시한·결정론)은 U2 경계 뒤 — 여기서 다루지 않는다.

---

## 1. 생성 진입·선행 조건

| ID | 규칙 |
|---|---|
| **BR-U3-01** | 등록 숙소 0이면 생성을 **차단**하고 사유를 안내한다. 예외 = "숙소 나중에" 온램프(US-SCHED-11) — 이때는 숙소 없이 동선 기준으로 생성한다 |
| **BR-U3-02** | 앵커 지오코딩 실패 시 생성을 **보류**하고 지도에서 위치 지정을 요청한다. 실패한 채로 생성하지 않는다 |
| **BR-U3-03** | 생성 요청의 `deadlineMs`는 **호출자(backend)가 소유**한다 — day1 5,000ms(BR-U2-11 승계) |
| **BR-U3-04** | `day1ReadyAt` 도달 시 **1일차만 먼저 노출**하고 나머지는 백그라운드로 채운다. 로딩 화면은 단계 텍스트·진행률·[백그라운드로]·[취소]를 제공한다 |
| **BR-U3-05** | [취소]는 세션을 `CANCELED`로 두고 부분 결과를 버린다. [백그라운드로]는 세션을 유지한 채 화면만 이탈한다 |
| **BR-U3-06** | 생성 방식(완전 AI·같이 고르기·직접)은 **언제든 전환** 가능하며 **진행분을 보존**한다(US-SCHED-10). 전환이 이미 만든 슬롯을 지우지 않는다 |

## 2. 표시 규칙

| ID | 규칙 |
|---|---|
| **BR-U3-07** | **시각 노출 단계 정책(DEC-U3-3)**: 초안(h11·h17)은 **시간대 라벨**(`오전·활동`·`점심·식사`·`오후·전시`·`저녁·활동`·`저녁·숙소`)만. 완성·확정(h25·h26·h34)은 **검증 시각**(`09:30`). **고정 블록은 초안에서도 시각 노출**(숙소 `21:00 도착 · 변경 불가`) |
| **BR-U3-08** | 구간 정보는 **거리 + 이동수단**만(`도보 950m` · `차량 3.1km`). **소요시간 표기 금지**(INV-3). [길찾기]는 외부 지도앱으로 위임한다 |
| **BR-U3-09** | 슬롯의 영업시간·휴관 경고는 **backend가 C7 정본을 조회해 합성**한다(DEC-U3-9). 영업시간 미확인이면 "영업시간 미확인"으로 표시하고 확정 배치 대신 **사용자 확인 후보로 분리**한다(US-SCHED-03 예외) |
| **BR-U3-10** | 추천 이유(`explanations`)는 **시각·소요시간을 언급하지 않는다**(BR-U2-09 승계). 설명과 실제 배치 시각이 어긋나면 **검증 시각을 기준으로 표시**한다(US-SCHED-05 예외) |
| **BR-U3-11** | 폴백·강등은 **항상 표시**한다 — `isFallback`·`solveMode=MINIMAL`·`candidatesSummary.level=LOW` 각각에 대응 문구가 있다(INV-4, 침묵 실패 금지) |

## 3. 편집·재검증

| ID | 규칙 |
|---|---|
| **BR-U3-12** | 편집 중 재검증(`validate`)은 **변경을 차단하지 않는다.** 위반은 배지·사유로 표시만 한다(BR-U2-12 승계) |
| **BR-U3-13** | 위반이 있는 채로 저장하려 하면 "○곳에서 시간이 안 맞아요" 요약 후 **[AI 자동 보정] / [그대로 저장]** 을 선택하게 한다. 저장 후에도 위반 블록을 **지속 가시화**한다 |
| **BR-U3-14** | [AI 자동 보정] = `repair` — **시각·순서만 최소 조정, POI 불변**. 고정 블록은 보정도 건드리지 않는다 |
| **BR-U3-15** | 슬롯 추가 시 **삽입 가능한 시간대만** 후보로 제시한다(US-SCHED-07) |
| **BR-U3-16** | 저장 중 네트워크 오류는 **로컬 임시 보관 + "저장 대기 중"** 표시 후 재연결 시 자동 동기화한다 |

## 4. 재생성 계열 (DEC-U3-2·4)

| ID | 규칙 |
|---|---|
| **BR-U3-17** | **재생성 계열 = { 추천 강도 변경, 동선 정리, 명시적 재생성 }** — 전부 `generate` 재호출로 구현한다. `recalculate`는 개통하지 않는다 |
| **BR-U3-18** | 재생성 전에 **사용자 편집분이 있으면 확인 대화**를 띄운다("직접 바꾼 N곳이 사라져요"). 확인 없이 편집분을 덮어쓰지 않는다 |
| **BR-U3-19** | 재생성 **직전 상태를 리비전으로 스냅숏**한다(INV-U3-08). 되돌리기 지점이 없는 재생성은 금지 |
| **BR-U3-20** | **동선 정리 결과가 개선되지 않으면 원본을 유지**하고 "지금 동선이 이미 짧아요"로 안내한다. 더 나쁜 결과를 적용하지 않는다 |
| **BR-U3-21** | 동선 정리 전·후 비교(h28)는 **클라이언트가 계산**한다 — 총 이동거리 합·추가/삭제/이동 슬롯 분류. 서버는 새 일정만 준다 |
| **BR-U3-22** | 추천 강도(`최소·균형·많이`)는 **재생성 트리거**이며 클라이언트 필터가 아니다. 강도만 바꾼 재생성도 BR-U3-18·19를 따른다 |

## 5. 슬롯 교체 (DEC-U3-5)

| ID | 규칙 |
|---|---|
| **BR-U3-23** | [다른 후보 N]은 **완전 AI·같이 고르기 공통** 경계 `proposeSlotCandidates`를 쓴다. 경로별로 다른 API를 두지 않는다 |
| **BR-U3-24** | 후보는 **closed-set**(INV-1) — backend가 임의 POI를 섞지 않는다. 이미 일정에 있는 POI는 `excludePoiIds`로 제외한다 |
| **BR-U3-25** | 후보 0건이면 **반경 확대 / 컨셉 변경**을 제안한다(h15). 확대 반경은 응답의 `radiusMUsed`로 사용자에게 표시한다(`약 11.3km`) |
| **BR-U3-26** | 교체 후 시각은 **재검증 전에는 노출하지 않는다.** 초안 단계는 시간대 라벨만이므로(BR-U3-07) 자연히 지켜진다 |

## 6. 확정 (US-SCHED-12)

| ID | 규칙 |
|---|---|
| **BR-U3-27** | 확정 시 모든 슬롯의 `poiSnapshotId`를 **동결**한다(INV-U3-05). 동결 실패 슬롯이 하나라도 있으면 확정을 거부한다 |
| **BR-U3-28** | `CONFIRMED` 상태에서 슬롯 변경 API는 **거부**한다(INV-U3-04). 화면은 읽기전용(h34) |
| **BR-U3-29** | **확정 후 재편집**: [일정 수정] 선택 시 `CONFIRMED → PLANNED`로 되돌리고 그 사실을 리비전에 남긴다(`kind=EDIT`, actor=USER). 도메인 `ItineraryStatus`가 현재 단방향이므로 **역전이 허용은 이 규칙이 신설하는 변경**이다(갭 G-U3-6 해소). 동결된 `poiSnapshotId`는 유지한다 |
| **BR-U3-30** | 확정 화면은 D-day·출발 맥락과 확정의 의미(최종본 잠금)를 **한 줄로** 설명한다 |

## 7. 편집 이력 (DEC-U3-1)

| ID | 규칙 |
|---|---|
| **BR-U3-31** | U3가 기록하는 리비전은 **`BASELINE`(AI 최초 생성) · `GENERATE`(재생성) · `EDIT`(사용자 편집) · `RESTORE`(되돌리기)** 4종뿐이다. Plan-B 재계획은 **U4가 기록**한다 |
| **BR-U3-32** | 되돌리기는 **과거 리비전을 삭제하지 않고 새 리비전을 쌓는다**(INV-U3-06). 되돌리기의 되돌리기가 가능하다 |
| **BR-U3-33** | 되돌려도 **고정 블록의 시각은 바뀌지 않는다**(INV-U3-03) — 복원 스냅숏이 고정 블록과 충돌하면 고정 블록이 이긴다 |
| **BR-U3-34** | `with-companions`(동행자 편집 표시)는 **1차 미구현**(DEC-U3-8). 컬럼·필드도 만들지 않는다 |

## 8. PBT 대상 (클라이언트 순수 함수 · fast-check)

| ID | 속성 |
|---|---|
| **PBT-U3-1** | **총 이동거리 합산** — 임의 구간 거리 목록의 합이 순서·단위(m/km)에 무관하게 일관. 표시 문자열 파싱 왕복 항등 |
| **PBT-U3-2** | **시간대 라벨 사영**(BR-U3-07) — 임의 `startAt`에 대해 라벨이 정확히 하나로 결정되고, 경계값(정오·자정 넘김)에서도 누락·중복 없음 |
| **PBT-U3-3** | **전·후 diff 분류**(BR-U3-21) — 임의 두 일정에 대해 추가/삭제/이동 분류가 서로 배타적이고, 분류 결과를 원본에 적용하면 대상 일정이 재현 |
| **PBT-U3-4** | **`slotKey` 왕복**(BR-U2-04 정합) — 생성·파싱 왕복 항등, 같은 날 중복 POI 없음 |
| **PBT-U3-5** | **재생성 안전성**(BR-U3-19) — 임의 재생성 시나리오에서 직전 상태 리비전이 항상 선행 기록됨(리비전 없는 재생성 경로 0) |
