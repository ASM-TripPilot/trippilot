## 2. 컴포넌트 경계 (U1 확정판)

```text
U1
├─ C7 Place Data      poi·poi_snapshot·수집 게이트·POI 표준화        [U3→U1 이동, DEC-4]
├─ C3 Accom Search    숙소 탐색·필터·상세·최저가 스냅숏·라이브 정확가
├─ C4 Saved Accom     저장(♥)·등록(거점)·구간 배정·커버리지 해소      [앵커 소유자]
├─ C5 Affiliate Link  OTA 딥링크 생성·아웃바운드 기록·복귀 핸드오프
└─ C6 Trip Creation   여행 생성·라이프사이클·필수 방문지·예산·홈 집계
```

- **의존 방향**: C3·C6 → C7(장소·좌표) / C6 → C4(앵커) / C3 → C5(딥링크) / 전부 → U0(인증·프로필·취향). **역방향 없음.**
- **U3 이후에 제공하는 것**: `RegisteredStayFacade.getAnchors(tripId)` · `TripFacade.getTripContext(tripId)` · `PlaceDataFacade.resolveCandidatePool(...)` — U3 솔버·일정 생성의 입력.
- **INV-1 집행 위치가 U1로 내려옴**: 웹·외부 출처 POI는 수집 게이트를 통과해 `poi`에 등록된 뒤에만 후보가 된다. **U1이 폐쇄 후보풀의 소유자**이며, 이에 따라 "closed-set gate PBT 100%" CI 게이트도 U1로 이동한다.

## 3. 핵심 플로우

### F-1. 탐색 → 담기 → 여행 만들기 (Case A · 장소 우선)

```text
탐색 탭(d01)
  ├─ 여행지 칩/지역 선택(d1b)  → 목적지 상세(d03) → 인기 스팟·이 지역에서 묵을 곳
  ├─ 장소 탐색(d04) ──담기──→ saved_place        → 담은 장소(d02)
  └─ 묵을 곳 ──→ [F-2 숙소 탐색]
                        ↓
        "담은 곳 N곳 · 여행 만들기"(d01/d02/d03/d04 하단 CTA)
                        ↓
        여행 생성 1/2(g01) — 담은 곳이 '꼭 갈 곳' 시드로 프리필
```

- 담기는 **로그인 필수**(계정 귀속, US-STAY-04 동형). 비로그인 진입 시 로그인으로 유도.
- 담은 장소는 여행 생성 시 `must_visit`(ANYTIME) 시드로 복사된다 — **복사 시점에 `poi_snapshot` 동결**(원본 POI가 폐업·변경돼도 여행 내용은 불변).

### F-2. 숙소 탐색 → 저장 → 외부 예약 (Case B · 숙소 우선)

```text
e00 지역 선택 ──→ e02 검색 결과(날짜 미정 허용) ──필터/정렬──→ e03 상세
                        │                                      ├─ ♥ 저장 → saved_stay
                        │                                      ├─ [외부에서 예약하기] → OTA 선택 시트 → 딥링크(C5)
                        │                                      └─ [일정에 추가] → 여행 선택 → base_assignment
                        └─ 부분 실패 시 "일부 숙소 정보를 불러오지 못했어요" + 가격 미확인 카드 유지
```

- **가격 2단 모델(DEC-11)**: 목록·카드·지역카드 = `최저가 스냅숏`(정적, 갱신 주기 명시). 상세 진입·딥링크 직전 = `라이브 정확가`(캐싱 금지).
- 복귀 핸드오프: 딥링크 이탈 후 앱 복귀 시 "방금 본 [숙소명], 예약하셨나요? → 거점 등록" 카드(무시 가능).

### F-3. 숙소 등록 3경로 → 거점 (앵커 확정)

```text
e05 숙소 등록
  ├─ 탭1 지도 검색 → 후보 다중 시 선택(multi-candidate) → 좌표 확정
  ├─ 탭2 링크 붙여넣기 → OTA URL 파싱 → 숙소명·좌표 추출(실패 시 탭1·3으로 폴백)
  └─ 탭3 핀 지정 → 지도에서 직접 핀
        ↓ 공통: 체크인/아웃 입력(수정 가능) → 좌표 미확정이면 등록 차단(conflict 변형)
        ↓
   saved_stay 생성 ──(여행에 배정)──→ base_assignment(date_from~date_to)
        ↓
   StayRegistered 이벤트 → 일정 생성 유도·알림(U6)
```

- 지도 API 실패 시 **침묵 실패 금지** — `error-mapapi` 변형대로 핀 지정 폴백 제시(ADR-0011).

### F-4. 여행 생성 2단계 위저드 (g01 → g02)

```text
g01 (1/2) 담은 곳으로 여행 만들기
   여행지(다중 도시 · 도시별 박수) · 꼭 갈 곳(담은 곳 시드, 개별 제거·더 담기)
   · 기간(프리셋 + 날짜 범위) · 인원 스테퍼 · 동반 유형 · 취향 프리필 표시
        ↓ [다음]
g02 (2/2) 거점 숙소
   구간별 거점 표시(1~2박 부산 / 3박 경주) · 숙소 후보에서 "거점으로 지정"
   · [이 거점으로 일정 만들기]  ·  [숙소 없이 시작하기]
        ↓
   Trip 생성 + base_assignment N개 + trip_base_day 확정 → TripCreated
```

- **숙소 0개 시작 허용**(US-TRIP-02 · "숙소 없이 시작하기") — 단 AI 일정 생성은 U3에서 별도 온램프(US-SCHED-11).
- **거점이 2개 이상이면 커버리지 해소가 선행**(DEC-8, 차단형) — 아래 F-5.

### F-5. 거점 커버리지 해소 (차단형 · DEC-8)

```text
입력: trip(start~end) · base_assignment[]
  각 날짜 d에 대해:
    후보 = { a ∈ base_assignment | a.date_from ≤ d < a.date_to }
    |후보| = 1 → trip_base_day(d, 그 숙소, resolution=auto)
    |후보| = 0 → 공백일  ─┐
    |후보| ≥ 2 → 겹침일  ─┴→ 미해결로 표시(차단)
출력: 미해결 날짜가 하나라도 있으면 → 일정 생성 진입 차단 + 해소 시트
       사용자 선택 → trip_base_day(d, 선택 숙소, resolution=user_pick)
```

- 해소 시트가 제시하는 선택지: 겹침일 = 후보 숙소 목록 / 공백일 = 직전 숙소 · 여행지 중심 · 숙소 지정.
- **자동 채움은 하지 않는다**(US-TRIP-06 원안의 비차단 스마트 기본값을 DEC-8이 대체 — 갭 G-U1-06).

### F-6. 여행 라이프사이클 (DEC-7)

```text
PLANNED ──(일정 확정: U3)──→ CONFIRMED ──(시작일 도래·여행중 진입: U4)──→ ACTIVE
   │                              │                                        │
   └──────────── soft delete(deleted_at) ────────────┘        수동 종료 ──→ ENDED → TripEnded
```

- U1이 소유: 상태 필드·전이 규칙·소프트 삭제·수동 종료 API·`TripCreated`/`TripEnded` 발행.
- U1이 소유하지 않음: 전이를 **유발하는** 사건(일정 확정=U3, 여행중 진입=U4) — 그 유닛이 U1의 facade를 호출한다.
