# U1 Accommodation & Trip Setup — Business Rules

> 규칙 ID `BR-U1-##`. **판정 정본은 항상 서버** — 클라이언트 검증은 UX용 사본(차단 아님)이며 `frontend-components.md`에 대응 표기.
> 근거 표기: `Q#`·`CQ#` = 계획/명확화 답변, `US-*` = 인셉션 스토리, `INV-U1-*` = `domain-entities.md` 불변식, `D-*`/`G-U1-*` = Figma 드리프트·갭.

## 장소·탐색 (BR-U1-01~09) — C7 · 밴드 d

| ID | 규칙 | 근거 |
|---|---|---|
| BR-U1-01 | 후보풀에는 수집 게이트를 통과한 `dataStatus=ACTIVE` POI만 들어간다. 외부·웹 출처는 `UNVERIFIED`로 먼저 등록되며 게이트 통과 전 추천·후보 노출 금지 | INV-1 · CQ3=B |
| BR-U1-02 | 좌표 없는 POI는 저장·담기·필수 방문지 지정 대상이 될 수 없다 | INV-U1-02 |
| BR-U1-03 | 담기(♥)는 로그인 사용자만. 담은 장소는 계정에 귀속되어 기기를 바꿔도 유지된다 | US-STAY-04 동형 |
| BR-U1-04 | 담기는 토글이다. 해제 시 즉시 목록에서 빠지며, 이미 여행에 시드된 필수 방문지는 **영향받지 않는다**(복사본이므로) | INV-U1-04 |
| BR-U1-05 | 탐색 랜딩은 여행지·묵을 곳·가볼 곳·여행자 일정 4구획으로 구성한다. **여행자 일정 구획은 1차에서 자리만 두고 실데이터를 채우지 않는다** | Q13=A · D-9 |
| BR-U1-06 | 장소 목록의 "N 저장"·"지금 급상승"은 `savedPlace` 집계에서 파생한다. 집계 실패 시 배지를 생략할 뿐 카드를 숨기지 않는다 | ADR-0011 |
| BR-U1-07 | 지역(여행지) 선택 화면은 목적이 둘(여행지 선택 · 숙소 지역 선택)이며 **같은 컴포넌트가 목적 파라미터로 분기**한다. 카피와 다음 목적지만 다르다 | G-U1-13 |
| BR-U1-08 | 목적지 상세는 인기 스팟·"이 지역에서 묵을 곳" 진입·여행 만들기 CTA를 갖는다. 인기 스팟은 담기 가능하다 | d03 |
| BR-U1-09 | 담은 곳이 1개 이상이면 탐색 계열 모든 화면 하단에 "담은 곳 N곳 · 여행 만들기" CTA를 노출한다. 0개면 CTA 대신 안내 + 검색 진입 | d01·d02·d04 · US-SHELL-05 |

## 숙소 탐색·가격 (BR-U1-10~18) — C3 · 밴드 e

| ID | 규칙 | 근거 |
|---|---|---|
| BR-U1-10 | 숙소 탐색은 **날짜·인원 없이** 가능하다. 날짜 미지정 상태를 "날짜 미정"으로 명시 표기한다 | US-STAY-01 · D-13 |
| BR-U1-11 | 위치 권한이 거부된 상태에서 '내 주변'을 시도하면 등록 숙소 또는 여행지 중심 좌표로 대체 조회한다 | US-STAY-01 예외 |
| BR-U1-12 | **목록·카드·지역 카드에 노출되는 금액은 최저가 스냅숏("부터 가격")뿐이다.** 정확 1박가는 저장하지 않고 상세·딥링크 시점에만 조회한다 | Q11=A · INV-U1-05 |
| BR-U1-13 | 정확 1박가는 **캐싱 금지**. 조회 결과는 표시 후 폐기하며 어떤 저장소에도 남기지 않는다 | ADR-0012 |
| BR-U1-14 | 스냅숏이 없으면 금액 자리에 "가격 미확인"을 표기한다. 가격 부재는 카드 제외 사유가 아니다 | INV-U1-06 · US-STAY-11 |
| BR-U1-15 | 정렬은 **최저가순**을 제공한다(정확 가격 전수 호출을 전제하는 '실시간 가격순'은 미제공) | Q11=A · G-U1-01 |
| BR-U1-16 | 필터가 결과를 0건으로 만들면 **어떤 필터가 0을 만들었는지 표기**하고 완화를 제안한다 | US-STAY-02 예외 · e02 filter-zero |
| BR-U1-17 | 일부 공급자 실패 시 "일부 숙소 정보를 불러오지 못했어요" + 재시도와 함께 **가용 결과를 즉시 노출**한다. 전부 실패면 "지금 숙소 정보를 불러올 수 없어요" + 재시도 + 수동 등록 우회 | US-STAY-11 · e02 partial-failure |
| BR-U1-18 | 숙소 상세는 정적 콘텐츠 위주로 표시하고 **리뷰·평점은 앱 내부에 두지 않는다**(외부 OTA 위임). 누락 항목은 빈칸이 아니라 "미확인" | US-STAY-03 |

## 저장·등록·거점 (BR-U1-19~28) — C4

| ID | 규칙 | 근거 |
|---|---|---|
| BR-U1-19 | 저장(♥)과 거점은 **다른 개념**이다. 저장은 계정 귀속 목록(`SavedStay`), 거점은 여행×숙소×날짜구간 관계(`BaseAssignment`)다 | CQ1=A · INV-U1-07 |
| BR-U1-20 | 저장 목록 화면의 `거점` 배지는 저장된 필드가 아니라 **현재 여행의 배정에서 파생**한다 | INV-U1-07 · e04 |
| BR-U1-21 | 숙소 등록 경로는 **3가지** — 지도 검색 · 링크 붙여넣기 · 핀 지정. 예약번호·메일 자동 인식은 두지 않는다 | Q6=A · FR-STAY-03(개정 대상 G-U1-02) |
| BR-U1-22 | 좌표가 확정되지 않으면 등록 버튼을 비활성화하고 "지도에서 위치를 확인해 주세요"를 표시한다 | INV-U1-08 · e05 conflict |
| BR-U1-23 | 지도·장소 검색 API가 실패하면 **침묵 실패 없이** 핀 직접 지정 흐름으로 폴백한다 | ADR-0011 · e05 error-mapapi |
| BR-U1-24 | 링크 붙여넣기 파싱에 실패하면 원문을 유지한 채 지도 검색·핀 지정 탭으로 유도한다(입력 소실 금지) | Q6=A |
| BR-U1-25 | 숙소 상세의 `[일정에 추가]`는 **여행 선택 → 해당 여행에 거점 배정**으로 정의한다. 여행이 없으면 여행 생성으로 보낸다 | G-U1-12 |
| BR-U1-26 | 체크아웃은 체크인보다 뒤여야 한다. 날짜 없이 저장은 가능하되 **거점 배정은 불가** | INV-U1-09 |
| BR-U1-27 | 체크인/아웃이 여행 기간을 벗어나면 경고하고 **여행 기간 자동 확장 여부를 묻는다**(임의 확장 금지) | US-TRIP-03 예외 |
| BR-U1-28 | 다박 숙소는 하나의 배정으로 등록하고 "N박 체류"로 묶어 표시한다 | US-TRIP-07 |

## 제휴 링크 (BR-U1-29~32) — C5

| ID | 규칙 | 근거 |
|---|---|---|
| BR-U1-29 | 예약·결제는 전량 외부 OTA로 위임한다. **앱은 예약·결제·재고를 갖지 않는다** | FR-STAY-02 |
| BR-U1-30 | 딥링크 이동 전 제휴 고지를 노출한다 — "예약·결제는 외부 OTA에서 진행되며, TripPilot은 제휴(어필리에이트) 수수료를 받을 수 있어요" | US-STAY-05 · D-4 |
| BR-U1-31 | 복수 OTA면 **OTA명과 표시 가격으로 선택**하게 한다. 링크가 깨졌거나 응답이 없으면 다른 OTA·장소 검색 우회를 제시한다 | US-STAY-05 · e03 affiliate-sheet |
| BR-U1-32 | 전환·수수료 지표는 내부 운영용으로만 저장하고 **사용자 대면 응답에 포함하지 않는다.** 포스트백은 멱등 처리한다 | INV-U1-10 · ADR-0003 |

## 여행 생성 (BR-U1-33~42) — C6 · 밴드 g

| ID | 규칙 | 근거 |
|---|---|---|
| BR-U1-33 | 여행 생성은 **2단계 위저드**다 — (1/2) 여행지·꼭 갈 곳·기간·인원·동반 (2/2) 거점 숙소 | g01·g02 |
| BR-U1-34 | 여행지는 **다중 도시**를 허용하며 도시별 박수를 갖는다. 도시별 박수 합은 여행 기간을 넘을 수 없다 | G-U1-08 · INV-U1-14 |
| BR-U1-35 | 목적지가 하나라도 대한민국 밖이면 여행을 생성하지 않고 "지금은 국내 여행만 지원해요"로 차단한다 | Q9=A · INV-U1-12 |
| BR-U1-36 | 종료일이 시작일보다 빠르면 생성을 막는다. 기간 프리셋(이번 주말·다음 주말·1박2일·3박4일) 선택 시 날짜를 자동 채우되 **직접 수정 가능**하다 | US-TRIP-01 · g01 |
| BR-U1-37 | 담은 장소가 있으면 '꼭 갈 곳'에 자동 시드하고 개별 제거·추가를 허용한다. 시드는 **복사**이며 원본 담기 상태와 독립이다 | US-SHELL-05 · INV-U1-04 |
| BR-U1-38 | 취향은 온보딩 값을 프리필해 "당신 취향으로 맞췄어요"로 보이고, **여행 단위로 덮어쓸 수 있다**(계정 취향은 불변) | G-U1-11 · g01 |
| BR-U1-39 | 인원 기본값은 1, 동반 유형은 혼자·친구·연인·가족. 온보딩 `커플`은 `연인`으로 매핑한다 | G-U1-10 · g01 |
| BR-U1-40 | 숙소 미등록 상태로도 여행을 생성할 수 있다("숙소 없이 시작하기"). 이 경우 "숙소 미등록"으로 표시하고 동선 기준 숙소 추천 온램프를 안내한다 | US-TRIP-02 · g02 |
| BR-U1-41 | 등록 숙소가 있으면 '등록 숙소에서 날짜 가져오기'를 제공하고, 이미 입력된 기간과 충돌하면 **두 값을 나란히 보여주고 고르게 한다**(임의 덮어쓰기 금지) | US-TRIP-05 |
| BR-U1-42 | 여행 상태는 `PLANNED→CONFIRMED→ACTIVE→ENDED` 단방향이며, 삭제는 소프트 삭제(`deletedAt`)다. 종료·삭제 후 편집 불가 | Q7=A · INV-U1-13 |

## 거점 커버리지 (BR-U1-43~47) — 차단형

| ID | 규칙 | 근거 |
|---|---|---|
| BR-U1-43 | 날짜별 거점은 후보가 **정확히 1개일 때만 자동 확정**(`resolution=auto`)한다 | DEC-8 |
| BR-U1-44 | 겹침일(후보 ≥ 2)과 공백일(후보 0)은 **미해결**로 표시하고, 해결 전에는 AI 일정 생성 진입을 차단한다 | Q8=B · CQ2=A · INV-U1-16 |
| BR-U1-45 | 해소 시트의 선택지 — 겹침일: 후보 숙소 목록 / 공백일: 직전 숙소 · 여행지 중심 · 숙소 지정. 선택 결과는 `resolution=user_pick`으로 기록한다 | CQ2=A |
| BR-U1-46 | 전 날짜 확정 시 `TripBaseResolved`를 발행해 일정 생성 게이트를 연다 | DEC-8 |
| BR-U1-47 | 등록 숙소가 0개인 여행은 커버리지 차단 대상이 **아니다**(BR-U1-40과 구분) — 차단은 거점이 있는데 날짜 귀속이 모호할 때만 적용한다 | US-TRIP-02 |

## 필수 방문지 (BR-U1-48~51)

| ID | 규칙 | 근거 |
|---|---|---|
| BR-U1-48 | 기본은 '아무 때나 꼭 가기'(`ANYTIME`)이며, '시간 정해두기' 토글로 `FIXED`(날짜·시각 고정)로 바꿀 수 있다 | US-TRIP-08 |
| BR-U1-49 | `FIXED`는 날짜·시각이 필수이고 날짜는 여행 기간 안이어야 한다 | INV-U1-17 |
| BR-U1-50 | 같은 여행에 동일 장소를 중복 추가할 수 없다. 좌표를 확인할 수 없으면 지도에서 직접 지정하도록 요청한다 | INV-U1-18 · US-TRIP-08 예외 |
| BR-U1-51 | 필수 방문지는 생성·재생성 후에도 누락되지 않는다. **U1은 입력 보존만 책임지며 배치 실현가능성 판정은 U2·U3가 소유한다** | US-TRIP-09 · INV-2 |
