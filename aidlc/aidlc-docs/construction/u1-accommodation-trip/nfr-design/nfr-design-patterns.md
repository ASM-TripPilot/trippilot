# U1 Accommodation & Trip Setup — NFR Design Patterns

> 입력: `u1-accommodation-trip/nfr-requirements/` 2종. 답변 확정 2026-07-23 — Q1~Q6 **전항 추천 채택**.
> U0 패턴(P-RES/SCALE/PERF/SEC/DEP/OBS 24종) 위에 U1 델타만 추가. 명명 `P-{영역}-U1-#`.
> ⚠ **기준선 변경**: U0 "분산 캐시 미도입"을 U1이 뒤집어 **Redis 도입**(§3). 그 외는 U0 결정 계승.

## 1. 복원력 패턴 (RES-U1-01~05 · Q1)

### P-RES-U1-1 — 다벤더 서킷 브레이커 격리
U0 P-RES-2(IdP별 서킷)의 확장. **외부 포트마다 + 벤더마다 서킷 인스턴스 분리** — 콘텐츠·라이브가·딥링크·장소검색·지도, 그리고 OTA 벤더별.
- 임계: 슬라이딩 윈도우 **실패율 50%(최소 20호출)** → open · **30초 후 half-open** 소수 시험 → 성공 시 close.
- **한 OTA·한 지도 벤더 장애가 다른 경로를 막지 않는다**(벌크헤드). BR-U1-31의 "다른 OTA 우회"가 이 격리 위에서 성립.

### P-RES-U1-2 — 재시도 없음 + 부분 결과 우선
RES-U1-02 확정분. 조회 실패는 **즉시 부분 결과로 전환**(재시도 안 함). 지연보다 응답성 우선(Q3=B의 근거).
- 안전망은 **UX-U1-01의 부분 실패 배너 + 수동 재시도 버튼** 하나뿐 — 필수 구현. 자동 재시도가 없으므로 순간 흔들림이 곧 표면화된다(NFR §RES 주의 계승).
- 비대화형(스냅숏 배치)은 예외적으로 백오프 재시도 허용(사용자 지연과 무관).

### P-RES-U1-3 — stale-if-error
서킷 open·조회 실패 시 **마지막 스냅숏·캐시 값을 노출**하되 "가격 미확인/이전 정보"로 표기(RES-U1-04). 검증·표시를 중단시키지 않는다. U0 P-RES-3의 가격 도메인판.

### P-RES-U1-4 — 침묵 실패 금지 폴백 사슬
- 지도 렌더 실패 → 핀 지정 폴백(BR-U1-23) · 장소 검색 실패 → 주소 직접 입력 · '내 주변' 거부 → 여행지 중심 좌표(BR-U1-11). 모든 폴백은 사용자 가시(ADR-0011).

## 2. 확장성 패턴 (SCALE-U1-01~03 · Q2)

### P-SCALE-U1-1 — 단일 프라이머리 유지 (읽기 복제본 미도입)
U0 P-SCALE-2 계승. POI 5만~10만·목록 조회 주 트래픽이지만 **읽기 복제본을 도입하지 않고** 인덱스 + Redis 캐시(§3)로 흡수. 과설계 회피 — 실측 병목 시 재평가(§6).

### P-SCALE-U1-2 — 인덱스·커서 페이지네이션·공간 인덱스
- 숙소·POI 목록: 지역·카테고리·좌표 **복합 인덱스** + **커서 페이지네이션**(오프셋 금지 — 대량 목록 안정).
- 근접('내 주변'·거리순): **PostGIS GiST 공간 인덱스**. 거리 산출은 좌표만 사용(INV-3 — 소요시간 없음).

### P-SCALE-U1-3 — 스파이크 흡수 계승
U0 오토스케일(min 2) + 429 저하 계승. U1 델타 없음(외부 쿼터 소진은 §4 COST로 별도 처리).

## 3. 성능·캐시 패턴 (PERF-U1-01~04 · Q3) ⚠️ 기준선 변경

### P-PERF-U1-1 — 응답 예산 2계층
- **자체 데이터 경로**(여행·거점·담은 장소·저장 숙소·홈 집계) p95 < 300ms.
- **외부 의존 경로**(숙소 검색·라이브가) p95 < 1.5s — 초과 시 스켈레톤 유지 + 부분 결과(끊지 않고 채움).

### P-PERF-U1-2 — Redis 조회 캐시 (도입 · U0 미도입 뒤집음)
| 캐시 대상 | TTL | 무효화 |
|---|---|---|
| 숙소 검색 결과 | 10분 | 스냅숏 배치 완료 시 관련 지역 키 |
| 지역 집계(숙소 수·최저가) | 1시간 | 스냅숏 배치 완료 |
| POI 검색 결과 | 10분 | POI `data_status` 변경 |
| 장소 검색어(디바운스 뒤) | 5분 | — (COST 겸용, PERF-U1-03) |

- **캐시하지 않는 것**: 최저가 스냅숏·POI 원본(= 캐시가 아니라 **PG 영속 테이블**) · **정확 1박가(DATA-U1-03 절대 금지)**.
- **캐시는 가속층일 뿐 정합성 원본이 아니다** — 캐시 미스·Redis 장애 시 PG 직읽기로 폴백. 정합성은 항상 PG.

### P-PERF-U1-3 — 입력 디바운스 + 순수 계산 클라 처리
지도·장소 검색 입력 디바운스 300ms. 커버리지 판정·박수 합 검증은 서버 왕복 없이 클라(프론트 PBT 대상).

## 4. 보안·비용 패턴 (SEC-U1-01~05 · COST-U1-01~03 · Q4)

### P-SEC-U1-1 — 객체 수준 인가 단일 관문
U0 P-SEC-5 계승. 여행·저장 숙소·담은 장소는 소유 계정만, 타 계정 접근은 404(존재 은닉). facade 진입에서 일괄 검사.

### P-SEC-U1-2 — 딥링크 무결성
- 아웃바운드에 **서버 생성 추적 ID**. 포스트백은 **제휴사별 공유 시크릿 HMAC-SHA256** 검증(키·검증 로직은 `OtaPartner` 설정 보유) + **타임스탬프 skew ±5분** 재전송 차단 + **거래 ID 멱등**.
- 검증 실패는 저장하지 않고 보안 이벤트로 기록. 전환·수수료 지표는 **응답 스키마 수준에서 사용자 노출 차단**(INV-U1-10).

### P-SEC-U1-3 — 입력 경계 방어
- 링크 붙여넣기 URL은 **허용 OTA 도메인 화이트리스트**(외부화)로만 파싱, 그 외 거부(SSRF 방지). 실패 시 원문 유지 + 타 탭 유도(BR-U1-24).
- 지도·검색 API 키는 **서버 프록시 엔드포인트 뒤에만** 존재(클라 원 키 노출 금지).

### P-COST-U1-1 — 쿼터는 상한 대신 관측
COST-U1-01(Q5=B). 지도·검색 쿼터에 하드 상한을 두지 않고 **소진율을 지표화**(OBS-U1-02)해 추이 경보. 상한 부재의 유일한 방어가 관측이므로 경보 가능 수준 필수. 검색어 5분 캐시로 소모 억제. 실연동·정식 출시 전 재평가(§6).

## 5. 데이터 신선도·관측 패턴 (DATA·OBS)

### P-DATA-U1-1 — 배치 스냅숏 + 신선도 게이트
최저가 스냅숏 **일 1회 배치**(ShedLock 단일 실행). 조회 시 **48시간 초과면 금액 숨김**("가격 미확인") — 신선도 판정은 조회 시점 `capturedAt` 비교(별도 배치 아님).

### P-OBS-U1-1 — U1 관측 델타
U0 OBS 자산(구조화 JSON·상관 ID·Sentry) 계승 + U1 지표: **포트별 지연·실패율·서킷 상태**(P-RES-U1-1) · **쿼터 소진율**(P-COST-U1-1) · **스냅숏 최신성**(가장 오래된 스냅숏 나이) · **포스트백 서명 실패·전환 이벤트**(보안/정산 분리).

## 7. 미도입 결정·재평가 트리거 (과설계 회피)

| 항목 | 현재 | 재평가 조건 |
|---|---|---|
| 읽기 복제본 | 미도입(단일 프라이머리) | 목록·검색 읽기 부하 실측 병목 시 |
| 조회 재시도 | 없음(P-RES-U1-2) | 부분 실패율이 사용성 해칠 만큼 높으면 멱등 조회 1회 복원 |
| 지도 쿼터 하드 상한 | 없음(관측만) | 실연동·정식 출시 전, 또는 소진율 경보 반복 시 |
| Redis(도입, 역방향) | U1 조회 캐시 신규 | 실측 캐시 적중률 낮으면 인메모리로 축소 |
| 블루/그린·카나리 | 미도입(롤링 계승) | U0와 동일 — 규모 확대 시 |
