# U8 Conversational Assistant — Business Rules

> **상속(재서술 금지)**: ai `assistant-dialogue` FD의 **BR-DLG-\***(인자 추출·되묻기 상한·보류 프레임·closed-set)은 ai 쪽 규칙이고 여기서 다시 적지 않는다 — 아래는 **backend·앱이 지는 규칙**이다. 편집 재검증·확정 잠금(BR-U3-\*), 재계획 확정(BR-U4-\*), 회고(BR-U5-\*)도 각 유닛 소유다.
> 불변식 INV-1~4(루트 `CLAUDE.md`)는 전 규칙의 전제다.

---

## 1. 호출·컨텍스트 (US-ASSIST-01)

| ID | 규칙 |
|---|---|
| **BR-U8-01** | 도우미는 **현재 화면을 떠나지 않고** 그 위에 시트로 열린다. 시트가 열린 동안 **하단 탭바는 보이지 않는다**(루트 스택 투명 모달 — DEC-U8-13, 앱 셸 스토리 4) |
| **BR-U8-02** | 열 때 앱이 보내는 문맥은 **`surface` enum과 `tripId`뿐**이다. 나머지 컨텍스트(여행·숙소·일정)는 서버가 권한 확인 후 직접 조회한다 — 클라가 보낸 일정 내용을 AI 입력으로 쓰지 않는다 |
| **BR-U8-03** | 시트 상단에 **사용한 컨텍스트를 칩으로 표기**한다(`부산 2박 3일 · 등록 숙소 서면` — `b01`). 칩 문구는 서버가 스냅샷과 **같은 원천**으로 만든다 — 칩과 실제 AI 입력이 다를 수 없다 |
| **BR-U8-04** | 시작 시 **예시 quick reply**를 보이고, `내가 할 수 있는 것 보기`를 **상시** 노출한다(PRD 02-1) |
| **BR-U8-05** | 여행이 없는 상태로 열면 **비활성화하지 않고** 일반 도움 모드(`b07`)로 연다 — 일정·동선 요청에는 "먼저 여행을 만들거나 숙소를 등록하면…" + `CREATE_TRIP`·`OPEN_STAY_SEARCH` |
| **BR-U8-06** | **모든 도우미 응답은 다음 행동을 1개 이상 동봉한다**(INV-U8-03). 앱이 모르는 `next_action.type`은 그리지 않고 `SHOW_CAPABILITIES`로 대체한다 — 빈 버튼 줄로 끝나지 않는다 |
| **BR-U8-07** | 도우미를 여는 것 자체가 실패하면(세션 생성 실패) 오류와 [다시 시도]를 보이고 **현재 화면은 그대로 쓸 수 있다**(PRD 02-1 예외) |
| **BR-U8-08** | **비로그인 갈래는 N/A** — 앱에 비로그인 상태로 도우미에 닿는 경로가 없다(Q14, 부트스트랩 `GUEST → LOGIN`). 대화 API는 전부 인증 필수 |

## 2. 재질의·검토 (US-ASSIST-02·03)

| ID | 규칙 |
|---|---|
| **BR-U8-10** | 재질의는 **보류 프레임으로 이어진다**(ai FD). backend는 `dialogue_context`를 매 턴 저장·반송할 뿐 판정하지 않는다(INV-U8-07) |
| **BR-U8-11** | 인자 되묻기는 **한 요청에 1회**다(BR-DLG-23·33 승계). 앱은 `CLARIFY` 메시지의 보기를 quick reply로 그리고, 보기가 없으면 자유 입력을 기다린다 |
| **BR-U8-12** | 대체 후보·제안에 나오는 장소는 **후보 풀(closed-set)에서 온 실재 장소뿐**이다(INV-1). 도우미가 장소 이름을 지어 말하지 않는다 — 문구는 템플릿, 장소는 기존 후보 경로의 값(DEC-U8-6) |
| **BR-U8-13** | 넘기기 응답(재계획·재생성·숙소)에는 **바꾼 조건을 칩으로 요약**한다. 목적 화면 입력값 프리필은 1차 밖(G-U8-7) — 프리필된 것처럼 말하지 않는다("이 조건으로 다시 짜 보세요"는 되고 "이 조건으로 맞춰 뒀어요"는 안 된다) |
| **BR-U8-14** | 진행 검토가 지적하는 **문제는 솔버가 이미 표기한 위반(`hasViolation`·`violationReason`)과 구조적 사실(숙소 미등록·빈 일자·일정 없음)뿐**이다. 도우미가 "빠듯해 보여요"를 스스로 판정하지 않는다(PRD 02-3) |
| **BR-U8-15** | 검토 카드의 모든 시각·거리는 **저장된 일정 값 그대로**다. 소요시간을 계산하거나 표시하지 않는다(INV-2·3). `b01 review`의 "이동 1.8km이라 빠듯해요"는 **위반 사유 문구가 그 거리를 담을 때만** 그린다 |
| **BR-U8-16** | 검토할 일정이 없으면 "아직 검토할 일정이 없어요" + 여행 만들기/숙소 등록. 원천 조회가 일부 실패하면 **추측하지 않고** "일부 정보를 확인할 수 없어요" + 가용 범위만 |

## 3. 이력·세션 (US-ASSIST-05)

| ID | 규칙 |
|---|---|
| **BR-U8-17** | 세션은 **(계정, 여행)마다 하나**, 여행 없는 일반 세션은 계정당 하나다(INV-U8-01). 같은 여행에서 다시 열면 **직전 대화를 이어서** 보인다 |
| **BR-U8-18** | 다른 여행 화면에서 열면 **그 여행 세션**으로 연다 — 이전 여행 맥락을 끌고 오지 않는다. 이전 대화는 `b06` 목록에서 다시 열 수 있다 |
| **BR-U8-19** | 도우미가 일으킨 실제 변경은 **`ACTION_LOG` 메시지로 남고**, 일정 쪽 추적은 **기존 축**을 따른다 — 여행 중이면 `change_log`(`source = ASSISTANT`), 여행 전이면 리비전(h36, reason 접두 `[도우미]`). **대화 자체를 일정 확정 데이터로 쓰지 않는다**(PRD 02-5) |
| **BR-U8-20** | 사용자는 세션 이력을 **지울 수 있다**(`b06 이력 지우기`). 지워도 이미 적용된 일정 변경·change log·리비전은 남는다 — 이력은 보조 기록이다 |
| **BR-U8-21** | 대화 저장 실패는 침묵하지 않는다. 앱은 "임시 보관" 표시 후 같은 `clientTurnId`로 재전송하고, 서버는 멱등으로 처리한다(INV-U8-05) |

## 4. 가드레일 (US-ASSIST-06·07)

| ID | 규칙 |
|---|---|
| **BR-U8-22** ★ | **컨텍스트 스냅샷은 화이트리스트다**(business-logic-model §5). 다른 계정 데이터는 조회 단계에서 null이고(소유 확인 퍼사드), 제휴 수수료·내부 지표·후보 점수는 싣는 코드가 없다. **이 비노출을 프롬프트 지시에 기대지 않는다**(PRD 02-6) |
| **BR-U8-23** | 입력은 AI 호출 **전에** `TextModerationFacade.inspect`로 검사한다. 위반이면 AI를 부르지 않고 거절하며 **원문을 저장하지 않는다**(`redacted`). 사전이 없어 검사가 예외면 **통과시키지 않고** FALLBACK(fail-closed) |
| **BR-U8-24** | **계정당 분당 20턴**(사용자 턴 기준, 최근 60초). 초과면 429 + `Retry-After`, 턴을 기록하지 않는다. ACTION 턴도 센다(LLM은 0회지만 남용 경로다) |
| **BR-U8-25** | 거절(금칙어·범위 밖)이 **연속 2회**면 같은 거절을 되풀이하지 않고 **사용 안내**로 전환한다(PRD 02-6·7 예외). 정상 턴이 오면 카운터를 0으로 |
| **BR-U8-26** | 도우미가 화면에 내는 문장은 **템플릿**이다(DEC-U8-6). LLM 자유 생성 문장을 그대로 내지 않는다 — 예외는 기존 검증 경로의 산출(편집 위반 사유·`/explanations` 설명)뿐 |
| **BR-U8-27** | 예약·결제 요청은 처리하지 않고 **외부 OTA로 위임**한다 — "예약·결제는 외부 사이트에서 진행돼요" + `OPEN_OTA`(숙소 문맥이 있을 때) 또는 `OPEN_STAY_SEARCH` |
| **BR-U8-28** | "이 시간에 갈 수 있어?"류는 **솔버 검증 결과로만** 답한다 — 저장된 일정의 위반 표기 또는 편집 제안 경로로 연결. 도우미가 가능/불가를 단정하지 않는다 |
| **BR-U8-29** | 턴바이턴 길찾기·실시간 가격 보증을 약속하지 않는다 — 길찾기는 외부 지도앱, 가격은 외부 OTA로 보낸다 |

## 5. 액션 위임 (US-ASSIST-04)

| ID | 규칙 |
|---|---|
| **BR-U8-30** ★ | **도우미 경로의 변경은 전부 제안이다.** ai `apply_mode = AUTO_APPLY`여도 저장하지 않는다. 사용자가 비교 카드의 **[적용]**을 눌러야만 저장한다(DEC-U8-2) |
| **BR-U8-31** | **위반이 있는 제안에는 [적용]을 주지 않는다.** 위반 사유를 보이고 대안(다른 시간대·다른 날·이 장소 빼기 — US-SCHED-04 예외)을 quick reply로 준다 |
| **BR-U8-32** | 적용은 **기준 지문이 일치할 때만** 일어난다(INV-U8-04). 불일치면 `STALE` 409 — "일정이 바뀌어 다시 제안할게요" |
| **BR-U8-33** | 적용은 **기존 편집 경로**(`ItineraryEditFacade` → `EditItineraryService`)로만 저장한다. 어시스턴트 모듈이 일정 테이블을 직접 쓰지 않는다 — 재검증·확정 잠금(여행 시작 전 CONFIRMED 409)·리비전·거절 기록이 그대로 걸린다 |
| **BR-U8-34** | 적용 후 재검증이 제안 때와 다르게 위반을 판정하면, **저장된 값이 이긴다**(PRD 02-8 예외). 그 사실을 알리고 `RESTORE_REVISION` 되돌리기를 준다 — 조용히 넘어가지 않는다 |
| **BR-U8-35** | 비교 카드의 시각·거리는 **ai 조립이 검증해 돌려준 값**만 그린다. 이동은 **거리만**(`이동 630m`), 소요시간은 없다(INV-2·3, `b02`) |

## 6. 폴백 (US-ASSIST-08)

| ID | 규칙 |
|---|---|
| **BR-U8-40** | 해석·디스패치 실패는 **반드시 `FALLBACK` 메시지 1건**으로 끝난다 — 빈 응답·무응답 금지(INV-4) |
| **BR-U8-41** | 모든 FALLBACK에는 **"도우미 없이 계속"**(현재 화면의 기존 동작)이 있다 — 핵심 흐름은 도우미 없이 완결된다 |
| **BR-U8-42** | 솔버 비가용이면 **시각·실현가능성을 추측해 채우지 않는다** — "지금은 시간·동선 검증을 할 수 없어요" + 직접 편집 / 결정론 재시도(`b05 solver-unavailable`) |
| **BR-U8-43** | 의도가 안 갈리면(OUT_OF_SCOPE가 아닌 FALLBACK) **임의로 실행하지 않는다** — "내가 할 수 있는 것" + 후보 행동 quick reply(DEC-U8-11) |
| **BR-U8-44** | 한 턴은 **15s 상한**이다. 앱은 진행 표시를 유지하고 [대기 취소]를 준다. 취소는 클라 중단이며, 서버가 끝낸 결과는 다음 조회에서 보인다(제안이라 저장되지 않으므로 안전 — DEC-U8-7) |
| **BR-U8-45** | ai `/interpret` 실패를 **일정 폴백 신호로 쓰지 않는다** — 도우미 실패가 일정 데이터를 바꾸는 경로는 없다 |

## 7. 진입점 ✦ FAB (Q12=B)

| ID | 규칙 |
|---|---|
| **BR-U8-50** | ✦ FAB는 **1차 진입 화면 4곳**(홈 · 숙소 검색 e02 · 일정 상세 `itinerary-plan` · 여행 중 허브 `live`)의 우하단에 **기존 FAB 스택 맨 위**로 쌓는다. 규격은 기존 FAB와 같다(56×56, `right-lg`, 스택 간격 12) |
| **BR-U8-51** | **탭바와 겹치지 않는다.** 탭 화면은 기존 스택 기준(1단 바닥 84 · 2단 152)을 따라 ✦는 **바닥 220**(2단 스택 위) — 1단만 있는 화면은 152. 탭 밖 화면(`itinerary-plan`·`live`)은 그 화면의 FAB 앵커를 따른다(`live`는 시트를 따라 움직이는 `execution-live-fab-anchor` 열의 맨 위) |
| **BR-U8-52** ★ | **토스트와 겹치지 않는다.** ✦가 있는 화면에서 토스트 바닥은 **✦ 윗변 + 12**(2단 스택 화면 = 288)로 올린다(G-U8-10). 토스트를 ✦ 뒤로 숨기거나 ✦를 토스트 동안 숨기는 방식은 쓰지 않는다 — 둘 다 터치 가능한 상태를 유지한다 |
| **BR-U8-53** | 시트·키보드·다른 바텀시트가 열린 동안에는 ✦를 그리지 않는다(기존 FAB의 `fabHidden`·키보드 규칙과 같다 — 보이지 않는 FAB가 터치를 가로채지 않게) |

## PBT (property-based · 블로킹 게이트)

| ID | 성질 | 층 |
|---|---|---|
| **PBT-U8-1** ★ | **단독 확정 없음** — 임의의 턴 열(발화·액션·ai 응답 `AUTO_APPLY`/`CONFIRM_REQUIRED` 조합)에 대해, `apply` 호출이 없는 한 일정 저장 퍼사드 호출 수는 **0**이다 | backend(Kotest property) |
| **PBT-U8-2** | **dead-end 없음** — 임의의 디스패치 결과(성공·각 폴백 원인·거절·범위 밖)에 대해 생성된 도우미 메시지의 `next_actions` 길이 ≥ 1이고, 모든 `type`이 closed-set 안이다 | backend |
| **PBT-U8-3** ★ | **권한 경계** — 임의의 두 계정 A·B와 임의의 여행 데이터에 대해, A의 턴에서 만든 컨텍스트 스냅샷 직렬형에 **B 소유 여행·슬롯 id·이름이 나타나지 않는다**. 그리고 스냅샷 키 집합 ⊆ 화이트리스트 | backend |
| **PBT-U8-4** | **리미터 창** — 임의의 턴 시각 열에 대해, 어느 60초 창에서도 수락된 사용자 턴 ≤ 20이고, 거절된 턴은 기록되지 않는다 | backend |
| **PBT-U8-5** | **멱등** — 같은 `(sessionId, clientTurnId)`를 N번 보내도 사용자 메시지·도우미 메시지는 각각 1건이고 응답이 같다 | backend |
| **PBT-U8-6** | **제안 상태기계** — 임의의 이벤트 열(적용·취소·만료·지문 변경)에 대해 `APPLIED`는 많아야 1회, 종결 상태에서 나가는 전이 없음, 지문 불일치 시 저장 호출 0 | backend |
| **PBT-U8-7** | **`DialogueContext` 왕복** — 임의의 ai 직렬형을 저장 → 조회 → 반송하면 `turn_index` 외 바이트 동일(INV-U8-07) | backend |
| **PBT-U8-8** | **INV-3** — 임의의 카드 페이로드·템플릿 문구·제안 diff에 소요시간 필드·문자열(`분 소요`·`duration`)이 없다 | backend · FE(fast-check, 카드 렌더 모델) |
| **PBT-U8-9** | **closed-set 디스패치** — 임의의 `Intent` 값(13종 + `OUT_OF_SCOPE`)에 대해 디스패치 표가 정확히 한 처리기를 고르고, 표 밖 값은 생성 불가(역직렬화 거부) | backend |
| **PBT-U8-F1** | **FAB 겹침** — 임의의 스택 구성(1~2단)·화면 종류에 대해 계산된 ✦ 바닥 ≥ 기존 스택 윗변 + 12, 토스트 바닥 ≥ ✦ 윗변 + 12 (배치 계산 순수 함수) | FE |

ai 쪽 DLG-P1~P12(인자표·되묻기 상한·직렬화)는 ai 게이트이고 여기 다시 세지 않는다.

## 미결 (O-U8-\*)
