# U10 GPS·위치 자동화 — Business Rules

> 규칙 우선순위는 U2~U5와 같다: **실장 우선 → 양쪽 실장이 다르면 문서가 결정 → 불변식(INV-1~4)·위치 법정 로그 append-only·LEGAL-01은 개정 대상 아님.**
> U0·U4·U5·U6의 BR은 전부 승계한다. 아래는 **U10이 새로 정하거나 바꾸는 것만**이다. 바뀐 원 규칙은 원 문서에 `[개정 · 2026-10-12 · U10 FD]` 블록으로 표시했다(`business-logic-model.md` §15).
> 임계값(반경·정확도·체류·이탈 확인·리전 수)은 **설정으로 뺀 기본값**이다 — 값 조정은 규칙 개정이 아니다(O-U10-2).

---

## 1. 권한 사다리 · 무장 (DEC-U10-1·11·12·13)

| ID | 규칙 |
|---|---|
| **BR-U10-01** | U10이 꺼져 있어도 **어떤 기능도 막히지 않는다.** 기본 상태는 MANUAL(수동 [도착]·[방문 완료] + 단발 측위)이고, U10은 그 위에 얹히는 선택적 자동화다(INV-4 · MOBILE-U4-03) |
| **BR-U10-02** | 자동 기록(지오펜스 + 경로)은 **다섯 조건이 모두 참일 때만** 무장한다 — ① OS '항상 허용' ② 정확한 위치 ③ 앱 위치 토글 ON(L2·L3) ④ 여행 날짜 구간 안(여행지 기준 시간대) ⑤ 기능 플래그 ON. 이 판정은 **저장하지 않고** 앱 시작·포그라운드 복귀·백그라운드 깨어남마다 다시 계산한다 |
| **BR-U10-03** | OS 권한이 when-in-use뿐이면 **수동 체크인 사용자**다. when-in-use로 동작하는 포그라운드 자동 도착·포그라운드 경로 기록을 두지 않는다(Q1=B·Q3=B 문면) |
| **BR-U10-04** | 앱 위치 토글이 OFF인 사용자에게 '항상 허용' 설명·요청을 **띄우지 않는다** — 위치 동의를 끈 의사와 반대 방향의 요청이다 |
| **BR-U10-05** | 설명 화면은 **여행 날짜 구간 안 i01 허브 첫 진입**에서만 뜬다(온보딩·설정 진입에서 자동으로 띄우지 않는다). [나중에]를 누르면 **그 여행에서는 다시 묻지 않는다.** OS가 더 묻지 못하는 상태(거부 확정)면 설명 대신 l06의 "설정 열기"만 남긴다 |
| **BR-U10-06** | '항상 허용' 거절·대략 위치·미응답은 **오류가 아니라 정상 경로**다. 오류 화면·재시도 유도·반복 요청을 하지 않는다 |
| **BR-U10-07** | 기능 플래그는 **빌드 시점 값**이며 JS 동작과 **네이티브 권한 표면**(always 용도 문구 · iOS 백그라운드 위치 모드 · Android 백그라운드 위치·포그라운드 서비스 권한)을 **함께** 켠다. 플래그 OFF 빌드의 권한 표면은 TRIP-936 이후 출시 빌드와 같아야 한다 |
| **BR-U10-08** | 백그라운드 경로 기록 중 **iOS 상태바 위치 표시를 숨기지 않는다.** Android는 기록 중 포그라운드 서비스 알림을 띄운다(OS 요구). 둘 다 설명 화면에서 미리 고지한다 |

## 2. 지오펜스 리전 (DEC-U10-21 · O-U4-1 해소)

| ID | 규칙 |
|---|---|
| **BR-U10-09** | 등록 리전 = **진행 중 슬롯(도착 확정·미완료·미건너뜀) 전부 + 당일 남은 슬롯을 계획 순번대로**, 합계 **최대 10**. 진행 중 슬롯은 이탈 감지에 필요하므로 상한 때문에 빠지지 않는다 |
| **BR-U10-10** | 리전은 **도착 확정 · 완료 확정 · 건너뛰기 · 자동 기록 되돌리기 · 일정 변경(재계획 확정·수동 편집) · 날짜 전환**마다 다시 고른다. 그 외 주기 재등록을 하지 않는다(wake 예산) |
| **BR-U10-11** | 좌표가 없는 슬롯과 즉석 방문은 리전이 될 수 없다 — 그 슬롯은 수동 전용이다(DEC-U10-17) |

## 3. 도착·완료 판정 (기기 · DEC-U10-2·22)

| ID | 규칙 |
|---|---|
| **BR-U10-12** | 정확도가 **100m를 넘는 표본은 판정 근거로 쓰지 않는다.** 판정 창 안에 근거 표본이 없거나 OS 정확도 권한이 "대략"이면 그 슬롯의 자동 판정을 **보류**한다(기록 없음 — 수동 폴백). 보류는 사용자에게 오류로 보이지 않는다 |
| **BR-U10-13** | 리전 반경은 **150m**다(기본값). `geofence.ts`의 120m 자리값은 이 값으로 대체한다 |
| **BR-U10-14** | 도착은 **진입 후 3분 동안 이탈이 없을 때** 확정하고, 도착 시각은 **진입 시각으로 소급**한다. 확정은 다음 깨어남에서 해도 된다 — 시각은 이미 정해져 있다 |
| **BR-U10-15** | 진입 후 3분 안에 이탈하면 **아무것도 기록하지 않는다**(지나가기) |
| **BR-U10-16** | 이탈은 **이탈 후 3분 동안 재진입이 없을 때** 확정한다. 완료 시각은 **첫 이탈 시각**이다(확인 대기 시간을 더하지 않는다). 3분 안에 재진입하면 이탈을 취소한다 |
| **BR-U10-17** | 이탈 확정 시 `이탈 시각 − 도착 시각 ≥ 10분`이면 자동 완료(`AUTO_GEOFENCE_EXIT`), 미만이면 **자동 완료하지 않고** 도착만 남긴다(수동 [방문 완료]로 마무리) |
| **BR-U10-18** | **보조 규칙** — 다음 순번 슬롯의 자동 도착이 확정될 때 직전 순번 슬롯이 도착 후 10분 이상 지난 미완료 상태면, 직전 슬롯을 `completedAt = 다음 슬롯 진입 시각`, `AUTO_NEXT_ARRIVAL`로 완료한다. 하루 마지막 슬롯에는 적용되지 않는다 |
| **BR-U10-19** | 겹치는 리전에서 같은 판정 창에 진입이 둘 이상이면 **중심이 가장 가까운 하나만** 도착 후보로 올린다. 서버도 `(trip_id, slot_key)` 유니크로 하나만 확정한다 |

## 4. 결과 전송 (DEC-U10-8·16)

| ID | 규칙 |
|---|---|
| **BR-U10-20** | 자동 결과는 **배치 엔드포인트 1요청/깨어남**으로 보낸다. 각 항목은 클라 `eventId`로 멱등이고, 서버에 이미 그 슬롯의 기록이 있으면 **서버 값이 이긴다**(항목은 `ALREADY_RECORDED`/`CONFLICT`로 끝나고 기기는 버린다). 배치 하나의 실패 항목이 다른 항목을 막지 않는다 |
| **BR-U10-21** | 서버는 `occurredAt`을 받아들이되 **여행 날짜 구간 밖 · 슬롯 날짜와 다른 날 · 서버 시각 + 5분보다 미래 · 도착보다 앞선 완료**면 그 항목을 `OUT_OF_WINDOW`로 거절한다 |
| **BR-U10-22** | 보내지 못한 자동 결과는 **여행지 기준 당일까지만** 기기에 둔다. 날짜가 바뀌면 버리고, 버린 건수를 i01(또는 j01)에 **1줄로 알린다**(침묵 실패 금지). 사용자 입력 오프라인 기록은 여전히 만들지 않는다(2026-09-11 보류 유지) |

## 5. `DELAY` 파생 (서버 · DEC-U10-9)

| ID | 규칙 |
|---|---|
| **BR-U10-23** | `DELAY`는 **방문 체크 시각·출처와 계획 시각만으로** 서버가 만든다. 좌표·현재 위치를 판정 입력으로 받지 않는다 |
| **BR-U10-24** | `completion_source = AUTO_NEXT_ARRIVAL`인 완료는 체류가 이동 시간을 포함하므로 **체류 초과 판정 입력에서 제외**한다. 이 출처의 체류를 어떤 화면에도 표시하지 않는다(INV-U4-03 승계) |
| **BR-U10-25** | **체류 초과(완료 시점)**: 완료 시각이 계획 종료 + `T_over`를 넘고 **다음 시각 고정 슬롯이 위협될 때만** 신호를 만든다. 다음 고정 슬롯이 없으면 만들지 않는다(US-PLANB-02 (d) 문면) |
| **BR-U10-26** | **진행 중 체류 초과**와 **이동 지연**은 **자동 기록이 무장된 여행에서만** 판정한다. 이동 지연은 추가로 **직전 슬롯이 자동 출처로 완료**됐을 때만 판정한다 — "도착 기록 없음"을 지연으로 읽는 판정이라, 수동 사용자에게 켜면 허위 알림이 된다 |
| **BR-U10-27** | 트리거 종류는 늘리지 않는다 — 두 신호 모두 `DELAY`이고 `payload.variant`(`OVERSTAY`·`TRANSIT`)로 가른다(BR-U4-01). 억제·민감도·빈도 상한·무발화 기록은 기존 `TriggerService` 그대로 적용한다 |
| **BR-U10-28** | 지연은 **배너·푸시 문구로만** 알린다. 슬롯 시각을 재추정하지 않고, 문구에 소요시간·지연 분을 숫자로 쓰지 않는다(DEC-U4-9 · INV-3). 이동 시간 예측도 표시하지 않는다 |

> **[개정 · 2026-10-19 · situation-awareness FD]** BR-U10-27 메모 — 상황 감시가 같은 `TriggerService` 를 바꾼다
> ① 스윕은 `DELAY` 를 만료·해제하지 않는다(`WEATHER`·`CLOSURE` 만). ② `evaluate` 는 시그니처를 유지하되 의미가 바뀐다 — 대상 식별에 날짜가 들어가고(kind × affectedDate × slotKey), 호출 1번이 대표 1건짜리 알림 사건이며, `severity` 없는 `DELAY` 는 위험(푸시 대상)이다. ③ "억제·민감도·빈도 상한 그대로"는 개정된 판정(날짜·심각도 억제, 푸시 사건 상한)을 받는다. ④ `OVERSTAY`·`TRANSIT` 은 같은 변형 enum 에 더한다. ⑤ 야간 창은 `DELAY` 를 묶지 않는다.

## 6. 출처 · 정정 (DEC-U10-6·15)

| ID | 규칙 |
|---|---|
| **BR-U10-29** | `completion_source`는 **완료가 있을 때만, 반드시** 채운다. 기존 `source`는 **도착 출처**로 읽는다. 수동 [방문 완료]는 `MANUAL`이다 |
| **BR-U10-30** | 사용자가 시각을 보정(`PATCH /visits/{id}`)해도 **출처는 바꾸지 않는다.** 보정 사실은 `updated_at`이 남긴다 |
| **BR-U10-31** | 되돌리기는 **자동 출처 부분만** 연다 — 자동 완료는 완료만 비우고(도착 유지), 자동 도착(완료 없음)은 도착을 비운다. 수동 기록에는 열지 않는다. 완료를 되돌리면 그 슬롯의 재계획 잠금(INV-U4-04)도 풀린다 — 화면은 되돌리기 전에 이를 한 줄로 고지한다. 사진·메모가 붙은 방문의 도착 되돌리기는 거절하고 먼저 지우라고 안내한다(기록을 조용히 잃지 않는다) |
| **BR-U10-32** | 도착을 되돌린 슬롯은 **그날 자동 대상에서 빠진다**(리전 제외 + 서버 `SUPPRESSED`). 타임스탬프가 하나도 없는 실적 행은 방문 목록·회고·요약 집계에서 **제외**한다. 그 슬롯의 수동 도착은 그 행을 재사용한다 |

## 7. 실제 경로 (DEC-U10-3·4·5·7)

| ID | 규칙 |
|---|---|
| **BR-U10-33** | 경로는 **BR-U10-02 무장 조건 + L3(GPS 옵트인)** 일 때만 기록한다. 여행 날짜 구간 밖에서는 기록하지 않는다 |
| **BR-U10-34** | 기록은 **저전력**이다 — 낮은 정확도 등급 · 이동 거리 필터 · 지연 일괄 전달. 정확도 100m를 넘는 표본은 버린다. 구체 값은 NFR 단계가 배터리 예산으로 정한다 |
| **BR-U10-35** | **원시 표본은 기기 밖으로 보내지 않는다.** 당일분만 보관하고 업로드 ack 뒤 지운다. 업로드 실패분은 **여행 종료 + 1일**까지 재시도하고 그 뒤 지운다(그날은 근사 표기) |
| **BR-U10-36** | 업로드 전 **다운샘플**한다 — 허용 오차(기본 제안 15m) 안에서 점을 줄이고 하루 점 상한(기본 제안 2,000)을 넘지 않는다. 다운샘플 결과만으로는 개별 정지 지점·체류 위치를 재구성할 수 없어야 한다는 것이 목표다(값은 O-U10-8) |
| **BR-U10-37** | 기록이 끊긴 구간(표본 간격 10분 초과 또는 1km 초과 점프)에서 **세그먼트를 나눈다.** 세그먼트끼리 선으로 잇지 않는다 — 잇는 순간 실제로 가지 않은 직선이 "실제 경로"가 된다 |
| **BR-U10-38** | 거리는 기기가 **원시 표본(공백 구간 제외)으로** 잰다. 서버는 저장 시 **폴리라인 길이를 하한**, **기록 구간 대비 물리적 상한**(도보·차량 혼재 상식선 — NFR 값)을 상한으로 클램프하고, 클램프했으면 `distance_clamped = true`로 남긴다 |
| **BR-U10-39** | 거리 출처는 **날짜 단위**다 — 경로가 있는 날은 `ROUTE`, 없는 날은 `VISIT_LINE`. 여행 요약 전체 출처는 **모든 날이 `ROUTE`일 때만** `ROUTE`다. 요약이 이미 생성된 뒤 경로가 오면 **stats만** 재계산한다 |
| **BR-U10-40** | 경로·요약·회고 어디에도 **소요시간·이동 시간·속도를 표시하지 않는다.** 기록 구간 시각(`recorded_from/to`)은 저장·검증용이며 화면에 기간으로 표시하지 않는다. 걸음 수를 만들지 않는다(INV-3 · DEC-U4-8) |
| **BR-U10-41** | 지도의 실제 경로 레이어는 그날 경로가 있을 때만 켤 수 있다. 위치 동의가 없거나 경로가 없으면 **비활성 + 사유 표기**하고 계획 동선만 보인다(BR-U4-42·BR-U5-53 승계). 계획 동선은 흐리게, 실제 경로는 점선으로 구분한다(US-PLANB-13) |

## 8. 동의 · 강등 · 파기 · 법정 로그 (DEC-U10-7·10·13·14)

| ID | 규칙 |
|---|---|
| **BR-U10-42** | 앱 위치 토글 OFF(L2·L3 철회) 즉시 기기는 지오펜스·경로를 멈추고 **원시 표본 · 미전송 자동 결과 · 미업로드 경로를 지운다.** 철회 뒤에는 아무것도 올리지 않는다 |
| **BR-U10-43** | 서버는 L3 철회(`GpsRecordingOptOut`)를 받으면 그 계정의 **`actual_route_day` 전량을 삭제**하고 지운 건수로 `PURGE(ACTUAL_ROUTE)` 1건을 남긴다. 지울 것이 없으면 로그를 남기지 않는다. 처리는 멱등이다(at-least-once) |
