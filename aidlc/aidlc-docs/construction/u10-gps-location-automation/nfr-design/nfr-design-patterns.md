## 1. 백그라운드 실행 (P-BG-U10) — 주제 ①

### P-BG-U10-1 — 태스크 정의는 라우트 트리 밖, 엔트리 첫 줄에서

앱이 꺼진 상태에서 OS가 지오펜스로 앱을 깨우면 **JS 번들만 평가되고 UI는 그려지지 않을 수 있다.** `TaskManager.defineTask`가 그 평가 안에서 실행되지 않으면 이벤트는 정의 없는 태스크로 떨어진다(F-4).

```
frontend/package.json   "main": "index.ts"            (expo-router/entry 에서 바꾼다)

frontend/index.ts       (리포 루트 엔트리 - FSD 밖, 조립만)
  require('@/app/entrypoint/registerBackgroundTasks')  -- 1) 먼저
  require('expo-router/entry')                          -- 2) 그다음

src/app/entrypoint/registerBackgroundTasks.ts   (FSD app 층 - FD 2.2 의 '등록 자리')
  if (Constants.expoConfig?.extra?.locationAutomation === true) {
    require('@/shared/location/automation/tasks')       -- defineTask x2 (모듈 최상위)
  }
```

- **`import`가 아니라 `require`로 순서를 고정한다** — ES `import`는 끌어올려져 평가 순서를 글로 보장하지 못한다.
- **플래그 OFF면 `tasks.ts`가 평가되지 않는다**(BR-U10-07 "코드 경로 0"). 번들에는 들어가지만 실행되지 않는다.
- `tasks.ts`는 React·page·feature를 import하지 않는다(FD §2.2 유지). 렌더 트리가 없는 실행에서 끌려 들어오면 그 자체가 결함이다.
- FD §2.2 "루트 레이아웃이 그 엔트리를 거치는지는 6-b에서 확인"은 **이 패턴으로 닫는다** — 거치지 않는다고 보고 설계했다. 6-b #3(앱 종료 상태 wake)은 여전히 실증 항목이다.

### P-BG-U10-2 — wake 파이프라인: 기한(deadline) 구동 · 전송 전 커밋

wake 하나는 **기한 하나**(`deadline = t0 + 9,000ms`, PERF-U10-01의 10초에서 마지막 커밋·종료 여유 1초)를 받고, 모든 단계가 "남은 시간"을 보고 움직인다. MOBILE-U10-04 목록 밖의 일(경로 업로드 · 다운샘플 · 캐시 갱신)은 **하지 않는다.**

```
wake(event, t0)                                       deadline = t0 + 9000ms
 L1  store.lock(); state = store.read()               읽기 throw -> 쓰기 없이 종료 (P-STORE-U10-2)
 L2  arming = resolveArming(OS 권한, state.ctx, 킬 스위치 캐시, now)
       ARMED 아님 -> degrade(state) -> S 로              (P-BG-U10-6)
 L3  적재: 위치 배치 -> 원시 JSONL 추가 (정확도 > 100m 버림, 하루 상한)
           지오펜스 이벤트 -> 판정 입력
 L4  judge = reduce(state.judge, events, now); emit -> outbox; dropStale(여행지 당일)
 L5  COMMIT #1                                        <- 이 줄 뒤로는 판정 결과가 사라지지 않는다
 L6  네이티브: 슬롯 상태가 바뀌었으면 리전 재선택, 지오펜스 wake 면 경로 재시작 (P-BG-U10-4)
 S   전송: planSend(now, deadline, outbox) 가 고른 요청만 (P-BG-U10-3)
       요청 1 = 자동 결과 배치 / 요청 2 = 구간 보고 (남은 시간이 될 때만)
 C   COMMIT #2 (항목 결과 반영); store.unlock(); 태스크 promise 종료
```

| 규칙 | 값 | 근거 |
|---|---|---|
| 요청 시작 조건 | 남은 시간 ≥ **3,000ms** | 8초 타임아웃을 다 못 쓰더라도 응답 한 번을 받을 수 있는 최소치(서버 p95 ≤ 500ms, PERF-U10-04) |
| 요청 타임아웃 | **min(8,000ms, 남은 시간 − 1,000ms)** | PERF-U10-01의 8초는 **상한**이다 — 두 요청이 각각 8초를 쓰면 10초를 넘는다 |
| 요청 수 | wake당 ≤ 2, 순서 = 자동 결과 배치 → 구간 보고 | PERF-U10-01 · 사용자에게 보이는 쪽이 먼저 |
| 같은 wake 재시도 | 없음 | REL-U10-02 |
| 판정·리전 선택 | 순수 함수 ≤ 100ms | PERF-U10-02 |

- **전송 전 커밋(L5)이 신뢰성의 본체다.** 판정 직후·네트워크 전에 큐가 디스크에 있으므로, 전송 중 OS가 태스크를 끊어도 잃는 것은 "이번 전송"뿐이다(REL-U10-01).
- **판정과 큐는 한 파일**(P-STORE-U10-1)이라 L5는 원자적이다 — "판정은 ARRIVED로 넘어갔는데 큐에 ARRIVE가 없다"는 상태가 생길 수 없다.
- `planSend`는 순수 함수다(시각·기한·큐 → 다음 요청과 타임아웃 또는 없음). **PBT-U10-F8**로 잠근다(§LC 배치표).
- 백그라운드가 쓰는 문맥(여행 id · 여행 날짜 구간 · 여행지 시간대 · 전 일정 슬롯 좌표 · 당일 실적 · L2/L3 토글)은 **포그라운드가 미리 써 둔 `ctx`** 다. 백그라운드는 서버에서 문맥을 받아 오지 않는다(잠금·토큰 만료로 못 받을 수 있다). `ctx` 갱신 시점 = 무장 · 포그라운드 복귀 · 일정 변경 · 동의 변경. 날짜가 바뀌어도 전 일정이 `ctx`에 있으므로 백그라운드가 다음 날 리전을 고를 수 있다.

### P-BG-U10-3 — 백그라운드 전송 경로 분리 (토큰: 읽기만, 갱신 없음)

백그라운드는 **`authedClient`·orval 생성 함수를 부르지 않는다**(F-1). 쓰는 것은 `shared/api`의 백그라운드 전용 함수 둘(자동 결과 배치 · 구간 보고)이고, 요청·응답 타입만 orval 생성물을 공유한다.

```
sendInBackground(req, timeoutMs)
  1. tokens = storage.getTokens()          throw -> LOCKED        (WHEN_UNLOCKED, 잠긴 기기)
                                           null  -> NO_SESSION
  2. exp = jwtPayload(access).exp          exp <= now + 30s -> TOKEN_EXPIRED   (요청을 보내지 않는다)
  3. state.authBlocked == true             -> AUTH_401 (이번 wake 도 보내지 않는다)
  4. POST (인터셉터 없는 전용 인스턴스, timeout = timeoutMs, Authorization: Bearer access)
       2xx -> 결과 반영
       401 -> 큐 유지 + state.authBlocked = true      (갱신, clearTokens, onSessionExpired 호출 금지)
       409 AUTOMATION_DISABLED / automationEnabled=false -> 킬 스위치 캐시 false -> degrade
       네트워크, 타임아웃 -> 큐 유지 (다음 wake / 포그라운드)
```

| 결정 | 이유 |
|---|---|
| **토큰을 저장소에서 직접 읽는다**(메모리 홀더 아님) | 앱이 죽었다 깨면 홀더가 비어 있다 — 홀더를 믿으면 무인증 요청이 나간다 |
| **갱신하지 않는다 · 세션 만료 처리도 하지 않는다** | 포그라운드와 동시 갱신 = 재사용 감지 → 체인 전체 무효화(SEC-U10-04 · U0 SEC-02). 백그라운드의 401은 "포그라운드를 기다려라"이지 "로그아웃하라"가 아니다 |
| **`exp` 선판정** | 만료 토큰으로 요청을 보내면 wake 예산을 401 왕복에 쓴다. 서명 검증 없는 디코드로 충분하다(판단만 하고 신뢰하지 않는다) |
| **`authBlocked`는 포그라운드가 푼다** | 401 뒤 매 wake 같은 401을 반복하지 않는다. 포그라운드 갱신 성공 시 해제 |
| **잠금 감지 = 저장소 읽기 실패** | 기기 잠금 상태를 묻는 API가 없다. `WHEN_UNLOCKED` 읽기 throw가 곧 신호다(SEC-U10-03 "오류로 다루지 않는다") |

- 보류 사유(LOCKED·TOKEN_EXPIRED·AUTH_401)는 사유별로 세어 구간 END 보고의 선택 필드로 싣는다(Q3=A · OBS-U10-08 확장 — 서버는 카운터만, 저장 안 함).
- 포그라운드 flush(`useLocationAutomation`)는 **일반 `authedClient` 경로를 쓴다** — 포그라운드에서는 갱신이 정상이다. 같은 큐를 두 경로가 보내도 서버가 `eventId`·`(trip_id, slot_key)`로 수렴시킨다(BR-U10-20).

### P-BG-U10-4 — 자동 정지 후 재개: 지오펜스 wake마다 재시작 호출

iOS `pausesUpdatesAutomatically`는 멈춘 곳에서 갱신을 끊고, **앱이 다시 시작을 불러야** 재개된다(MOBILE-U10-03).

- **지오펜스 wake(진입·이탈 모두)마다, ARMED + L3면 `startLocationUpdatesAsync(ROUTE_TASK, 같은 옵션)`을 무조건 호출한다.** "이미 시작됐나"(`hasStartedLocationUpdatesAsync`)로 거르지 않는다 — 자동 정지 중에도 태스크는 등록돼 있어 "시작됨"으로 보일 수 있다 **[6-b #13 확인]**.
- 같은 호출이 **OS가 앱을 종료한 뒤 지오펜스로 다시 띄운 경우**의 복구도 겸한다(일반 위치 갱신은 종료된 앱을 다시 띄우지 않지만 리전 모니터링은 띄운다).
- 포그라운드 복귀도 같은 재시작을 부른다.
- 재개 전 공백은 세그먼트로 끊긴다(BR-U10-37) — 결함이 아니다.
- **한계**: 그날 남은 리전이 0개(마지막 슬롯 완료 후)면 재개 계기가 없어 **귀환 경로가 자동 정지 지점에서 끝날 수 있다** → 미결 O-U10-ND-3.

### P-BG-U10-5 — 단일 작성자: 저장소 직렬 실행

포그라운드 훅과 백그라운드 태스크는 **같은 JS 런타임에서 동시에** 돌 수 있다(앱이 떠 있는 중에 지오펜스 이벤트). 둘 다 상태 파일을 읽고-고치고-쓰면 나중 쓰기가 앞 쓰기를 지운다.

- `localStore`가 **모듈 수준 promise 체인 잠금**(`withStore(fn)`)을 소유하고, 상태 파일 접근은 전부 이 함수를 지난다.
- 잠금은 **wake 전체(전송 포함)** 를 덮는다. 포그라운드 flush가 최대 ~9초 기다릴 수 있으나 화면은 저장소를 렌더 입력으로 쓰지 않으므로(서버 값을 그린다 — FD §0) 사용자에게 보이지 않는다. 전송 중 항목 표식 같은 세밀한 장치보다 **중복 전송·유실 경로가 아예 없는** 쪽을 고른다.
- 프로세스는 하나라 프로세스 간 락은 필요 없다.

### P-BG-U10-6 — 게이트와 해제 순서

| 상황 | 순서 | 디렉토리 |
|---|---|---|
| **강등**(always 철회 · 대략 위치 · 여행 구간 밖 · 플래그 OFF · **킬 스위치 OFF**) | ① OS 해제(`stopGeofencingAsync` · `stopLocationUpdatesAsync`) → ② 열린 구간 END를 큐에 → ③ i01 1줄 표식 → ④ 남은 시간이 되면 전송 | **유지** — 큐는 flush, 원시 표본은 업로드 대상(REL-U10-06 "데이터를 버리지 않는다") |
| **동의 철회**(L2·L3 OFF) · 서버 `REJECTED_CONSENT`/409 | ① OS 해제 → ② **디렉토리 삭제**. END를 보내지 않는다 — 철회 뒤에는 아무것도 올리지 않는다(BR-U10-42). 서버가 철회 이벤트로 구간을 닫는다 | 삭제 |
| **로그아웃 · 계정 삭제 요청** | ① OS 해제 → ② END 1회 시도(토큰이 아직 있을 때, 실패 무시 — 스위퍼가 닫는다) → ③ 디렉토리 삭제 → ④ 토큰 삭제 | 삭제(SEC-U10-02) |

- **OS 해제가 언제나 먼저다.** 디렉토리를 먼저 지우면 그 사이 wake가 빈 상태로 파일을 다시 만든다.
- OS 해제 호출은 "등록돼 있지 않음" 예외를 삼킨다(이미 해제된 상태에서 다시 불러도 같은 결과 — 멱등).
- 킬 스위치 강등의 END `endReason` = **`REMOTE_DISABLED`**(FD §12.4 enum 추가 제안 — §7). OBS-U10-04가 사용자 측 강등과 운영 차단을 구분해야 한다.

## 2. 다운샘플 · 정지 지점 (P-PRIV-U10 · P-PERF-U10) — 주제 ②

### P-PRIV-U10-1 — 닻 배제 → RDP → 인코딩 (O-U10-8 해소, Q1=A)

**왜 RDP만으로는 안 되나.** Ramer–Douglas–Peucker는 "모든 원시 점이 출력에서 ε 안"을 보장하려고 **꺾이는 점과 끝점을 남긴다.** 정지 지점은 정확히 그 모양으로 남는다 — 머무는 동안의 GPS 튐은 지그재그 꼭짓점 묶음이 되고, iOS 자동 정지는 멈춘 곳에서 기록을 끊어 **세그먼트 끝점 = 정지 지점**(숙소 포함)을 만든다. 충실도 보장과 정지 지점 은닉은 반대 방향이라, **은닉은 단순화와 별개 단계**로 둔다.

**파이프라인**(포그라운드 전용 · 원시 하루치 입력 · 결정론):

```
raw(t, lat, lng, acc)  -- 정확도 > 100m 은 적재 시 이미 버림 (BR-U10-12)
 1. 세그먼트 분할      : dt > 10분 또는 점프 > 1km  (BR-U10-37)
 2. 거리 산출          : 세그먼트별 하버사인 누적 = distanceM            (BR-U10-38, 배제 전 원시 기준)
 3. 닻 찾기            : (a) 체류 지점 = D_stop 안에 T_stop 이상 머문 점 묶음의 중심
                        (b) 원시 세그먼트 양 끝점
 4. 닻 배제            : 어떤 닻에서든 R_priv 안에 있는 원시 점을 전부 지운다
                        - 세그먼트 가운데가 빠지면 앞뒤 남은 점을 그대로 잇는다(현 - 기록이 이어진 구간 안)
                        - 끝이 빠지면 그만큼 짧아진다
                        - 남은 점 < 2 인 세그먼트는 버린다
 5. 단순화             : 세그먼트마다 지역 평면 투영(등장방형, 세그먼트 첫 점 기준, 미터) 후 반복형 RDP(eps)
 6. 상한               : 전체 점 > N_max 이면 eps *= 1.5 로 5 를 다시 (전체 <= N_max 까지)
                        세그먼트 > S_max 이면 경로 길이가 긴 S_max 개만 남긴다
 7. 인코딩             : Google encoded polyline, 정밀도 1e-5
 8. 세그먼트 0개        : 업로드하지 않는다 -> 그날은 근사(VISIT_LINE)
```

**값**(전부 `automation/config.ts`, 설정값)

| 기호 | 값 | 근거 |
|---|---|---|
| ε₀ | **15m** | FD BR-U10-36 제안값 승계 |
| N_max | **2,000점/일**(전 세그먼트 합) | FD BR-U10-36 · SEC-U10-07 |
| ε 증가 | ×1.5, N_max 이하가 될 때까지 | 세그먼트당 최소 2점 × S_max 200 = 400 < 2,000이라 반드시 끝난다 |
| S_max | **200 세그먼트/일** | SEC-U10-07 |
| **R_priv** | **150m** | Q1=A — 이 시스템이 "그 장소에 있다"고 보는 반경(BR-U10-13)과 같게. 출력이 "머물렀다"와 "반경 안을 지나갔다"를 구분하지 못하게 하는 최소값. **근거 없는 초기값** |
| **D_stop** | **100m** | 정확도 게이트(BR-U10-12) — 그보다 작은 반경은 GPS 튐을 체류로 못 묶는다 |
| **T_stop** | **3분** | 도착 확정 체류(BR-U10-14)와 같게 — 시스템이 "방문"으로 볼 수 있는 머묾은 전부 닻이다. 신호 대기(~2분)는 닻이 아니다 |

**체류 탐지 알고리즘** — 원시 점 i에서 시작해 `dist(p_i, p_j) ≤ D_stop`인 동안 j를 늘린다. `t_{j−1} − t_i ≥ T_stop`이면 `p_i..p_{j−1}`의 중심을 닻으로 두고 i = j, 아니면 i + 1(stay-point detection). **시각 간격을 그대로 쓰므로** 자동 정지로 점이 두 개뿐인 7분 정지(공백 < 10분이라 세그먼트가 안 끊김)도 닻이 된다.

**"정지 지점 재구성 불가"의 판정 기준** — 서버에 저장되는 것(인코딩 세그먼트 · 점 수 · 거리 · 기록 구간 시각)만 가진 관찰자에 대해:

| # | 기준 | 반증 방법 |
|---|---|---|
| K1 | **출력의 어떤 꼭짓점도 어떤 닻의 R_priv 안에 없다** — 정지 지점을 R_priv보다 좋은 해상도로 가리키는 점이 없다 | PBT-U10-F5 ⑥ |
| K2 | **세그먼트 끝점이 정지 지점을 가리키지 않는다** — 원시 끝점이 닻이므로 K1에 포함된다 | 〃 |
| K3 | **체류 여부·길이를 출력에서 읽을 수 없다** — 점별 시각이 없고(FD §12.3), 닻 주변 꼭짓점이 0이라 밀도 신호도 없다 | PBT-U10-F5 ⑤(시간 필드 없음) + K1 |

**주장하지 않는 것**(한계를 숨기지 않는다):
- 경로가 **어디를 지나갔는지**는 드러난다 — 그것이 기능이다.
- 막다른 곳에 들렀다 되돌아 나오면 경로 끝이 정지 지점에서 R_priv 떨어진 곳에서 꺾이는 **"가시"** 가 남아, 정지 지점이 대략 2·R_priv 범위로 추정될 수 있다.
- 계획된 장소의 방문은 `visit_check`로 이미 서버에 있다 — 이 단계가 지키는 대상은 **계획 밖 체류와 숙소**다.
- `recorded_from/to`는 하루 기록 시작·끝 시각을 남긴다(FD 결정 · 표시 금지 INV-U10-7).

**정합**
- 현(4단계)은 **기록이 이어진 구간 안**에서만 생기고 길이는 대략 2·R_priv(+원시 점 간격)로 묶인다 — 기록 공백을 잇지 않는다(INV-U10-9 유지).
- 배제·단순화는 경로를 **짧게만** 만든다(삼각부등식) → "거리(2단계) ≥ 출력 폴리라인 길이"가 유지되고, 서버 하한 클램프(BR-U10-38)와 충돌하지 않는다.
- 사용자에게 보이는 효과: 실제 경로가 숙소·들른 곳 **150m 앞에서 끝나거나 그 구간을 직선 하나로 지난다.** 계획 동선(흐린 선)과 POI 핀이 같은 지도에 있으므로 맥락은 남는다.

**탈락안**

| 후보 | 탈락 이유 |
|---|---|
| RDP만(ε 확대) | 끝점·되돌아 나온 끝을 원리적으로 못 지운다(K2 위반) |
| Visvalingam–Whyatt | 면적 기준이라 **거리 상한이 없다** — PBT-U10-F5 "모든 원시 점이 허용 오차 안"을 진술할 수 없다 |
| 균등 추출(n번째 점) | 상한 보장만 있고 모양·은닉 둘 다 보장 없음 |
| 좌표 잡음(geo-indistinguishability 류) | 표시 경로가 흔들리고 "거리 ≥ 폴리라인" 하한 클램프와 충돌. 잡음은 반복 관측에서 평균으로 벗겨진다 |
| 외부 라이브러리(`simplify-js` 등) | 미터 투영·상한 루프·닻 배제를 어차피 감싸야 한다. 핵심 RDP는 반복형 40줄 남짓 — 신규 의존 0 유지(tech-stack 델타 6) |

### P-PERF-U10-1 — 다운샘플은 포그라운드에서만, 결과는 재계산

- 업로드 계기(날짜 전환 · 여행 구간 종료 · 강등 · 포그라운드 복귀 — FD §7) 중 **실행은 포그라운드 복귀 시점 하나**로 모은다. 백그라운드 wake는 "그날 업로드 대기" 표식만 남긴다(MOBILE-U10-04 · PERF-U10-03).
- **다운샘플 결과를 저장하지 않는다.** 원시 → 출력이 결정론이라 재시도마다 다시 계산한다(디스크에 두 벌이 생기지 않고, 업로드 ack 뒤 원시만 지우면 끝).
- RDP는 반복형(명시적 스택)으로 쓴다 — 재귀 깊이가 점 수에 비례하는 최악 입력에서도 스택이 넘치지 않는다.
- 예산 확인 = jest 벤치(하루 상한 20,000점 · 지그재그 최악 생성기)로 회귀를 보고, 기준 기기 실측(PERF-U10-03 ≤ 2초)은 6-b #10과 같은 회차에 잰다. 2초를 넘으면 원시 적재 시 반경 사전 거르기(5m)를 더한다(그때 PBT 허용치 = ε + 5m).

## 3. 로컬 저장소 (P-STORE-U10) — 주제 ③

### P-STORE-U10-1 — 디렉토리 배치

```
<cache>/trippilot-u10/                 iOS Caches / Android cacheDir - 백업 제외 (SEC-U10-01)
  state.a.json                         상태 A/B 슬롯 (P-STORE-U10-2)
  state.b.json
  raw/<tripId>/<YYYY-MM-DD>.jsonl      원시 표본, 여행지 기준 날짜별, 추가 쓰기만
```

**상태 파일 하나에 묶는 것**(크기 수 KB~20KB):

| 필드 | 내용 | 수명 |
|---|---|---|
| `schema` · `gen` · `owner` | 형식 버전 · 세대 번호 · 계정 id | — |
| `ctx` | 무장 문맥(P-BG-U10-2) — 여행 id · 날짜 구간 · 시간대 · 전 일정 슬롯(`slotKey`·`poiId`·좌표·순번) · 당일 실적 · L2/L3 | 포그라운드가 갱신 |
| `judge` | 슬롯별 판정 상태(FD §5.1) · 당일 되돌린 슬롯 | 당일 |
| `outbox` | 자동 결과 항목(당일 — BR-U10-22) + 구간 START/END 보고(**여행 종료 + 1일까지** — 그 뒤는 서버 스위퍼가 닫는다) | 항목별 |
| `intervals` | 열린 구간 id(kind별) | 구간 수명 |
| `kill` | 킬 스위치 직전 값 `{enabled, observedAt}` | 계정 수명 |
| `explainerAsked` | 설명 질문 이력(여행 id) | 여행 수명 |
| `counters` | 당일 wake 수 · 판정 보류 · 전송 보류(사유별) · 폐기 · 원시 점 수 · 상한 도달 | 구간 END 보고 후 초기화 |
| `routePending` · `authBlocked` · `notice` | 업로드 대기 날짜 · 401 표식 · i01 1줄 표식(강등 사유 · 폐기 건수) | 소비 시 해제 |

- **판정 상태와 큐를 한 파일에 둔 이유**: 두 파일이면 "판정은 넘어갔는데 큐 항목이 없다"(유실) 또는 그 반대(중복)가 강제 종료 시점에 따라 생긴다. 한 파일이면 커밋 한 번이 둘을 함께 옮긴다(P-BG-U10-2 L5).
- **원시 표본만 따로 두는 이유**: 크고(하루 ≤ 20,000점 ≈ 1.2MB) 추가만 하며, 상태처럼 통째로 다시 쓰면 wake마다 MB 단위 쓰기가 된다.
- 무장 상태(ARMED)는 저장하지 않는다(BR-U10-02) — `ctx`는 판정 **입력**이지 판정 결과가 아니다.

### P-STORE-U10-2 — A/B 교대 쓰기 (원자적 교체의 플랫폼 공통 구현)

F-3 때문에 "임시 파일에 쓰고 rename으로 덮기"를 iOS·Android 공통 원시 연산 하나로 만들 수 없다. 대신 **마지막으로 성공한 파일을 절대 건드리지 않는다.**

```
write(next):
  next.gen = current.gen + 1
  target   = (next.gen 이 짝수) ? state.a.json : state.b.json      -- 현재 세대가 든 슬롯의 반대편
  target.write(JSON.stringify(next))                               -- 비원자여도 된다
  실패 -> 메모리의 next 를 버리고 오류 반환 (디스크의 current 는 그대로)

read():
  a, b 를 각각 읽는다
    파일 없음                       -> 후보 아님
    읽기 자체가 throw (보호/권한)    -> UNREADABLE : wake 를 쓰기 없이 끝낸다   (!)
    JSON 파싱 실패, 스키마 불일치    -> 후보 아님 (찢어진 쓰기)
  후보 중 gen 최대를 고른다
  후보 0 개: 둘 다 없음 -> 빈 상태(gen 0)
             파일이 있었는데 전부 무효 -> 빈 상태 + 사유 코드 STATE_RESET
```

- **강제 종료가 쓰기 중간에 오면** 찢어진 쪽은 파싱에 실패하고 반대 슬롯(직전 세대)이 살아 있다 → 결과는 **"직전 큐"** 다. 둘 다 없을 때만 **"빈 큐"** 다 — PBT-U10-F7의 진술 그대로다(REL-U10-01).
- JSON 최상위 객체는 마지막 바이트(`}`)가 있어야 파싱되므로 앞부분만 쓰인 파일은 반드시 무효가 된다. 별도 체크섬을 두지 않는다.
- ★ **읽기 실패 ≠ 손상.** 재부팅 후 첫 잠금 해제 전에는 OS 파일 보호가 읽기를 막는다. 이것을 손상으로 읽고 빈 상태를 쓰면 **멀쩡한 큐를 스스로 지운다.** 그래서 throw는 "이번 wake 포기"로만 끝낸다 → 6-b #15.
- `STATE_RESET`(둘 다 무효)은 OS 캐시 퍼지 등 드문 경우다. 잃은 항목 수를 알 수 없으므로 i01 숫자 1줄 대신 **사유 코드만** Sentry로 보낸다(좌표 없음 — SEC-U10-05). 그날 경로는 근사로 떨어진다(SEC-U10-01과 같은 폴백).

**원시 표본 JSONL**
- 추가 = 파일 핸들을 열어 끝 오프셋에 한 묶음을 쓰고 닫는다. 한 줄 = `{"t":…,"la":…,"ln":…,"a":…}`.
- 읽기 = 줄 단위 파싱, **파싱 안 되는 줄은 건너뛴다**(강제 종료로 찢긴 마지막 줄). 건너뛴 수는 `raw/stored` 지표에 섞지 않고 버린다.
- 원시 추가 → 상태 커밋 순서. 그 사이에서 끊기면 카운터가 한 묶음 덜 세질 뿐이다(하루 상한은 안전 장치라 정확할 필요가 없다).

### P-STORE-U10-3 — 킬 스위치 직전 값 캐시 + 다시 켜짐 탐침

| 계기 | 캐시 |
|---|---|
| 처음(관측 전) | `enabled = true`(서버 기본 ON) |
| 자동 결과 배치 응답 `automationEnabled` | 그 값 |
| 구간 START 409 `AUTOMATION_DISABLED` | `false` |
| 응답을 못 받음(오프라인 · 잠김 · 타임아웃) | **바꾸지 않는다**(REL-U10-06 직전 상태 유지) |

- `false`는 `resolveArming`의 입력이다 → **ARMED도 EXPLAINER도 나오지 않는다**(원격 차단 중에 always를 묻지 않는다). PBT-U10-F1을 이 입력으로 확장한다.
- ★ **다시 켜짐을 알 길을 따로 둔다.** 꺼진 기기는 무장하지 않아 배치도 START도 보내지 않으므로, 응답에 기대면 영원히 꺼져 있다. 그래서 **포그라운드 복귀 때 캐시가 `false`면 빈 배치(`events: []`)를 1회 보낸다** — 응답의 `automationEnabled`가 탐침 결과다. 신규 엔드포인트 없이 기존 배치를 쓴다(FD §12.1에 "빈 배치 허용" 명시 필요 — §7).
- 꺼져도 큐는 계속 보낸다 — 서버가 정상 처리한다(REL-U10-06).

### P-STORE-U10-4 — 삭제와 소유자 확인

- 삭제는 **디렉토리째**(`trippilot-u10/` 하나)이고 순서는 P-BG-U10-6(OS 해제가 먼저).
- 업로드 ack 뒤에는 그날 `raw/<tripId>/<date>.jsonl`만 지운다(BR-U10-35). 여행 종료 + 1일이 지난 원시 파일은 포그라운드에서 지우고 1줄 안내(FD §11).
- **소유자 확인**: 포그라운드가 세션을 확인할 때(앱 시작 · 로그인 직후) `state.owner ≠ 현재 계정`이면 OS 해제 → 디렉토리 삭제. 로그아웃 중 삭제가 중간에 끊긴 잔여물이 다음 사용자에게 넘어가는 경로를 막는다(SEC-U10-02). 백그라운드에서는 확인하지 않는다 — 잠긴 기기에서 현재 계정을 알 수 없고, 로그아웃이 OS 등록을 먼저 해제했으므로 그 잔여물로는 wake가 생기지 않는다.
