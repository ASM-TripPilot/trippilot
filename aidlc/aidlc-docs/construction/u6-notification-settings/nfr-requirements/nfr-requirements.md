# U6 Notification & Settings — NFR Requirements

> **방침**: 얇게 — U0·U1·U3·U4·U5 상속분은 **재서술하지 않는다**(§8에 목록만).
> **답변(2026-08-24)**: **Q1=B**(야간 조용시간 미도입 — 그냥 발송) · Q2~Q6=A
> **이 스테이지를 돈 이유**: Q3=A(Expo Push)로 **푸시를 열었다.** 발송량 비용 · 릴레이 신뢰성 · 토큰 수명 · 잠금화면 노출이 U0~U5 어디에도 없던 축이다.

---

## 0. 이 유닛에서 새로 생기는 축

| 축 | 왜 지금 | 상속으로 안 되는 이유 |
|---|---|---|
| **COST** 발송량 | 계정당 하루 수십 건이 구조적으로 가능 | U1 COST는 지도·검색 쿼터, U3는 LLM 토큰 — **발송 단가 축이 없다** |
| **RELIABILITY** 릴레이 | 아웃박스 릴레이가 U6에서 처음 실장된다 | U0 복원력은 외부 포트 폴백 중심. **내부 비동기 전달 실패**는 다룬 적 없다 |
| **DATA** 토큰·알림 수명 | 푸시 토큰은 썩고, 알림은 무한 누적된다 | U5 DATA는 여행 단위 파기. **계정 단위 시계열 정리**는 처음 |
| **SEC** 잠금화면 | 푸시 본문이 **잠금 상태에서 노출**된다 | 기존 SEC은 토큰·전송 구간. **화면 노출 표면**은 새로 |

## 1. 비용 (COST-U6-\*)

| ID | 요구 |
|---|---|
| **COST-U6-01** | 계정당 푸시 발송 **소프트 상한 = 시간 10건 · 일 50건**. 초과분은 **인앱함에만 적재**하고 푸시를 생략한다 |
| **COST-U6-02** | 상한 초과는 **버리는 것이 아니다** — 인앱함에 남고 catch-up으로 전달된다(INV-U6-02). 사용자에게 알림이 사라지지 않는다 |
| **COST-U6-03** | 상한 초과 건수를 **메트릭으로 남긴다**(OBS-U6-03). 상한이 실제로 물리는지 모르면 값을 조정할 근거가 없다 |
| **COST-U6-04** | Expo Push는 **무료 티어 전제**로 시작한다. 유료 전환·레이트리밋 도달은 **재평가 트리거**(§10) |
| **COST-U6-05** | 상한은 **정보성 알림 기준**이다. 광고성은 이 경로로 나가지 않는다(LEGAL-U6-02) |

## 2. 신뢰성 (REL-U6-\*)

| ID | 요구 |
|---|---|
| **REL-U6-01** | 릴레이 실패는 **최대 10회 · 지수 백오프**로 재시도한다(`outbox_event.attempts` 사용 — 컬럼이 이미 있다) |
| **REL-U6-02** | 10회 초과 행은 `published_at`을 찍지 않고 **메트릭·로그로 드러낸다**. **dead-letter 테이블을 신설하지 않는다** — 조회는 `WHERE published_at IS NULL AND attempts >= 10`으로 충분하다 |
| **REL-U6-03** | 침묵 실패 금지(INV-4)는 **관측으로 만족**한다. 사용자에게 "알림 전달 실패"를 보여주지 않는다 — 인앱함에는 이미 있기 때문이다 |
| **REL-U6-04** | 릴레이는 **다중 인스턴스에서 단일 실행**을 보장한다(`shedlock` 테이블 + ShedLock 라이브러리). 락이 없으면 같은 이벤트가 두 번 푸시된다 |
| **REL-U6-05** | 구독자 처리가 끝난 **뒤에만** `published_at`을 찍는다. 먼저 찍으면 실패한 알림이 영영 사라진다 |
| **REL-U6-06** | 서킷 브레이커는 **도입하지 않는다**(U1·U4 결정 승계 — `resilience4j`가 리포에 없다). Expo Push 장애 시에는 재시도 + 인앱 폴백으로 충분하다 |

## 3. 성능 (PERF-U6-\*)

| ID | 요구 |
|---|---|
| **PERF-U6-01** | 릴레이 폴링 주기 **5초**. `StalePartialSweeper`(60초)보다 촘촘한 이유 = 사용자 체감이 직접 걸린다 |
| **PERF-U6-02** | 시각 기반 알림(`notification_schedule`)의 **발화 오차 목표 1분 이내**. 리마인드는 분 단위 정확도면 충분하다 |
| **PERF-U6-03** | 알림함 조회(`GET /me/notifications`) **p95 500ms**. 인덱스 `(account_id, occurred_at DESC)`가 근거 |
| **PERF-U6-04** | 릴레이 배치 크기 상한을 둔다(예: 폴링당 100건) — 한 번에 다 집으면 락 보유 시간이 길어진다 |

## 4. 데이터 (DATA-U6-\*)

| ID | 요구 |
|---|---|
| **DATA-U6-01** | 푸시 토큰은 `last_seen_at` **90일 초과 시 무효화**한다 |
| **DATA-U6-02** | Expo가 `DeviceNotRegistered`를 반환하면 **즉시 무효화**(INV-U6-07). 죽은 토큰에 계속 쏘면 레이트리밋을 먹는다 |
| **DATA-U6-03** | 알림은 **90일 보관 후 삭제**한다. **인앱함은 아카이브가 아니다** |
| **DATA-U6-04** | 계정 파기 시 알림·토글·토큰·스케줄 **4종 모두 CASCADE 삭제**된다(append-only 아님) |
| **DATA-U6-05** | 정리 작업은 **기존 `@Scheduled` 패턴**으로 한다. 신규 스케줄링 인프라 0(U4 결정 승계) |

## 5. 법적 (LEGAL-U6-\*) ★ Q1=B의 조건

| ID | 요구 |
|---|---|
| **LEGAL-U6-01** | **야간 조용시간을 두지 않는다**(Q1=B, 2026-08-24 사용자 결정). 알림은 발생 시각에 발송한다 |
| **LEGAL-U6-02** ★ | **이 경로로는 정보성(거래·서비스) 알림만 발송한다.** 광고·마케팅성 알림은 `NotificationKind` 8종에 **없고**, 추가하지 않는다. 마케팅 수신은 `/me/marketing-consent`(실재)를 쓰는 **별도 경로**다 |
| **LEGAL-U6-03** | LEGAL-U6-02가 **LEGAL-U6-01의 성립 조건**이다. 광고성이 이 경로에 섞이는 순간 야간 발송의 근거가 사라지므로, 종류 추가 시 **재평가 트리거**가 걸린다(§10) |
| **LEGAL-U6-04** | 위치 관련 법정 로그(`location_legal_log`)는 **U0 소유**다. U6는 기록하지도 읽지도 않는다 |

## 6. 관측 (OBS-U6-\*)

`spring-boot-starter-actuator`·`micrometer-registry-otlp`가 **이미 있다**(실측). 파이프라인 신규 구축 없이 **카운터 4종만** 얹는다.

| ID | 지표 |
|---|---|
| **OBS-U6-01** | **릴레이 지연** — `outbox_event.occurred_at` → `published_at` p95 |
| **OBS-U6-02** | **푸시 발송 성공/실패** — 실패는 사유별(`DeviceNotRegistered`·레이트리밋·기타) |
| **OBS-U6-03** | **억제 건수** — 중복 억제(10분)·발송량 상한(COST-U6-01)로 푸시가 생략된 수 |
| **OBS-U6-04** | **미읽음 누적** — catch-up 건강도. 계속 쌓이면 전달이 아니라 **소비**가 깨진 것이다 |

> 열람률·전환은 **제품 분석 영역**이라 넣지 않는다(U3의 "행동 지표 2종만" 선례).

## 7. 보안 (SEC-U6-\*)

| ID | 요구 |
|---|---|
| **SEC-U6-01** ★ | 푸시 본문에 **민감정보를 넣지 않는다** — 잠금화면에 그대로 뜬다. 숙소 주소 전체·이메일·계정 식별자 금지. `l01` 실물 문안 수준(`○○호텔이 등록되었어요`)이 상한이다 |
| **SEC-U6-02** | 푸시 토큰은 **계정에 귀속**된다. 로그아웃 시 해당 기기 토큰을 무효화한다 — 안 하면 **다음 사용자에게 이전 사용자 알림이 간다** |
| **SEC-U6-03** | `catchUp`은 **본인 것만** 반환한다(`account_id` 스코프). U0 인가 규약 승계 |

## 8. 상속 (재서술하지 않음)

- **U0**: 인증·인가·토큰·삭제 유예·위치 동의 3층·보안 베이스라인(SECURITY-01~15)
- **U1**: 외부 포트 폴백·Redis 미도입·**서킷 미실장 사실**
- **U3**: LLM 비용·관측 파이프라인
- **U4**: 스케줄링 신규 인프라 0(`@Scheduled` 재사용)·모바일 권한 축·법정 로그 구간 단위
- **U5**: 여행/계정 파기 CASCADE 원칙

## 9. PBT (blocking)

FD에서 정의한 **PBT-U6-1~5**를 그대로 게이트로 쓴다. NFR 단계에서 추가하지 않는다 — 특히 **PBT-U6-1(catch-up 누락 0)** 이 이 유닛의 핵심 성질이다.

## 10. 재평가 트리거

| 트리거 | 재평가 대상 |
|---|---|
| **광고·마케팅성 알림 종류 추가 요구** | **LEGAL-U6-01(조용시간 미도입) 전면 재검토** — 근거가 무너진다 |
| Expo Push 무료 티어 초과 / 레이트리밋 도달 | COST-U6-04 · 유료 전환 또는 FCM 직결 전환 |
| 야간 발송에 대한 사용자 이탈·CS 유입 관측 | LEGAL-U6-01 재검토(조용시간 또는 `l02` 사용자 설정) |
| 릴레이 지연 p95가 목표를 반복 초과 | PERF-U6-01 주기·배치 크기, 또는 WS/SSE 재검토(현재 미도입) |
| 다중 인스턴스 운영 시작 | REL-U6-04 락 동작 검증(현재 로컬 단일 인스턴스) |
| U7 커뮤니티 개통 | `COMMUNITY` 종류 노출 + 발송량 급증 → COST-U6-01 재산정 |
