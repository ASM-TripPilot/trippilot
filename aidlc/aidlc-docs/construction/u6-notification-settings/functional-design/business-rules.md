# U6 Notification & Settings — Business Rules

> **상속**: U0(계정·닉네임·위치 3층·삭제 유예) · U1(숙소·제휴 `BR-U1-30`) · U4(Plan-B) · U5(회고)는 **재서술하지 않는다**(DEC-U6-2).
> 아래는 U6 고유 규칙이다.

---

## 1. 발화 (US-NOTIF-01~04)

| ID | 규칙 |
|---|---|
| **BR-U6-01** | 숙소 **등록**이면 숙소명·위치·체크인/아웃 + "이 숙소가 일정 생성 출발점으로 설정됐습니다"를, 단순 **저장(찜)** 이면 "일정에 반영하려면 등록하세요" 유도를 싣는다 |
| **BR-U6-02** | 체크인/아웃 **미입력** 등록이면 위 대신 "날짜를 입력해야 일정 생성이 가능합니다"를 발송한다 |
| **BR-U6-03** | 알림 본문은 **원천 데이터 안에서만** 쓴다. 없는 값을 채우지 않는다 |
| **BR-U6-04** | 리마인드는 **여행 D-1 · 당일 오전 기본 8시 · 일정 시작 전 기본 30분**(0/15/30/60)에 발화한다 |
| **BR-U6-05** | 일정 알림 본문은 **장소명·시작 시각·이동 거리**다. **소요시간을 넣지 않는다**(INV-3). 실물 문안이 정본: `다음 일정: ○○ · 14:30 · 840m` |
| **BR-U6-06** | 등록 숙소가 없어 일정이 없으면 "숙소를 등록하면 일정 알림을 받을 수 있습니다"를 **1회만** 발송한다 |
| **BR-U6-07** | 일정이 재생성·재계획되면 **미발화 스케줄을 재계산**한다(INV-U6-08). 지난 일정 알림은 발화하지 않고 취소한다(INV-U6-09) |
| **BR-U6-08** | Plan-B 알림은 **트리거 유형·영향 일정**을 본문에 명시하고 **`대안 일정 보기`** 액션을 준다 |
| **BR-U6-09** | 동일 일정 Plan-B는 **10분 내 1회**로 제한한다(`dedup_key`) |
| **BR-U6-10** | 외부 날씨/휴무 API 실패면 **침묵한다.** 잘못된 정보로 알리지 않고 다음 정상 응답에서 재평가한다(U4 승계) |
| **BR-U6-11** | **위치 동의 철회 시 이동 지연 알림을 발송하지 않는다.** 날씨·휴무 트리거 알림은 계속 동작한다(`l06`의 "동의를 꺼도 계속 동작해요"와 일치) |
| **BR-U6-12** | 회고 알림은 `ReflectionReady` 수신으로 발화한다. **회고에 쓸 데이터가 전혀 없으면** "기록할 활동이 없어 회고를 생성하지 못했습니다"를 발송한다 |

## 2. 채널·토글 (US-NOTIF-05)

| ID | 규칙 |
|---|---|
| **BR-U6-13** ★ | **인앱함 적재는 푸시 발송보다 먼저이고, 푸시 성공 여부와 무관하다**(INV-U6-02). 이 순서가 "누락 0"의 유일한 근거다 |
| **BR-U6-14** | 토글 변경은 **즉시 저장되고 다음 알림부터 반영**된다. 이미 발송된 것에 소급하지 않는다(`l02` 상단 문구) |
| **BR-U6-15** | 특정 종류의 **푸시를 꺼도 인앱함에는 누적**된다. 반대도 같다(`l02 permission-denied` 하단 문구) |
| **BR-U6-16** | OS 푸시 권한이 **거부**면 푸시 토글을 **비활성**으로 그리고(`권한 필요` 칩) **설정 이동** 링크를 노출한다. 인앱은 정상 동작한다 |
| **BR-U6-17** | **모든 채널을 꺼도 `SYSTEM` 알림은 인앱함에 표시**된다(INV-U6-03). `SYSTEM`은 토글 레코드를 만들지 않는다(INV-U6-04) |
| **BR-U6-18** | 토글 기본값: `SLOT_PRE`·`PLAN_B`는 **푸시 OFF·인앱 ON**, 나머지 5종은 **둘 다 ON**(실물 `l02` 기준) |
| **BR-U6-19** | `COMMUNITY` 토글은 **레코드는 만들되 U7 개통까지 UI에서 숨긴다**(INV-U6-05). 켤 수 없는 것을 켜게 두지 않는다 |

## 3. 전달·억제

| ID | 규칙 |
|---|---|
| **BR-U6-34** | 아웃박스 디스패치는 **멱등**이다 — `source_event_id` UNIQUE가 중복 알림을 막는다(INV-U6-01). 재시도가 사용자에게 두 번 울리지 않는다 |
| **BR-U6-35** | 디스패치 실패는 `attempts++` 후 **다음 폴링에서 재시도**한다. `published_at`은 **구독자 처리가 끝난 뒤에만** 찍는다 |
| **BR-U6-36** | 억제된 알림도 **인앱함에는 남긴다.** 억제는 "푸시를 안 쏜다"이지 "없던 일로 한다"가 아니다 |
| **BR-U6-37** | Expo가 `DeviceNotRegistered`를 반환하면 해당 토큰을 **즉시 무효화**한다(INV-U6-07) |
| **BR-U6-38** | 푸시 실패는 `push_failed_reason`에 남기고 **사용자에게 조용히 삼키지 않는다** — 인앱함에 이미 있으므로 전달 자체는 실패하지 않은 것으로 본다 |

## 4. 마이페이지 (US-NOTIF-06~08)

| ID | 규칙 |
|---|---|
| **BR-U6-20** | 등록 숙소 목록은 숙소명·위치·체크인/아웃·등록 출처·**연결 여행**을 보인다. 연결이 없으면 **`연결된 여행 없음`**(실물 `l04`) |
| **BR-U6-21** | "일정 출발점 등록/해제" 전환 시 **일정 재생성 여부를 묻는다.** 조용히 재생성하지 않는다 |
| **BR-U6-22** | 여행은 **예정 / 진행 중 / 종료** 3분류다. 각 카드에 목적지·기간·**등록 숙소 수**·일정 수를 보이고, 숙소가 없으면 **`숙소 미등록`** 칩(실물 `l03`) |
| **BR-U6-23** | 지난 여행에서 **회고로 바로 진입**시킨다. 종료 여행이 없으면 "아직 종료된 여행이 없습니다"만 표시하고 회고 진입을 **숨긴다** |
| **BR-U6-24** | 스타일 카드는 U5 `style_analysis`를 **읽기만** 한다. 누적 방문 **< 10곳이면** "10곳 이상 쌓이면 분석을 제공합니다(현재 N곳)"를 표시한다 — U5가 정식 분석을 만들지 않기 때문이다(INV-U5-09). **U6가 대신 계산하지 않는다** |

## 5. 계정·설정 (US-NOTIF-09~12)

| ID | 규칙 |
|---|---|
| **BR-U6-25** ★ | 계정 삭제 전 **함께 삭제되는 것을 구체적으로 고지**하고 재확인을 받는다. **목록은 U6가 소유**하며 유닛이 늘 때마다 갱신한다(DEC-U6-6). 현재 목록: 등록 숙소 · 여행·일정 · **방문 기록·사진 메타·메모**(U5) · **회고·요약·스타일 분석**(U5) · 알림함 · (U7 개통 시) 커뮤니티 공개 콘텐츠·좋아요·댓글 |
| **BR-U6-26** | 삭제는 **유예 상태로 들어간다**(`POST /me/deletion` → `DELETION_PENDING`, **GPS 즉시 파기**). 유예 내 철회는 `DELETE`. 유예 규칙 자체는 **U0 소유** |
| **BR-U6-27** | 닉네임·이메일 조회·수정과 **데이터 내보내기**를 제공한다. ⚠ 내보내기는 **엔드포인트가 없다**(G-U6-3) — 없는 기능을 되는 것처럼 그리지 않는다 |
| **BR-U6-28** | 취향 수정은 `PUT /me/preferences`로 저장하고 **다음 AI 일정 생성·재계획 입력에 반영**한다. **직접 설정값이 자동 분석 스타일보다 우선**한다(US-NOTIF-10) |
| **BR-U6-29** | 위치 동의 화면의 **토글 하나가 L2(법정)·L3(GPS 옵트인)를 함께** 움직인다(DEC-U6-11). L1(OS 권한)은 선결 조건이라 토글이 아니다 |
| **BR-U6-30** | 철회 **직전에** 영향을 구체 고지하고 재확인한다 — 이동 지연 알림 중단 · 실시간 Plan-B 제한 · 현위치 추천 비활성. 철회 후에도 **예정 일정 알림·날씨/휴무 트리거는 계속 동작**한다 |
| **BR-U6-31** | OS 위치 권한이 거부면 앱 내 토글을 **비활성**하고 설정 이동을 안내한다(`l06 permission-denied`) |
| **BR-U6-32** | 제휴 고지 시트 자체는 **U1 소유**다(`BR-U1-30`). U6는 건드리지 않는다 |
| **BR-U6-33** | "다시 보지 않기"는 **계정 단위 서버 저장**이고 `l05`의 `외부 이동 시 제휴 안내 다시 보기` 토글로 **재활성화**할 수 있다(DEC-U6-7a). 기기 로컬로 두지 않는다 — 설정에 있는 값이 기기마다 다르면 사용자 모델이 깨진다 |

## PBT (property-based · 블로킹 게이트)

| ID | 성질 |
|---|---|
| **PBT-U6-1** ★ | **catch-up 누락 0** — 임의의 이벤트 열과 임의의 푸시 성공/실패 조합에 대해, `since=0`으로 조회하면 **적재된 모든 알림이 정확히 한 번씩** 나온다 |
| **PBT-U6-2** | **디스패치 멱등** — 같은 `outbox_event`를 N번 디스패치해도 `notification` 행은 1개다(`source_event_id` UNIQUE) |
| **PBT-U6-3** | **토글 불변식** — 어떤 토글 조합에서도 `kind=SYSTEM` 알림은 항상 적재된다. 그리고 어떤 조합에서도 `SYSTEM` 토글 레코드는 생성되지 않는다 |
| **PBT-U6-4** | **스케줄 재계산** — 임의의 일정 변경 열에 대해, 발화되지 않은 스케줄 중 **일정 시각이 이미 지난 것은 발화되지 않는다**(INV-U6-09) |
| **PBT-U6-5** | 어떤 알림 본문에도 **소요시간 필드·문자열이 없다**(INV-3 · BR-U6-05) |

## 미결 (O-U6-\*)

| ID | 미결 | 왜 지금 못 정하나 |
|---|---|---|
| **O-U6-1** | **당일 오전 알림 시각의 사용자 변경 가능 여부** — 기본 8시는 정해졌으나 `l02`에 시각 선택 UI가 없다 | 디자인 확인. 고정으로 가면 규칙은 단순해진다 |
| **O-U6-2** | **전역 빈도 상한 수치** — 시간당 몇 건인가 | 인셉션에 값이 없다. 실사용 관측 후 결정이 정확하다 |
| **O-U6-3** | **인앱 토글 OFF일 때 알림함 표시 여부** — 적재는 하는데(BR-U6-15) 목록에서 감추나 | `l02`의 "인앱" 토글이 *수신*을 끄는지 *배너*만 끄는지 화면으로 못 가른다 |
| **O-U6-4** ★ | **야간 조용시간** — 푸시를 여는 이상 필요하다. 스토리에 없다 | 국내 야간 발송 관행·`/me/marketing-consent`(실재)와의 경계 판단이 필요. **정보성 알림도 심야에 울리면 이탈 요인** |
| **O-U6-5** | 제휴 "다시 보기" 값의 저장 위치 — `/me/preferences` 확장 vs `account_setting` 신설 | `/me/preferences`가 "여행 취향" 의미로 좁게 정의됐는지 U0 계약 확인 필요 |
| **O-U6-6** | `SLOT_PRE` 간격(0/15/30/60) 선택 UI 부재 | 디자인 확인(G-U6-5). 기본 30분으로 동작은 가능 |
