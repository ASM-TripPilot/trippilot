# U4 In-trip & Plan-B — Business Rules

> 규칙 우선순위는 U2·U3와 동일: **실장 우선 → 양쪽 실장이 다르면 문서가 결정 → 불변식은 개정 대상 아님.**
> 솔버 내부 규칙(HC1~HC4·시한·결정론)은 U2 경계 뒤 — 여기서 다루지 않는다.
> U0·U1·U2·U3의 BR은 전부 승계한다. 아래는 **U4가 새로 정하는 것만**이다.

## 1. 트리거 감지 (C9 · US-PLANB-02)

| ID | 규칙 |
|---|---|
| **BR-U4-01** | 트리거 종류는 **`WEATHER`·`CLOSURE`·`DELAY`·`MANUAL` 4종뿐**이다. 새 종류를 백엔드가 임의로 늘리지 않는다 — ai `TriggerKind`가 정본(DEC-U4-4). '체류 초과'는 `DELAY`의 payload 변형이고, '교통'은 **존재하지 않는다** |
| **BR-U4-02** | 감지는 **여행 날짜 구간(시작~종료) 안에서만** 동작한다. 구간 밖에서는 어떤 트리거도 만들지 않는다 |
| **BR-U4-03** | 감지 신호는 클라가 모으고 **판정은 서버가 한다**(DEC-U4-6). 클라는 임계값을 알지 못하며, 자체 판단으로 배너를 띄우지 않는다 |
| **BR-U4-04** | 앱이 꺼져 있을 때의 감지는 **지오펜스 진입 이벤트가 앱을 깨운 그 순간 1회**만 수행한다. 주기 백그라운드 실행·서버 스케줄러는 없다 |
| **BR-U4-05** | **외부 API가 실패하면 트리거를 만들지 않는다**(무발화). 실패는 관측에만 남기고, 화면은 수동 경로만 유지한다. 만료된 캐시로 발화하지 않는다 |
| **BR-U4-06** | 트리거는 **남은 일정에 실제로 닿을 때만** 유효하다 — 이미 지난 슬롯·완료된 슬롯만 건드리는 신호는 폐기한다 |
| **BR-U4-07** | **동일 `kind` × 동일 `slotKey`는 1회**만 발화한다. 재발화하려면 억제가 만료되거나 대상 슬롯이 바뀌어야 한다 |
| **BR-U4-08** | 전역 빈도 상한과 민감도(`LOW`·`NORMAL`·`HIGH`)를 **감지 단계에서** 적용한다. 화면 단계에서 거르지 않는다(INV-U4-02) |
| **BR-U4-09** | 트리거는 **제안까지만** 한다. 어떤 트리거도 일정을 자동으로 바꾸지 않는다 — 사용자가 [대안 보기]를 눌러야 재계획이 시작된다 |

> **[이연 · 2026-10-12 → U10] BR-U4-04.** "앱이 꺼져 있을 때 지오펜스 wake 1회 판정"은 U10 "GPS·위치 자동화"(미구현) 소관이다. 현행은 앱 켜짐 경로뿐이고 지오펜스는 `frontend/src/shared/location/geofence.ts` degrade 스텁이다. 나머지 BR-U4-01~09(서버 판정·무발화·억제)는 `backend/modules/planb-detection/`에 실재한다.

> **[개정 · 2026-10-12 · U10 FD] BR-U4-03·04.** BR-U4-04("앱이 꺼져 있을 때의 감지는 지오펜스 wake 1회 · 서버 스케줄러 없음")는 **폐기**한다 — 기기는 wake에서 Plan-B 평가를 요청하지 않고 방문 결과만 보낸다. `DELAY`는 서버가 `VisitChecked` 구독 + **서버 스케줄러**로 파생한다(U10 DEC-U10-9 · BR-U10-23~28). BR-U4-03("클라는 임계를 모르고 판정은 서버")은 `DELAY`에 대해 **더 강하게** 성립한다 — 클라는 신호조차 만들지 않는다. 단 도착·완료 **판정**은 기기가 한다(U10 DEC-U10-8 — Plan-B 판정과 다른 층).

> **[개정 · 2026-10-19 · situation-awareness FD]** BR-U4-01~09 · DEC-U4-4 — 서버 감시 스윕과 트리거 수명
> 규칙 본문은 situation-awareness FD 에 있다. 위 U10 블록(`DELAY`)과 함께 읽는다.

> - **BR-U4-06**: 지난 대상의 만료(원인 4종 — `WEATHER`·`CLOSURE` 만)와 해제(그 트리거를 띄운 감지기가 해제 임계 아래로 확인 — 이력 현상)가 생긴다. → [BR-SA-06·07](../../situation-awareness/functional-design/business-rules.md)
> - **BR-U4-07**: 1회의 단위가 대상 (kind, affectedDate, slotKey)당 `ACTIVE` 1개로 바뀐다. 변화는 제자리 갱신(triggerId 유지)이고, 다시 알리는 것은 알린 최고 심각도를 넘을 때뿐이며, 같은 위험이 연일 반복되면 둘째 날부터 배너만 띄운다. → [BR-SA-05·08 · O-SA-11](../../situation-awareness/functional-design/business-rules.md) · [INV-SA-4](../../situation-awareness/functional-design/domain-entities.md)

## 2. 재계획 진입·지시 입력 (US-PLANB-01·12 · `i10`)

| ID | 규칙 |
|---|---|
| **BR-U4-10** | 재계획은 **여행 구간 안이면 언제든** 수동으로 시작할 수 있다. 트리거가 없어도, 등록 숙소가 0이어도 가능하다 |
| **BR-U4-11** | 바꿀 범위는 **`지금 이후`(`PARTIAL_SLOTS`) · `오늘 전체`(`FULL_DAY`) 2종뿐**이다. 다일 재계획은 제공하지 않는다(DEC-U4-3) |
| **BR-U4-12** | 사유(`왜`)·방향(`어떻게`)은 **다중 선택**이며 **전부 선택 사항**이다. 하나도 고르지 않아도 재계획을 시작할 수 있다("그냥 바꾸고 싶어요"가 그 경로) |
| **BR-U4-13** | 자유 텍스트는 **선호 가중치 입력**이다. 텍스트에서 뽑은 장소를 후보로 승격하지 않는다 — 후보 풀은 U1 closed-set 그대로(INV-1) |
| **BR-U4-14** | 자유 텍스트가 이 여행에서 바꿀 수 없는 요청(여행지·날짜 변경 등)이면 **거절하고 사유를 말한다**(`i10 · 범위 밖`). 조용히 무시하거나 임의로 해석하지 않는다 |
| **BR-U4-15** | `i10`의 감지 배너 `[끄기]`는 **억제 레코드를 만든다**(§`plan_b_suppression`). 화면에서 배너만 감추는 동작이 아니다 |
| **BR-U4-16** | `[직접 고르기]`(수동 편집)는 **API 오류가 아니어도** 항상 선택 가능하다(US-PLANB-12) |

> **[개정 · 2026-10-12] BR-U4-11 — 범위 2종·하루 단위는 그대로, 대상 일자는 오늘이 아니어도 된다.** `오늘 전체`(`FULL_DAY`)는 "고른 날 전체"로 읽는다. 오늘이 아닌 날짜에는 `지금 이후`(`PARTIAL_SLOTS`)가 없다(서버 400 · 앱은 칩을 `{N}일차 전체`(일차를 모르면 `이 날 전체`) 하나로 줄인다). 다일 재계획은 여전히 없다. 근거·경계는 `business-logic-model.md` 의 DEC-U4-3 개정 블록(TRIP-1182·TRIP-1195).

> **[개정 · 2026-10-19 · situation-awareness FD]** BR-U4-10 · 13 · 15
> - **BR-U4-10**: 트리거로 들어온 재계획은 서버가 대상 일자를 그 트리거 날짜로 강제한다. 여행 시작 전날에는 트리거로 들어온 첫날 `FULL_DAY` 재계획만 연다(지평 `pre-trip`). 트리거 없는 진입은 여행 구간 안에서만이다. → [BR-SA-20](../../situation-awareness/functional-design/business-rules.md) · [DEC-SA-7](../../situation-awareness/functional-design/business-logic-model.md)
> - **BR-U4-13**: "텍스트에서 뽑은 장소를 후보로 승격하지 않는다"는 AI 재계획 실장과 어긋난다 — 뽑은 장소명은 등록 POI 이름 대조·지도 실재·그날 영업을 모두 통과한 것만 필수 방문이 되고 풀에 합류한다(`ai/src/trippilot/agents/planb/request_verification.py` · `ai/src/trippilot/api/wiring.py:2316-2329`). 후보는 여전히 등록 POI 뿐이다(INV-1). 기회 카드의 [넣어서 다시 짜기]가 이 경로를 쓴다. → [BR-SA-22](../../situation-awareness/functional-design/business-rules.md)
> - **BR-U4-15**: [끄기] 억제는 끈 트리거의 날짜·심각도까지 적는다 — 주의를 끈 것이 같은 날 위험 격상을, 오늘을 끈 것이 내일 대상을 막지 않는다. 허브 알약의 ×는 서버 억제가 아니라 기기 로컬 숨김(TRIP-748 D3)이다. → [BR-SA-09](../../situation-awareness/functional-design/business-rules.md)

## 3. 재계획 산출·검증 (US-PLANB-03·04·05·07)

| ID | 규칙 |
|---|---|
| **BR-U4-17** | 재계획 입력은 **현재 위치 · 현재 시각 · 남은 슬롯 · 완료 슬롯 · 시각 고정 슬롯 · 등록 숙소 앵커 · 영업시간 · 이동 거리**다. `fromInstant` 이전은 대상이 아니다 |
| **BR-U4-18** | **완료 슬롯 · 시각 고정 슬롯 · 등록 숙소 체크인/아웃은 불변**이다. 항상 `lockedSlotKeys`로 넘겨 `FixedBlock`(HC3) 보호를 받게 한다. 숙박 예약 자체는 어떤 경우에도 바꾸지 않는다(ADR-0006) |
| **BR-U4-19** | 현재 위치가 없으면 **기준점 사다리**(실측 → 수동 입력 → 마지막 완료 방문지 → 숙소 앵커)로 내려가되, **차단하지 않고** 어떤 가정을 썼는지 화면에 표기한다 |
| **BR-U4-20** | 산출물은 **단일 재계획안 1개**다. 일정 단위 대안 2~3안을 만들지 않는다(DEC-U4-1) |
| **BR-U4-21** | 재계획안의 시각·순서는 **솔버 검증값만**이다(INV-2). 백엔드·클라가 시각을 재계산하지 않는다 |
| **BR-U4-22** | 슬롯 후보 교체는 **U3 `proposeSlotCandidates`를 그대로 호출**한다. 직전 슬롯 자리에 **현재 위치**를 넣는 것이 유일한 차이다 |
| **BR-U4-23** | 후보 표시는 **추천 이유 · 현재 위치로부터 거리 · 이동 수단 · 다음 고정까지 여유**를 갖춘다. **소요시간은 표시하지 않는다**(INV-3) |
| **BR-U4-24** | '여유 시간'은 **두 확정 시각의 차**로 계산한다(`다음 고정 슬롯 시각 − 현재 시각`). 슬롯의 도착 예정 시각을 새로 추정해 노출하는 것과 다르다 |
| **BR-U4-25** | 일부 방문지를 더 못 넣으면 **제외·이월 항목을 명시**하고 확정 전에 동의를 받는다. 조용히 빼지 않는다. **개정(2026-10-14)**: 일정 화면 [다시 짜기] **원탭**은 사전 동의 단계가 없다(사용자 결정 — 누르는 행위가 동의, BR-U4-28 개정 주). 빠진 곳은 적용 전 복원 지점으로 되돌릴 수 있다 — **단, 확정 일정은 지금 복원이 409 라 되돌릴 수 없다**. 적용 뒤 제외 항목을 보여 주는 표면은 **아직 없다** — 후속 TRIP-1412(BE: 적용된 세션 diff·확정 일정 되돌리기)·TRIP-1413(FE: 빠진 곳 표시·[되돌리기]) |
| **BR-U4-26** | 제약을 만족하는 안이 0개면 **`남은 방문지 1개 건너뛰기` · `휴식 모드로 전환` · `수동으로 일정 수정` 3옵션과 사유 한 줄**을 제시한다. 어느 진입 경로(AI/직접)에서든 **대칭으로** 제시한다. **개정(2026-10-14)**: [다시 짜기] **원탭**은 해가 없으면 **원 일정을 그대로 두고 안내 한 줄 + [닫기]** 로 끝낸다(아무것도 쓰지 않는다). 3옵션은 사유를 고르는 명시적 재계획(허브·트리거·알림·어시스턴트 → i10) 경로에서 그대로 제시한다 |
| **BR-U4-27** | 휴식 모드는 **재개 시각 입력 또는 즉시 재개** 뒤 남은 일정을 다시 재정렬 대상으로 삼는다 |

> | 휴무 `TEMP_CLOSED` → `closed` · 예약 마감 `FULLY_BOOKED` → `fully_booked` · `canceled` | `NEARBY` | — | — | 근처 새 스팟으로 대체. 대상 장소 제외는 `excluded_poi_ids` 가 한다 |
> | 그냥 `JUST_CHANGE` → `none` · 미지 | — | — | — | 변화 없음 |

> - **경로 감점**(`ItineraryProblem.travel_weight`, 점수/도로 km — 표 `_REASON_ROUTE_WEIGHT`)은 조립 **선택**에 이동 비용을 넣는다. `LESS_MOVE` 는 앵커에서 먼 *후보* 를 내릴 뿐이고 재정렬(B)은 고른 집합 안의 순서만 바꿔서, 흩어진 후보끼리 오가는 경로는 못 줄였다(2026-10-13 실스택 부산: 피로 26.1 → 30.1km, 우천 51.8km). OR 은 지나는 아크마다 −w×km, 규칙 폴백은 지금 위치에서의 km×w 를 뺀 순서(같은 의미의 그리디판). 사유가 여럿이면 최댓값, 사용자 칩 `LESS_MOVE` 도 0.05. 감점은 축 판정(아래 사용자 우선)과 별개다 — 사용자가 거리 축을 `NEARBY` 로 정해 암시 `LESS_MOVE` 가 빠져도 감점은 남는다(같은 방향이라 사용자 지시와 부딪히지 않는다). 목적식 항이라 가해 여부는 바꾸지 않고, 조립의 재시도(pace 무보정·몰아주기)는 이것도 끄고 푼다. 재정렬(B)은 감점을 뺀 소프트 항 합을 A 값 이상으로 묶는다 — 거리를 줄이려 식사창을 내주지 않는다. 기본 0 — 자유 생성 무영향. A 가 OPTIMAL 이면 같은 풀·시드에서 켠 경로 ≤ 끈 경로가 풀마다 성립하고, 결정론 한도에 끊긴 큰 풀은 집계로만 성립한다.
> - **방문 상한 원−1**(`ItineraryProblem.max_visits_per_day` — 표 `_REASON_VISIT_CAP`)은 그 하루 방문 수를 "원 일정 중 아직 안 지난 방문 수 − 1"(최소 1)로 묶는다. 느긋한 속도(체류 ×1.4)만으로는 방문이 줄지 않았다 — 경로 감점이 줄인 이동 시간과, 액티비티·자연(긴 체류)을 카페·쇼핑(짧은 체류)으로 바꾼 회피가 늘어난 체류를 덮었다(2026-10-13 실스택 부산: 원 6곳 → 피로 7곳·15.0km, 조립은 OR 1차 해 — pace 무보정 재시도 0건). 고정·잠금·필수 방문은 상한에 **세되 빼지 않는다** — 상한은 자유 방문 몫만 깎는다(그것만으로 넘치면 자유 방문 0). 지난 잠금과 재계획 시작 시각 전에 끝난 슬롯(FULL_DAY 는 놓친 슬롯이 잠기지 않은 채 온다)은 세지 않고, 원 일정이 비면 상한도 없다. 사용자 "한 곳 추가"(`ADD_CAFE`·`ADD_FOOD`)는 필수 방문으로 올라가 상한 **안에서** 센다 — 피로면 총 방문은 그대로 원−1 이고 그 한 곳이 다른 자유 방문을 대신한다. OR 은 자유 방문 불리언 합 ≤ 몫, 규칙 폴백은 몫에서 삽입 중단(같은 의미). pace 와 달리 하드라 조립 재시도도 끄지 않는다. 사용자 칩 `FILL_MORE` 가 있으면 생략(사용자 우선). 걸리면 노트 `planb_visit_cap: <상한>`. 기본 None — 자유 생성 무영향.

> - **[추가 · 2026-10-14] 다시 짜기가 바꿀 정도는 요청 종류가 정한다.** 한 곳 추가(맛집·카페 칩, "카페 가고 싶다")면 남은 일정은 그대로 두고 그 한 곳을 더한다 · 장소 사유(휴무·만석·취소)뿐이면 그 곳만 바꾼다 · 하루 방향 지시·사유(실내로·피로·날씨·자유 입력)면 맞지 않는 곳만 바꾼다 · 사유도 요청도 없으면 절반 이상 새 곳으로. 종류는 코드가 정해 구성 프롬프트에 한 줄로 싣는다(AI `agents/planb/composition.change_rule`). **진행 중인 방문**(시작은 지났고 끝은 안 지남)은 제외 대상이 아니면 그 시각 그대로 남긴다 — BE 는 바꿀 수 있게 잠그지 않고 보내지만 AI 는 지금 이후만 채워 그 곳이 사라졌다. 장소 사유인데 제외 대상을 안 보냈으면 잠그지 않는다. 남긴 곳은 고정 표시 없이 나간다(노트 `in_progress_kept: <n>`).

> - **[추가 · 2026-10-19] 솔버가 뺀 곳은 까닭과 함께 구성 LLM 에 한 번만 되묻는다**(2026-10-18 사용자 승인 — 반복이 아니라 1회 수리). 다시 짜기에서 구성 LLM 이 고른 곳을 조립이 못 놓으면, 그 까닭(그날 휴무·영업시간 밖·너무 멂·시간 부족)과 지금 해의 빈 시간을 붙여 **그 빈 틈에 그대로 드는 후보만** 주고 대신할 곳을 다시 고르게 한 뒤 한 번 더 푼다. 2차 해는 **1차에 놓인 곳을 하나도 잃지 않고 더 많이 놓으며 조립 단계를 낮추지 않을 때만** 채택한다 — 아니면 1차 그대로. 이름으로 집은 곳·밤 일정 지시로 넣은 곳만 빠졌으면 되묻지 않고(다른 곳을 골라도 그 요청은 안 채워진다), 솔버 밖에서 원 시각 그대로 되실릴 잠금이 있는 날도 되묻지 않으며(되싣기가 겹치는 새 방문을 빼서 채택 판정이 사용자가 보는 일정과 어긋난다), 재계획 시한(25s)에 구성 바닥 5s + 조립 바닥이 남지 않으면 건너뛴다. 못 하면 노트(`llm_repair_skipped`·`llm_repair_fallback`)와 폴백 이벤트로 밝힌다(INV-4). 시각·순서는 여전히 조립값(INV-2), 후보는 같은 closed-set(INV-1). 정본 AI `api/wiring.py` `_repair_day`.
> - **다중 사유는 합집합**이다. PlanB 에 주는 대표 사유 하나는 우선순위 `weather > closed > fully_booked > canceled > delay > fatigue` 로 고른다(못 가는 사유가 사용자 사정보다 앞).

| **BR-U4-35** | 지연·비 예보 같은 상황 변화는 **배너 문구로만** 알린다. 슬롯의 시각 숫자를 흔들지 않는다 |
| **BR-U4-36** | 자동 도착 감지는 **지오펜스 진입**으로만 한다. 위치 권한이 없거나 정확도가 낮으면 **수동 체크인으로 대체**하고 자동 감지를 보류한다 |
| **BR-U4-37** | 방문 완료는 **실제 체류(`completedAt − arrivedAt`)를 산출**해 `DELAY` 트리거 입력으로 넘긴다. 이 값을 사용자 화면에 체류 시간으로 표시하지 않는다 |
| **BR-U4-38** | 사진·메모 버튼은 **표시하되 동작하지 않는다**(U5 소관, DEC-U4-10). 눌렀을 때 오류를 내지 않는다 — 준비 중임이 드러나는 처리를 한다 |
| **BR-U4-39** | 다음 예정지 정보는 **거리 + 이동 수단**만이다. 실제 길안내는 **외부 지도앱에 위임**하고, 복귀 시 활성 일정으로 매끄럽게 돌아온다 |
| **BR-U4-40** | 현재 장소 상세의 결측 항목은 **빈칸이 아니라 "미확인"**으로 표기한다 |
| **BR-U4-41** | 실제 경로는 **앱을 켜 둔 구간만** 기록되며, 그 한계를 화면에 명시한다. **걸음 수는 기록·표시하지 않는다** |
| **BR-U4-42** | 위치 동의가 없으면 실제 경로 레이어를 **비활성 + 사유 표기**하고 계획 동선만 보인다 |

> **[이연 · 2026-10-12 → U10] BR-U4-36·41·42.** 지오펜스 자동 도착(BR-U4-36의 자동 부분)과 실제 경로 기록·레이어(BR-U4-41·42, US-PLANB-13)는 U10 소관이다. BR-U4-36의 "권한이 없으면 수동 체크인으로 대체"는 현재 **상시 동작**이다(`frontend/app.config.ts` '항상 허용' off — TRIP-936). BR-U4-41의 "걸음 수 기록·표시 금지"는 U4에 그대로 유효하다.
> **[개정 · 2026-10-12] BR-U4-38 — 사진·메모는 동작한다.** U5 구현과 TRIP-939(숨김 기능 복원 결정)로 방문 사진·메모가 기능화됐다 — `frontend/src/features/attach-visit-media/`(`pickPhotoForVisit.ts`·`useVisitMemo.ts`·`MemoInline.tsx`). "버튼만, 동작 없음"은 낡은 서술이다.

> **[개정 · 2026-10-12 · U10 FD] BR-U4-36·37·41.**
> - **BR-U4-36**: 자동 도착 감지는 여전히 지오펜스 진입으로만 하되 임계가 정해졌다 — 반경 150m · 정확도 100m 초과 표본은 근거로 쓰지 않음 · 진입 후 3분 체류로 확정(도착 시각 = 진입 시각). "권한이 없거나 정확도가 낮으면 수동 대체"는 그대로다(U10 BR-U10-12~15). when-in-use 사용자는 수동 체크인 사용자다(포그라운드 자동 없음 — Q1=B).
> - **BR-U4-37**: "방문 완료는 실제 체류를 산출해 `DELAY` 입력으로 넘긴다"를 **개정**한다. ① 완료는 수동만이 아니다 — 이탈 자동 완료(`AUTO_GEOFENCE_EXIT`)·다음 도착 시 직전 완료(`AUTO_NEXT_ARRIVAL`)가 생기고 `visit_check.completion_source`가 출처를 남긴다(Q2=A·Q6=A). ② **`AUTO_NEXT_ARRIVAL` 완료의 체류는 이동 시간을 포함하므로 `DELAY` 체류 초과 입력에서 제외**한다. ③ 체류 초과는 완료 시점(`VisitChecked` 구독)과 진행 중(서버 스케줄러, 무장 여행만) 두 갈래로 판정한다. "체류를 화면에 표시하지 않는다"는 그대로(U10 BR-U10-24·25·26).
> - **BR-U4-41**: "실제 경로는 앱을 켜 둔 구간만"은 **개정** — 무장(always + 정확 + 동의 + 여행 구간 + 플래그) 동안 백그라운드 저전력 연속 기록, 하루치 다운샘플만 서버 저장(U10 BR-U10-33~41). **"걸음 수는 기록·표시하지 않는다"는 유효**하다.

> **[개정 · 2026-10-19 · situation-awareness FD]** BR-U4-35 — 상황 문구 규칙
> 문구로만 알리고 슬롯 시각을 흔들지 않는다는 원칙은 그대로다. 상황 문구는 공용 가드를 지난다: 200자 이하, 상대 날짜어·소요시간·좌표 금지(장소명 자리는 비우고 검사), 단정하지 않는 표현. 기상청·에어코리아 자료는 출처를 함께 보인다(공공누리 1·3유형).

> **[개정 · 2026-10-12] PBT-U4-1 주석 — 경로 변경.** 재계획은 ai `regenerate` 직결이 아니라 `POST /ai/v1/planb/replan`(와이어 `locked_blocks`·`current_slots`)이다. "AI 쪽에서 이미 성립"의 근거는 이제 replan 경로의 조립 결과로 확인해야 한다 — 이 개정에서 재검증하지 않았다.
