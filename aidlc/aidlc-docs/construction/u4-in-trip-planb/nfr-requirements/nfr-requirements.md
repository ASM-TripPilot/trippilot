# U4 In-trip & Plan-B — NFR Requirements

> **방침**: 얇게. U0·U1·U3 NFR과 상속 기반선(50 RPS · 99.9% · 재시도 없음 · 서킷 분리 · stale-if-error · security-baseline Full · PBT blocking)은 **그대로 승계**하고 여기 다시 적지 않는다.
> **FD 중복 금지**: 무발화(BR-U4-05) · 감지 단계 억제(08) · 확정 전 무변경(28·32) · 시각 재추정 없음(34·35) · 연속 추적 없음·걸음 수 없음(41) · 수동 전환 폴백(43·45) · 기준점 사다리(19)는 **`business-rules.md`가 정본**이다.
> **결정 근거 (2026-08-09)**: U3 선례대로 **실장을 먼저 확인하고 실장을 우선**했다. 실장 확인 결과는 각 요구의 "실장 / 근거" 열에 그대로 적는다. 답변 = Q1~Q6 전부 추천안(A).

---

## 0. 이 유닛에서 새로 생기는 축

U0~U3에 없던 것은 **모바일 기기 자원**(배터리·권한·네이티브 빌드)과 **위치 데이터의 법적 처리**다. 나머지는 대부분 상속이다.

---

## 1. 모바일 기기 (NFR-U4-MOBILE) — 이 스테이지를 도는 주된 이유

**실장 확인 결과**: `expo-location ~19.0.8`은 있으나 **`expo-task-manager`가 없고**, `app.config.ts`의 `expo-location` 플러그인은 **`locationWhenInUsePermission` 하나만** 설정돼 있다. 지오펜스는 이 둘이 다 갖춰져야 동작한다.

| ID | 요구 | 실장 / 근거 |
|---|---|---|
| **MOBILE-U4-01** | 지오펜스 도입에 **`expo-task-manager` 의존 1개**를 추가한다. `startGeofencingAsync`는 `TaskManager.defineTask` 없이 동작하지 않는다 | **실장 부재 확인** — `frontend/package.json`에 없음 |
| **MOBILE-U4-02** | `app.config.ts`의 `expo-location` 플러그인에 **`locationAlwaysAndWhenInUsePermission` + Android 백그라운드 위치 플래그**를 추가한다. 이 변경은 **네이티브 설정이라 OTA 불가 — EAS 재빌드가 선행**된다 | 실장: 현재 `locationWhenInUsePermission`만 |
| **MOBILE-U4-03** | **'항상 허용' 거부는 정상 경로다.** 거부 시 앱은 수동 체크인 + 수동 위치 입력으로 강등되고 **어떤 기능도 막히지 않는다**. 권한 요청 실패를 오류로 처리하지 않는다 | BR-U4-36·19 · Q1=A |
| **MOBILE-U4-04** | 지오펜스 리전은 **다음 예정지 위주로 소수만** 등록한다(iOS 20 · Android 100 상한). 상한 초과 시 선택 정책이 필요하다 — **O-U4-1 미결** | 플랫폼 제약 |
| **MOBILE-U4-05** | **연속 위치 추적을 켜지 않는다.** 배터리 예산의 근거가 여기 있다 — 지오펜스는 셀타워·와이파이 기반이라 연속 GPS 대비 소모가 한 자릿수 %다 | DEC-U4-7 |
| **MOBILE-U4-06** | 만보계·모션 센서 권한을 **요청하지 않는다** | DEC-U4-8. `expo-sensors` 미설치 유지 |
| **MOBILE-U4-07** | 지오펜스 wake에서 하는 일은 **평가 요청 1회 + 필요 시 로컬 알림**뿐이다. 깨어난 김에 동기화·프리페치를 하지 않는다 | wake 예산은 OS가 짧게 준다 |

## 2. 성능 (NFR-U4-PERF)

| ID | 요구 | 실장 / 근거 |
|---|---|---|
| **PERF-U4-01** | **포그라운드 트리거 평가는 이벤트 기반 — 주기 폴링 없음.** 평가 요청 시점 = ① 여행 중 화면 진입 ② 앱 포그라운드 복귀 ③ 슬롯 경계 통과 ④ 방문 체크 직후 | Q2=A. **실장 근거 없음**(U0~U3 어디에도 폴링 주기 없음) → 상황이 실제로 바뀌는 순간에만 묻는다 |
| **PERF-U4-02** | 여행 중 화면의 지도는 **WebView 1장**을 넘지 않는다. `일정 ⇄ 지도` 전환은 **데이터 재요청 없이** 로컬 상태 전환 | PERF-U3-03·04 승계 |
| **PERF-U4-03** | 재계획 응답 예산은 **U3 생성보다 짧게** 잡는다 — 범위가 하루 이내이므로. 구체값은 **O-U4-4 미결**(생성 day1 5s·전체 20s가 상한선) | BR-U3-03 승계 · 미결 유지 |
| **PERF-U4-04** | 실제 경로 폴리라인은 **표시 전 다운샘플링**한다(화면 픽셀 밀도 기준). 원본 점열을 그대로 WebView에 넘기지 않는다 | 하루 수백~수천 점 가능 |
| **PERF-U4-05** | 도착 체크는 **낙관적 갱신**으로 즉시 반영하고 실패 시 되돌린다. 서버 왕복을 기다려 UI를 막지 않는다 | 현장에서 회선이 나쁠 수 있다 |

## 3. 비용·외부 호출 (NFR-U4-COST)

| ID | 요구 | 실장 / 근거 |
|---|---|---|
| **COST-U4-01** | **열린 재계획 세션이 있으면 같은 여행의 새 요청을 409로 거부**한다. 임의 쿨다운 상수를 만들지 않는다 | COST-U3-01 형태 승계 · INV-U4-06이 이미 요구 |
| **COST-U4-02** | 날씨는 **`(격자, 발표시각)` 단위로 캐시**한다. TTL = 다음 발표까지(기상청 단기예보 3시간 간격). 캐시 저장소는 **DB 테이블 `weather_snapshot`** | Q4=A. Redis는 U1이 결정만 하고 **미도입**(`libs.versions.toml` 부재 확인) — 여기서 끌어오지 않는다 |
| **COST-U4-03** | 날씨 조회 대상은 **여행 중인 사용자의 당일 격자만**이다. 동시 사용자가 늘어도 호출은 **격자 수만큼만** 는다 | 〃 |
| **COST-U4-04** | 영업시간·휴무는 **C7(U1) 정본 조회**다 — U4가 외부 POI API를 직접 부르지 않는다 | 소유 경계 |
| **COST-U4-05** | 거리 추정은 `TravelEstimatePort` 승계. U4가 별도 지도 API 예산을 만들지 않는다 | U1 소유 |
| **COST-U4-06** | LLM 상한은 **C1 실장값 승계**(`max_tokens`·`temperature`·`timeout_sec`). U4가 별도 상한을 만들지 않는다 | COST-U3-04 승계 |

## 4. 데이터·법적 처리 (NFR-U4-DATA / LEGAL) ★

**실장 확인 결과**: `V1.3__auth_location.sql`에 **위치 동의 3층**(`os_permission_mirror` L1 · `legal_consent` L2 · **`gps_recording_opt_in` L3**)과 **append-only `location_legal_log`**(`event_type`에 `COLLECTION`·`USE`·`PURGE`, `detail`에 **원시 좌표 미포함**)가 이미 있다.

| ID | 요구 | 실장 / 근거 |
|---|---|---|
| **LEGAL-U4-01** | 실제 경로 기록은 **기존 L3 동의(`gps_recording_opt_in`)에 걸린다.** 새 동의 축을 만들지 않는다 | **실장 승계** |
| **LEGAL-U4-02** | 법정 로그는 **수집 구간(세션) 시작·종료에 각 1건**(`COLLECTION`)만 남긴다. 좌표 점마다 남기지 않는다 — 점 수만큼 행이 폭증한다 | Q3=A |
| **LEGAL-U4-03** | `location_legal_log.detail`에는 **구간 시각·점 개수·목적**만 싣는다. **원시 좌표 금지**(스키마 주석이 이미 요구) | 실장 |
| **LEGAL-U4-04** | 동의 철회 시 **이후 수집 즉시 중단** + `CONSENT_REVOKED` 로그. 기존 점열 파기 시 **`PURGE` 로그**를 남긴다 | `event_type` 실재값 사용 |
| **LEGAL-U4-05** | 재계획에 쓰는 **일회성 현재 위치**는 `actual_route_point`에 적재하지 않는다 — 세션 입력으로만 쓰고 세션 종료 시 사라진다. L3 동의가 없어도 재계획은 가능해야 하기 때문(BR-U4-19) | 동의 축 분리 |
| **DATA-U4-01** | 실제 경로 좌표는 **최소 이동 거리 기준 샘플링**(예: 50m). 정확도 임계 미달 점은 **폐기**한다 | Q3=A. 임계값은 설정값 — 초기값 제안 50m·accuracy 100m, **근거 없는 초기값** |
| **DATA-U4-02** | 실제 경로 보존은 **여행 종료 후 N일**, 이후 파기 + `PURGE` 로그. N은 설정값 — 초기값 제안 90일, **근거 없는 초기값** | U5 기록 승계 시 재평가(G-U4-5) |
| **DATA-U4-03** | `plan_b_trigger`는 **발화하지 않은 판정도 기록**한다(무발화의 근거). 대신 **여행 종료 후 정리 대상**이다 | INV-U4-01 |
| **DATA-U4-04** | `replan_session`의 `draft`(json)는 **세션 수명 동안만** 유지한다. 확정분은 `change_log_entry`·`itinerary_revision`이 이미 남기므로 중복 보관하지 않는다 | DEC-U4-11 |
| **DATA-U4-05** | 만료된 `replan_session` 정리는 **기존 `StalePartialSweeper` 패턴을 재사용**한다 | **실장**: `AsyncConfig.kt`에 `@EnableScheduling` 실재 — 신규 스케줄링 인프라 0 |

## 5. 관측 (NFR-U4-OBS)

**실장 확인 결과**: backend actuator(`health,info,metrics`) + OTLP 엔드포인트가 이미 배선돼 있다. U4는 **지표 이름만** 더한다.

| ID | 요구 | 실장 / 근거 |
|---|---|---|
| **OBS-U4-01** | **무발화를 관측 가능하게** 한다 — 판정 총수 대비 발화 수, 무발화 사유별 분류(임계 미달·억제·외부 실패·영향 없음). "왜 알림이 안 왔나"에 답할 수 있어야 한다 | BR-U4-05가 침묵을 정상 동작으로 만들었으므로 **관측이 유일한 근거** |
| **OBS-U4-02** | **허위 알림 지표** — 발화 후 사용자가 `[끄기]`·`기존 유지`를 고른 비율. 민감도 초기값 조정의 근거가 된다 | MOBILE·알림 상한 재평가 입력 |
| **OBS-U4-03** | 재계획 세션의 **종료 상태 분포**(`APPLIED`·`CANCELED`·`NO_SOLUTION`·`FAILED`)를 지표로 남긴다 | `NO_SOLUTION` 급증 = 후보 풀·제약 문제 신호 |
| **OBS-U4-04** | 외부 포트별 실패율을 **벤더 단위로 분리**해 기록한다(날씨·거리·POI) | 서킷 분리(U0·U1 상속)와 같은 축 |
| **OBS-U4-05** | 지오펜스 wake 횟수와 그중 발화 수를 기록한다. **wake는 배터리 비용**이므로 효율(발화/wake)이 낮으면 리전 정책을 재평가한다 | MOBILE-U4-04 재평가 입력 |

## 6. 오프라인 (NFR-U4-OFFLINE)

**정책 원본**: `frontend/README.md` — "일정 조회 오프라인 캐시는 제공하지 않는다. 기록 입력(방문 체크·사진·메모)만 로컬 큐."

| ID | 요구 | 실장 / 근거 |
|---|---|---|
| **OFFLINE-U4-01** | **정책을 그대로 따른다.** 여행 중 화면도 일정 조회는 온라인 전제 — 끊기면 오류 + 재시도 | Q6=A. 여행 중 예외를 만들지 않는다 |
| **OFFLINE-U4-02** | **방문 체크는 `shared/storage` 큐에 쌓고** 복구 시 동기화한다. 체크 시각은 **기기 시각으로 확정해 큐에 싣는다**(동기화 시각이 아니라) | 실적의 정확성 |
| **OFFLINE-U4-03** | **재계획은 온라인 전용**이다. 오프라인에서는 진입 자체를 막고 사유를 표시한다 — 솔버 호출이라 우회 경로가 없다 | 침묵 실패 금지 |
| **OFFLINE-U4-04** | 오프라인 감지는 기존 `@react-native-community/netinfo`를 쓴다 | **실장 실재** |
| **OFFLINE-U4-05** | U3 `OFFLINE-U3-01`(확정 일정 로컬 캐시)이 구현되면 여행 중 화면이 **자동으로 그 혜택을 받는다**. U4가 별도 캐시를 만들지 않는다 | 중복 방지 |

## 7. 보안 (NFR-U4-SEC)

| ID | 요구 | 근거 |
|---|---|---|
| **SEC-U4-01** | 트리거·세션·방문 실적·경로는 **객체 수준 인가** — 소유 계정만, 타 계정은 404 | SEC-U1-01·SEC-U3-01 승계 |
| **SEC-U4-02** | **알림 딥링크가 `trips/**` 경로로 들어온다.** 이 경로는 `(tabs)` 밖이라 `Stack.Protected` guard에 안 걸리므로 **미인증 진입이 가능**하다 — 데이터 노출 차단은 **서버 인가가 유일한 방어선**이다 | **실장 경고**(`frontend/docs/structure.md`) |
| **SEC-U4-03** | 자유 텍스트는 **LLM 입력이자 저장 대상**이다 — 플레인 텍스트로만 렌더하고 HTML/링크 해석을 하지 않는다 | SEC-U3-03 승계 |
| **SEC-U4-04** | 로컬 알림 본문에 **정확한 위치·좌표를 싣지 않는다**(잠금화면 노출면). 장소명·사유까지만 | 잠금화면은 인증 이전 표면 |

## 8. PBT (blocking 게이트)

`business-rules.md` §7의 **PBT-U4-1~5**(서버)와 `frontend-components.md` §9의 **PBT-U4-F1~F3**(클라)를 그대로 승계한다. NFR 관점에서 추가하는 것은 없다.

## 9. 재평가 트리거

| 트리거 | 조치 |
|---|---|
| 지오펜스 **발화/wake 효율이 낮게 실측** | 리전 선택 정책 재설계(O-U4-1) 또는 포그라운드 전용으로 후퇴 |
| **`[끄기]`·`기존 유지` 비율이 높게 실측**(OBS-U4-02) | 민감도 초기값 하향 · 임계값 재조정(O-U4-3) |
| `NO_SOLUTION` 비율 급증(OBS-U4-03) | 후보 풀·제약 완화 규칙 재검토 + O-SOLVER 회의(BR-U2-14 승계) |
| 실제 경로 저장량이 문제로 실측 | DATA-U4-01 샘플링 간격 상향 · DATA-U4-02 보존 단축 |
| 동시 여행 사용자 증가로 날씨 격자 수가 급증 | Redis 도입(U1 Q8=B 결정 실행) 재검토 — 지금은 DB 캐시로 충분 |
| 재계획 응답이 체감상 느리게 실측 | PERF-U4-03 예산 확정(O-U4-4) 및 범위 축소(`PARTIAL_SLOTS` 기본화) |
