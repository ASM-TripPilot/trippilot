# U0 Foundation — NFR Requirements

> **캘리브레이션(사용자 지시 2026-07-17)**: "적당한 규모 서비스 + 쾌적한 사용자 경험" — 과설계 없는 중간 규모 용량 가정, 체감 성능·피드백 품질은 우선순위 상향.
> 익스텐션: security-baseline **Full(blocking)** · resiliency-baseline **Full** · PBT **부분(PBT-02·03·07·08·09 blocking)**. RESILIENCY-04(CI/CD·롤백)·14(복원력 테스트)는 NFR Design 이연(기지시).
> BR 참조는 `../functional-design/business-rules.md`.

## 1. 규모 (NFR-U0-SCALE)

| ID | 요구 |
|---|---|
| SCALE-01 | 설계 부하 가정: DAU 1만 · MAU 5만 · 피크 동시 ~500 세션 · 요청 피크 ~50 RPS |
| SCALE-02 | 마케팅 스파이크 대비 10x 헤드룸(단시간 500 RPS)에서 오류율 급증 없이 저하(rate limit 429) |
| SCALE-03 | 단일 리전·다중 AZ 내 수평 확장(무상태 앱 — 액세스 토큰 무상태 검증이 전제)으로 충분. 리전 간 DR 비대상(기지시) |

## 2. 성능 (NFR-U0-PERF)

| ID | 요구 |
|---|---|
| PERF-01 | 핵심 API 서버 처리 p95 < 500ms · p99 < 1.5s — 대상: `/bootstrap`·`/auth/social/*`·`/auth/token/refresh`·온보딩 저장 계열 |
| PERF-02 | 앱 콜드 스타트 → 첫 유의미 화면 < 2.5초(정상 네트워크), 스플래시 총 대기 상한 3초(타임아웃 폴백 BR-U0-27) |
| PERF-03 | 화면 전환 체감 300ms 내 응답 — 즉시 전환 + 스켈레톤, 서버 완료 대기로 UI를 막지 않는다 |
| PERF-04 | 온보딩 단계 저장은 낙관적 진행(다음 단계 즉시 전환, 실패 시 복귀+재시도) — 위저드 7단계 체감 지연 최소화 |

## 3. UX 품질 (NFR-U0-UX) — "쾌적한 사용자 경험" 구체화

| ID | 요구 |
|---|---|
| UX-01 | **침묵 실패 금지**: 모든 실패는 사용자 가시 피드백(표준 오류 패턴 — shared/ui) + 재시도 경로 제공 |
| UX-02 | 로딩은 스켈레톤 표준 패턴(스피너 단독 금지), 200ms 미만 응답은 로딩 표시 생략(깜빡임 방지) |
| UX-03 | 온보딩 입력은 실패·이탈 시에도 보존 — 재진입 시 남은 첫 단계 복귀(BR-U0-26)·기입력값 유지 |
| UX-04 | 소셜 로그인 취소·거부는 오류가 아닌 안내 톤(BR-U0-06), 재시도 즉시 가능 |
| UX-05 | 접근성 기본: 터치 타깃 ≥ 44pt, OS 폰트 스케일 대응, 스크린리더 라벨(핵심 여정 화면) |

## 4. 가용성 (NFR-U0-AVAIL)

| ID | 요구 |
|---|---|
| AVAIL-01 | 월간 가용성 목표 99.9%(다중 AZ 전제), shallow 헬스체크(`/health/liveness` — openapi 기존) 기반 축출 |
| AVAIL-02 | 인증은 fail-closed(가용성 저하 시 익명 접근 허용 금지) — 완충은 스플래시 로컬 폴백(BR-U0-27)과 UX-01 피드백 |
| AVAIL-03 | 무중단 배포 내성(그레이스풀 셧다운·롤링) — 상세 절차는 NFR Design(RESILIENCY-04 이연분) |

## 5. 보안 (NFR-U0-SEC) — security-baseline Full

| ID | 요구 |
|---|---|
| SEC-01 | 토큰: JWT **ES256** + JWK 셋(kid 롤오버 가능 구조). `none`·대칭 알고리즘 다운그레이드 거부 고정. 서명 키는 시크릿 매니저 보관(제품 선정 Infra Design) |
| SEC-02 | 리프레시: 해시만 저장·회전 체인·재사용 감지 시 체인 전체 무효화 + **건당 즉시 보안 이벤트**(BR-U0-07~08) |
| SEC-03 | 레이트리밋: `/auth/social/*`·`/auth/token/refresh`·닉네임 검사에 IP·계정 2축, 429+`retryAfter`, 임계는 재배포 없이 조정 가능(외부화). 카운터 정본은 PostgreSQL(적당 규모 — 병목 시 재평가) |
| SEC-04 | deny-by-default: 공개 엔드포인트는 명시적 화이트리스트만(소셜 로그인·토큰 갱신·약관 조회·부트스트랩 비세션부·liveness). 아키텍처 테스트로 "가드 없는 공개 핸들러" CI 검출 |
| SEC-05 | 객체 수준 인가: 토큰 주체 accountId 기준으로만 자기 리소스 접근(IDOR 원천 차단) |
| SEC-06 | 소셜 자격 증명 검증 fail-closed: id_token 서명·iss·aud·exp(·nonce), SDK 토큰은 제공자 조회 API 검증(BR-U0-02). 클라이언트 시크릿·p8 키는 서버만 보유 |
| SEC-07 | 로그 금지 항목: 전 토큰류·소셜 코드/SDK 토큰·이메일·생년월일·Authorization 헤더 — 프레임워크 레벨 마스킹(TRIP-148 로깅 자산에 컨버터 추가) |
| SEC-08 | 동의 증적·법정 데이터: append-only + app DB 역할 UPDATE/DELETE 권한 회수(V1.7 기존재) 유지. 파기 시에도 증적 보존(BR-U0-13) |
| SEC-09 | 전송·저장: 전 구간 TLS, 클라 토큰은 OS 보안 저장소만(frontend 정본 기확정) |
| SEC-10 | 입력 검증: 전 DTO 선언적 제약(+문자열 최대 길이 명시), 파라미터라이즈드 쿼리, 닉네임 저장 전 금칙어 검사(BR-U0-17) |

## 6. 복원력 (NFR-U0-RES) — resiliency-baseline Full

| ID | 요구 |
|---|---|
| RES-01 | 소셜 IdP 어댑터: 타임아웃 3초 + 서킷 브레이커, 장애 시 해당 제공자 버튼만 저하 안내(타 제공자 로그인 가능 유지) |
| RES-02 | 아웃박스: 상태 변경과 단일 TX 적재, at-least-once + 이벤트 ID 멱등 소비 규약(릴레이 실소비는 U1+, 골격 Q9) |
| RES-03 | JWKS·제공자 메타데이터는 인메모리 캐시(TTL) — 제공자 일시 장애가 기존 세션 검증에 영향 없게 |
| RES-04 | CI/CD·롤백 절차(RESILIENCY-04)·복원력 테스트 시나리오(RESILIENCY-14)는 **NFR Design에서 확정**(기지시 이연분) |

## 7. 관측성 (NFR-U0-OBS)

| ID | 요구 |
|---|---|
| OBS-01 | 서버 로그: stdout 구조화 JSON + 요청당 상관 ID(응답 헤더 반환·비동기 전파) — TRIP-148 자산 채택 |
| OBS-02 | 보안 이벤트 5분류 정의(U0): 가입 · 로그인 실패 급증 · 리프레시 재사용 감지(건당) · 429 급증 · 삭제 요청/복구. 수집·대시보드·알림 라우팅 제품은 Infra Design 이연 |
| OBS-03 | 클라이언트: Sentry(frontend 정본) — `beforeSend` 토큰·PII 스크러빙, 부트스트랩 폴백 발동률·로그인 실패율 계측 이벤트 정의 |

## 9. PBT 게이트 매핑 (blocking: PBT-02·03·07·08·09)

| 대상 | 속성 | 층 |
|---|---|---|
| 부트스트랩 분기 `resolveEntry` | 임의 입력 조합에서 우선순위 역전 0·유일 목적지 | 클라(fast-check) |
| 버전 비교 | 반대칭·전이성·페일오픈 | 클라 |
| 온보딩 진행 판정 | 임의 완료 상태에서 유일한 다음 단계 | 클라·서버 동형 |
| 동의 상태 fold | 임의 GRANT/REVOKE 시퀀스에서 최신 레코드 일치·멱등 | 서버(Kotest) |
| 리프레시 회전 체인 | 임의 갱신·재사용 인터리빙에서 체인당 현행 ≤1(INV-R1)·재사용 감지 누락 0 | 서버 |
| 취향 중립 파생 | 임의 NULL 조합에서 응답 완전성(BR-U0-21) | 서버 |
