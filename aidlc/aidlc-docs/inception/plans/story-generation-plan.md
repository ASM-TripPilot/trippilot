### Question 1 — PRD 기존 스토리 처리 방식
PRD가 이미 120개 유저스토리를 보유합니다. 이를 어떻게 다룰까요?

B) **선별 재작성** — 핵심여정 모듈만 정규화하고 나머지는 요약. 표현도 자유롭게 재구성.

C) **백지 신규 작성** — PRD를 참고만 하고 스토리를 처음부터 새로 작성.

X) 기타 (직접 서술)

### Question 2 — 후속 게이트 3모듈(02 어시스턴트·10 커뮤니티·11 공동편집) 스토리 깊이

### Question 3 — 스토리 구조(분해) 방식

C) 페르소나 기반 — 페르소나별로 스토리 그룹핑.

D) 하이브리드(에픽 기반 + 여정 오버레이) — 에픽으로 조직하되 여정 흐름을 상위 인덱스로 병기.

X) 기타 (직접 서술)

[Answer]: A

## A2. 확정 결정 (Resolved — 2026-07-12)

- **Q1 = A + 보강**: PRD 120 스토리를 AIDLC 포맷으로 정규화하되, **스토리 간 공백은 채우고 부자연스러운 스토리는 수정**.
- **Q2 = C**: 후속 게이트 3모듈(02 어시스턴트·10 커뮤니티·11 공동편집)은 `stories.md`에서 **에픽 헤더만**(상세 스토리는 후속 인셉션으로 이연).
- **Q3 = A**: 에픽 = 모듈 매핑.
- **Q4 = A (확정)**: 페르소나 **4종 = 동행 4축(혼자·커플·친구·가족) × 대표 여행 스타일**. 부모님·반려동물·진입경로(장소/숙소우선)·예산·페이스·이동·음식은 각 페르소나의 **속성**으로 병기.
- **Q5 = A**: 수용기준 = **Given–When–Then**.
- **Q6 = A**: **PRD + FR 양방향** 추적성.
- **제품 범위 = A (B2C 유지)**: 붙여넣은 'Full Scope(양면 마켓)' 예시는 **형식만 차용**, B2B 숙박업주 내용은 **미채택**. 승인된 `requirements.md`·`SCOPE.md`·Figma 정본 **그대로 유효**.
- **PRD 형식 = 담백**: 기존 `docs/PRD/` 16파일 **보존**하고, **새 단일 파일 `docs/PRD/PRD-lean.md`** 생성. 상세 수용기준·예외는 `stories.md`로 **위임**.
