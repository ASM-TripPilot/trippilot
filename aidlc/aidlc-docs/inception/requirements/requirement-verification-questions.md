# Requirements 검증 질문 — TripPilot (Comprehensive)

> **작성 배경**: `docs/PRD/`(16개 문서·120 유저스토리·17 모듈·17 ADR)와 `docs/design/wireframes.md`는 이미 기능 동작·수용 기준·예외·비즈니스 규칙을 매우 상세히 정본화하고 있습니다. 따라서 아래 질문은 PRD가 이미 확정한 사항을 되묻지 않고, **① 확장(Extension) 적용 여부**와 **② 인셉션 산출물의 범위·비기능 요구 수록 수준**처럼 PRD가 열어 둔(또는 이번 실행에서 사용자 결정이 필요한) 사항에만 집중합니다.
>
> **답변 방법**: 각 질문의 `[Answer]:` 뒤에 보기 문자(A/B/C…)를 적어 주세요. 마지막 보기(X)는 '기타'이며, 선택 시 `[Answer]:` 뒤에 직접 서술해 주세요. 모두 작성하신 뒤 "완료"라고 알려 주시면 답변의 모순·모호성을 점검한 후 `requirements.md`를 생성합니다.

## Question 2
복원력(Resiliency) 베이스라인을 이 프로젝트에 적용할까요?

**설명**: 활성화 시 AWS Well-Architected(Reliability Pillar) 기반의 **설계 시점 방향성 베스트프랙티스**(장애 내성·고가용성·관측성·복구성 등 15개 실천 영역)를 요구·설계·코드에 반영합니다. 단, 이것이 프로덕션 준비 완료나 가용성/RTO/RPO 보장을 뜻하지는 않으며 **좋은 첫 초안**일 뿐입니다.

A) 예 — 복원력 베이스라인을 방향성 베스트프랙티스로 적용 (비즈니스 크리티컬 워크로드 권장)

B) 아니요 — 복원력 베이스라인 미적용 (빠른 반복이 중요한 PoC·프로토타입에 적합)

X) 기타 (아래 [Answer]: 뒤에 직접 서술)

[Answer]: A

## Question 3

**참고**: TripPilot은 일정 솔버(OPTW/TOPTW·시간창·이동시간 제약), 계획/실제/변경이력 데이터 변환, 좌표·거리 추정, 마스킹·직렬화 등 **알고리즘·데이터 변환 로직이 풍부**합니다.

A) 예 — 모든 PBT 규칙을 강제 제약으로 적용 (비즈니스 로직·데이터 변환·직렬화·상태 컴포넌트가 많은 프로젝트 권장)

B) 부분 — 순수 함수·직렬화 왕복(round-trip)에만 PBT 적용

C) 아니요 — PBT 미적용 (단순 CRUD·UI 전용·얇은 통합 계층에 적합)

X) 기타 (아래 [Answer]: 뒤에 직접 서술)

[Answer]: B

## Question 4

C) **핵심 여정 유닛만** 이번 인셉션에서 전개하고, 어시스턴트·커뮤니티·공동편집은 이번 유닛 산출에서 제외(후속 인셉션으로 미룸)
