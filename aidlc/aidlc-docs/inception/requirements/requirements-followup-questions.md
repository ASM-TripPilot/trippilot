## Question 1
"AI 솔버를 AWS Bedrock AgentCore 에이전트로 새로 설계하고 기존 PRD 솔버 내용은 잊는다"는 지시의 **적용 범위**는 어디까지인가요?

A) **엔진/메커니즘만 교체** — 일정 지능 엔진(모듈 8 일정생성·9 Plan-B 감지·10 재계산, 그리고 어시스턴트·공동편집이 참조하는 '솔버' 개념)의 *내부 구현*을 결정론적 OPTW/TOPTW 하이브리드 → **Bedrock AgentCore 에이전트**로 대체. **사용자에게 보이는 일정 기능·플로우·수용 기준(등록 숙소=출발점, 영업시간·이동시간·필수 방문지 준수, 시간표/지도 2뷰, 편집·재검증, Plan-B 대안 등)은 유지** (권장)

B) **엔진 + 일부 규칙까지** 재정의 — 위 엔진 교체에 더해, 기존 PRD가 강제하던 특정 제약(예: "LLM 생성 시각 노출 금지", "이동 소요시간 표시 안 함" 등)도 이 기회에 재검토/완화 대상에 포함

C) **일정 지능 영역 전체를 백지에서 재정의** — 관련 유저스토리·수용 기준까지 이번에 새로 쓸 것이므로, 해당 영역은 PRD 대신 사용자와 새로 정의

## Question 2
새 Bedrock AgentCore 에이전트가 일정의 **실현가능성(영업시간·이동시간·숙소 앵커·시각 충돌 없음)을 어떻게 보장**하길 원하시나요? (테스트 기준·사용자 신뢰와 직결)

A) **에이전트 + 검증 도구(tool) 조합** — 에이전트가 LLM 추론으로 취향 해석·후보 선별·설명을 하되, 실현가능성(제약 충족·시간창·순서)은 에이전트가 호출하는 **결정론적 검증/최적화 도구**가 소유·보장. 사용자에게 보이는 시각·순서는 항상 도구가 검증한 값(환각 시각 노출 불가) — PRD의 "실현가능성은 솔버가 소유" 원칙을 도구로 계승 (권장)

B) **에이전트 자율 추론 중심** — 실현가능성 판단도 상당 부분 에이전트(LLM) 추론에 맡기고, 결정론적 하드 검증은 최소화(best-effort). 유연하지만 시각·제약 정확도는 보장 약화

C) 아직 미정 — 요구엔 "실현가능성은 보장되어야 한다"만 두고, **보장 방식(도구 vs 자율)은 Application Design에서 결정**

X) 기타 (아래 [Answer]: 뒤에 직접 서술)

[Answer]: A
