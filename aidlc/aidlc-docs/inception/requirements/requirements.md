## 3. 기능 요구사항 (Functional Requirements)

> 출처: PRD 01~12 (120 유저스토리). 각 FR은 PRD 섹션을 정본으로 상속하며, 여기서는 **요구 수준의 골격**만 규정한다. 세부 수용기준은 PRD 원문 + User Stories 단계에서 전개한다.

### FR-CORE — 이중 진입 & 앵커 (ADR-0002/0004 계승)
- **FR-CORE-01**: 두 진입 경로를 모두 1급 지원한다 — **장소 우선(Case A)**: 저장 POI가 여행 생성 시 '필수 방문지' 시드로 투입 / **숙소 우선(Case B)**: 등록 숙소(위치+체크인/아웃)가 일정의 출발점. 두 경로는 "등록된 숙소 = 출발점" 상태로 수렴한다.
- **FR-CORE-02**: 저장 POI 집합으로부터 숙소 권역을 역추천하지 **않는다**(숙소 선택은 사용자). 단, 일정을 먼저 완성 후 숙소를 나중 등록하는 경우 완성 동선 기준 숙소 추천을 제공한다.

### FR-SHELL — 앱 셸 (PRD 01)
- **FR-SHELL-01**: 스플래시 → 홈 대시보드 → 5탭 바텀 네비게이션. 특정 플로우에서 탭바 숨김.
- **FR-SHELL-02**: 장소 우선(Case A) — 장소 저장 시 '필수 방문지' 시드로 연결.

### FR-ONBOARD — 계정 및 온보딩 (PRD 03)
- **FR-ONBOARD-01**: 소셜 + 이메일 로그인, 약관 동의, 닉네임.
- **FR-ONBOARD-02**: 위치 권한 요청 흐름(위치정보법 동의 요건 반영 — LEGAL-01).
- **FR-ONBOARD-03**: 취향 7종(스타일·페이스·예산·동행·활동·이동·음식) 수집 + 기본값. 이 취향이 일정 생성 개인화 입력이 된다.

### FR-STAY — 숙소 탐색/저장/외부 예약 (PRD 04)
- **FR-STAY-01**: 검색·필터·상세·위시리스트. 날짜·인원 없는 숙소 검색 허용(Figma 반영 확인됨).
- **FR-STAY-02**: OTA 딥링크로 예약·결제 위임(앱 내 예약/결제/재고 없음).
- **FR-STAY-03**: 등록 2경로 — (a) 앱 OTA 링크 전환 확인 시 1탭 등록 후보 제시, (b) 그 외 위치·체크인/아웃 수동 입력. **예약번호·메일 연동 자동 인식은 두지 않는다.**

### FR-TRIP — 여행 생성 (PRD 05)
- **FR-TRIP-01**: 여행 생성. 숙소 미등록 시작 허용. 다중/다박 거점, 필수 방문지 지정.

### FR-SCHED — AI 일정 생성 (PRD 06) → **FR-SOLVER 아키텍처 적용**
- **FR-SCHED-01**: 등록 숙소 위치·체류기간 기준으로 취향 반영 방문지 선정 + 영업시간·이동시간·하루 시간예산 하드 제약을 풀어 날짜별 동선으로 정렬.
- **FR-SCHED-02**: 시간표 뷰 / 지도 뷰 2보기. 생성 방식 분기, 확정 플로우.
- **FR-SCHED-03**: 사용자에게 보이는 시각·순서는 항상 검증된 값(환각 시각 노출 금지).

### FR-PLANB — Plan-B 재계획 (PRD 07)
- **FR-PLANB-01**: 수동/자동 트리거(날씨·휴무·지연·취소 감지) → 영향 분석 → 대안 후보 → 비교 → 이력.
- **FR-PLANB-02**: 방식 분기(AI 재계획 / 직접 편집), 계획↔실제 경로 토글.
- **FR-PLANB-03**: 자동 감지 범위는 외부 데이터 커버리지에 비례. 미커버 POI는 수동 트리거·미확인 분리로만 대응(ADR-0011 '침묵 실패 금지').

### FR-ONTRIP — 여행 중 현장 이용 (PRD 08)
- **FR-ONTRIP-01**: 장소 도착·방문 체크, 현재 장소 상세, 다음 이동 거리 표기(실제 길안내는 외부 지도앱 위임 — ADR-0012).

### FR-RECORD — 여행 기록/회고 (PRD 09)
- **FR-RECORD-01**: plan / actual / changelog 3종 기록. 방문 체크·사진·메모를 일정 위에 남김.
- **FR-RECORD-02**: 종료 후 날짜별 기록·지도 경로·회고 자동 생성, 스타일 분석, SNS 공유 카드, 캘린더.

### FR-NOTIF — 알림/마이페이지/설정 (PRD 12)
- **FR-NOTIF-01**: 알림 채널 토글, 마이페이지, 취향 편집, 위치 동의 관리(철회/일시중지 — LEGAL-01), 제휴 고지.

### FR-ASSIST — 앱 전반 AI 어시스턴트 (PRD 02) — *후속 게이트*
- **FR-ASSIST-01**: 대화형 도우미(모달/바텀시트). 호출·컨텍스트·재질의·진행 검토·액션 위임·이력·범위 한계·가드레일·폴백. 기존 모듈(숙소탐색·일정생성·솔버)을 대화로 호출·설명·재질의만 하며 실현가능성 결정은 솔버가 소유(ADR-0008·0015).

### FR-COMMUNITY — 여행자 커뮤니티 / UGC (PRD 10) — *후속 게이트*
- **FR-COMM-01**: 공개 일정 둘러보기·읽기전용 보기·프로필 보기·'내 여행으로 가져오기'(원본 분리 사본 복제)·좋아요·댓글. 기본 비공개·명시적 옵트인 공개. 팔로우/구독/스크랩/평판 그래프 없음.
- **FR-COMM-02 (출시 선결)**: UGC 모더레이션 최소 인프라 — (i) 신고 접수·큐, (ii) '검토 중' 노출 보류(침묵 삭제 금지·사유 고지), (iii) 금칙어 기본 사전(닉네임·제목·캡션·댓글 공통), (iv) 차단(양방향 숨김). 이 4종은 커뮤니티 출시 전 구현 필수.
- **FR-COMM-03**: 민감 필드 마스킹 — 숙소 위치 권역화·여행 날짜 상대화·실시간 소재지 비공개. 사진 EXIF GPS 자동 제거. 자유텍스트 PII·얼굴·핀 역추론은 best-effort + 게시 전 제3자 동의·책임 고지.

### FR-COEDIT — 동행 공동 편집 (PRD 11) — *후속 게이트*
- **FR-COEDIT-01**: 동행자 초대, 권한(소유자/편집자/뷰어), 실시간 공동 편집, 충돌 해소, **솔버 재검증**, 변경 이력.

### FR-SOLVER — AI 솔버 전략 (단계적·진화형 교체 · 사용자 지시로 PRD 부분 대체 · 2026-07-12 확정)
> **이 요구는 PRD의 결정론적 OPTW/TOPTW 솔버 서술(ADR-0008/0009, 모듈 8·9·10)을 정제·대체하는 1급 사용자 지시다.** 이전(2026-07-11) "솔버 전면 폐기·에이전트 대체" 지시는 폐기됨.
> **"하이브리드"의 의미 = 단계적 교체 전략**: 런타임 이중 엔진(요청마다 폴백)이 아니라, **일단 결정론적 AI 솔버로 구현·출시하고, 그 솔버의 산출물 품질이 부적절하면 향후 엔진을 Bedrock AgentCore 에이전트로 교체**하는 프로젝트 수준의 진화(마이그레이션) 결정이다.

- **FR-SOLVER-01 (Phase 1 — 초기 구현·출시)**: 일정 지능을 **결정론적 AI 솔버(OPTW/TOPTW, PRD ADR-0009 계승)**로 구현한다. 이것이 초기 출시 엔진이며, 이 단계에서는 솔버 자체가 실현가능성을 소유·보장한다.
- **FR-SOLVER-02 (향후 — 조건부 엔진 교체)**: Phase 1 솔버의 **산출물 품질이 부적절('별로')하다고 판단되면**, 일정 지능 엔진을 **AWS Bedrock AgentCore 에이전트 방식으로 교체**한다. 이는 **런타임 요청별 폴백이 아니라 프로젝트 수준의 단계적 교체(마이그레이션) 결정**이다. (부적절 판정의 기준·게이트는 Application Design/운영에서 정의 — Open Item O-SOLVER.)
- **FR-SOLVER-03 (교체 범위 = 옵션 B)**: 교체 시 범위 = **엔진 교체 + 기존 PRD 강제 규칙 일부(예: 생성 시각 노출 금지, 이동 소요시간 미표시 등)의 재검토/완화 대상 포함**. 완화 여부·범위는 교체 설계 시 확정한다.
- **FR-SOLVER-04 (실현가능성 소유 = 결정론적 컴포넌트, 두 단계 불변)**: 실현가능성(등록 숙소=출발점 앵커, 영업시간, 이동시간, 필수 방문지, 시각 충돌 없음)은 항상 **결정론적 컴포넌트**가 소유·보장한다 — Phase 1은 솔버 자체가, 교체 후에는 **에이전트가 호출하는 결정론적 검증/최적화 도구**가 소유(Q2=A). 사용자에게 보이는 시각·순서는 항상 검증된 값이며 **LLM 환각 시각 노출은 금지**한다.
- **FR-SOLVER-05 (참조)**: 어시스턴트(모듈 16)·공동편집(모듈 17)이 참조하는 '솔버' 개념은 **현행 일정 지능 엔진**(Phase 1 = 솔버, 교체 후 = 에이전트 + 결정론적 검증도구)을 가리킨다.
- **불변식 (두 단계 공통 유지)**: 등록 숙소 앵커, 실현가능한 동선, 필수 방문지 반영, 취향 개인화.

```

──────────────────────────           ─────────────────────────────────────────
결정론적 AI 솔버                              [솔버 산출물 품질 '별로' 판정 시]
```

## 4. 비기능 요구사항 (Non-Functional Requirements)

> **Q6=B**: 아래 정량 목표는 **가정(Assumption)**으로 수록한다. CONSTRUCTION의 NFR Requirements/Design에서 실측·재확정한다.

### NFR-PERF — 성능 (가정)
- **NFR-PERF-01 (가정)**: 앱 주요 화면 상호작용 응답 P95 < 300ms(로컬), 서버 API P95 < 800ms.
- **NFR-PERF-02 (가정)**: AI 일정 생성 완료(정상 경로, 솔버) P95 < 10s; 에이전트 개입 경로 P95 < 30s. 진행 표시(스켈레톤/프로그레스) 제공.
- **NFR-PERF-03 (가정)**: 외부 API(지도·장소·날씨·OTA·LLM) 호출은 캐싱·rate-limit·폴링 상한을 두어 비용·배터리·rate-limit을 통제(PRD Further Notes 선결과제).

### NFR-SCALE — 확장성 (가정)
- **NFR-SCALE-01 (가정)**: 초기 국내 출시 동시 사용자 규모를 가정으로 산정(예: 초기 MAU 수만 규모)하고 오토스케일 상·하한을 둔다(RESILIENCY-09). 서버리스 동시성 상한 설정.

### NFR-AVAIL — 가용성 (가정, 복원력 결정 반영)
- **NFR-AVAIL-01 (가정)**: 목표 가용성 99.9%(가정). **단일 리전 + 다중 AZ**에 의존(Q3=E, Q4=A). 리전 간 DR은 초기 범위 아님.
- **NFR-AVAIL-02**: 컴퓨트는 2개 이상 AZ 분산, 데이터스토어는 다중 AZ 복제, 로드밸런싱은 AZ 간 분산, 정적 안정성(한 AZ 장애 시 컨트롤플레인 개입 없이 지속) 확보(RESILIENCY-08).

### NFR-USABILITY — 사용성/접근성
- **NFR-USA-01**: Figma 정본을 UI/UX 정본으로 준수. 상태 컴포넌트(EmptyState/ErrorState/SkeletonCard/Banner, DS-Catalog 59:2) 사용.
- **NFR-USA-02**: 추정 정보(이동시간)는 단일값이 아닌 범위/추정으로 고지(ADR-0009).

### NFR-DATA — 데이터/신선도 (출시 게이트)
- **NFR-DATA-01 (출시 게이트)**: 초기 지역 실제 데이터 커버리지를 **정량 게이트**로 확인 후 출시 — POI 영업시간 필드 채움률·장소 좌표 확보율 임계(값은 CONSTRUCTION 확정).
- **NFR-DATA-02**: 국내 지도 API 약관 준수 — **응답 데이터 영구 캐싱 금지·실시간 호출·출처 표기**를 데이터 모델에 반영(LEGAL-02).
- **NFR-DATA-03 (사진 저장 모델 · 2026-07-12 결정)**: 회고/기록 사진은 **기기 로컬 자산 참조 + 서버는 메타데이터만**(자산 식별자·촬영 시각·EXIF 위치·연결 장소) 저장하고 S3에 일괄 저장하지 않는다. **커뮤니티 공개에 포함한 사진만 EXIF GPS 제거 후 S3 업로드**(FR-COMM-03). **멀티 디바이스 미지원** — 로컬 사진은 단일 기기, 기기 변경 시 유실(메타데이터만 잔존)은 수용된 트레이드오프.

## 5. 보안 요구사항 (Security — 확장 ON / Full, 전 규칙 blocking)

> 출처: `security-baseline.md` (SECURITY-01~15). 요구 수준으로 상속하며, 규칙별 준수 검증은 각 CONSTRUCTION 단계에서 수행. 적용성은 산출물 생성 시점에 평가.

- **SEC-ENCRYPT (SECURITY-01)**: 모든 영속 저장소 저장시 암호화 + 전송중 TLS 1.2+.
- **SEC-LOG (SECURITY-02·03·14)**: 네트워크 중개자 액세스 로깅 + 앱 구조화 로깅(타임스탬프·상관ID·레벨), PII/토큰/비밀 로그 금지, 보안 이벤트 알림, 로그 append-only·최소 90일 보존.
- **SEC-INPUT (SECURITY-05)**: 모든 API 입력 검증(타입·길이·형식 allowlist·XSS 방지·파라미터화 쿼리).
- **SEC-AUTHZ (SECURITY-08)**: 기본 거부, 객체 수준 인가(IDOR 방지 — 특히 공동편집·커뮤니티 리소스 소유 검증), 서버측 토큰 검증, CORS 제한.
- **SEC-AUTH (SECURITY-12)**: 소셜+이메일 로그인 — 비밀번호 정책·적응형 해싱·세션(Secure/HttpOnly/SameSite·로그아웃 무효화)·브루트포스 방지·비밀 하드코딩 금지(시크릿 매니저).
- **SEC-LEASTPRIV (SECURITY-06·07)**: IAM 최소권한(와일드카드 금지), 기본 거부 네트워크 구성.
- **SEC-DESIGN (SECURITY-11·13·15)**: 보안 핵심 로직 격리, 공개 엔드포인트 rate-limit, 오용 시나리오 고려, 안전한 역직렬화, 감사 가능한 데이터 변경(공동편집 변경 이력과 정합), 예외 시 fail-closed·전역 에러 핸들러.
- **SEC-SUPPLY (SECURITY-10)**: 의존성 핀·락파일·취약점 스캔·SBOM·신뢰 소스만.
- **SEC-HEADERS (SECURITY-04)**: 웹 서빙 엔드포인트가 있으면 CSP·HSTS·X-Content-Type-Options 등 적용(모바일 전용이면 해당 표면에 N/A 판정 가능 — CONSTRUCTION에서 확정).

## 8. 법적·규제 요구사항 (Legal — 출시 선결)

- **LEGAL-01 (🔴 출시 선결, 위치정보법)**: TripPilot은 이용자 GPS(개인위치정보)로 근처 추천·여행 중 안내를 제공하므로 **위치기반서비스사업 신고(위치정보법 제9조) 의무**가 있다. '내 위치만 쓴다'·'외부 API 위임'으로 면제되지 않음. (a) 방송미디어통신위 신고 + 사업자등록 전제, (b) 이용약관 명시·동의·철회/일시중지·목적달성 후 즉시 파기·수집이용 로그 보존(제16·18·19·23·24조)을 온보딩 위치 권한·설정에 반영(FR-ONBOARD-02·FR-NOTIF-01). 출시 전 전문 법무 자문·사전상담으로 최종 확인.
- **LEGAL-02 (국내 지도 API)**: 국내 지도 API(카카오·네이버·TMap) 우선 채택으로 구글 국외반출 규제 회피. 약관상 **응답 데이터 영구 캐싱 금지·실시간 호출·출처 표기**를 데이터 모델에 반영(NFR-DATA-02).

- 소셜 그래프(팔로우·구독·스크랩·평판) 없음.
- **멀티 디바이스 사진 동기화 없음** — 회고 사진은 로컬 단일 기기(메타데이터만 서버·커뮤니티 공개 사진만 S3). 클라우드 사진 백업은 후속 검토(NFR-DATA-03).
