# Feature Specification: 범위 밖 질문의 도구 계획 (DIALOGUE_PLAN · 2‴)

**Feature Branch**: `feat/ai-dialogue-plan`

**Created**: 2026-10-19

**Status**: Draft (FD 개정 = 같은 PR 머지가 승인)

**Input**: User description: "다룰 수 있는 카테고리를 늘려라. 그리고 정해진 의도에 맞춰 수행하는 것만이 아니라, 현재 구조에서 agent·provider 를 어떻게 활용하면 좋을지 생각하는 LLM orchestrator 를 둬라. 지금은 POI DB 를 제공하는 쪽으로 가면 되는데, 정해진 의도에서 벗어난다고 아무 일도 안 하면 안 된다."

> 설계 정본은 FD `ai/aidlc-docs/construction/assistant-orchestrator/functional-design/` 3종(BR-AO-28·29, DEC-AO-17·18, AO-P18~21)이다.
> 이 spec 은 **무엇을·왜**만 적는다. 첫 단계(장소 탐색 EXPLORE_PLACES)는 #1413 으로 이미 들어갔다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 정해진 기능에 딱 맞지 않아도 조회로 도울 수 있으면 돕는다 (Priority: P1)

여행자가 "내일 비 오면 실내에서 갈 만한 데 있어?", "다음 일정 어디고 그 근처 맛집도", "해운대랑 광안리 야경 둘 다 보고 싶어"처럼
의도 하나로 딱 떨어지지 않는 말을 하면, 도우미가 지금 쓸 수 있는 조회 도구(일정·다음 장소·날씨·거리·장소 정보·대신 갈 곳·장소 찾기) 중
도움이 되는 것을 최대 2개 골라 그 결과로 답한다. 장소는 등록 장소에서만 나온다.

**Why this priority**: 사용자가 지적한 실패 — "정해진 의도에서 벗어난다고 아무 일도 안 한다" — 를 고친다. 분류가 "할 일 없음"으로 닫은 말이
지금은 전부 범위 밖 카드("그건 제가 도와드리기 어려워요")다.

**Independent Test**: 분류가 null 로 닫는 조건부·복합 발화 5개를 보내 각각 도구 결과(후보 카드·날씨 카드 등)가 담긴 답이 9초 안에 오고,
후보 장소가 전부 등록 장소인지 확인한다.

**Acceptance Scenarios**:

1. **Given** 여행 중인 세션, **When** "내일 비 오면 실내에서 갈 만한 데 있어?" 라고 보내면, **Then** 날씨와 장소 찾기를 함께 조회해 후보 카드와
   날씨를 담은 문장 하나로 답한다.
2. **Given** 같은 세션, **When** "다음 일정 어디고 그 근처 맛집도" 라고 보내면, **Then** 다음 일정과 근처 맛집 후보로 답한다.
   (분류가 이 말을 null 로 닫아야 성립한다 — 분류 0.2.3 은 GET_NEXT_SLOT 하나로 잡아 계획 단계로 오지 않았다. 0.2.4 가 "서로 다른 조회 둘
   이상이면 null" 규칙을 더했다, 2026-10-20.)
3. **Given** 여행이 없는 세션, **When** 일정이 필요한 도구만 고른 말이면, **Then** 여행 만들기 안내로 답한다.

### User Story 2 - 도구로 답할 수 없는 말은 지금처럼 정직하게 거절한다 (Priority: P1)

예약·결제·환율·번역·택시 호출·계정 설정·잡담처럼 조회 도구로 답할 부분이 없는 말, 지시를 바꾸려는 말은 지금과 같은 범위 밖 카드로 답한다.
지어낸 답을 하지 않는다.

**Why this priority**: 계획 단계가 "아무거나 답하는" 길이 되면 안 된다 — 거절의 정직함이 지금의 품질이다.

**Independent Test**: "KTX 표 좀 끊어 줘", "엔화로 바꾸면 얼마쯤 돼?", 지시 주입 꼴 발화를 보내 범위 밖 카드가 오고 장소·사실이 지어지지 않는지 본다.

**Acceptance Scenarios**:

1. **Given** 어떤 세션, **When** 도구로 답할 부분이 없는 말이면, **Then** 종전 범위 밖 카드(숙소 화면이면 숙소 검색 버튼 포함)가 온다.
2. **Given** 어떤 세션, **When** 계획 LLM 이 실패·시한 초과면, **Then** 종전 범위 밖 카드가 오고 폴백 이벤트가 남는다.

---

### User Story 3 - 운영자가 계획 단계를 켜고 끄고 잴 수 있다 (Priority: P2)

계획 단계는 기능별 모델 배정(DIALOGUE_PLAN)이 있을 때만 켜진다. 결정(도구·도구 없음·거절·실패·생략)은 턴마다 한 줄 로그로 남는다(발화·인자
값 없음).

**Independent Test**: 배정 없이 띄우면 종전과 같고 기동 줄에 "off"가, 배정하면 "on — 도구 N종"이 찍힌다. 단 분류 0.2.4 부터 두 가지를
같이 묻는 말은 배정이 없으면 SCOPE 카드다(0.2.3 은 절반만 답했다) — 0.2.4 는 대상마다 배정이 끝난 뒤에 머지한다(BLM §13).

### Edge Cases

- 분류가 의도를 고른 턴은 계획하지 않는다(분류를 덮지 않는다).
- 맞장구·인사("고마워")는 계획보다 먼저 한마디로 답한다.
- 잔여 시간이 4.6초 미만이면 계획을 부르지 않는다(계획·팬아웃 뒤에도 답변 시도선 1.5초가 남는 최소 4,542ms).
- 계획 턴은 서비스 LLM 3회(분류·계획·답변)를 쓰므로 그 턴의 기억 요약은 한 번만 다음 차례로 미루고, 이미 미룬 차례면 결정론 압축으로 저장한다.
- 같은 계획에서 시각을 내는 도구(일정표·다음 일정·장소 정보)는 하나만 쓴다 — 둘을 고르면 앞의 것만(일정표는 다음 일정을 담고,
  일정 시각과 영업 시각이 섞이면 영업 시각을 방문 시각으로 쓴 문장을 가려낼 수 없다).
- 날씨 도구는 날짜 하루만 본다 — "주말에 비 오면"의 기간은 받지 않는다.
- 여러 도구 결과를 합친 답에서 한 결과의 시각을 다른 결과의 장소에 붙이면 정해진 문구로 답한다. 한 문장에 시각과 다른 장소를
  같이 쓰면 맞는 답도 정해진 문구가 된다(감수하는 대가).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 분류가 판단해서 "할 일 없음"으로 닫은 발화(`{"intent": null}`·범위 밖 라벨·목록 밖 라벨)에만 계획 LLM 을 1회 부른다.
  분류 0.2.4 부터 null 은 "의도 하나로 안 떨어지는 범위 안 조회 둘 이상"도 뜻한다(BR-AO-02).
  분류 인프라 실패·깨진 출력·주입 거름·맞장구·보류 되묻기 답은 종전대로다.
- **FR-002**: 계획이 고를 수 있는 도구는 정보 핸들러 7종 중 이 배선에서 포트가 다 있는 것뿐이고, 한 턴에 최대 2개다. 쓰기·넘기기 의도는 도구가 아니다.
- **FR-003**: 도구 인자는 인자표에 있는 이름의 문자열(1..40자)뿐이고, 시각·소요시간·연락처·주입 꼴·필수 인자 누락은 게이트가 버린다.
- **FR-004**: 도구 결과는 기존 핸들러가 만들고, 여러 결과는 하나의 사실 묶음으로 합쳐 기존 답변 단계가 문장을 짓는다. 후보·문장 속 장소는 등록 장소에서만
  나온다(INV-1). 보이는 시각은 사실에 있는 값뿐이다(INV-2). 소요시간은 보이지 않는다(INV-3).
- **FR-005**: 도구 없음·거절·계획 실패·시한 부족은 종전 범위 밖 카드로 수렴하고, 실패에는 폴백 이벤트가 짝으로 붙는다(INV-4).
- **FR-006**: 계획 답은 프레임 없는 답(ANSWER)이라 와이어·백엔드·앱 변경이 없다.
- **FR-007**: 턴당 서비스 LLM 은 3회 이하다.
- **FR-008**: 배정(DIALOGUE_PLAN)이 곧 켜기다 — 새 환경변수를 더하지 않는다.

### Key Entities

- **계획(Plan)**: 고른 도구 호출(도구 이름 + 문자열 인자) ≤2 · 거절 여부 · 도구 없음의 분류(관측 전용).
- **도구(PlanTool)**: 정보 핸들러 하나 + 모델에게 보일 설명 한 줄 + 쓰는 포트.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 도구 1·2개 측정셋(20문장)에서 도구 집합 완전 일치 ≥80%, 허용 일치 ≥90%, 인자 키 정밀도 ≥90%.
- **SC-002**: 도구 없음 측정셋(10문장)에서 calls 비움 ≥90%, 주입 측정셋(8문장)에서 도구 0 ≥95% 이고 게이트 뒤 위험 인자 0.
- **SC-003**: 계획 지연 p90 ≤2.6s, 계획 폴백률 ≤5%, 게이트 드롭률 ≤3%.
- **SC-004**: 계획 턴 지연 p90 ≤8.5s(백엔드 메시지 latency).

## Assumptions

- 장소 탐색(EXPLORE_PLACES, #1413)이 develop 에 있다.
- 모델은 자리값 luna 로 두고, luna·terra·sol 을 실 GPT 로 재서 정한다.
- 답변 프롬프트(dialogue_answer.yaml)는 소유 세션 몫이라 바꾸지 않는다 — 여러 사실 묶음(`also`)을 어떻게 다룰지는 측정 뒤 소유자와 정한다.
