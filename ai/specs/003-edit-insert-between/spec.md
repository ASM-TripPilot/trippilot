# Feature Specification: 두 일정 사이에 한 곳 더 넣기 (편집 ①a)

**Feature Branch**: `feat/ai-edit-insert-between`

**Created**: 2026-10-22

**Status**: Draft (PR 머지가 승인)

**Input**: 사용자 요청(다른 세션 경유): "이태원에서 홍대로 넘어갈 때 한 군데 더 추가" — "edit agent 호출해서 얘가 일정변경하거나
그 사이 갈만한 곳 하나 더 추천해서 이거 넣을까요? 이런식으로 가도 되잖아!"

> 이 기능의 설계 정본은 이 문서다(2026-10-19 결정: 새 AI 설계는 `ai/specs/`, `ai/aidlc-docs` 는 동결). 편집 파이프라인 전체(번역 → 검증 →
> 확인 게이트 → 재타이밍 → 어셈블리 검증)는 `agents/edit/agent.py` docstring 과 TRIP-431 결정 그대로이고, 여기서는 그 앞에 붙는 ①a 와
> ADD 기준점만 적는다. 설계는 세 안(번역기 강화·대화 쪽 후보 카드·편집 ①a)을 판정관 둘이 따로 비교해 둘 다 ①a 를 골랐다(둘 다 7.5점, 다른 두 안은 4.5~6점).

## 배경

1. 2026-10-20 개발 서버: "이태원에서 홍대로 넘어갈 때 한 군데 더 추가"가 "어떻게 바꿀지 알아듣지 못했어요"로 끝났다. 번역 LLM 이 "어느 두
   슬롯 사이"와 "무엇을" 둘 다 골라야 하는데, 일정 슬롯 이름에 '이태원'·'홍대'가 없으면 기준점을 못 잡는다.
2. develop 결함: `ADD_SLOT` 의 `afterPoiId`·`beforePoiId` 는 게이트와 `validate_command` 를 통과하지만 `apply_command` 가 버리고 맨 끝에 붙인 뒤
   `APPLIED` 를 냈다. "사이에 넣기"가 끝에 붙고 '반영됨'으로 나갔다(INV-4 위장).

## User Scenarios & Testing

### User Story 1 - 사이에 넣을 곳을 코드가 골라 제안한다 (Priority: P1)

"A에서 B로 넘어갈 때 한 군데 더", "A랑 B 사이에 카페 하나", "B 가기 전에 뭐 하나", "A 다음에 갈 만한 곳"처럼 **정해지지 않은 한 곳**을 두 일정
사이(또는 한 일정의 앞·뒤)에 넣어 달라고 하면, 그 동선에서 크게 돌아가지 않는 등록 장소 하나를 넣은 안을 제안 카드로 낸다. LLM 은 부르지 않는다.

**Independent Test**: 서울 좌표 시드로 `/edit` 에 위 발화를 보내 `APPLIED` 와 함께 새 장소가 두 슬롯 사이에 있고, 앞 슬롯 시각은 그대로, 뒤 슬롯은
앞당겨지지 않았는지 본다. LLM 을 배선하지 않은 앱에서 APPLIED 가 나와야 한다(`tests/api/test_api_edit_insert_between.py`).

**Acceptance Scenarios**:

1. **Given** 경리단길(이태원 권역) 다음에 연남동(홍대 권역)이 있는 하루, **When** "이태원에서 홍대로 넘어갈 때 한 군데 더", **Then** 둘 사이에
   효창공원(우회 ≤ 2km)이 들어간 안. 슬롯 이름에 지역명이 없어도 지역 중심표(`domain/region_centers.py`)로 푼다.
2. **When** "이태원이랑 홍대 사이에 카페 하나", **Then** 카페만. **When** "…카페 말고 한 군데 더", **Then** 카페는 뺀다.
3. **Given** 여행 당일, **When** 뒤 일정이 이미 시작했으면 **Then** 넣지 않는다(사유 `past_gap`). 이동 중이면 새 곳은 지금 이후에 시작한다.

### User Story 2 - 못 하면 지어내지 않고 정직하게 (Priority: P1)

자리를 못 풀면 종전처럼 번역기로 넘긴다. 자리는 풀었는데 넣을 곳이 없거나 다 안 맞으면 위반 없는 `REJECTED`(앱 문구 "그렇게는 바꿀 수 없어요")다 —
사용자가 고른 적 없는 장소의 위반을 보이지 않는다. 자리를 말한 요청을 번역기가 기준점 없이 옮기면 끝에 붙이지 않고 `TRANSLATION_FAILED` 다.

### User Story 3 - 기준점 있는 ADD 는 어느 진입이든 그 자리에 (Priority: P1)

구조화 명령(버튼)이든 번역(말)이든 `ADD_SLOT` + `afterPoiId`/`beforePoiId` 는 그 자리에 들어간다. 기준점 둘이 이웃이 아니거나 모르는 슬롯이면 거부한다.
이름을 콕 집은 말("효창공원을 경리단길 끝나고 넣어줘")은 번역이 "무엇"을 고르고, 번역이 기준점을 빼면 코드가 말의 자리를 풀어 채운다
(2026-10-22 실측: 실 번역 LLM 이 기준점을 빼 효창공원이 맨 끝에 붙었다). 자리를 못 풀면 끝에 붙이지 않고 `TRANSLATION_FAILED` 다.

## Requirements

- **FR-001 읽기**(`insert_between.parse_insert_ask`): 더하기 말 + 정해지지 않은 한 곳("한 군데"·"하나 더"·"어디/뭐 하나"·"갈 만한 곳"·"카페 하나")
  + 자리 말(사이·다음·전)일 때만 잡는다. **자리·한 곳·더하기·종류·밤 말을 지운 나머지가 채움말뿐일 때만** 코드가 맡는다 — 낱말 표 밖의 말이 남았다면
  그 말이 뜻을 바꾼다(2026-10-22 리뷰: "효창공원 하나 더"·"카페 빼고 공원 하나"·"점심 먹고 …"를 결정론이 다른 안으로 바꿨다). 빼기·옮기기·바꾸기·
  여럿("하나씩"·"두 군데")·이름 지목·부정("넣진 마"·"안 해도 돼"·"필요 없어")은 None — 번역기 몫이다. 종류는 자리 구절을 뺀 말 전체에서 하나만 걸릴
  때만 쓰고(오탐보다 미탐), "말고·빼고·싫고·아니면"이 붙은 종류는 뺀다. 술·맥주·한잔·클럽은 밤 말이다. 끝 말은 한 낱말·15자로 묶는다(역추적).
- **FR-002 자리**(`resolve_gap`): 끝 말 → 그 날 슬롯을 이름 부분일치 → 하루 끝 말 → 지역 중심표 반경 순으로 찾고, **이웃 짝이 정확히 하나**일 때만
  자리다. 아니면 사유 문자열(`unresolved_from`·`not_adjacent`·`ambiguous_gap`·`ambiguous_clause` …)이고 번역기로 넘긴다. 날은 경계가 준
  `target_date` 하나만 본다.
  - 끝 말 해소 순서: 이름 → 동네 권역(반경 ≤3km, '홍대입구역'은 홍대) → 하루 끝 말 → 광역 권역('포항'). 지역이 그 날 슬롯을 다 덮으면 가리키는 게 없다.
  - 하루 끝은 꼴로 가른다(2차 리뷰: '공항 다음에'·'마지막 일정 전에'가 끝으로 갔다). B 쪽 떠나는 곳(공항·숙소·호텔·집·서울역·터미널·KTX/비행기
    타기 전에) = 마지막 슬롯 뒤. A 쪽 하루 마지막(일정 끝나고, 마지막 일정 다음에) = 같은 자리. B 쪽 '마지막(일정)' = 마지막 슬롯 앞. 종전 끝 추가가
    맞던 말을 '못 알아들음'으로 바꾸지 않는다. '오전·점심 일정'처럼 수식어가 붙은 일반 낱말은 하루 끝으로 단정하지 않는다(번역기).
  - 뜻이 안 서는 끝 말(쪽·근처·앞·일정·1자)은 앞 낱말과 붙여 읽는다("이태원 쪽에서"). 부정 꼴("카페 말고")은 붙이지 않는다.
  - 출발이 지금 있는 곳(지금·여기·있는 곳·숙소·호텔에서 B 가는 길에)이면 B 앞이다.
  - 자리 말 밖에 다른 행위 서술절("점심 먹고"·"구경하고")이 있으면 어느 틈인지 단정하지 않는다(`ambiguous_clause`). 바람("가보고 싶은데")·
    나열("조용하고 예쁜")·동반("데리고")은 절이 아니다. 부정은 더하기 동사에 붙은 꼴만 본다('예약 필요 없는'은 조건).
- **FR-003 후보 풀**: 경계가 넘긴 콘센트 `EditTask.segment_pool(중심, 반경)` 으로 **같은 요구표·PlaceProvider 경로**의 그 날 풀을 한 번 더 모은다
  (INV-1 — 재계획 지역 풀 #1454 와 같은 모양). 중심·반경은 우회 타원(초점 A·B, 우회 ≤ slack)을 덮는 가장 작은 원. 시한 < 2s·콘센트 오류·빈 풀이면
  받은 기본 풀로 고른다.
- **FR-004 순위**(`rank_on_segment`): 우회 거리 A→X→B − A→B ≤ slack(도보 1 · 대중교통 2 · 자차 5km). 이미 일정에 있는 곳과 **이름이 서로 들어가는
  곳**(경의선숲길 ↔ 경의선숲길공원)·숙소·뺄 종류·그 날 휴무가 증명된 곳·표시 못 할 이름은 뺀다. 술집(태그·BAR)은 밤 말에만. 종류를 안 말했으면
  먹는 곳은 다른 게 없을 때만. 순서는 (우회 ≤ slack/2 우선, **끝점 옆 뒤로**, 밤 말이면 술집·야경 먼저, '요즘 인기', 평판 가점, 영업시간 보유,
  저장 수, **길 위 가운데**, 우회, id) — 결정론. 길 위 가운데 = A→B 투영 진행률 t 가 0.5 에 가까운 곳(한쪽만 있으면 가까운 곳), 끝점 옆 = t < 0.2
  또는 > 0.8(구간 1km 이상). 우회만 보면 끝점 바로 옆이 늘 0 이라 앞·뒤 일정의 옆집이 뽑힌다 — 2026-10-22 실측에서 다음 슬롯의 옆 입구(우회
  0.06km)가, 재적재 뒤에는 B 옆 0.48km '요즘 인기' 암장이 1등이었다. '두 끝까지 거리 중 짧은 쪽이 긴 곳'으로 재면 우회 한도 가장자리가 1등이 됐다.
- **FR-005 검증**: 상위 5곳을 차례로 `ADD_SLOT(targetPoiId, afterPoiId, beforePoiId)` 로 만들어 기존 ②~⑤(동등 검증·확인 게이트·재타이밍·어셈블리
  validate)에 태우고 처음 통과한 안을 낸다(INV-2). 체류는 그 날 중앙값과 60분 중 작은 값.
- **FR-006 재타이밍**: 기준점 있는 ADD 는 있던 슬롯을 원래 시각보다 앞당기지 않는다(`keep_earlier`) — 끼운 곳이 미는 시간은 빈 시간이 먼저 받는다.
  기준점 없는 끝 추가는 종전대로 하루를 다시 흘린다.
  - 여행 당일 규칙은 `_apply` 한 곳에 건다 — 넣을 자리 바로 뒤 일정이 이미 시작했으면 거부(past_gap), 아니면 새 곳의 시작을 지금 이후로 둔다
    (`RetimeContext.not_before`). ①a·이름 지목 자리 채우기·번역이 기준점을 채워 온 추가가 같은 규칙을 탄다.
  - '지금'은 현지 시각으로 바꿔 분 올림한다. BE 는 requested_at 을 UTC(…Z)로 보내는데, 그대로 하한으로 쓰면 슬롯이 UTC 벽시계(13:10 → 04:10)로
    나가고 HC1·HC4 도 그 시·분으로 판정했다(2026-10-22 리뷰 재현).
- **FR-012 검증 범위·수단**: 어셈블리 validate 는 **고친 날만** 본다(HC1~4 는 날 단위). 다른 날 시각은 이 편집이 만든 것이 아니다 — 생성이 다른
  추정기(액티비티 취향 걷기 1.0km 등)로 잡은 날을 기본 추정기로 다시 재면 손 안 댄 날의 HC2 가 모든 편집을 막았다(develop 부터, 2차 리뷰 재현).
  문제의 수단은 편집 요청의 수단으로 맞춘다(문제 빌더는 와이어에 수단이 없어 대중교통으로 채운다) — 안 맞추면 자차 여행은 재타이밍(자차)이 잡은 간격을
  검증(대중교통)이 늘 HC2 로 떨어뜨렸다. 둘 다 사이 넣기만이 아니라 편집 전반(빼기 포함)의 결함이다.
- **FR-013 안전망**: 번역이 기준점 없는 ADD 를 냈고 말에 자리 단서(다음·전에·사이·가는 길·끝나고…)가 있는데 자리를 못 읽었으면 끝에 붙이지 않고
  `TRANSLATION_FAILED(position_unread)` 다('다음 날'·'다음 주'는 자리 단서가 아니다).
- **FR-007 기준점 ADD**(`commands._insert_at`): 기준 0개 = 맨 끝(종전), 1개 = 그 슬롯 뒤·앞, 2개 = 지금 이웃일 때만 그 사이. 같은 쪽 둘·모르는 슬롯·
  이웃 아님은 `EditRejected`.
- **FR-008 와이어 무변경**: 결과는 기존 `EditOutcome` 상태값이다. 실패 사유는 `reason` 의 `insert_between: …` 접두로 남는다(앱 문구는 상태값으로 정해진다).
- **FR-009 관측**: 턴마다 `edit_insert {json}` 한 줄 — outcome·shape·kind·resolved_by·pool_source·pool·within·tried·detour_km·category·segment_ms.
  발화·장소 이름은 싣지 않는다. 운영에서 within·tried 로 slack 을 조정한다.

## 불변식

- INV-1: 후보는 경계가 모은 등록 풀에서만 — `validate_command` 가 풀 소속을 다시 본다.
- INV-2: 보이는 시각·순서는 어셈블리 validate 통과분만 — 실패 후보의 시각은 나가지 않는다.
- INV-3: 소요시간 필드 없음(와이어 무변경).
- INV-4: 실패는 전부 사유 있는 상태값. 기준점을 버린 끝 추가는 `APPLIED` 로 나가지 않는다.

- **FR-010 대화 쪽 날**(`orchestrator/dialogue_handlers.insert_day`): BE 는 day → 가리킨 장소의 날 → 여행 중이면 오늘로 고른다(`ProposalCards.targetDate`).
  분류는 사이 넣기 말의 `target` 에 '한 군데'·'카페'를 싣고 `day` 는 비워서, 여행 전에는 "어느 날 일정을 바꿀지 알 수 없었어요"로 끝났다(2026-10-22
  실측 5말 중 4). 그래서 날을 말하지 않은 사이 넣기는 말의 자리가 **오늘 이후 한 날에만** 이웃 짝으로 풀리면 그 날을 `day` 로 싣는다. 지역 이름으로
  풀려면 좌표가 필요해, 이름으로 한 날도 안 풀릴 때만 슬롯 좌표를 장소 정보 공급자로 한 번 묻는다(LLM 0, 남은 턴 시한 1.5s 미만이면 묻지 않고, 실패하면
  이름으로만). 둘 이상의 날이면 싣지 않는다. 말한 날은 바꾸지 않는다.
- **FR-011 되묻기 생략**: 분류가 자리만 주고 day·target 을 다 비우면 오케스트레이터가 "며칠째 일정을 바꿀까요?"로 되묻는데, 답 턴에는 원문이 없어
  (`PendingFrame` 에 발화 칸이 없다) 편집이 "알아듣지 못했어요"로 끝난다. FR-010 의 날이 풀리면 되묻지 않고 그 날로 FRAME 을 낸다.

## 범위 밖 · 후속

- 요일("토요일에 …")은 `resolve_day` 가 못 읽어 BE 가 날을 못 고른다 — 사이 넣기만의 문제가 아니라 따로 다룬다. 되묻기 답 턴의 원문 소실도 편집 전반의 문제다.
- **카드 문구 "○○ 넣을까요?"**: BE 템플릿(`ProposalCards.proposed`). 질문형이면 사용자가 [적용] 대신 "응"을 치고, 분류의 짧은 수락 규칙이 그 "응"을 편집으로
