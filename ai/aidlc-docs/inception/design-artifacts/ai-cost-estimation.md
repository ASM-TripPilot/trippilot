# TripPilot AI 비용 산정 (테스트 단계)

> 짝 문서: [ai-architecture.md](./ai-architecture.md) §4.2(티어 전략)·§9(비용·성능·관측), [ai-prompt-design.md](./ai-prompt-design.md) §2(feature별 스펙), [ai-testing-guide.md](./ai-testing-guide.md)(실 LLM 호출 범위).
> 본 문서는 **테스트 단계(출시 전 개발 기간)의 Claude API 비용 추정 정본**이다. 출시 후 운영 비용 산정(P6)은 본 문서의 실측 데이터를 근거로 별도 수행한다.
> 작성 기준일: 2026-07-12. 단가는 Anthropic 공시 가격 기준이며 변동 시 본 문서를 갱신한다.

---

## 1. 과금 모델 이해

- Claude API는 **구독제가 아니라 선불 크레딧 충전(pay-as-you-go)** 방식이다. Claude Pro/Max 구독과 완전히 별개이며, 구독에 API 크레딧이 포함되지 않는다.
- 과금 단위는 토큰: **입력 토큰 단가 + 출력 토큰 단가** (모델별 상이, 1M 토큰 기준).
- 프롬프트 캐싱 사용 시 캐시 읽기는 입력 단가의 ~0.1×, 캐시 쓰기는 ~1.25×.
- Batch API(비실시간)는 전 토큰 50% 할인.

## 2. 테스트 단계 모델 선정 (D11 미확정에 대한 잠정치)

D11은 "단일 관리형 벤더 · 티어 2종"까지만 확정했고 구체 모델은 운영 결정 미확정이다. **테스트 단계에서는 아래 잠정 매핑을 사용**한다.

| 티어 | 잠정 모델 | 단가 (입력/출력, per 1M tokens) | 담당 feature |
|---|---|---|---|
| 경량 | Claude Haiku 4.5 (`claude-haiku-4-5`) | $1 / $5 | PreferenceScoring, INTENT 라우터 |
| 상위 | Claude Sonnet 5 (`claude-sonnet-5`) | $3 / $15 (인트로: $2 / $10, ~2026-08-31) | Explanation, Reflection, PlaceExtraction |

> 상위 티어 인트로 가격 종료(2026-08-31) 후에는 비용이 정가 기준으로 최대 1.5배가 되므로, 이후 산정 시 정가로 재계산한다.

### 2.1 선정 근거

- **경량 = Haiku 4.5**: 지연 예산이 결정적이다. LLM 호출 타임아웃 **2.5초**(ai-architecture.md §9)·도우미 첫 응답 3초 안에서 현실적인 선택지는 Haiku뿐이다. 구조화 출력(스키마 강제)을 지원하므로 closed-set 게이트(INV-1)와도 정합.
- **상위 = Sonnet 5**: Explanation·Reflection은 한국어 2~3문장 서술이고 **비동기(사용자 대기 미차단)**라 속도 부담이 없다. 이 용도에 Opus 4.8($5/$25)은 과하다. 단, Reflection 품질이 회귀 평가에서 미달하면 Reflection에 한해 Opus 테스트 여지를 남긴다(비동기라 지연 무관, 비용만 ~2.5배).

### 2.2 라우터 승격 기준 (Haiku → Sonnet 5)

INTENT 라우터는 출력 스키마가 가장 복잡한 feature다(의도 분류 + 슬롯 + 디스패치 + 편집 명령 + applyMode + 응답 + nextSuggestion 동시 산출). **Haiku로 시작하되 아래 기준 초과 시 INTENT만 Sonnet 5로 승격**한다 — PreferenceScoring은 Haiku 유지.

| 계측 항목 | 승격 임계 | 근거 |
|---|---|---|
| 의도 오분류율 | > 5% | ai-prompt-design.md §3.2 회귀 평가 기준과 정렬 |
| OutputSchema 파싱 실패율 | > 5% | 동일 |

승격 시 비용 영향: INTENT 1회 ~$0.006 → ~$0.012 (입력 ~3K/출력 ~0.5K 기준). §4 시나리오 기준 월 +$5~20 수준으로 예산 내 흡수 가능.

## 3. feature별 1회 호출 비용 추정

토큰 추정은 ai-prompt-design.md §2의 입력 컨텍스트·OutputSchema 기준. 인트로 가격 적용.

| Feature (티어) | 가정 | 입력 토큰 | 출력 토큰 | 1회 비용 |
|---|---|---|---|---|
| PreferenceScoring (경량) | 후보 POI ~100개 (ID+카테고리+태그) | ~6K | ~4K (전 후보 점수+reason) | **~$0.026** |
| INTENT 라우터 (경량) | 대화 5턴 + 일정 요약 | ~3K | ~0.5K | **~$0.006** |
| Explanation (상위) | 일정 슬롯 ~10개 | ~2K | ~1.5K | **~$0.019** |
| Reflection (상위) | 당일 방문 기록 | ~2K | ~0.5K | **~$0.009** |
| PlaceExtraction (상위) | 웹 문서 1건 | ~10K | ~1.5K | **~$0.035** |

**주의 — 최대 비용 변수는 PreferenceScoring 후보 풀 크기다.** 규모 가정(G142)의 지역당 POI 5천 개를 통째로 넣으면 호출당 입력 ~150K + 출력 ~200K 토큰(회당 $1+)까지 커진다. 테스트 시에는 후보를 **100~300개로 절단**해 넣는다. 이 절단 상한은 운영 설계에서도 후보 프리필터(어셈블리 앞 단) 파라미터로 유지한다.

## 4. 한 달(30일) 테스트 시나리오별 예산

실 LLM 호출 범위는 ai-testing-guide.md 원칙을 따른다: **PR CI는 전부 FakeLlmAdapter — 과금 0**. 실 과금은 (a) 개발 중 수동 통합 테스트, (b) 프롬프트 튜닝 반복, (c) 릴리스 회귀 평가에서만 발생한다.

| 시나리오 | 하루 호출 가정 | 일 비용 | 월 비용 (30일) |
|---|---|---|---|
| 가볍게 | E2E 생성 ~20회 + 라우터 ~30회 | ~$1 | **$20~40** |
| 보통 | E2E 생성 ~50회 + 라우터 ~50회 + 회고/웹소싱 각 ~10회 | ~$3 | **$60~100** |
| 집중 (프롬프트 튜닝 + 회귀 반복) | E2E 생성 ~100회 + 라우터 ~100회 + 회고/웹소싱 각 ~20회 | ~$6 | **$150~250** |

- E2E 생성 1회 = PreferenceScoring 1회 + Explanation 1회로 계산.
- **권장 운영: $50 충전으로 시작 → Console usage 대시보드로 소진 속도 확인 → 필요 시 추가 충전.** 월 상한 예산은 $100로 잡는다.

## 5. 비용 절감 레버 3종

| 레버 | 적용 대상 | 효과 |
|---|---|---|
| **프롬프트 캐싱** | 시스템 프롬프트 + few-shot (feature별 고정 접두부) | 반복 테스트 시 입력 비용 ~90% 절감. 고정부를 프롬프트 앞에, 가변부(후보 목록·대화)를 뒤에 배치해야 캐시가 유지된다 |
| **Batch API** | 릴리스 회귀 평가(§ai-testing-guide llm-regression) | 전 토큰 50% 할인. 실시간성 불필요한 평가는 전부 Batch로 |
| **후보 절단** | PreferenceScoring 입력 | 후보 100~300개 상한 (§3 주의 참조) |

## 6. 계측 — 출시 선결 과제(P6) 실측 근거 확보

ai-architecture.md §9에 계획된 "LLM 비용 계측 메트릭"을 테스트 초기부터 가동한다.

- 모든 실 LLM 호출에서 응답의 `usage.input_tokens` / `usage.output_tokens` / `usage.cache_read_input_tokens`를 feature·promptVersion 태그와 함께 로깅한다.
- 목적: (1) 본 문서 §3 추정치의 실측 보정, (2) P6(LLM 벤더 계약·비용 산정)의 근거 데이터, (3) 후보 풀 크기↔비용 상관 확인.
- 캐시 적중 검증: 동일 접두부 반복 호출에서 `cache_read_input_tokens`가 0이면 캐시 무효화 원인(타임스탬프·비결정적 직렬화 등)을 점검한다.
