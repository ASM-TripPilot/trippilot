## ADR-0008: LLM + 솔버 하이브리드 아키텍처 채택

**상태**: 확정

**맥락**:
일정 생성을 LLM 단독으로 처리할 경우 영업시간·이동시간 같은 하드 제약을 신뢰성 있게 만족시키지 못하고, 없는 장소를 지어내는 환각 문제가 발생한다. 실서비스(D01) 품질에서 이는 치명적이다.

**결정**:
LLM(C1)과 최적화 솔버(C2)를 분리해 역할을 나눈다.
- C1: 취향 해석·선호 점수·설명 생성 (판단)
- C2: 선택·순서·시각 배치·하드 제약 검증 (사실)

**결과**:
- 4대 불변식(INV-1~4)이 이 결정에서 파생된다
- LLM 실패 시 결정론적 솔버 모드로 폴백 가능 (INV-4)
- LLM 벤더 교체가 C2에 무영향

## ADR-0009: 이동시간 추정 — 실시간 경로 API 미사용

**상태**: 확정

**맥락**:
실시간 경로 API(카카오모빌리티 등)는 비용·rate-limit·응답 지연 문제가 있다. 또한 추정값은 본질적으로 부정확하다.

**결정**:
- 도로 거리 우선 + 이동 수단별 안전계수로 추정
- 단일값이 아닌 범위/추정으로 표시
- **소요시간은 어떤 화면·DTO에도 표시하지 않는다** (INV-3, D25)
- ~~어댑터 순서: 카카오모빌리티 → 네이버 → 직선거리 추정~~ → **정정 (2026-08-25)**: 실제 체인은 **TMAP(1차 실측) → 하버사인 직선거리 추정(2차 폴백)** 2단이다 (`solver_engine/adapters/tmap.py` · `chained_travel.py`, TRIP-382·405·422·432). 카카오모빌리티·네이버는 **도입된 적이 없다** — 키 설정도 `TMAP_API_KEY` 하나뿐(`.env.example` · `docker-compose.yml`).
  결정의 취지(실시간 경로 API 미사용 → 도로 거리 + 안전계수 추정, INV-3)는 그대로다 — 바뀐 것은 벤더뿐이다.

**결과**:
- `VisitSlotDisplay`에 `internalDuration` 필드 부재를 컴파일 타임 보장
- 솔버 내부 버퍼 15분, 자동 지연 트리거 30분으로 오차 흡수 (G106)

## ADR-0011: 침묵 실패 금지 — 결정론적 폴백 필수

**상태**: 확정

**맥락**:
LLM·외부 API·솔버 중 어느 것이 실패해도 사용자가 빈 화면을 보는 것은 허용되지 않는다. AI 실패가 여정을 인질로 잡아서는 안 된다.

**결정**:
모든 AI 기능은 자기 폴백 계단을 소유한다.
- LLM 실패 → 규칙 점수 기반 결정론적 솔버 모드
- 외부 API 실패 → 캐시·직선거리 추정으로 지속
- 전체 실패 → 숙소 + 시각 고정 필수 방문지만의 최소 일정

**결과**:
- 동일 입력은 동일 출력 (시드 고정, 무작위성 제거)
- 폴백 발생 자체는 관측 지표로 계측 (침묵 실패 계측)
- 핵심 여정은 LLM 없이도 완결

## ADR-0015: AI 어시스턴트 — 통역·중개자, 결정권자 아님

**상태**: 확정 · **M16 1차 승격(AI-D02, 2026-07-07)** — 통역·중개자 원칙은 유지

**맥락**:
대화형 AI가 일정을 단독으로 확정·저장하거나 미검증 수치(시각·거리)를 생성하면 INV-2·INV-3를 위반한다.

**결정**:
M16은 C1 위의 순수 소비자 계층이다. 자연어를 해석하는 **라우터**이자, 워커·솔버를 호출·조립하는 중개자다(AI-D02).
- 미검증 수치 직접 생성 금지 — C2 검증값만 인용
- 자연어를 **편집 명령으로 번역**해 버튼·드래그와 동일한 솔버 검증 경로로만 반영 (별도 확정 경로 없음)
- **반영은 하이브리드**(AI-D02): 경미=자동반영+되돌리기 / 파괴적(삭제·대규모·Plan-B)=제안·확인 필수
- 모든 응답에 다음 행동 1개 포함 (dead-end 금지)
- 역할 변경·지시 유출·유해 요청 거절

**결과**:
- 자연어 진입은 라우터 경유, 버튼·이벤트 진입은 기존 결정론 파이프라인 유지 — AI 실패가 핵심 흐름을 막지 않음(INV-4)

**상태**: 확정

**결정**:

## AI-D01: AI 코어(C1+C2)를 독립 Python 서비스로 구축 — D11 대비 분기

**상태**: 확정 (AI팀 결정, 2026-07-07) · **TripPilot 백엔드팀과 D11 개정 정합 필요**

**맥락**:
D11 원안은 C1(LLM 게이트웨이)만 프로세스 분리 여지를 두고, 실현가능성을 소유하는 C2(솔버)는 Kotlin 모놀리스(D02/D04)에 인프로세스로 유지하도록 규정했다. AI 개발을 전면 Python으로 진행하기로 하면서 C2도 Python으로 이동한다.

**결정**:
- C1 + C2 + AI 오케스트레이션을 **하나의 독립 Python 서비스**로 구축한다.
- TripPilot Kotlin 백엔드(M8·M9·M10)는 이 AI 서비스를 **API로 호출**한다.
- 솔버 라이브러리는 Python 생태계에서 선정한다(자체 구현 / OR-Tools(Python) / Timefold — ai-implementation-design.md §4.3).

**결과 (D11 대비 변화)**:
- M8→C2가 인프로세스 호출이 아니라 **서비스 간 호출** → C2 앞에도 타임아웃·서킷 브레이커 필요('C2는 외부 다운 없음' 전제 폐기).
- 지연 예산(day1 5초·전체 20초)에 **네트워크 홉** 반영 필요.
- 하드 제약 검증·결정론 폴백·closed-set 등 **불변식(INV-1~4)과 PBT 속성은 언어 무관**하게 유지(테스트는 pytest + Hypothesis).

**후속 조치**:
- TripPilot 백엔드팀과 D11 개정(또는 신규 ADR) 협의 — AI 서비스 경계·프로토콜(REST/gRPC)·배포 단위 확정.

## AI-D02: 멀티 에이전트 오케스트레이션 — 라우터 + 특화 워커 (자연어 진입 전용)

**상태**: 확정 (AI팀 결정, 2026-07-07)

**맥락**:
와이어프레임의 일정 편집은 **버튼·드래그앤드롭·DB선택**으로 이뤄지며, 그 옆에 자연어 **AI 도우미**(사이드 패널)를 추가한다. 자연어 요청은 의도가 모호하므로, 단일 LLM 호출로만 쓰던 C1을 **의도 파악 라우터 + 특화 워커** 구조로 재정리한다. 단 시각·순서 확정은 여전히 솔버(C2)가 소유한다(INV-2).

**결정**:
- **라우터(의도 파악 agent)**: C1 게이트웨이에 `INTENT` feature(경량 티어) 신설. 자연어 입력의 **의도 분류 + 슬롯 추출 → 워커 디스패치**. **자연어 진입점에만** 둔다.
- **워커(특화 agent)**: 기존 C1 feature를 워커로 재분류 — PreferenceScoring·Explanation·Reflection + 재계획 사유 해석·스타일 분석. 각자 프롬프트·OutputSchema·티어 고정. **"판단·생성"만** 하고 확정은 하지 않는다.
- **진입점 분리**: 버튼·드래그·DB선택·시스템 이벤트(날씨 폴링·위치 tick)는 라우터를 **거치지 않고** 기존 결정론 파이프라인(M8/M9/M10) 그대로.
- **솔버는 워커가 아니다**: C2는 결정론 유지. 어떤 agent도 시각·순서를 확정하지 않는다(INV-2). AI는 "무엇을", 솔버는 "몇 시에·어떤 순서로".
- **편집 파이프라인 수렴**: AI 도우미는 자연어를 **편집 명령**으로 번역해, 버튼·드래그가 쓰는 **동일한 솔버 검증 경로**(`validate_edit`/`apply_edit`)로 흘려보낸다. 별도 반영 로직을 만들지 않는다.
- **반영 방식 — 하이브리드**:
  - 추가·경미한 조정 → **자동반영 + 되돌리기**(changelog 기록)
  - 삭제·대규모 재배치·Plan-B → **제안·확인 필수**(사용자 명시적 적용)

**결과**:
- INV-2 강화: "라우터·워커는 **제안만**, 확정은 솔버 `validate`/`solve` 경유"(§3).
- INV-4 확장: 폴백 지점에 "라우터 실패 → 기본 의도/수동 경로", "워커 부분 실패 → 그 워커만 규칙 폴백" 추가.
- ADR-0015 계승: AI 도우미는 통역·중개자이지 결정권자가 아니다. M16을 후속에서 **1차 범위로 승격**하되 결정권 없음 원칙은 유지.
- 배포: AI-D01의 통합 Python 서비스 안에 라우터·워커·솔버가 함께 산다(신규 프로세스 아님).

**후속 조치**:
- 라우터 **의도 오분류율**·워커 **부분 폴백률** 계측 지표 정의(관측 대시보드 확장 슬롯).
- 하이브리드 반영의 "파괴적 편집" 분류 기준표 확정(§ai-implementation-design.md §3.4).

## AI-D03: 웹서치 후보 소싱 — 계층형(Places API → 자유 웹) + 백그라운드 보강

**상태**: 확정 (AI팀 결정, 2026-07-08)

**맥락**:
버튼·드래그 입력으로 DB(M7)에서 관련 POI를 불러오는데, 데이터 수집에 한계가 있어 후보가 부족한 지역·카테고리가 생긴다. 웹에서 후보를 보강하되 INV-1(closed-set)·솔버 데이터 의존·지연 예산(5초/20초)·INV-4(폴백)를 깨지 않아야 한다.

**결정**:
- **계층형 소싱**: ① **Places API 어댑터**(카카오 로컬·구글 Places 등 — 구조화 데이터) 우선 → ② 그래도 부족하면 **자유 웹 소싱 워커**(검색→읽기→LLM 추출). 이동추정 어댑터 순서(TMAP→하버사인 직선거리 — ADR-0009 2026-08-25 정정)와 동형.
- **수집 게이트(강한 검증)** — 웹 원본은 이 게이트를 통과해 **M7에 등록된 뒤에만 후보**가 된다(웹 원본 직접 후보화 금지):
  1. **스키마 검증** — 좌표·영업시간·카테고리 필수. 결손 시 격리(후보 제외)
  2. **실재 검증** — 지오코딩 성공 + 가능하면 Places API 재조회 교차확인. 실재 확인 안 되면 격리
  3. **중복 제거** — 이름+좌표 근접 동일 카테고리는 기존 POI와 병합
  4. **신뢰 태깅** — `source=WEB`·confidence·"정보 확인 필요" 배지, 커버리지 게이트(G192)
  5. **정책** — 가격 캐싱 금지(D13/G195), 약관 허용 TTL
- **타이밍 — 백그라운드 보강**: 생성은 **현재 M7 스냅샷**으로 즉시 진행(5초 지킴), 웹 보강은 비동기 잡으로 M7을 두텁게 만들어 **다음 번**에 반영. 웹 서치는 **보강**이지 생성의 **의존**이 아니다(INV-4).
  - 예외: 커버리지 바닥(거의 0) 지역만 1회 온디맨드 보강 + "지역 정보 수집 중" 진행 화면(D38 점진 노출).

**결과**:
- INV-1 유지: LLM은 여전히 M7 안에서만 선택 — 웹은 풀을 키울 뿐, 게이트가 환각·불량 데이터를 차단.
- 자유 웹 추출은 **워커**(C1 `PLACE_EXTRACTION`)로 편입 — 멀티 에이전트 구조 안. Places API는 LLM 아닌 **어댑터**.
  - **(미배선 — 2026-08-25 기준 프로덕션 호출자 0)**: `llm_gateway/workers/place_extraction.py`(`PlaceExtractionWorker`)·
    게이트·프롬프트 `place_extraction.yaml` 은 실재하고 테스트도 green 이지만 어느 프로덕션 경로도 호출하지 않는다.
    현행 POI 소싱은 **TourAPI 단일 소스**이고, 실제로 배선된 LLM 추출은 행사 전용 `EVENT_EXTRACTION`
    (NAVER 검색 → LLM 추출 → 카카오 로컬 지오코딩 → `JsonEventStore`)뿐이다. 즉 ② '자유 웹 소싱 워커' 단계는
    아직 가동되지 않는다.
- 폴백: 웹 소싱 실패 → DB 후보로 정상 진행(생성 무영향).
- 관측: Places API 쿼터·웹 소싱 비용·게이트 격리율 계측.

**후속 조치**:
- Places API 벤더 선정 + 약관(스크래핑·저장·가격) 검토(P6 계열).
- 자유 웹 추출 워커 프롬프트·검증 규칙·게이트 임계(confidence·dup 반경) 확정.

**부기 (2026-08-23, TRIP-421)**: 행사(Event) 수집은 본 결정의 소싱 파이프라인(Places API→자유 웹→게이트→M7 등록)과 **별개 경로**다 — 웹소싱 새벽 배치(`ai-event-collect`)가 `event_store`(JsonEventStore)를 채우고 EventProvider가 읽는다. M7 등록 게이트를 타지 않는 이유: 행사는 후보(POI)가 아니라 **선호 점수의 소프트 가점 재료**라 INV-1 closed-set의 적용 대상이 아니기 때문(agent-structure-v2 §3 행사 반영 방식 참조). 행사가 POI로 승격되어야 하는 경우(상설 전시장 등)에만 본 결정의 게이트를 탄다.

## AI-D04: 입력 정규화·엔티티 해소 — 별도 교정 agent 없이

**상태**: 확정 (AI팀 결정, 2026-07-08)

**맥락**:
사용자가 프롬프트에 오타·잘못된 표기를 넣을 수 있다("강능 여행", "성심땅 빵집"). 별도 교정 LLM(agent)으로 처리할지 검토했으나, 라우터(INTENT) 자체가 이미 LLM이라 **의도·자유문장 오타는 네이티브로 흡수**한다. 별도 교정 단계는 LLM 호출·지연·환각(오교정) 위험만 늘린다.

**결정**:
- **별도 교정 agent를 두지 않는다.** 의도·자유문장 오타는 라우터 LLM이 흡수(추가 호출 없음, D11).
- **DB에 매칭돼야 하는 엔티티(지역명·POI명)만 결정론적 엔티티 해소**(fuzzy match, edit-distance) — M7·지역 목록에 대조. LLM 임의 교정 아님(결정론·테스트 가능, INV-4).
- **신뢰도 낮으면 조용히 고치지 않고 확인**한다("'강능'을 강릉으로 이해했는데 맞나요?" 또는 후보 제시) — 통역·중개자·dead-end 금지(ADR-0015), 하이브리드 반영과 동일 정신.
- **M7에 없으면 AI-D03 웹 소싱**으로 연결(오타 처리 → 엔티티 해소 → 없으면 웹 소싱).

**배선 상태 (2026-08-25)**: `poi_curation/entity_resolver.py`(`fuzzy_match`·`similarity`)는 구현·테스트
완료지만 **프로덕션 호출자가 0이다** — 결정론 엔티티 해소는 어느 요청 경로에서도 실행되지 않는다.
자연어 진입점(AI-D04가 전제하는 "라우터 슬롯 채우기")이 미배선인 것과 같은 이유다(intent-matching-design.md
배선 상태 註 참조). 아래 '결과'는 배선 시점의 목표 상태다.

**결과**:
- 엔티티를 실제 M7 `poi_id`로 해소 = **입력단의 closed-set 그라운딩**(INV-1 연장).
- 라우터 슬롯 채우기에 `resolve_entities` 결정론 단계 추가(ai-implementation-design.md §3.4).
- 프롬프트는 엔티티를 임의 교정하지 않도록 가드레일(ai-prompt-design.md §2.4).

**후속 조치**:
- fuzzy match 임계(edit-distance·자동확정 vs 확인 컷) 캘리브레이션.

## AI-D05: ML 도입 전략 — soft 신호만, 규칙 폴백 유지

**상태**: 확정 (AI팀 결정, 2026-07-08)

**맥락**:
설계에 손으로 튜닝한 휴리스틱·정적 테이블이 있고(선호 점수 규칙 가중치·체류 기본값 G51·이동 안전계수 G106), 문서에 "실측 보정/튜닝 예정"으로 표시돼 있다. 이는 **데이터로 학습하면 더 좋아지는 ML 지점**이다. 단 하드 제약·검증은 솔버가 결정론으로 소유해야 한다.

**결정**:
- **ML은 soft 신호(추정·점수·개인화)에만** 들어간다. 하드 제약 검증·시각 확정은 여전히 결정론 솔버 — LLM↔솔버 분업과 **동일 경계**(ML도 "무엇을/얼마나", 솔버는 "가능한가/언제").
- **도입 후보 (임팩트 순)**:
  1. **선호 점수 — 추천/Learning-to-Rank**(GBDT·two-tower). 유저 피드백(수락·재배치·방문)에서 학습. 목적함수 보상값이라 품질 임팩트 최대. LLM/규칙보다 개인화 우위.
  2. **체류 시간 예측 — 회귀**(POI+유저+시간대 → 실제 체류 분). 정적 테이블(G51) 대체, 시간 예산 정밀화.
  3. *(후속)* 이동시간 보정 — 회귀(고정 안전계수 G106 → 시간·지역별). 내부 추정만 개선, INV-3(미표시) 유지.
- **규칙 폴백 유지(INV-4)**: 각 ML 자리엔 이미 규칙 버전이 폴백으로 존재 — ML 선호점수 실패→`build_rule_score`, ML 체류예측 실패→정적 테이블, ML 이동보정 실패→고정 안전계수. ML은 **규칙 위에 얹힌다**.
- **결정론**: 고정 모델 버전으로 추론 → 동일 입력 동일 출력(INV-4). 모델 버전 로깅.
- **시점**: 1차는 규칙/LLM 부트스트랩 + **입출력·피드백 로깅**. 데이터 충분 시 선호점수→체류시간 순 전환. DAU 1천(G142) 규모에 과설계 금지.

**결과**:
- ML 모델 호스팅은 SageMaker 엔드포인트가 등판. C1/솔버 어댑터 뒤에 스왑 → 소비 모듈·불변식 무영향.
- closed-set 게이트(INV-1)는 ML 선호점수에도 그대로 — 후보 풀 안에서만 점수.

**후속 조치**:
- 학습 데이터 로깅 스키마 선반영(선호 피드백·실제 체류·도착 델타).
- 전환 트리거(볼륨·비용·품질 기준) 정의.

## AI-D07: U2 솔버 시간 정책 — day1 5초 유지 + 시한 인지 하이브리드 체인

**상태**: AI팀 확정 (2026-07-25, 같은 날 개정: 10초 상향안 철회 → **day1 5초 유지, D38 무변경** — 기획·백엔드 합의 절차 불필요)

**결정**:
1. **day1 예산은 5초 유지(D38 그대로)**하되, **하이브리드 체인은 day1부터 전 경로에 동일하게 적용**한다.
   모순은 **시한 인지(deadline-aware) 체인**으로 해소한다:
   - `HybridSolverFacade.solve(problem, deadline)` — 체인의 각 단계는 **진입 전 잔여 시간을 확인**하고, 자기 요구 시간(예: LLM 2차 = 타임아웃 2.5s)보다 잔여가 적으면 **그 단계를 건너뛰고 다음(규칙 폴백)으로** 간다.
   - 체인 구조는 전 경로 동일: `OR-Tools → LLM 2차 → 규칙 폴백`. **경로마다 다른 것은 deadline뿐.**
   - > **배선 상태 (2026-08-25) — 2차 단계 미배선**: `api/wiring.py` 가 조립하는 실가동 체인은
     > `stages = (OrToolsSolver, RuleFallbackSolver)` **2단**이다. `solver_engine/llm_solver.py`(`LlmSolver`)는
     > 존재하나 프로덕션 호출자가 0이며, 사유는 소스 주석이 적어뒀다 — **"솔버 프롬프트 정본·모델 설정이
     > 아직 없다"**. 결과로 바로 아래 "잔여 ≥ 2.5s 일 때 2차가 돈다"는 분기와 4항의 경로별 모델 티어 분리는
     > **현재 어떤 경로에서도 발생하지 않는다**(day1·백그라운드·regenerate·Plan-B 전부 `OR-Tools → 규칙 폴백`).
     > `llm_stage_timeout_ms=2500`(`solver_engine/config.py`)의 유일한 소비처가 그 `LlmSolver` 라 함께 잠들어 있다.
   - day1(5s)에서 2차가 실제로 도는 경우: OR-Tools가 **조기 실패**(infeasible 판정 등, 타임아웃 전에 끝남)해서 잔여 ≥ 2.5s일 때. OR-Tools가 3초를 다 쓰고 실패하면 잔여 부족 → 규칙 직행 (자연스러운 강등, INV-4).
   - 백그라운드 일자·regenerate(시간 여유)·Plan-B(10s)에서는 2차가 사실상 항상 실행 가능.
   - 효과: day1 5초 예산·D38·프론트 UX 전부 무변경. 하이브리드의 가치는 시간이 허락하는 만큼 자동으로 제공.
2. **솔버 라이브러리: OR-Tools 우선 벤치마크** (미결 #3 진행 방식 확정) — U2 첫 절편으로 후보 50~5,000개 규모에서 day1 예산 내 달성 여부 측정, 통과 시 확정·실패 시 자체 구현 검토.
3. **SPEED remote config 초기값**: 도보 4 / 대중교통 20 / 차 30 km/h.
   - U1 FakeTravel의 임시값(차 40)은 이 값으로 정정한다(완료). 안전계수(G106: 1.4/1.5)·버퍼 15분과 별도 적용. 실측(travel_actual 로그) 후 튜닝.
4. **2차 LLM 솔버 모델 티어 (AI-D06 연장)**: 경로별 분리 —
   - **day1·Plan-B (인터랙티브)**: `claude-sonnet-5` (응답 속도 확보)
   - **백그라운드 일자·regenerate**: `claude-opus-4-8` (품질 우선, 시간 무관)
   - model_id는 전부 설정값 — 하드코딩 금지.

**이유**: 예산 상향(10초안)은 D38 개정·프론트 UX 재작업이라는 팀 간 비용이 큼. 시한 인지 체인은 예산을 건드리지 않으면서 하이브리드를 전 경로에 일관 적용하는 해소책 — "체인은 하나, 시계가 결정한다".
