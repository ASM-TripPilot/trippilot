# ReflectAgent — 회고 생성 설계

> 여행 기록을 분석해서 회고·요약·스타일 분석을 만들어주는 에이전트.
> 핵심 패턴: **LLM Generation** (데이터 수집 → 프롬프트 → 서술 생성)

---

## 1. 접근 방식

### 1차: A — 단순 LLM Generation

방문 기록을 DB에서 가져와서 프롬프트에 넣고 Bedrock 1회 호출.
가장 단순하고 비용 낮음. RAG·어셈블리 불필요.

### 추후 확장: C — Multi-step Generation

통계 집계 → 하이라이트 추출 → LLM 서술 → 스타일 분류.
각 step이 단순하지만 조합하면 품질 높은 구조화된 회고.

---

## 2. 1차 설계 (A: 단순 LLM Generation)

### 흐름

```
트리거 발생 (일자 경계 / 여행 종료)
        |
        v
[1] DB 조회 — 방문 기록 가져오기
        +→ 당일 방문 POI 목록
        +→ 각 POI 체류시간
        +→ 사진 수
        +→ 일정 변경 이력 (Plan-B 발동 여부)
        |
        v
[2] 충분성 판단 (규칙)
        +→ 방문 0건 → 스킵 (회고 안 함)
        +→ 방문 1건+ → 생성 진행
        |
        v
[3] LLM 호출 (Bedrock 1회)
        +→ 방문 기록을 프롬프트에 주입
        +→ 회고 텍스트 생성
        |
        v
[4] 결과 반환
        +→ 성공 → Reflection(title, body, highlights, mood)
        +→ 실패 → FallbackCard(통계 카드)
```

### 할당 Tool (1차)

| Tool | 용도 |
|---|---|
| `db.get_visit_history` | 방문 기록 조회 (당일 또는 전체) |
| `llm.generate_reflection` | Bedrock 호출 — 회고 서술 생성 |

**2개만.** 가장 가벼운 에이전트.

### 프롬프트 구조 (1차)

```
[System]
너는 여행 회고 작가야.
사용자의 오늘 방문 기록을 보고 따뜻한 회고를 써줘.
실제 방문한 데이터만 사용해. 없는 내용 생성 금지.

[Context — DB에서 조회한 데이터]
## 오늘 방문 기록
- 10:00~11:30 경복궁 (체류 90분, 사진 5장)
- 12:00~13:00 삼청동 맛집 (체류 60분)
- 14:30~16:00 북촌 한옥마을 (체류 90분, 사진 8장)
- 16:30~17:30 인사동 (체류 60분, Plan-B로 변경됨 — 원래 남산이었음)

## 날씨
- 오전 맑음, 오후 소나기 (Plan-B 원인)

[Task]
JSON 형식으로 반환:
{
  "title": "한 줄 제목",
  "body": "3~5문장 회고 본문",
  "highlights": ["하이라이트 1", "하이라이트 2"],
  "mood": "relaxed | adventurous | cultural | ..."
}
```

### 폴백

| 실패 조건 | 폴백 |
|---|---|
| LLM 타임아웃 / 파싱 실패 | FallbackCard(통계 기본 카드) 반환 |
| 방문 기록 0건 | 생성 스킵 (PENDING 유지) |

```python
@dataclass
class FallbackCard:
    visit_count: int        # 방문 N곳
    distance_km: float      # 총 이동거리
    photo_count: int        # 사진 N장
    plan_b_count: int       # Plan-B 적용 횟수
    # 사용자가 직접 작성 가능 → USER_WRITTEN 상태로 전이
```

## 3. 추후 확장 (C: Multi-step Generation)

1차(A)가 안정되면 아래 step을 추가:

### 확장 흐름

```
[1] DB 조회 (규칙) — 방문 기록·체류시간·사진·일정 변경 이력
[2] 통계 집계 (규칙) — 총 이동거리, 방문 N곳, 카테고리 분포
[3] 하이라이트 추출 (규칙) — 체류 가장 길었던 곳, Plan-B 발동 곳
[4] LLM 서술 생성 (Bedrock 1회) — ①②③을 프롬프트에 넣고 회고 텍스트 작성
[5] 스타일 분류 (조건부) — 누적 10곳 이상이면 7축 분류 (LLM 추가 1회)
```

### 확장 시 추가 Tool

| Tool | 용도 | 추가 시점 |
|---|---|---|
| `llm.analyze_style` | 7축 택소노미 분류 (누적 10곳 게이트) | C 확장 시 |

### 스타일 분류 (7축 택소노미) — 추후

누적 방문 10곳 이상일 때 활성화:
- 자연/도시
- 활동/휴식
- 맛집/관광
- 혼자/함께
- 아침형/저녁형
- 절약/여유
- 계획/즉흥

10곳 미만: `StylePreview` (임시 미리보기, "정식 아님" 명시)

## 4. 상태 머신

```
[트리거] → PENDING
              |
         방문 1건+
              |
              v
         GENERATING ──실패──> FALLBACK_CARD
              |
           성공
              |
              v
           DRAFT ──사용자 수정──> EDITED
              |                       |
         (여행 종료 후)          (여행 종료 후)
              |                       |
              v                       v
          PUBLISHED             PUBLISHED

재생성: DRAFT|EDITED → overwrite 확인 → GENERATING
```

---

## 5. 트리거 조건

| 트리거 | 조건 | 비고 |
|---|---|---|
| 당일 회고 | 일자 경계(자정) + 방문 1건+ | 0건이면 PENDING 유지 |
| 전체 요약 | 여행 종료 이벤트 (TripCompleted) | 전 일자 하이라이트 종합 |
| 스타일 분석 | 누적 방문 ≥ 10곳 (단일 게이트) | 미달 시 임시 미리보기만 |

---

## 6. ScheduleAgent · PlanBAgent와의 차이

| 항목 | ScheduleAgent | PlanBAgent | ReflectAgent |
|---|---|---|---|
| 어셈블리 사용 | O | O | **X** |
| RAG/벡터 검색 | X | O | **X** |
| LLM 호출 | 2회 (점수+설명) | 1회 (대안 선택) | **1회** (서술 생성) |
| 시간 압박 | 20초 | 10초 | **여유** (백그라운드) |
| Tool 수 | 6개 | 7개 | **2개** (1차) |
| 핵심 | 최적화 | 상황 적응 | **텍스트 생성** |
