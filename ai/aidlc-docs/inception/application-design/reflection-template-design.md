# 회고 연출 템플릿 계약 — LLM은 장면 구성만, 결합은 서비스 (j03·j04·j06)

> `reflect-agent-design.md`(1차 A안)의 산출 포맷 확정 — 미결 #3("전체 요약 포맷") 해소.
> FE 합의(2026-08-21~22): LLM은 회고 **결과물(카드뉴스·릴스·영상)의 연출 템플릿**을 생성하고,
> 사용자가 사진을 넣으면 서비스가 결합해 최종 결과물을 렌더한다.
> 화면 정본: Figma 밴드 j — j03(오늘의 회고)·j04(여행 요약)·j06(공유 카드, no-photo 변형 존재).

---

## 1. 두 층을 구분한다 — 화면과 결과물

| 층 | 무엇 | LLM 개입 |
|---|---|---|
| **기록 화면** (j03·j04) | 고정 레이아웃 — 통계 카드·지도·일자 탭·사진 스트립 | 최소 — 캡션·하이라이트 문구만 |
| **회고 결과물** (j06 확장 — 카드뉴스·릴스·영상) | **LLM이 연출을 설계**하는 공유물 | 장면 시퀀스 전체 |

1차 결과물 포맷은 **CARD_NEWS**(정적 장면 시퀀스 — FE 렌더만으로 완성)다.
REELS·VIDEO는 같은 장면 스키마를 소비하는 합성 파이프라인이 생기면 확장한다(포맷 enum만 열어 둠).

## 2. 원칙 — 무엇을 누가 만드나

| 산출 | 만드는 곳 | 근거 |
|---|---|---|
| 연출(장면 순서·레이아웃 선택·캡션·표지·해시태그) | **LLM** — 단, 숫자는 자리표시자로 | 연출·서술은 LLM의 몫 |
| 통계(방문 N·이동 km·사진 N) | **서버 집계값** — 렌더 시 바인딩 | 숫자 환각 구조적 차단 |
| 사진 | **사용자 업로드분** — 슬롯에 바인딩 | LLM은 이미지를 보지 않는다 |
| 지도 장면 | 방문 기록 좌표 — 서비스 렌더 | LLM은 자리만 지정 |

핵심 장치는 **자리표시자**다. 캡션 속 숫자는 `{visit_count}`·`{distance_km}`처럼 뚫려 있고
렌더 시 서버 실측값이 바인딩된다 — 캡션 숫자가 틀릴 방법 자체가 없다
(일정 생성의 "Agent 출력은 Proposal이라 시각을 만들 수 없다"와 동형).

## 3. 스키마

### 3.1 봉투

```json
{
  "template_id": "uuid",
  "kind": "DAILY | TRIP_SUMMARY",
  "format": "CARD_NEWS",
  "generated_at": "iso8601",
  "is_fallback": false
}
```

### 3.2 연출 본문 — 장면 시퀀스

```json
{
  "cover": {
    "title": "사흘의 기록",
    "subtitle": "{region} · {start_date}~{end_date}",
    "photo_slot": { "visit_ref": { "date": "...", "poi_id": "..." } }
  },
  "scenes": [
    { "layout": "PHOTO_FULL",    "photo_slot": {"visit_ref": {...}},
      "caption": "첫날은 {poi:0.name}부터" },
    { "layout": "PHOTO_CAPTION", "photo_slot": {"visit_ref": {...}},
      "caption": "골목마다 색이 달랐던 감천" },
    { "layout": "STATS",
      "caption": "{visit_count}곳 · {distance_km}km · 사진 {photo_count}장" },
    { "layout": "MAP",
      "caption": "이렇게 움직였어요" },
    { "layout": "EVENT",         "source_event": "PLAN_B",
      "caption": "휴무를 만나 코스를 한 번 바꿨어요" }
  ],
  "hashtags": ["#부산여행", "#감천문화마을", "#TripPilot"]
}
```

- `layout`은 **닫힌 enum** — `PHOTO_FULL | PHOTO_CAPTION | STATS | MAP | EVENT`.
  LLM의 연출 자유는 "어떤 장면을 어떤 순서로, 무슨 캡션으로"까지고, 각 장면의 픽셀 배치는
  FE 렌더러가 소유한다(포맷별 9:16/1:1/4:5 변환 포함 — j06 탭 3종).
- `photo_slot.visit_ref`: 자리와 참조뿐 — 렌더 시 그 방문의 사용자 업로드 사진을 채우고,
  없으면 장면 생략 또는 no-photo 얼굴(j06 변형 선례).
- `EVENT` 장면은 `source_event`가 입력 이벤트(Plan-B·건너뜀)에 실재할 때만 유효.
- 기록 화면(j03 본문·j04 일자 캡션)은 이 스키마의 부분 소비다 — j03 본문 = DAILY의
  캡션 연결, j04 일자 캡션 = TRIP_SUMMARY 장면 캡션의 일자 대표.

## 4. 품질 판정 — 드롭이 아니라 N회 생성 → 최선 채택

한 번 생성해 통과/드롭으로 가르지 않는다. **총 3회까지 생성**하고(초회 + 재생성 2회,
위반이 0이면 조기 종료) 후보들을 결정론 규칙으로 랭킹해 **최선을 채택**한다.

### 4.1 위반 등급

| 등급 | 항목 | 최종 처리 |
|---|---|---|
| **하드** | 시간 표현(INV-3: `\d+분`·`\d+시간`·`오전 \d+시`류) · 자리표시자 어휘 밖 참조 · `visit_ref` ⊄ 방문 기록 · `source_event` 미실재 | 최선 후보에도 남으면 **그 장면/필드만 교체** — 참조는 유효한 값으로 갈아끼우고 캡션은 그 참조에 맞는 안전 문구로. **장면을 생략하지 않는다** |
| **소프트** | 캡션 길이 초과 · 장면 수 범위 밖(3~8) · 중복 visit_ref · 허용 밖 해시태그 | 랭킹 감점 |

> **개정 (2026-08-25, TRIP-558)** — 두 가지가 바뀌었다.
> ① **허용 밖 해시태그를 하드 → 소프트로 내렸다.** 하드(자동 삭제)로 두면 `#제주여행`처럼
> 지역명에 접사가 붙은 정당한 합성어까지 지운다. 소프트면 감점만 받아 더 나은 후보가
> 있을 때만 밀려나고, 없으면 그대로 나간다 — 부작용 없이 품질 압력만 남는다.
> ② **하드 교체가 장면을 생략하지 않는다.** 종전에는 `visit_ref` 오류(사진 필수 레이아웃)와
> `source_event` 미실재를 장면 생략으로 처리했는데, 카드 수가 줄어드는 대신 참조를 유효한
> 값으로 교체하고 캡션을 **그 참조에 맞는** 안전 문구로 바꾼다. 캡션을 함께 바꾸는 이유는
> 원 캡션이 다른 장소를 서술하면 갈아끼운 사진과 어긋나 거짓이 되기 때문이다.

### 4.2 랭킹 (결정론)

`(하드 위반 수 ↑ 낮을수록, 소프트 위반 수 ↑ 낮을수록, 장면 수 채움 ↑ 많을수록, 생성 차수 ↑ 이를수록)`
사전식 비교. LLM 심판(best-of-N judge)은 1차에서 쓰지 않는다 — 비용·비결정성.

### 4.3 폴백

3회 전부 실패(파싱 불가 등) 시 자리표시자·STATS·MAP 장면만으로 구성된 고정 템플릿
(`is_fallback: true`) — 정본 FallbackCard의 연출판. 서버 숫자는 항상 참이므로 폴백도
거짓 없는 결과물이 된다(INV-4).

## 5. 경계

- **`POST /ai/v1/reflection/generate` 신설** (경계 3종 → 4종). 요청: `kind` + 방문 기록·
  이벤트·페르소나 요약 — **백엔드가 조립해 전달**(generate와 동형, AI stateless).
  사진은 "어느 방문에 몇 장" 메타만 — 바이너리 절대 미포함.
- 시간 여유 작업 — deadline 미지정(TRIP-473). N회 생성 비용은 백그라운드라 허용.
- 트리거·상태 머신은 정본(reflect-agent-design.md §4·5) 그대로.

## 6. 백엔드 의존 (TRIP-478로 요청됨)

1. **사진 업로드 API** — 저장소(바이너리) + 메타(photo_id·trip·date·poi 연결) + 수명주기
   (계정 삭제 연쇄 포함). 현재 방문 체크에 photo 필드 없음(2026-08 실측).
2. `/ai/v1/reflection/generate` 호출 배선 + 결과 저장.
3. 방문 기록·Plan-B 이벤트 컨텍스트 조립.
