> **v0.1 초안 (2026-09-26)** · 상위 정본: `inception/application-design/mlops-llmops-design.md`
> 이 유닛이 다루는 것은 **"모델을 어디서 어떻게 돌리고, 바꿨을 때 어떻게 아는가"** 다.
> 프롬프트·평가·비용 정책(LLMOps)은 상위 정본이 이미 정했고 여기서 바꾸지 않는다.

## 1. 이 유닛의 대상 — 우리가 직접 돌리는 모델 2종

외부 API 로 부르는 생성 LLM(Anthropic·OpenAI)은 이 유닛 밖이다. **가중치를 우리가 들고
있는 것**만 여기 들어온다.

| # | 모델 | 쓰이는 곳 | 크기 | 하드웨어 |
|---|---|---|---|---|
| M-1 | `nlpai-lab/KURE-v1` (임베딩) | KB 검색·자유 입력 매칭 | fp32 2.1GB / 상주 4.2 GiB | CPU |
| M-2 | `local-reminder-qwen3-4b-v1` (리마인드 문구) | `POST /ai/v1/notification/copies` | 병합본 8GB | GPU 또는 서버리스 |

## 2. `ServingRoute` — 모델이 실제로 도는 자리

`main.py::_local_route` 가 env 로 고르는 전송로. **값 객체가 아니라 조립 시점의 분기**이고,
그 분기 규칙 자체가 계약이다.

| 전송로 | 환경변수 | 지금 상태 | 성격 |
|---|---|---|---|
| **Bedrock Custom Model Import** | `TRIPPILOT_BEDROCK_MODEL_ARN` | **실서비스(배포됨)** | 서버리스 · 무요청 0원 · 5분 창 과금 |
| OpenAI 호환 서버(vLLM·MLX) | `TRIPPILOT_LOCAL_LLM_BASE_URL` | 로컬 개발·Mac 검증 | 프로세스 하나 |
| 인클러스터 Triton(vLLM 백엔드) | 위와 같은 변수 + 차트 `reminderLlm.enabled` | **매니페스트만 · 꺼짐** | GPU 노드 · KEDA 0↔1 |

### 우선순위가 계약이다

    TRIPPILOT_REMINDER_TRANSPORT 가 있으면 그것이 이긴다.
    없으면 ARN 이 이긴다. 둘 다 없는데 local* 모델이 배정돼 있으면 기동 실패.

암묵 규칙(ARN 우선)은 실서비스 설정이 개발용 잔재를 덮는 방향이다. 반대로 두면 누가
`.env` 에 남겨 둔 localhost 로 실서비스가 나간다.

> **함정이었던 것**: 그 규칙만 있으면 **인클러스터 파드를 켜도 ARN 이 살아 있는 한 트래픽이
> 안 온다.** 에러가 아니라 "켜 놓고 왜 안 쓰이지"를 뒤지는 형태다. 그래서 전환이 파드를
> 띄우는 일이 아니라 **Secrets Manager 에서 ARN 을 지우는 일**이 되고, 되돌리기가 시크릿
> 복원이라 **실험이 아니라 전환**이 된다.
>
> **해소 (2026-09-26)**: `TRIPPILOT_REMINDER_TRANSPORT=bedrock|local` 이 ARN 을 지우지 않고
> 전송로를 고른다. 되돌리기는 값 하나다. 차트는 `reminderLlm.transport` 로 노출하고,
> **파드를 켜면 기본이 `local`** 이다 — 아무도 안 부르는 파드가 위 함정 그 자체이므로.
> 파드는 띄우되 트래픽은 두고 싶으면(섀도) `bedrock` 으로 명시한다.
>
> 미설정은 **종전 동작 그대로**다. 기본값이 동작을 바꾸면 이 스위치 자체가 사고다.

## 3. `ModelIdentity` — 이름 하나가 3중 계약

`local-reminder-qwen3-4b-v1` 문자열은 세 곳에서 **정확히 같아야** 한다.

| 자리 | 무엇 |
|---|---|
| `TRIPPILOT_LLM_FEATURE_MODELS` 의 `REMINDER_COPY` 배정값 | 앱이 보내는 `model=` |
| vLLM `--served-model-name` / Triton 모델 레포지토리 디렉토리명 | 서버가 아는 이름 |
| 런북·차트 `reminderLlm.servedModelName` | 배포가 박는 값 |

그리고 **`local` 로 시작해야 한다** — 아니면 `_local_route` 가 라우트를 아예 안 만들고
호출이 **예외 없이 외부 벤더로 나간다.** 에러가 아니라 "파인튜닝 모델이 안 쓰이는" 형태다.

**두 번째 함정**: 이름이 맞아도 **병합 안 된 베이스 가중치**가 그 이름으로 서빙되면
그럴듯한 답이 나온다. 그래서 이름 확인과 별개로 문체 대조가 런북 §4 에 있다.

## 4. `EmbeddingBackend` — 같은 모델을 다른 엔진으로

| 값 | 엔진 | 상태 |
|---|---|---|
| `sentence-transformers` (기본) | PyTorch 계열, 프로세스 안 | 현행 |
| `triton` | ONNX Runtime, 별도 컨테이너 | 구현됨 · 꺼짐 · **채택 보류** |

**전환 전제는 지연이 아니라 동등성이다.** 벡터가 다르면 적재된 공간과 어긋나 검색이 조용히
엉터리가 된다 — 차원이 같아 `dim` 검사도 호출측 모델 대조도 못 잡는다.

동등성 판정(고정): **문서벡터 코사인 ≥ 0.9999 ∧ top-4 순위 전부 동일**.

## 5. `MeasurementRecord` — 판정에 쓸 수 있는 숫자의 조건

이 유닛의 결정은 전부 측정으로 갈린다. 그래서 **측정 자체가 도메인 개념**이다.

| 필드 | 왜 필요한가 |
|---|---|
| 아키텍처(arm64/amd64) | **우열이 뒤집힌다** — 맥 네이티브에서 ONNX 1.29배 빠름, 맥 컨테이너에서 1.60배 느림 |
| 스레드 수 | 안 맞추면 백엔드 비교가 아니라 코어 수 비교가 된다 |
| 실행 형태(네이티브/컨테이너/VM) | Docker Desktop VM 벌점이 백엔드마다 다르다(torch 2.42× · ORT 5.01×) |
| 표본 수·중앙값 | 공유 러너는 분산이 크다 |
| 어느 모델이 실제로 답했는지 | 아니면 A/B 한쪽이 외부 모델 성적이 된다 |

**조건이 다른 두 숫자를 나란히 놓지 않는다.** 이 리포가 이미 같은 함정을 겪었다
(KB 24건 표 ↔ 49건 표를 이어 붙일 수 없음).

### 지금 가진 기준선

| 대상 | 값 | 조건 |
|---|---|---|
| M-2 Bedrock CMI | 문구 1건 **1,375ms**(in 602 / out 72) · CMU 1 · 5분 창 과금 · 무요청 0원 | 실배포 실호출 1건 |
| M-1 현행 vs ONNX | 0.87× · 0.85× (ONNX 가 빠름) | amd64 · 4스레드 · KB-3 38건 · 2회 |
| M-2 EKS GPU | **없음** | — |

## 6. 상위 정본과 어긋난 것

> ⚠️ **§2.1 단계 전략** — 정본은 "**모델은 DAU 1천 이후**(Phase M1)"라고 적었다. 실제로는
> 2026-09 에 리마인드 문구용 Qwen3-4B 를 파인튜닝해 서빙까지 갔다. 정본이 전제한 모델
> (선호 점수 LTR·체류시간 회귀)과 **종류가 다르다** — 자체 학습 랭킹/회귀가 아니라 **문장
> 생성 LLM 의 경량 대체**다. 정본 §3 유형 표에도 이 칸이 없다. 단계를 어긴 것이 아니라
> 정본이 예상하지 않은 축이 생긴 것이고, 정본에 유형 E(생성 모델 자체 서빙)를 추가하는
> 것이 맞다.

> ⚠️ **§2.3 파이프라인** — 정본은 서빙을 "SageMaker 엔드포인트"로 적었다. 실제 경로는
> **MLX 로 학습(Mac) → 병합 → Bedrock Custom Model Import 서빙**이고, SageMaker 는 어디에도
> 쓰이지 않는다. 학습이 클라우드가 아니라 개인 Mac 48GB 에서 도는 것도 정본에 없다.

두 건은 [[모순 장부]] 에 올린다 — 정본을 근거로 다음 설계를 세우면 틀린다.
