# MLOps 서빙·운영 — 비즈니스 규칙 + 테스트 게이트 (FD)

> **v0.1 초안 (2026-09-26)** · 규칙 ID 는 `BR-MLO-nn`.
> 이 유닛의 규칙은 대부분 **"조용히 틀리는 것"을 시끄럽게 만드는 장치**다. 서빙은 틀려도
> 예외가 안 나는 영역이라(다른 모델이 답해도, 벡터 공간이 어긋나도 200 이 나간다) 규칙이
> 없으면 사고가 지표로만 드러난다.

---

## 1. 전송로·모델 정체성

### BR-MLO-01 — `local*` 접두어가 라우트를 켠다

`TRIPPILOT_LLM_FEATURE_MODELS` 의 배정값이 `local` 로 시작할 때만 로컬 라우트를 만든다.
아니면 호출은 **예외 없이 외부 벤더로 나간다.**

**강제**: 차트 스키마 패턴 `^local[a-zA-Z0-9._-]*$` · 차트 렌더 테스트 ·
`scripts/smoke_reminder_copy.py::assert_served_model`.

### BR-MLO-02 — 배정됐는데 전송로가 없으면 기동 실패

`local*` 이 배정됐는데 `TRIPPILOT_BEDROCK_MODEL_ARN` · `TRIPPILOT_LOCAL_LLM_BASE_URL` 이
둘 다 없으면 **RuntimeError 로 기동을 막는다.** 조용히 기본 벤더로 나가면 파인튜닝 모델이
안 붙은 채 정상처럼 보인다. 런타임 연결 실패는 다른 이야기이고 폴백 계단이 받는다(INV-4).

### BR-MLO-03 — ARN 이 이긴다

둘 다 설정되면 Bedrock 이 이긴다. 실서비스 설정이 개발용 잔재를 덮는 방향이다.

**따름 규칙**: 인클러스터 서빙으로 **전환하는 행위는 파드를 켜는 것이 아니라 ARN 을 내리는
것**이다. 파드만 켜면 트래픽이 안 오고, 그 상태는 에러로 드러나지 않는다.

### BR-MLO-04 — 이름이 맞아도 가중치는 별도로 확인한다

병합 안 된 베이스 모델이 같은 이름으로 서빙돼도 그럴듯한 답이 나온다. 배포 직후 **문체
대조**(런북 §4)를 한다. 자동화된 것은 이름 확인까지이고, 가중치 확인은 사람이 본다.

## 2. 임베딩 엔진 교체

### BR-MLO-05 — 동등성이 지연보다 먼저다

엔진을 바꾸려면 **문서벡터 코사인 ≥ 0.9999 ∧ top-4 순위 전부 동일**. 하나라도 어긋나면
지연 이득과 무관하게 채택 불가다. 적재된 벡터와 다른 공간으로 질의하면 검색이 **예외도
로그도 없이** 엉터리가 된다.

### BR-MLO-06 — 풀링 모드는 내보내기 시점에 검사한다

KURE-v1 은 CLS 풀링이다. mean 으로 잘못 구현해도 차원은 1024 그대로라 `dim` 검사도 호출측
대조도 테스트도 못 잡는다 — 실측으로 코사인이 **0.71** 까지 떨어진다.
`export_onnx.py` 가 `1_Pooling/config.json` 을 읽어 검사하고, **모르는 설정 모양이면
통과시키지 않는다**(sentence-transformers 5.x/6.x 의 dict 모양이 다르다).

### BR-MLO-07 — 풀링·정렬·정규화는 한 벌만 존재한다

측정 하네스도 서빙 코드(`_embed_triton`)를 그대로 탄다. 추론 함수만 주입해 바꾼다. 두 벌로
구현하면 갈라지는데 차원이 같아 아무 검사도 못 잡는다.

### BR-MLO-08 — `/embed` 응답의 `model`·`dim` 은 어떤 백엔드에서도 같다

백엔드에 따라 `model` 을 다르게 실으면 `HttpEmbeddingAdapter` 가 **모델 교체로 읽고** 전량
재적재를 요구한다. 내부 구현이 바뀌어도 이 두 필드는 불변이다.

## 3. 캐시

### BR-MLO-09 — 벡터 캐시 키는 텍스트 정확일치다

유사도로 벡터를 재사용하지 않는다. 적재된 공간과 다른 값을 쓰게 되고 BR-AF-09(차원)도
collection 이름 규칙(TRIP-519)도 이걸 못 잡는다.

### BR-MLO-10 — `dim`·`model_id` 는 래퍼가 가리지 않는다

`model_id` 가 collection 이름에 들어간다. 래퍼가 가리면 적재와 질의가 다른 collection 을
본다.

### BR-MLO-11 — 실패는 캐시하지 않는다

일시 장애를 굳히면 프로세스를 재시작해야 풀린다.

### BR-MLO-12 — 세만틱 캐시는 **출력이 닫힌 키인 경로에만**

자유 입력 → 지시 키 경로(KB-4)에만 둔다. 틀린 별칭이 끼어도 사전 조회와 게이트가 막는다.
**생성 문구(리마인드·설명·차선책)에는 두지 않는다** — 게이트가 "이 요청의 장소 집합"으로
막기 때문에 유사 요청의 답을 재사용하면 절감이 아니라 **드롭**으로 나타난다.

### BR-MLO-13 — 되먹임 별칭은 회귀 게이트 뒤에서만 켠다

별칭이 늘면 **과다선택이 먼저 오른다**(실측 2026-09-12: 임계 0.74 = 정확일치 18/23 ·
과다선택 3). 켜기 전 `scripts/measure_directive_match.py` 를 돌려 **정확일치 ≥ 18/23 ∧
과다선택 ≤ 3** 을 확인한다. 적재분에는 `source: feedback` 표식과 멱등 doc_id 를 박아
되돌리기를 DELETE 한 줄로 만든다.

## 4. 스케일링

### BR-MLO-14 — 임베딩에는 오토스케일링을 두지 않는다

파드가 5Gi 를 요청하고 모델 로드가 수십 초다(startupProbe 최대 15분). 부하를 보고 늘리면
이미 늦고, 워커를 늘리는 길은 프로세스당 4.2 GiB 라 막혀 있다. **values 에 키 자체를 두지
않고 스키마가 추가를 거부한다.**

### BR-MLO-15 — HPA 가 켜진 컴포넌트는 `replicas` 를 렌더하지 않는다

둘 다 실으면 다음 `helm upgrade` 가 HPA 가 정한 수를 되돌린다.

### BR-MLO-16 — `metrics-server` 없이 HPA 를 켜지 않는다

목표치가 `<unknown>` 인 채 replica 소유권만 가져가 **늘지도 줄지도 않으면서 수동 조절을
막는다.**

### BR-MLO-17 — GPU 한도는 values 가 아니라 템플릿에 박는다

빠지면 파드가 CPU 노드에 스케줄되고, 기동 실패가 아니라 **런타임 실패**로 늦게 드러난다.

## 5. 측정

### BR-MLO-18 — 조건이 다른 숫자를 나란히 놓지 않는다

아키텍처·스레드 수·실행 형태(네이티브/컨테이너)가 같아야 비교다. **우열이 실제로 뒤집힌
전례가 있다** — 맥 네이티브 ONNX 1.29배 빠름 ↔ 맥 컨테이너 1.60배 느림.

### BR-MLO-19 — 판정용 측정은 배포 대상 아키텍처(amd64)에서 한다

개발 맥은 arm64 다. `ai-embedding-backend-bench` 워크플로가 그 자리다.

### BR-MLO-20 — A/B 는 누가 답했는지 먼저 확인한다

확인 없이 재면 한쪽이 외부 모델 성적일 수 있다. 조회 실패를 "해당 없음"으로 읽지 않는다.

### BR-MLO-21 — 미측정은 미측정으로 적는다

추정치를 만들어 채우지 않는다. 상위 정본의 원칙("없는 값은 미측정으로 적는다")을 따른다.

## 6. 비용

### BR-MLO-22 — 전송로를 옮기는 근거는 비용이다(지연이 아니다)

M-2 는 비동기 배치라 더 느려도 된다. 기준선은 **1건 1,375ms · CMU 1 · 5분 창 과금 ·
무요청 0원**이고, 옮기려면 **이보다 싸야** 한다.

### BR-MLO-23 — "0원"은 설계가 아니라 청구서로 확인한다

KEDA 0 스케일·Karpenter 노드 반납은 매니페스트의 주장이다. 첫 배포 후 **무요청 24시간
청구액 0** 을 보기 전까지 "예산이 샌다"는 우려는 닫히지 않는다. Bedrock 쪽도 같은 확인이
아직 안 됐다.
