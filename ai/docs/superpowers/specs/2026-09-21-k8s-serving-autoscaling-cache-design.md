# K8s 서빙·오토스케일링·Triton·세만틱 캐시 설계

**작성 2026-09-21 · 기준 커밋 `42c576cb` · 상태: 사용자 리뷰 대기**

## 1. 목적과 범위

사용자 지시는 "쿠버네티스에서 서빙하고, 트래픽에 따라 오토스케일링하며, Triton Inference
Server 로 파이프라인을 구축한다" + "세만틱 캐싱도 적용"이고, **목적은 실제 운영 효율
개선**(학습·전시용 아님, 2026-09-21 확인). 적용 범위는 **로컬 kind 에서 만들고 재서,
이긴 것만 EKS 차트 PR 로 올려 두는 것**까지다. 머지는 이 문서의 범위가 아니다.

### 이미 있는 것과 없는 것

| 요소 | 현재 | 출처 |
|---|---|---|
| K8s 서빙 | **있다** — 로컬 kind(`deploy/k8s/`) + EKS Helm 차트(`deploy/eks/chart/`) | `deploy/README.md` |
| 오토스케일링 | **없다** — `HorizontalPodAutoscaler` 0건, replicas 고정 | 차트 템플릿 9종 |
| Triton | **없다** | 리포 전체 0건 |
| 세만틱 매칭 | **있다** — 자유 입력→지시 키 임계 0.74 | `agents/planb/directives.py` |
| 캐시 | (페르소나, poi_id) LRU 1종 | `workers/preference_cache.py` |

자체 호스팅 모델은 둘뿐이다. **KURE-v1 임베딩**(CPU, 상주 4.2 GiB)과 **REMINDER_COPY
파인튜닝 Qwen3-4B**(GPU). 생성 LLM 나머지는 전부 외부 API 다.

## 2. 전제 — 결정에 영향을 주는 사실 넷

1. **리마인드 모델 서빙은 아직 배포되지 않았다.** 코드(`modal_app.py`·런북 §4)는
   develop 에 있으나 Modal 인증·볼륨 업로드·배포·대조 검증은 미실행이다. 즉 **비교할
   기준선이 없다.** 품질만 검증돼 있다(홀드아웃 28/30, 심판 블라인드 학생 12 : 교사 8 :
   상수 0).
2. **EKS 에 GPU 노드가 없다.** EKS Auto Mode 의 `general-purpose` 풀은 C·M·R 계열
   amd64 on-demand 이고 GPU 를 포함하지 않는다. 별도 NodePool 은 인프라 변경이고
   `infra/terraform/` 은 백엔드 소유(TRIP-885)다. 신규 계정 GPU 쿼터는 0 이다.
3. **임베딩 동적 배칭은 여기서 값을 못 한다.** 런타임 임베딩은 자유 텍스트 요청에서만
   1회/요청 발생한다. 상황 KB·페르소나 KB 질의는 `TriggerKind` 4 × `_REASON_KO` 7 =
   **28가지 닫힌 집합**이고 칩 조회는 벡터를 안 탄다. 정점(4.37 GiB) ≈ 상주(4.29 GiB)라
   배칭으로 아낄 메모리도 없다. → `ai/docs/임베딩-사이징-근거.md`
4. **모델 이름이 계약이다.** `main.py::_local_route` 는 배정 모델명이 `local` 로 시작할
   때만 로컬 라우트를 만든다. 어긋나면 **예외 없이 외부 벤더로 나간다** — 파인튜닝
   모델이 안 붙은 채 정상처럼 보인다.

## 3. 설계

네 덩어리다. 각각 독립적으로 채택·폐기할 수 있다.

### 3-1. 오토스케일링 (HPA)

- **대상은 `ai` 와 `gateway`.** 둘 다 상태 없는 CPU 바운드이고 기동이 빠르다.
- **임베딩에는 붙이지 않는다.** 파드가 5 GiB 를 요청하고 모델 로드에 수십 초가 걸린다
  (`startupProbe.failureThreshold: 180`). 부하를 보고 늘리면 늦고, `--workers` 를 늘리면
  프로세스당 4.2 GiB 라 OOM 이다. replicas 1 유지 근거를 차트 주석에 남긴다.
- 지표는 CPU 사용률 1종으로 시작한다. 커스텀 지표는 값이 증명되기 전엔 넣지 않는다.
- 로컬 kind 에 `metrics-server` 를 넣어야 동작한다 — `deploy/bin/cluster-up.sh` 에 추가.

```
values.yaml
  ai.autoscaling: { enabled, minReplicas, maxReplicas, targetCPUUtilizationPercentage }
  gateway.autoscaling: 동일
  embedding: autoscaling 키 자체를 두지 않는다 (주석으로 이유)
```

### 3-2. Triton — 모델 서버 한 장

두 모델을 한 제어면에 모은다. 어느 쪽도 **호출측 계약을 바꾸지 않는다.**

**임베딩(CPU, ONNX 백엔드).** 기존 FastAPI 단일 파일 서비스를 계약 표면으로 **유지**하고,
그 안에서 `SentenceTransformer` 대신 Triton 을 호출하는 경로를 플래그로 추가한다.
`POST /embed` 응답의 `model`·`dim` 보증이 살아 있어야 `HttpEmbeddingAdapter` 의 거부
장치가 그대로 동작하기 때문이다. 채택은 §4 A/B 가 이길 때만.

**리마인드 LLM(GPU, vLLM 백엔드).** Triton 모델 레포지토리 디렉토리명을
`local-reminder-qwen3-4b-v1` 로 **정확히** 고정한다(§2-4). KEDA 로 0↔1, GPU 노드는
Karpenter 가 파드 pending 시에만 띄운다. 채움 잡이 발송 수 시간~며칠 전에 도는 비동기
경계라 노드 기동 수 분을 감당한다.

> **이 칸은 지금 수치로 정당화되지 않는다.** 기준선이 없고(§2-1) GPU 노드도 없다(§2-2).
> 사용자 지시로 **매니페스트와 A/B 하네스까지 작성**하되, 채택 판정은 Modal 배포 후
> 비교가 가능해질 때로 미룬다. GPU NodePool·쿼터 신청은 백엔드 티켓으로 분리한다.

### 3-3. 세만틱 캐시 — 세 층

**T1. 임베딩 정확 캐시 + 닫힌 질의 선계산.** 텍스트 해시 → 벡터. 28가지 닫힌 질의는
기동 시 미리 계산한다. 파드가 1개라 프로세스 내 `lru_cache` 로 충분하다 — Redis 를 넣지
않는다.

**T2. 지시 번역 되먹임 캐시.** LLM 워커가 번역해 낸 (발화, 키) 쌍을 별칭 벡터로 되써서,
다음 유사 발화를 0.74 매칭이 LLM 없이 잡게 한다. **우리 구조에서 세만틱 캐시가 값을
하는 유일한 자리**다 — 출력이 닫힌 키라 틀려도 게이트가 막는다.

**T3. 생성 문구에는 세만틱 캐시를 넣지 않는다.** 리마인드·설명·차선책 게이트는 "이 요청의
장소 집합 안의 이름만" 통과시킨다(INV-1). 유사 요청의 답을 재사용하면 이번 요청에 없는
장소가 실려 **드롭**된다. 절감이 아니라 품질 저하로 나타난다. 정확 키 캐시조차 히트율을
먼저 재고 결정한다(슬롯 조합이 여행마다 달라 히트율이 낮을 것으로 본다).

### 3-4. 판정용 측정

채택 여부를 수치가 정한다. 측정 없는 채택은 이 설계의 실패 모드다.

## 4. 측정과 채택 기준

| 대상 | 방법 | 채택 조건 |
|---|---|---|
| 임베딩 Triton | `scripts/measure_embedding_precision.py` — **CPU 4스레드 고정 · KB-3 24건 × 질의 6종** 동일 조건 | p95 지연이 유의미하게 낮고 순위가 동일 |
| T1 캐시 | 요청 1회당 임베딩 호출 수 | 닫힌 질의 경로 호출 0회 |
| T2 되먹임 | `scripts/measure_directive_match.py` 회귀 | **정확일치 ≥ 18/23 ∧ 과다선택 ≤ 3** 유지. 깨지면 되먹임 off |
| HPA | 로컬 부하 발생 → 파드 수·p95 | 스케일 아웃이 p95 를 낮춤 |
| 리마인드 Triton | 대조 검증 + 지연·비용 | 기준선 생긴 뒤 판정 |

**하네스 필수 단언**: 응답한 모델이 실제로 파인튜닝 모델인지 확인한다(§2-4). 없으면
A/B 한쪽이 외부 모델 성적일 수 있다.

## 5. 비용

| 구성 | 월 비용 |
|---|---|
| 서울 리전 GPU 상시 | 40만~50만원 (설계문서 실측) |
| Modal 서버리스 | 무요청 0원 · 무료 크레딧 월 50 GPU시간 |
| EKS + KEDA 0으로 축소 | 사용분만 + 노드 기동 지연 |

`modal_app.py` 가 적어 둔 AWS 이전 트리거는 **실운영 배포 / 팀원 직접 운영 / 상시 GPU 가
더 싼 호출량** 셋이다. 지금 호출량은 셋 중 무엇도 만족하지 않는다.

## 6. 위험과 되돌리기

| 위험 | 완화 |
|---|---|
| 모델명 불일치로 외부 LLM 으로 조용히 빠짐 | 하네스 단언 + 차트 값 검증 테스트 |
| 되먹임 별칭 증가 → 과다선택 | 회귀 임계(§4), 미달 시 off. 별칭은 별도 collection 으로 분리해 롤백을 적재 단위로 |
| Triton 도입이 임베딩 계약을 깨뜨림 | FastAPI 표면 유지, `model`·`dim` 보증 불변 |
| HPA 가 임베딩까지 흔듦 | 임베딩에 autoscaling 키를 두지 않음 |
| EKS 차트 변경이 백엔드 트랙과 충돌 | PR 만 열고 머지는 백엔드 리뷰 |

모든 항목은 플래그 또는 값으로 꺼진다. 되돌리기는 값 한 줄이다.

## 8. 이 설계가 하지 않는 것

- 외부 LLM 호출을 자체 서빙으로 바꾸지 않는다.
- 벡터 DB 에 인덱스를 만들지 않는다(1 MB 미만, 정확검색이 더 빠름).
- 생성 문구에 세만틱 캐시를 넣지 않는다(§3-3 T3).
- Redis 를 도입하지 않는다(파드 1개, 프로세스 내 캐시로 충분).
- `deploy/eks/` 를 머지하지 않는다.
