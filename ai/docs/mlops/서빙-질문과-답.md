## Q1. 오토스케일링을 왜 기본값으로 꺼 두나? 켜는 게 낫지 않나?

**지금 켜면 동작하지 않는다.** HPA 는 파드의 CPU 사용률을 metrics API 로 읽어서 판단하는데,
그 값을 공급하는 `metrics-server` 가 클러스터에 없다.

    $ grep -ril "metrics-server" deploy infra
    (0건)

metrics-server 없이 HPA 를 켜면 이렇게 된다.

1. HPA 오브젝트는 생성된다. 에러도 안 난다.
2. `kubectl get hpa` 의 TARGETS 가 `<unknown>/70%` 로 뜬다.
3. **그 상태에서 HPA 가 replica 소유권을 가져간다.** Deployment 는 `replicas` 를 렌더하지
   않으므로(그래야 `helm upgrade` 가 HPA 가 정한 수를 되돌리지 않는다), 아무도 수를 정하지
   않는 상태가 된다.

즉 "켜 두면 필요할 때 늘어난다"가 아니라 **"켜 두면 늘지도 줄지도 않으면서 수동 조절만
막는다"** 가 된다. 그래서 기본값이 꺼짐이고, 이건 보수적으로 잡은 것이 아니라 선행 조건이
안 갖춰졌기 때문이다.

### 켜려면 필요한 것

| 필요한 것 | 현재 |
|---|---|
| `metrics-server` 설치 | 없음 |
| 부하 실측(어느 지표로 늘릴지) | 없음 |
| `deploy/eks` 소유자(백엔드) 동의 | PR 리뷰 대기 |

### 권고

metrics-server 가 들어가면 **prd 부터 켜는 것이 맞다.** prd 는 이미 ai·backend·gateway 가
replicas 2 로 고정돼 있어서, 고정 2 를 "최소 2, 최대 4"로 바꾸는 것은 순이득이다. dev 는
부하가 없어 켤 이유가 없다.

**임베딩에는 어느 쪽이든 붙이지 않는다.** 파드가 5Gi 를 요청하고 모델 로드가 수십 초라
(startupProbe 최대 15분) 부하를 보고 늘리면 이미 늦고, 프로세스당 4.2 GiB 라 워커를 늘리는
길도 막혀 있다. 근거는 [[임베딩-사이징-근거]].

## Q2. GPU 매니페스트는 뭐 하는 건가?

리마인드 문구를 쓰는 **우리가 직접 파인튜닝한 모델**(Qwen3-4B)을 쿠버네티스 안에서 돌리기
위한 배포 설정이다. 파일은 `deploy/eks/chart/templates/reminder-llm.yaml`.

핵심은 **안 쓸 때 0으로 내려가는 것**이다.

```
요청 없음 → KEDA 가 replica 를 0 으로 → 파드가 사라짐 → Karpenter 가 GPU 노드를 반납
요청 도착 → replica 1 → 노드가 새로 뜸(수 분) → Triton 기동 → 응답
```

리마인드 문구 채움은 발송 **몇 시간~며칠 전에** 도는 배치라 사용자가 기다리는 경로가 아니다.
그래서 수 분짜리 콜드스타트를 감당할 수 있고, 그게 0으로 내릴 수 있는 이유다.

## Q3. 표의 나머지 둘은 뭔가?

### Triton 임베딩 경로

KB 검색에 쓰는 임베딩 모델(KURE-v1)을 지금과 **다른 엔진으로 돌려 보는 경로**다. 계약은
그대로이고(`POST /embed` 가 벡터·모델명·차원을 돌려준다) 내부 구현만 env 하나로 갈린다.
기본값은 현행이라 켜지 않으면 아무 변화가 없다.

### amd64 벤치 워크플로

위 두 엔진을 **배포 대상과 같은 CPU 아키텍처(amd64)에서** 비교하는 수동 실행 워크플로다.
개발 맥은 arm64 인데, 실측에서 **아키텍처에 따라 우열이 뒤집혔다** — 맥 네이티브에서는
ONNX 가 1.29배 빨랐고 맥 컨테이너에서는 1.60배 느렸다. 그 숫자로는 결정할 수 없어서
GitHub 러너(amd64)를 쓰는 길을 냈다. PR 에 `bench-embedding` 라벨을 붙이면 돈다.

## Q4. Triton 과 ONNX 가 뭐고, 둘이 어떻게 다른가?

**층이 다르다. 경쟁 관계가 아니다.**

| | ONNX / ONNX Runtime | Triton Inference Server |
|---|---|---|
| 무엇인가 | 모델 **파일 형식**(ONNX) + 그걸 실행하는 **엔진**(ONNX Runtime) | 모델을 얹어 두고 HTTP·gRPC 로 **요청을 받는 서버** |
| 어디서 도나 | 우리 프로세스 **안** | **별도 컨테이너** |
| 무엇을 대신하나 | PyTorch — 즉 계산하는 주체 | uvicorn 같은 서빙 껍데기 |
| 비유 | 엔진 | 엔진을 담는 차체 |

Triton 은 내부적으로 ONNX Runtime 을 쓸 수도, PyTorch 를 쓸 수도, LLM 이면 vLLM 을 쓸 수도
있다. 즉 **Triton 을 쓴다고 빨라지는 게 아니라, 그 안의 엔진이 빠르면 빨라진다.**

### 우리 측정이 실제로 말한 것

amd64 에서 두 번 쟀고 방향이 같았다.

| 측정 | 현행(PyTorch 계열) | ONNX Runtime | 비 |
|---|---:|---:|---:|
| 1차 | 8,652 ms | 7,538 ms | 0.87× |
| 2차 | 9,636 ms | 8,226 ms | 0.85× |

벡터는 두 번 다 완전히 같았다(코사인 1.00000 · top-4 24/24 위치 동일) — 재적재 없이 바꿀
수 있다는 뜻이다.

그리고 **이 13~15% 는 엔진이 준 것이지 서버가 준 것이 아니다.** Triton 서버 자체의 몫은
측정에서 queue 1.8ms 수준으로 소수점이었다. 그래서 결론이 이렇게 갈린다.

| 안 | 속도 | 대가 |
|---|---|---|
| 현행 유지 | 기준 | 없음 |
| **ONNX 를 우리 프로세스 안에서** | 13~15% 이득 | 모델 변환 단계 하나 |
| Triton 별도 컨테이너 | 13~15% − 네트워크 왕복 | 컨테이너 1개 + 모델 2.1GB 상주(현 임베딩 파드 6Gi 와 **별도**) |

**단일 모델이면 Triton 은 수지가 안 맞는다.** Triton 이 값을 하는 조건은 여러 모델을 한
제어면에 모아 버전·배치·지표를 한 곳에서 다룰 때다.

## 결정 기록 — Modal 대신 AWS GPU (2026-09-26, 사용자 결정)

리마인드 모델 서빙을 **Modal 서버리스가 아니라 AWS(EKS) GPU 로 간다.**

이전 결정(2026-09-12, `ai/scripts/finetune_reminder/modal_app.py`)의 기각 근거는 둘이었다.
① EC2 GPU 는 끄는 걸 잊으면 예산이 계속 나간다(서울 리전 24/7 월 40~50만 원대)
② 신규 계정 GPU 쿼터가 0 이라 증설 신청에 수일이 걸린다.

이번 결정으로 ①은 **설계로 막는다** — KEDA 가 replica 를 0 까지 내리고 Karpenter 가 노드를
반납하므로, 무요청 구간에 GPU 요금이 붙지 않는다. 다만 이건 **매니페스트가 그렇게 돼 있다**
는 뜻이지 아직 실물로 확인한 것이 아니다. 첫 배포 후 **무요청 24시간 구간의 청구액이 0인지**
반드시 확인한다. 이 확인 전까지는 ①이 해소됐다고 보지 않는다.

②는 남아 있고, 리드타임이 가장 길다. 그래서 순서가 정해진다.

1. GPU 서비스 쿼터 신청 — 지금 바로 (수일)
2. GPU NodePool + NVIDIA device plugin + KEDA 설치 — 백엔드 (TRIP-961)
3. 모델 가중치를 클러스터에서 읽을 자리 마련(PVC) + 첫 배포
4. 무요청 청구액 0 확인 → 그때 ①이 닫힌다

### 이 결정이 바꾸는 것

- **TRIP-961 의 성격이 바뀐다.** "조건 기록"으로 냈는데 이제 **착수 요청**이다.
- `modal_app.py` 와 런북 §4 는 **지우지 않는다.** 쿼터가 며칠 걸리고 그 사이 평가·시연이
  필요하면 Modal 이 유일한 길이다. 대신 머리말에 "운영 목표는 EKS"라고 적는다.
- 서빙 트랙 소유자(스케줄·로컬LLM 세션)에게 알린다 — 그쪽이 Modal 앱을 만들었다.
- 모델 이름 계약은 그대로다. `local-reminder-qwen3-4b-v1` 이 Triton 모델 디렉토리 ·
  요청의 `model=` · `TRIPPILOT_LLM_FEATURE_MODELS` 배정에서 **전부 같아야** 하고, `local`
  로 시작하지 않으면 앱이 로컬 라우트를 안 만들고 **예외 없이 외부 벤더로 나간다.**
