## 4. D-2 Triton 기각 — 판단이 두 번 뒤집힌 기록

### ① 첫 측정은 "3.5배 느림" 이었다

| 백엔드 | 지연(38건 인코딩) | 비 |
|---|---:|---:|
| 현행 sentence-transformers | 983 ms | 1.00× |
| Triton (ONNX Runtime) | 3,453 ms | 3.51× |

여기서 멈췄으면 "Triton 은 느리다"로 끝났을 것이다. **그런데 서버측 분해가 그 결론과
맞지 않았다** — queue 1.8ms · compute_input 0.05ms · compute_output 0.58ms 로 Triton 자신의
몫은 소수점이고 `compute_infer` 만 3,673ms 였다. 전송도 직렬화도 아니고 순수 연산이다.
즉 느린 것은 **서버가 아니라 그 안의 엔진이 도는 환경**이다.

### ② 교란을 제거하니 순위가 뒤집혔다

같은 ORT 버전·같은 그래프·같은 사전 토크나이즈 입력·같은 4스레드로 2×2 를 쟀다.

| | 네이티브 macOS | 컨테이너 linux/arm64 |
|---|---:|---:|
| torch | 992 ms | 2,406 ms |
| onnxruntime | 767 ms | **3,845 ms** |

**Docker Desktop VM 벌점이 백엔드마다 달랐다**(torch 2.42× · ORT 5.01×). 네이티브에서는
ORT 가 1.29배 빠르고 컨테이너에서는 1.60배 느리다. 개발 맥 숫자로는 어느 쪽도 결론이 안
된다는 뜻이고, 그래서 **배포 대상 아키텍처(amd64)에서 다시 쟀다.**

### ③ amd64 에서는 ONNX 가 이긴다

| 측정 | 현행 | ONNX Runtime | 비 |
|---|---:|---:|---:|
| 1차 | 8,652 ms | 7,538 ms | 0.87× |
| 2차 | 9,636 ms | 8,226 ms | 0.85× |

동등성은 세 환경 전부에서 통과했다 — **문서벡터 코사인 최소 1.00000, top-4 순위 6/6 질의
24/24 위치 동일.** 재적재 없이 전환 가능하다는 뜻이다.

### 결론

이득은 **엔진(ONNX Runtime) 몫이고 서버(Triton) 몫이 아니다.** 그래서 같은 이득을 컨테이너
없이 가져가는 쪽을 골랐다.

| 안 | 속도 | 대가 |
|---|---|---|
| 현행 유지 | 기준 | 없음 |
| **인프로세스 ONNX** ← 채택 | 13~15% | 모델 변환 단계 하나 |
| Triton 별도 컨테이너 | 13~15% − 네트워크 왕복 | 컨테이너 1개 + 모델 2.1GB 상주(현 임베딩 파드 6Gi 와 **별도**) |

**Triton 이 값을 하는 조건은 여러 모델을 한 제어면에 모을 때다.** 우리 둘은 CPU 임베딩과
서버리스 LLM 이라 공유할 제어면이 없다. 코드 경로는 플래그 뒤에 남겼다 — 모델이 늘면 그때
같은 하네스로 다시 잰다.

## 5. D-4 오토스케일링을 기본 꺼짐으로 둔 이유

보수적 선택이 아니라 **선행 조건 부재**다. `metrics-server` 가 클러스터에 없다(리포 전체
검색 0건). 없이 켜면 이렇게 된다.

```
HPA 생성됨 (에러 없음)
  → TARGETS <unknown>/70%
  → Deployment 는 replicas 를 렌더하지 않는다 (HPA 가 소유권을 가져갔으므로)
  → 아무도 수를 정하지 않는 상태
```

늘지도 줄지도 않으면서 **수동 조절만 막는다.** metrics-server 가 들어오면 prd 부터 켠다 —
거기는 이미 replicas 2 고정이라 "최소 2 · 최대 4"로 바꾸는 것이 순이득이다.

**임베딩에는 어느 쪽이든 붙이지 않는다.** 파드가 5Gi 를 요청하고 모델 로드가 수십 초라
(startupProbe 최대 15분) 부하를 보고 늘리면 이미 늦고, 워커를 늘리는 길은 프로세스당
4.2 GiB 라 막혀 있다. values 에 키 자체를 두지 않고 **스키마가 추가를 거부한다.**

## 6. 이 측정들을 믿을 수 있게 만든 장치 넷

숫자보다 이쪽이 오래 남는다.

| 장치 | 막는 사고 |
|---|---|
| **동등성이 지연보다 먼저** (코사인 ≥ 0.9999 ∧ top-4 전부 일치, 미달 시 종료 코드 1) | 빠른데 벡터가 다른 엔진 채택. 차원이 같아 `dim` 검사도 호출측 대조도 못 잡는다 |
| **풀링 구현은 한 벌만** (측정 하네스도 서빙 코드를 그대로 탄다) | CLS→mean 오구현. 실측으로 코사인 **0.71** 까지 떨어지는데 차원은 1024 그대로다 |
| **누가 답했는지 먼저 단언** (`assert_served_model`) | A/B 한쪽이 외부 모델·베이스 가중치 성적. 병합 안 된 모델도 그럴듯한 답을 낸다 |
| **조건 고정**(4스레드·워밍업 2회·중앙값 3회·같은 아키텍처) | §4②처럼 환경이 결론을 뒤집는다 |

## 10. 추가 결정 — D-5 인클러스터 GPU 서빙 철회 (2026-10-01)

§2 의 M-2(리마인드 문구)를 EKS 안에서 직접 서빙하는 매니페스트(`reminder-llm.yaml`
+ KEDA scale-to-zero + 전송로 전환 env)를 **철회한다.** 커밋
`revert(mlops): 인클러스터 GPU 리마인드 서빙 철회` 가 템플릿·값·스키마를 지웠다.

### 왜

감사에서 매니페스트 결함 4건이 나왔다 — 넷 다 "배포하면 조용히 안 되는" 종류다:

| | 결함 | 증상 |
|---|---|---|
| ① | Triton 이 `/v1` OpenAI 프런트엔드를 안 띄우는데 앱은 `/v1` 로 부른다 | 파드는 Ready, 호출은 404 |
| ② | `trippilot.podSpec`·`containerSecurity` 미적용 | 차트의 다른 파드와 보안 기준선이 어긋난다 |
| ③ | 모델 PVC 없음 | 재시작마다 2.1GB 를 다시 내려받는다 |
| ④ | KEDA 트리거가 존재하지 않는 메트릭을 본다 | 스케일이 영구히 0 — 호출이 와도 안 깨어난다 |

**넷을 다 고쳐도 남는 것은 "Bedrock 과 같은 일을 하는 두 번째 운영 경로"다.** Bedrock
Custom Model Import 경로는 이미 머지·개통되어 있고(#742), 전송로 우선순위
(`TRIPPILOT_REMINDER_TRANSPORT` > ARN > base_url)도 그 경로를 전제로 돈다. 두 경로를
동시에 들고 있으면 "어느 쪽이 지금 트래픽을 받는가"가 운영 질문으로 남는다 —
리마인드 문구는 그 질문을 감당할 만큼 중요한 기능이 아니다.

### 무엇이 남나

HPA(ai·gateway)·시맨틱 캐시·인프로세스 ONNX 는 남는다. 감사에서 이쪽 결함은 없었고,
셋 다 M-1(요청 경로의 임베딩) 쪽 이야기라 D-5 와 무관하다.

### 되살리는 조건

전환 판정기(`ai/scripts/mlops/serving_judge.py`, 주 1회 CloudWatch·CE 실측)가 Bedrock 대비
EKS GPU 우위를 **수치로** 제안할 때다. 그때는 위 4건이 미해결 상태로 남아 있으니
매니페스트를 처음부터 다시 쓴다 — 이 커밋을 revert 하지 않는다.

값만 되살아나는 사고는 차트 테스트가 막는다
(`test_in_cluster_reminder_serving_was_withdrawn` — 스키마가 `reminderLlm` 을 거부한다).

## 11. 추가 — 오토스케일링을 실제로 켰다 (2026-10-04)

§5 가 "기본 꺼짐은 보수가 아니라 **선행 조건 부재**"라고 적은 그 조건을 갖췄다.

### 무엇이 없었나

`metrics-server`. **EKS Auto Mode 는 이것을 주지 않는다** — AWS 의 Auto Mode 시작 안내도
HPA 절에서 그것을 따로 배포하라고 적는다(확인 2026-10-04). 없으면 HPA 는 목표치가
`<unknown>` 인 채 **replica 소유권만 가져간다**: 차트가 HPA 를 켜면 Deployment 에서
`replicas` 를 빼므로, 아무도 수를 정하지 않는 상태가 된다.

### 어떻게 넣었나

**EKS 커뮤니티 애드온**으로 넣었다 — `infra/terraform/stack/eks.tf` 의
`aws_eks_addon.metrics_server`. `addon_version` 을 일부러 비웠다(EKS 가 클러스터 버전에
맞는 기본 호환 버전을 고른다). 헬름 릴리스를 따로 두지 않은 이유는 **이 클러스터의
애드온 수명주기를 EKS 가 이미 들고 있기 때문**이고, 버전을 핀하지 않은 이유는 리소스
메트릭 수집기가 우리 워크로드 계약에 걸리는 표면이 없어서다.

**권한은 손대지 않았다.** 부트스트랩 템플릿의 `ManageEnvironmentEks` 가 이미
`eks:CreateAddon` 계열을 `addon/trippilot-${Environment}/*` 범위로 들고 있었다 —
10-01 의 403 을 또 밟지 않으려고 코드를 쓰기 전에 먼저 확인했다.

### 어디까지 켰나

| | |
|---|---|
| 차트 기본값(`values.yaml`) | **꺼짐 유지** — metrics-server 없는 클러스터에 올려도 안전해야 한다 |
| dev (`values-dev.yaml`) | **ai HPA 켬**, min 1 · max 3 |
| prd | **고정 2 유지** — 사람이 켠다 |

dev 를 먼저 켠 것은 부하를 받으려는 게 아니라 **동작을 보려는 것**이다. dev 는 트래픽이
없어 HPA 는 minReplicas 에 머물고, 확인하고 싶은 것은 "목표치를 읽는가"다.

prd 를 같이 켜지 않은 이유: prd 배포는 리뷰어 승인을 거치므로 값만 미리 머지하면
**다음 prd 배포가 조용히 동작을 바꾼다.** prd 는 고정 2 라 "최소 2 · 최대 4"가 순이득인
것도 맞지만, 그 판단은 dev 실측을 보고 사람이 한다(TRIP-966).

### 증거를 어디서 보나

배포 스모크가 HPA 의 목표치·현재값을 **기록한다**(`deploy/eks/runtime_smoke.py`
`report_autoscalers`). 통과/실패를 가르지는 않는다 — 메트릭은 파드 기동 뒤 수십 초가
지나야 채워지므로, 단언하면 멀쩡한 배포가 타이밍으로 깨진다. 현재값이 비어 있으면
어디를 볼지(그 애드온)까지 같이 찍는다.

### 아직 못 본 것

**부하를 걸어 replica 가 실제로 늘어나는 것.** dev 에 트래픽이 없고, 부하를 만들어
재는 것은 별개의 작업이다. 지금 말할 수 있는 것은 "켤 수 있게 됐고 dev 에 켜져 있다"
까지다 — 그 이상을 적지 않는다.

## 12. 추가 — 컨테이너 안 실측 하네스 (2026-10-04)

§8 "아직 못 잰 것"의 첫 줄을 재는 자리를 만들었다. 숫자는 아직 없다 — **잴 수 있게
됐다**는 것까지다.

### 왜 기존 하네스로는 안 되나

`scripts/measure_triton_embedding.py` 는 **인프로세스**다. 측정 코드가 ORT 세션을 직접
만들고, 그래프도 측정 중에 `export_onnx.py` 로 내보낸 것을 읽는다. 그래서 채택 기준이
요구하는 네 가지를 못 잰다.

| 못 재는 것 | 왜 중요한가 |
|---|---|
| 이미지에 **구운** 그래프로 기동하는가 | `EMBEDDING_BAKE_ONNX` 산출물로 띄워 본 적이 없다 |
| 앱 자신의 세션 옵션 | `EMBEDDING_ONNX_THREADS` → `intra_op_num_threads`. 측정 코드는 4 를 박아 쓴다 |
| 파드의 **CPU 한도** 아래 지연 | 러너는 코어가 더 많다. 한도가 2 인데 스레드 4 면 스로틀된다 |
| `/embed` 한 번의 값 | FastAPI·토크나이저·HTTP 왕복이 빠져 있다 |

### 어떻게 재나

`scripts/measure_embedding_container.py` + `ai-embedding-backend-bench` 의 `container` 잡.
**이미지를 빌드해 띄우고 `/embed` 를 부른다** — 파드가 실제로 하는 일을 잰다.

- 두 백엔드를 **순차로** 띄운다. 같은 CPU 한도를 각자 다 써야 비교가 되고, 동시에
  띄우면 서로 코어를 빼앗아 두 숫자 다 못 쓴다
- `--cpus=2` + `EMBEDDING_ONNX_THREADS=2` + `OMP/MKL_NUM_THREADS=2` — 파드 한도와 같다
- `/health` 의 `loaded` 가 참이 될 때까지 기다린다. 파드가 Ready 인데 모델이 아직 안
  올라온 창이 수십 초 있어서, 그 창에서 재면 모델 로드가 지연에 섞인다
- 같은 규약: 워밍업 2회 → 3회 중앙값
- `model`·`dim` 이 다르면 **비교 자체를 거부**한다 — 다른 벡터 공간이라 지연 비교가 무의미하다

### 게이트는 한 벌이다

동등성 상수(질의 묶음·top-4·코사인 0.9999)를 `scripts/embedding_ab_gate.py` 로 떼어
두 하네스가 같은 것을 읽는다. 복사하면 한쪽만 느슨해진다(BR-MLO-05). 인프로세스
하네스에서 가져오지 **않는** 이유는 그쪽이 `torch`·`sentence-transformers` 를 모듈
수준에서 임포트해서다 — 프로젝트 의존성도 아니고, 컨테이너 하네스는 HTTP 클라이언트다.

판정 로직은 테스트로 묶었다(`tests/test_measure_embedding_container.py`, 6건) —
동등 미달·순위 어긋남·다른 모델이 각각 거부로 가는지, 느릴 때 "전환하면 안 된다"고
적는지, 상수가 두 벌이 아닌지.
