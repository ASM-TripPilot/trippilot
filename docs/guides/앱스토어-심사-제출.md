# 앱스토어 심사 제출

제출 전에 사람이 채워야 하는 칸과, **코드에서 확인한 사실**을 짝지어 둔다. ASC 설문은 추측으로
채우면 안 되고(거짓 신고는 제재 사유다), 리포를 읽을 수 없는 사람이 채우게 되므로 여기 적는다.

> 이 문서는 **값의 근거**를 모은 것이다. 절차 자체(EAS 빌드·업로드)는 아래 §순서에만 적는다.

## 순서

빌드가 없으면 제출 버튼이 안 열린다. `extra.eas.projectId` 가 플레이스홀더면 `eas init` 이 선행이다.

```
eas login → eas init(projectId 발급·app.config.ts 커밋) → 애플 자격 연결
→ eas build -p ios --profile production → eas submit → ASC 처리(10~30분)
→ 메타데이터(아래) → TestFlight 실기 확인 → 제출
```

**애플 자격은 ASC API 키를 권한다** — ASC → Users and Access → Integrations →
App Store Connect API. Issuer ID · Key ID · `.p8`. **Sign in with Apple 키와 다른 키다.**

## 빌드에 들어가야 하는 `EXPO_PUBLIC_*`

**이 절이 이 문서에서 가장 조용한 결함이다.** 앱은 `EXPO_PUBLIC_*` 를 17개 읽는데
`eas.json` production 은 2개만 준다(2026-10-05 실측). 그리고 `frontend/.env` 는
**gitignore 라 EAS 빌드가 보지 못한다**(`git check-ignore` 확인). 빠진 값은
`?? ''` 로 떨어지므로 **빌드는 성공하고 바이너리만 고장난다.**

특히 셋은 `app.config.ts` 의 플러그인이 읽어 **네이티브 프로젝트에 박는다** — 빈 값으로
구워지면 **재빌드 없이는 못 고친다**:

```
['@react-native-seoul/kakao-login',   { kakaoAppKey: kakaoNativeAppKey }]
['@react-native-seoul/naver-login',   { urlScheme: naverUrlScheme }]
['@mj-studio/react-native-naver-map', { client_id: naverMapClientId }]
```

넣는 곳은 **EAS 환경변수**다(git 에 비밀을 넣지 않는다):

```
cd frontend
npx eas-cli@latest env:set --environment production \
  --name EXPO_PUBLIC_KAKAO_NATIVE_APP_KEY --value '<값>' --visibility sensitive
```

`--visibility` 는 `plaintext | sensitive | secret`, `--environment` 는
`development | preview | production` 이다(공식 문서 기준). `sensitive` 면 대시보드에서
값이 가려지고 빌드에만 주입된다. expo.dev 의 프로젝트 → Environment variables 화면에서
넣어도 같다.

### 필수 — 없으면 기능이 죽는다

| 변수 | 없으면 | 값 출처 |
|---|---|---|
| `EXPO_PUBLIC_API_BASE_URL` | 서버에 못 붙는다 | `eas.json` (운영은 `https://api.trippilot.co.kr`) |
| `EXPO_PUBLIC_KAKAO_NATIVE_APP_KEY` | **네이티브 빈 키** → 카카오 로그인 불가 | `frontend/.env` |
| `EXPO_PUBLIC_NAVER_URL_SCHEME` | **네이티브 빈 값** → 네이버 콜백 불가 | `frontend/.env` |
| `EXPO_PUBLIC_NAVER_MAP_CLIENT_ID` | **네이티브 빈 값** → 네이버 지도 안 뜸 | `frontend/.env` |
| `EXPO_PUBLIC_NAVER_CLIENT_ID` | 빈 client_id → OAuth 실패 | `frontend/.env` |
| `EXPO_PUBLIC_NAVER_CLIENT_SECRET` | 토큰 교환 실패 | `frontend/.env` |
| `EXPO_PUBLIC_GOOGLE_CLIENT_ID` | 빈 client_id → 실패 | **루트 `.env` 의 `GOOGLE_CLIENT_ID`** (아래 주의) |
| `EXPO_PUBLIC_KAKAO_CLIENT_ID` | 빈 client_id → 실패 | **루트 `.env` 의 `KAKAO_CLIENT_ID`** (아래 주의) |
| `EXPO_PUBLIC_GOOGLE_REDIRECT_URI` | 빈 redirect → 실패 | 콘솔에 등록된 값과 일치해야 한다 |
| `EXPO_PUBLIC_KAKAO_REDIRECT_URI` | 빈 redirect → 실패 | 같음 |
| `EXPO_PUBLIC_NAVER_REDIRECT_URI` | 빈 redirect → 실패 | 같음 |

> **⚠ 앱과 서버가 같은 `client_id` 를 써야 한다.** 구글·카카오는 백엔드가
> `token-uri` 로 **코드를 교환**한다(`application.yml` 의 `trippilot.social.*`).
> 그 교환은 앱이 코드를 받을 때 쓴 것과 같은 `client_id` 를 제시해야 성립하므로,
> 앱의 `EXPO_PUBLIC_GOOGLE_CLIENT_ID` 는 서버의 `GOOGLE_CLIENT_ID` 와 **같은 값**이어야 한다.
> 다른 값을 넣으면 로그인이 **토큰 교환 단계에서** 깨진다(화면에는 그냥 실패로 보인다).

### 생략 가능 — 기본값이 있다

| 변수 | 생략하면 |
|---|---|
| `EXPO_PUBLIC_GOOGLE_SCOPES` | `openid profile email` 폴백(`DEFAULT_GOOGLE_SCOPES`) |
| `EXPO_PUBLIC_KAKAO_MAP_JS_KEY` | 카카오 지도를 안 쓰면 무관(현재 `frontend/.env` 도 빈 값) |
| `EXPO_PUBLIC_SENTRY_DSN` | 크래시 수집 안 함(`initSentry` 가 DSN 있을 때만 init) |

### 프로덕션에 **절대** 넣지 않는 것

```
EXPO_PUBLIC_API_MOCK · EXPO_PUBLIC_AUTH_FAKE · EXPO_PUBLIC_AUTH_FAKE_OUTCOME
```

목·가짜 인증 스위치다. 프로덕션 빌드에 섞이면 **심사관이 가짜 데이터를 본다.**
`eas.json` production 에 없는 것이 정상이고, EAS 환경변수에도 `production` 스코프로
넣지 않는다.

### iOS 푸시 — 사람이 손으로 켤 일은 없다

서버 `PUSH_MODE=expo` 를 켰으므로(2026-10-05) 앱 쪽 자격도 필요하다. 그런데
**EAS 가 알아서 한다** — `eas build` 가 로컬 엔타이틀먼트를 읽어 Apple Developer Portal 의
**Capabilities 를 자동 동기화**하고(`EXPO_NO_CAPABILITY_SYNC=1` 로 끌 수 있다),
APNs 키가 없으면 **빌드 중에 만들겠냐고 묻는다**(또는 `eas credentials` → iOS →
Push Notifications 로 미리 만든다).

`expo-notifications` 플러그인이 이미 `app.config.ts` 에 등록돼 있으므로 엔타이틀먼트는
붙는다. 그래서 developer.apple.com 에서 Push Notifications 를 **손으로 체크할 필요가 없다** —
빌드가 실패하거나 동기화 로그가 이상할 때만 포털을 직접 본다(`EXPO_DEBUG=1 eas build` 로
동기화 로그를 자세히 볼 수 있다).

ASC API 키 역할이 넉넉해야 동기화가 된다. 지금 키는 **Admin** 으로 발급돼 있어 충분하다.

### Expo 프로젝트 소유 — `eas init` 전에 정한다

`app.config.ts` 에 **`owner` 가 없다.** 그러면 `eas init` 을 실행한 사람의 **개인 계정**
아래로 프로젝트가 들어가고, `eas.json` 이 `appVersionSource: remote` 라 **빌드 번호도**
그 계정에 쌓인다. 그 사람이 떠나면 **스토어에 앱이 있는데 빌드를 못 올리는 상태**가 된다.

순서: expo.dev 조직 생성(무료) → 구성원 초대 → `app.config.ts` 에 `owner: '<조직 slug>'`
커밋 → `eas init`. 나중에 이전도 되지만 손이 더 간다.

## 누가 무엇을

기준은 **파일 소유**와 **계정 접근** 둘이다. 그 둘로 자르면 서로 기다릴 일이 거의 없다.

**EAS 사슬은 쪼개지 않는다.** `login → init → build → submit` 이 직렬이고, `init` 이
`app.config.ts` 를 고치고, build 가 애플 자격을 요구한다. 둘이 나눠 잡으면 서로를 기다린다.
그래서 **프론트 담당이 통째로 갖는다** — 그 두 파일이 그쪽 소유라 커밋 조율이 사라진다.

애플 자격은 **ASC API 키**로 분리한다. Account Holder 가 한 번 발급해 넘기면 프론트 담당이
남의 2FA 없이 빌드·업로드를 돌린다.

| 몫 | 할 일 |
|---|---|
| **Account Holder** | ASC API 키 발급(Users and Access → Integrations) · 프론트 담당을 **App Manager** 로 초대 · 최종 제출 |
| **프론트 담당** | EAS 사슬 전체 · `app.config.ts`(`init` 산물) · `eas.json` API 주소 · 푸시 권한 요청 처리 · 아이콘 반영 · (초대받으면) ASC 메타데이터 |
| **백엔드/인프라** | 인증서 교체 배포 · 스크린샷 이미지 생성 · 위치신고 설명자료 · 검증. **`frontend/**` 는 건드리지 않는다** |

`App Manager` 역할이면 메타데이터 편집·TestFlight·제출까지 된다. Account Holder 전용은
계약·세금·API 키뿐이다.

### 충돌 지점 하나 — 순서가 있다

**`eas.json` 의 API 주소와 인증서 교체 배포는 순서가 걸린다.** 교체 배포가 먼저고, 그 뒤에
`eas.json` 을 `api.trippilot.co.kr` 로 바꾼다. 반대로 하면 인증서가 아직 교체 전이라 **TLS 가
깨진다.** 신호는 "두 이름 모두 TLS 가 선다"를 확인한 시점이다.

`api-dev` 로 올리는 선택도 있다 — 더 단순하지만 나중에 prd 로 옮길 때 **앱 업데이트 한 번을
빚진다**(스토어 빌드에 주소가 박히므로 DNS 만으로는 못 옮긴다).

## App Privacy (수집 데이터 유형)

Apple 범주 ↔ 우리가 **실제로 저장하는 것**. 근거 컬럼을 같이 적었다.

| Apple 범주 | 항목 | 근거 | 목적 |
|---|---|---|---|
| Contact Info → Email Address | 이메일 | `account.email`(V1.1) · 소셜 제공자가 줄 때만 | App Functionality |
| Identifiers → User ID | 소셜 계정 식별자, 계정 id | `social_identity` · `account_id` | App Functionality |
| Identifiers → Device ID | 푸시 토큰 | `push_token`(V2.40) | App Functionality |
| User Content → Other | 닉네임 | `profile.nickname`(V1.5) | App Functionality |
| User Content → Other | 여행·일정·저장 장소·방문 메모·회고 | trip·itinerary·saved_* · visit_* | App Functionality · Personalization |
| Location → Precise Location | 재계획 출발 기준점, 사진 EXIF 좌표 | `replan_session.origin_*` · `visit_photo_meta.exif_lat/lng` | App Functionality |
| Usage Data → Product Interaction | 예약 이동 클릭 기록 | `affiliate_click` | Analytics · App Functionality |
| Other Data | 생년월일·연령 확인 | `account.birth_date` · `age_method`(V1.1) | App Functionality(14세 미만 차단) |

**모두 "계정에 연결됨(Linked to You)" 이고 "추적(Tracking)에는 쓰지 않는다."**
추적 없음은 코드에도 선언돼 있다 — `app.config.ts` 의 `NSPrivacyTracking: false`.

**사진은 수집하지 않는다.** 원본은 기기에만 있고 서버는 **메타정보만** 받는다
(`visit_photo_meta` — 기기·촬영시각·EXIF 좌표). 그래서 `User Content → Photos or Videos` 는
**체크하지 않는다.** EXIF 좌표는 Location 으로 신고한다.

**위치는 선택 동의 뒤에만 저장된다** — `gpsRecordingOptIn` 이 거짓이면 좌표를 **받지도 않는다**
(`VisitRecord.kt` · INV-U5-04). 그래도 "수집함"으로 신고한다 — 동의하면 저장하는 것이 사실이다.

> **⚠ 처리방침과 어긋나는 자리 2개(2026-10-05 발견).** 서버가 내보내는 처리방침의 수집 표에
> **이메일과 생년월일이 없다** — `account.email`·`account.birth_date` 는 실재한다(연령 확인 절에
> "가입 시 연령 확인"이라는 문장만 있다). ASC 설문은 사실대로 체크해야 하므로 위 표에 넣었고,
> **처리방침 쪽을 보강하는 것이 맞다.** 본문 개정은 법무 판단이라 코드 세션이 쓰지 않는다
> (`backend/docs/legal/README.md` 규약).

## 연령 등급

**4+ 로 받을 수 있다.** 제휴 링크는 `Linking.openURL` 로 **외부 Safari** 에서 열린다
(`stayOutbound.ts`) — 앱 내 웹뷰가 아니므로 설문의 "제한 없는 웹 접근"에 해당하지 않는다.

## App Review Notes (그대로 붙여 쓸 초안)

**이 메모가 없으면 거절된다.** 우리는 소셜 로그인만 있고 심사관은 카카오·네이버 계정이 없다.

```
[로그인]
이 앱은 소셜 로그인만 제공합니다(Google / Kakao / Naver / Apple). 심사 시에는
"Apple로 계속하기" 버튼으로 Sign in with Apple 을 사용해 주세요. 별도의 데모 계정은
구조상 제공할 수 없습니다. 만 14세 미만은 가입할 수 없어 가입 과정에서 연령 확인을 받습니다.

[계정 삭제]
하단 탭바 '마이' → '설정' → 목록 맨 아래 '계정 삭제' 에서 삭제할 수 있습니다.
2단계 확인을 거쳐 삭제가 요청되며, Apple 로그인 사용자의 경우 Apple 토큰도 함께
철회됩니다.

[주요 기능 확인 순서]
하단 탭은 '홈 / 탐색 / 일정 / 기록 / 마이' 입니다.
1. Apple 로 로그인 → 온보딩에서 여행 취향을 선택합니다
2. '탐색' 탭에서 장소를 둘러봅니다
3. '일정' 탭에서 여행을 만들고(지역·날짜·인원) AI 일정 생성을 실행합니다.
   생성에는 수십 초가 걸릴 수 있고, 1일차가 먼저 보인 뒤 나머지가 채워집니다
4. 생성된 일정에서 일정 변경(재계획)을 실행할 수 있습니다
5. 숙소 상세에서 '외부 사이트로 이동' 을 누르면 예약 사이트가 Safari 에서 열립니다

[위치 권한]
위치는 여행 중 일정 재계획의 '출발 기준점'을 추정하는 데만 사용합니다. 권한을 거부해도
앱은 정상 동작하며, 등록한 숙소나 목적지 중심을 기준점으로 대신 사용합니다.

[알림]
현재 서버 측 푸시 발송이 비활성 상태입니다. 알림 권한을 허용해도 발송되지 않습니다.
```

> 마지막 단락은 **푸시를 켜지 않고 제출할 때만** 넣는다. 받아놓고 아무것도 오지 않는 상태를
> 숨기면 2.1 이 되고, 밝히면 심사관이 그 전제로 본다. 켜고 제출하면 이 단락을 지운다.
>
> **라벨은 실측한 것만 단정했다.** 탭 5종(`app/(tabs)/_layout.tsx`) · '계정 삭제'
> (`SettingsScreen.tsx:214`) · "Apple로 계속하기"(`LoginPage.apple.test.tsx` 가 고정) ·
> '외부 사이트로 이동'(`OtaChoiceSheet.tsx`)은 코드에서 확인했다. 재계획 진입은 라이브 화면
> 리다이렉트 조건(오늘이 여행 구간 안인가)에 따라 갈려 **버튼 이름을 단정하지 않았다** —
> 심사관이 반드시 찾아야 하는 것은 로그인과 계정 삭제 둘이고, 그 둘만 정확하면 된다.
> 초안에 '여행' 탭·'다시 짜기'·'이동'으로 적었다가 전부 실측으로 고쳤다(그런 탭·문구는 없다).
