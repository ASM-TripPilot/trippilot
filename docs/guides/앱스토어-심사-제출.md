# 앱스토어 심사 제출

제출 전에 사람이 채워야 하는 칸과, **코드에서 확인한 사실**을 짝지어 둔다. ASC 설문은 추측으로
채우면 안 되고(거짓 신고는 제재 사유다), 리포를 읽을 수 없는 사람이 채우게 되므로 여기 적는다.

> 이 문서는 **값의 근거**를 모은 것이다. 절차 자체(EAS 빌드·업로드)는 아래 §순서에만 적는다.

## 순서

빌드가 없으면 제출 버튼이 안 열린다. `extra.eas.projectId` 가 플레이스홀더면 `eas init` 이 선행이다.

```
eas login → eas init(projectId 발급·app.config.ts 커밋) → 애플 자격 연결
→ eas build -p ios --profile production → eas submit → ASC 처리(10~30분)
→ 메타데이터(아래) → TestFlight 실기 확인 → 제출
```

**애플 자격은 ASC API 키를 권한다** — ASC → Users and Access → Integrations →
App Store Connect API. Issuer ID · Key ID · `.p8`. **Sign in with Apple 키와 다른 키다.**

## App Privacy (수집 데이터 유형)

Apple 범주 ↔ 우리가 **실제로 저장하는 것**. 근거 컬럼을 같이 적었다.

| Apple 범주 | 항목 | 근거 | 목적 |
|---|---|---|---|
| Contact Info → Email Address | 이메일 | `account.email`(V1.1) · 소셜 제공자가 줄 때만 | App Functionality |
| Identifiers → User ID | 소셜 계정 식별자, 계정 id | `social_identity` · `account_id` | App Functionality |
| Identifiers → Device ID | 푸시 토큰 | `push_token`(V2.40) | App Functionality |
| User Content → Other | 닉네임 | `profile.nickname`(V1.5) | App Functionality |
| User Content → Other | 여행·일정·저장 장소·방문 메모·회고 | trip·itinerary·saved_* · visit_* | App Functionality · Personalization |
| Location → Precise Location | 재계획 출발 기준점, 사진 EXIF 좌표 | `replan_session.origin_*` · `visit_photo_meta.exif_lat/lng` | App Functionality |
| Usage Data → Product Interaction | 예약 이동 클릭 기록 | `affiliate_click` | Analytics · App Functionality |
| Other Data | 생년월일·연령 확인 | `account.birth_date` · `age_method`(V1.1) | App Functionality(14세 미만 차단) |

**모두 "계정에 연결됨(Linked to You)" 이고 "추적(Tracking)에는 쓰지 않는다."**
추적 없음은 코드에도 선언돼 있다 — `app.config.ts` 의 `NSPrivacyTracking: false`.

**사진은 수집하지 않는다.** 원본은 기기에만 있고 서버는 **메타정보만** 받는다
(`visit_photo_meta` — 기기·촬영시각·EXIF 좌표). 그래서 `User Content → Photos or Videos` 는
**체크하지 않는다.** EXIF 좌표는 Location 으로 신고한다.

**위치는 선택 동의 뒤에만 저장된다** — `gpsRecordingOptIn` 이 거짓이면 좌표를 **받지도 않는다**
(`VisitRecord.kt` · INV-U5-04). 그래도 "수집함"으로 신고한다 — 동의하면 저장하는 것이 사실이다.

> **⚠ 처리방침과 어긋나는 자리 2개(2026-10-05 발견).** 서버가 내보내는 처리방침의 수집 표에
> **이메일과 생년월일이 없다** — `account.email`·`account.birth_date` 는 실재한다(연령 확인 절에
> "가입 시 연령 확인"이라는 문장만 있다). ASC 설문은 사실대로 체크해야 하므로 위 표에 넣었고,
> **처리방침 쪽을 보강하는 것이 맞다.** 본문 개정은 법무 판단이라 코드 세션이 쓰지 않는다
> (`backend/docs/legal/README.md` 규약).

## 연령 등급

**4+ 로 받을 수 있다.** 제휴 링크는 `Linking.openURL` 로 **외부 Safari** 에서 열린다
(`stayOutbound.ts`) — 앱 내 웹뷰가 아니므로 설문의 "제한 없는 웹 접근"에 해당하지 않는다.

## App Review Notes (그대로 붙여 쓸 초안)

**이 메모가 없으면 거절된다.** 우리는 소셜 로그인만 있고 심사관은 카카오·네이버 계정이 없다.

```
[로그인]
이 앱은 소셜 로그인만 제공합니다(Google / Kakao / Naver / Apple). 심사 시에는
"Apple로 계속하기" 버튼으로 Sign in with Apple 을 사용해 주세요. 별도의 데모 계정은
구조상 제공할 수 없습니다. 만 14세 미만은 가입할 수 없어 가입 과정에서 연령 확인을 받습니다.

[계정 삭제]
탭바 '마이페이지' → '설정' → '회원 탈퇴' 에서 삭제할 수 있습니다. 2단계 확인 후
삭제가 요청되며, Apple 로그인 사용자의 경우 Apple 토큰도 함께 철회됩니다.

[주요 기능 확인 순서]
1. Apple 로 로그인 → 온보딩(여행 취향 선택)
2. '탐색' 탭에서 장소 둘러보기
3. '여행' 탭 → 여행 만들기(지역/날짜/인원) → AI 일정 생성
4. 생성된 일정에서 '다시 짜기'(재계획) 실행
5. 숙소 상세 → '이동' — 외부 예약 사이트(제휴 링크)가 Safari 에서 열립니다

[위치 권한]
위치는 여행 중 일정 재계획의 '출발 기준점'을 추정하는 데만 사용합니다. 권한을 거부해도
앱은 정상 동작하며, 등록한 숙소나 목적지 중심을 기준점으로 대신 사용합니다.

[알림]
현재 서버 측 푸시 발송이 비활성 상태입니다. 알림 권한을 허용해도 발송되지 않습니다.
```

> 마지막 단락은 **푸시를 켜지 않고 제출할 때만** 넣는다. 받아놓고 아무것도 오지 않는 상태를
> 숨기면 2.1 이 되고, 밝히면 심사관이 그 전제로 본다. 켜고 제출하면 이 단락을 지운다.
