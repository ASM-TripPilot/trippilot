# 위치기반서비스사업 신고 — 위치정보시스템 설명자료 (초안)

> **초안이다. 제출 전에 사람이 검토해야 한다.**
> 아래 ⚖️ 표시는 **법률 판단이 필요한 칸**이다 — 내가 채우지 않았다. 나머지는 2026-10-09 기준
> **코드·스키마 실측**이고, 각 문단에 근거 파일을 달았다. 코드가 바뀌면 이 문서도 틀린다.

## 0. 제출 서류 중 이 문서의 위치

위치기반서비스사업 **신고**(위치정보법 제9조)에 필요한 것 중 "위치정보시스템의 구성 및
위치정보 수집·이용 방법에 관한 설명자료"에 해당한다. 다른 서류(신고서 양식, 사업계획서,
소상공인·중소기업 확인서)는 이 문서 범위가 아니다.

⚖️ **개인위치정보사업(수집·제공) 허가 대상인지, 위치기반서비스사업 신고로 충분한지**는 법률
판단이다. 아래 §2 가 "우리는 통신사·단말 제조사로부터 위치를 받아 **제공**하지 않고, 이용자
단말이 직접 준 좌표를 **서비스에 쓸 뿐**"임을 사실로 적어 두었으니 그 판단의 근거로 쓴다.

## 1. 서비스 개요

| 항목 | 내용 |
|---|---|
| 서비스명 | TripPilot (여행 일정 관리 애플리케이션) |
| 제공 형태 | iOS·Android 모바일 앱 |
| 위치정보 이용 목적 | **여행 중 일정을 다시 짤 때 '출발 기준점'을 정하는 것** 하나 |
| 위치정보 없이도 동작하는가 | **그렇다** — 거부하면 숙소·목적지 중심으로 대체한다(§2.1 사다리) |

위치는 **부가 기능**이다. 거부·철회해도 회원가입·일정 생성·확정·기록이 전부 동작한다.
이 점이 설명자료에서 가장 중요한 사실이라 먼저 적는다.

## 2. 수집하는 위치정보 — 두 종류뿐이다

코드베이스 전체 스키마에서 **이용자 본인의 좌표를 담는 테이블은 아래 둘뿐**이다. 나머지 좌표
테이블(`poi`·`poi_snapshot`·`region`·`stay`·`saved_stay`)은 **관광지·숙소의 위치**로,
공개된 장소 정보이지 개인위치정보가 아니다.

### 2.1 재계획 출발 기준점

| 항목 | 내용 |
|---|---|
| 저장 위치 | `replan_session.origin_kind` · `origin_lat` · `origin_lng` |
| 근거 | `V2.17__replan_session.sql` |
| 수집 시점 | 이용자가 **'일정 다시 짜기'를 누른 그 순간 1회**. 상시·주기 수집이 없다 |
| 좌표의 출처 | `origin_kind` 가 네 값 중 하나로 **출처를 기록한다** |

`origin_kind` 4종 중 **개인위치정보는 앞의 둘뿐**이다:

| kind | 뜻 | 개인위치정보인가 |
|---|---|---|
| `GPS` | 단말이 측정한 현재 위치 | **그렇다** |
| `MANUAL` | 이용자가 지도에 직접 찍은 핀 | **그렇다**(이용자가 지정한 위치) |
| `LAST_VISIT` | 그 날 마지막 방문 장소의 좌표 | 아니다 — 등록된 **장소** 좌표 |
| `STAY_ANCHOR` | 그 날 숙소 좌표 | 아니다 — 등록된 **숙소** 좌표 |

사다리는 `GPS → MANUAL → LAST_VISIT → STAY_ANCHOR` 순으로 내려간다. **위치 권한을 주지
않으면 앞의 둘이 비고 뒤의 둘로 동작한다** — 그래서 §1 의 "없어도 동작한다"가 성립한다.

**동의 철회 시 이미 저장된 좌표를 파기한다.** 게이팅만으로는 앞으로 들어올 좌표만 막고 이전
것이 남으므로, 철회 이벤트를 받아 기존 행의 좌표를 지우고 `origin_kind` 를 `PURGED` 로 바꾼다.
근거: `LocationLegalConsentRevokedSubscriber`(INV-L4).

### 2.2 사진 촬영 위치(EXIF)

| 항목 | 내용 |
|---|---|
| 저장 위치 | `visit_photo_meta.exif_lat` · `exif_lng` |
| 근거 | `V2.33__visit_photo_meta.sql` |
| 수집 조건 | **별도 동의(`gps_recording_opt_in`)가 없으면 받지도 저장하지도 않는다**(INV-U5-04) |
| 사진 원본 | **서버에 올리지 않는다** — 기기 로컬 자산 식별자(`local_asset_id`)와 촬영 시각만 받는다 |
| 철회 시 | 이미 저장된 좌표를 파기(`GpsRecordingOptOutSubscriber`) |

스키마 주석이 조건을 명시한다: *"위치 동의가 없으면 받지도 저장하지도 않는다. 사진에 좌표가
박혀 있어도 서버는 안 받는다 — 판정은 요청 시점의 동의 상태로 한다."*

## 3. 수집하지 않는 것

제출서에 "하지 않는다"를 적어 두면 심사·점검에서 되묻지 않는다.

- **상시·백그라운드 위치 추적이 없다.** 주기 수집 스케줄러가 없고, 수집은 이용자 조작에 붙어 있다.
- **이동 경로를 쌓지 않는다.** `replan_session` 은 세션 1건에 기준점 1개이고, 궤적 테이블이 없다.
- **제3자에게 제공하지 않는다.** 확인자료의 이벤트 어휘에 `PROVISION` 칸이 있지만 **기록되는
  경로가 없다** — 수집(`COLLECTION`)만 기록된다(`LocationLegalLogFacade` 주석).
  ⚖️ 자사 AI 서비스(같은 클러스터 내부 구성요소)로 좌표가 전달되는 것을 **처리위탁으로 볼지
  내부 처리로 볼지**는 법률 판단이다. 사실관계: 외부 사업자가 아니고, 같은 운영 주체의
  서비스이며, 거기서도 좌표를 영속 저장하지 않는다.
- **광고·분석 목적 이용이 없다.** 수집 목적은 §1 의 한 줄뿐이다.

## 4. 위치정보 이용·제공 사실 확인자료

위치정보법 제16조②의 확인자료다.

| 항목 | 내용 |
|---|---|
| 테이블 | `location_legal_log` (`V1.3__auth_location.sql`) |
| 기록 항목 | `account_id` · `event_type` · `detail`(jsonb) · `occurred_at` |
| 이벤트 어휘 | `CONSENT_GRANTED` · `CONSENT_REVOKED` · `COLLECTION` · `USE` · `PROVISION` · `PURGE` |
| **원시 좌표** | **담지 않는다** — 확인자료는 "언제 무엇을 했다"는 사실이지 위치 그 자체가 아니다(스키마 주석) |
| 보존기간 | **6개월**(기록 시점부터). 약관이 말하는 기간과 같다 |
| 파기 | `LocationLegalLogRetentionSweeper` 가 **일 1회** 경과분을 파기(`V2.49`) |

**약관이 6개월이라 말하는데 테이블이 영구 보존이면 약관이 거짓말이 된다** — 그래서 파기를
코드로 돌린다. 파기 건수는 로그로 남는다.

## 5. 보호조치

| 축 | 조치 | 근거 |
|---|---|---|
| 위·변조 방지 | 확인자료·동의기록은 **append-only** — 앱 DB 역할(`app_user`)에 `UPDATE`·`DELETE` **권한이 없다** | `V1.7__grants.sql`: `REVOKE UPDATE, DELETE ON consent_record, location_legal_log FROM app_user` |
| 파기 경로 단일화 | 삭제는 **보존기간 함수 하나로만** 가능하고 그 함수에만 실행 권한을 준다 | `V2.49` — `REVOKE ALL ON FUNCTION … ` + 지정 역할에만 `GRANT EXECUTE` |
| 전송 구간 | HTTPS/TLS. DB 연결도 `sslmode=require` | 배포 설정 |
| 저장 구간 | 관리형 DB(RDS) 저장 암호화 · 삭제 보호 · 자동 백업 | `infra/terraform` |
| 접근 통제 | 관리 콘솔은 SSO(최소권한 역할), 운영 DB 직접 접근은 상시 열어 두지 않는다 | 운영 규약 |
| 동의 분리 | 서비스 이용 동의와 위치 동의가 **별개 항목**이고, 사진 EXIF 는 **또 하나의 별개 동의** | `POST /api/v1/me/location-consent`, `gps_recording_opt_in` |

## 6. 이용자 권리 행사 방법

| 권리 | 방법 | 실측 근거 |
|---|---|---|
| 동의 철회 | 앱 **설정 → 위치정보** 화면(`/settings/location`)에서 **항목별로** 끈다. 끄는 즉시 기존 좌표를 파기한다(§2.1·2.2) | `PATCH /api/v1/me/location-consent` · `LocationConsentScreen` |
| 확인자료 열람 | 고객 지원 창구로 요청(아래) | — |
| 계정·데이터 삭제 | 앱 설정 목록의 **'계정 삭제'**(2단계 확인). Apple 로그인 계정은 Apple 토큰도 함께 철회한다 | — |
| 문의 | `trippilot.asm17@gmail.com` | 약관 고지 연락처와 같은 값 |

동의는 **두 개의 독립 항목**이다(한 번에 묶어 받지 않는다):

| 항목 | API 필드 | 없으면 |
|---|---|---|
| 위치정보 법정 동의 | `legalConsent` | 서버가 좌표를 받지 않는다 → 사다리 뒤쪽(숙소·목적지)으로 동작 |
| 사진 촬영위치(EXIF) 기록 | `gpsRecordingOptIn` | EXIF 좌표를 **받지도 저장하지도 않는다**(INV-U5-04) |

OS 권한 상태는 `osPermissionMirror` 로 별도 보관한다 — **OS 권한과 법정 동의는 다른 것**이고,
OS 권한이 있어도 법정 동의가 없으면 서버는 좌표를 쓰지 않는다.

공개 약관·처리방침: <https://asm-trippilot.github.io/trippilot/>

## 유지 규약

§2~§5 는 전부 코드·스키마에서 나온 값이다. 아래가 바뀌면 이 문서가 **거짓이 된다** —
바꾸는 PR 이 이 문서도 같이 고쳐야 한다.

- 좌표를 담는 새 열·테이블 추가
- `location_legal_log` 보존기간 또는 파기 주기 변경
- `V1.7__grants.sql` 의 권한 회수 되돌림
- 위치 동의 게이팅·철회 파기 구독자 제거
- 제3자(외부 사업자) 제공 개통
