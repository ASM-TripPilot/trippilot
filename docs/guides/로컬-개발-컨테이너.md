# 로컬 개발 컨테이너 가이드

팀원이 로컬에서 **FE·BE·AI·DB 전체 스택을 컨테이너로 띄워** 통합 테스트하는 방법.

> 스택: `docker-compose.yml`(루트) — `db`(postgres16) · `backend`(Spring/Kotlin) · `ai`(Python) · `frontend`(Expo Web 자리, 현재 nginx 스텁)
> 빌드 도구는 Gradle. compose 는 로컬 오케스트레이션 전용. 이미지는 CI 가 GHCR 에 발행.

## 0. 준비물 (딱 2개)

- **컨테이너 런타임** — [OrbStack](https://orbstack.dev) 권장 (Docker Desktop/colima 도 가능)
- **git**

JDK·Node·Python·Postgres 는 **호스트에 필요 없음** — 전부 컨테이너 안에서 빌드·실행됩니다.
(예외: FE 네이티브 실기 검증은 호스트 Xcode/시뮬레이터에서 `cd frontend && npx expo run:ios`)

## 1. 최초 1회 — GHCR 로그인 · 팀 볼트

### 1-1. GHCR 로그인

CI 가 발행한 이미지는 **private**(레포 권한 상속)입니다. pull 하려면 로그인 1회:

1. GitHub → Settings → Developer settings → **Personal access tokens (classic)** → 발급, 스코프 **`read:packages`** 체크
2. 로그인:
   ```bash
   echo <YOUR_PAT> | docker login ghcr.io -u <github-username> --password-stdin
   ```

### 1-2. 팀 볼트에서 `.env` 받기

시크릿 값은 git 에 없다. **Proton Pass 팀 볼트 `TripPilot`** 의 노트 `trippilot/.env (local dev)` 가 정본이다.

1. 볼트 초대 수락 → 그 노트 **본문 전체 복사**
2. 붙여넣기:
   ```bash
   ./scripts/env-sync.sh apply    # 클립보드 → .env (기존 값은 .env.bak 로 백업)
   ```
3. 변경 알림 훅 켜기(클론당 1회):
   ```bash
   git config core.hooksPath .githooks
   ```
   이후 `git pull` 할 때 볼트가 바뀌었으면 알려준다 → 1~2번 반복.

**키를 바꾸거나 추가하는 사람**은 두 가지를 같이 한다: 볼트 노트 수정 + `.env.example` 의 `# vault-rev:` 숫자 +1 후 커밋. 이 숫자가 팀원 로컬의 알림을 띄운다.

**`vault-rev` 는 언제 올리나** — 판정 기준은 하나다: **볼트 노트에 붙여넣을 값이 실제로 달라졌는가.**

| `.env.example` 변경 | 팀원이 할 일 | rev |
|---|---|---|
| 볼트 노트의 값이 바뀜 (키 추가·교체) | 볼트 복사 → `apply` | **+1** |
| 템플릿에 주석·선택 항목만 추가 | 없음 | **올리지 않는다** |

두 번째는 `AI_SCHEDULE_DEADLINE_ENFORCED`·`PLACE_GEOCODE_MODE` 처럼 **compose 에 기본값이 있는 스위치**들이다(`${…:-false}`). `.env` 에 없어도 정상 동작하므로 볼트에 넣을 값이 애초에 없다.

구분하지 않으면 알림이 죽는다 — 떠서 볼트를 열었는데 바뀐 게 없는 일이 두세 번 반복되면 사람은 알림을 닫기 시작하고, **진짜 키가 바뀐 날에도 무시한다.**

#### 사람마다 값이 달라야 하는 키

`apply` 는 `.env` 를 **볼트 내용으로 통째 교체**한다. 대부분의 키는 팀 공통이라 그게 맞지만, 일부는 사람마다 값이 다르다 — 예: `ANTHROPIC_API_KEY` 는 팀원은 볼트의 공용 키를 쓰고 **결제 계정 소유자는 자기 개인 키**를 쓴다(워크스페이스가 달라 지출 한도가 따로 걸린다).

그런 키는 `.env.keep-local` 에 한 줄씩 이름만 적는다(gitignore 됨):
```
ANTHROPIC_API_KEY
```
`apply` 가 볼트 값으로 덮은 뒤 이 목록의 키만 **직전 로컬 값으로 되돌린다**. 파일이 없으면 전부 볼트 값을 쓴다 — 팀원 대다수는 이 파일이 필요 없다.

**볼트에 넣을 것 / 넣지 말 것** — 새 키를 추가하기 전에 어느 칸인지 먼저 정한다.

| 분류 | 예 | 어디에 두나 |
|---|---|---|
| **팀 공유** — 팀원 전원 로컬에 같은 값이 필요 | IdP client-secret · `SERVICE_AUTH_TOKEN` · LLM 키 | 볼트 노트 (= `.env`) |
| **개인 발급** — 계정당 한도가 붙는 것 | `TOUR_API_KEY`(data.go.kr) | 각자 발급, 볼트 금지. 한도가 공유되고 누구 키인지 추적이 안 된다 |
| **머신 전용** — 특정 서버 한 대에서만 쓰는 것 | 수집 VM 의 GitHub 토큰 | 그 머신에만. 볼트에 넣으면 팀원 전원 노트북에 배포된다 |
| **CI 전용** — 워크플로만 쓰고 로컬 개발엔 안 쓰는 것 | `NAVER_SEARCH_*` · `KAKAO_REST_API_KEY_AI` · `ANTHROPIC_API_KEY`(CI 전용 키 별도 발급) | GitHub Actions Secrets. 볼트에는 재발급용 사본만(`trippilot/GitHub Actions secrets` 노트) — **`.env` 에는 넣지 않는다.** 과금되는 키를 로컬 3대에 뿌릴 이유가 없다 |


## 2. 실행 — 두 가지 모드

```bash
git clone git@github.com:ASM-TripPilot/trippilot.git
cd trippilot
cp .env.example .env
```

### pull 모드 (빠름 · 소스 빌드 안 함) — 대부분의 팀원
CI 가 구운 최신 이미지를 당겨서 실행:
```bash
docker compose pull                    # 최신 :develop 이미지 당겨오기
docker compose --profile full up -d    # 전체 스택 기동
```

### build 모드 (내 소스로) — 그 서비스 개발자
```bash
docker compose --profile full up -d --build
```

### 혼합 — 예: 프론트 개발자
자기 것만 빌드하고 나머지는 최신 이미지 pull:
```bash
docker compose pull backend ai
docker compose up -d --build frontend
```

## 3. 프로파일

| 명령 | 뜨는 것 |
|---|---|
| `docker compose up -d` | `db` 만 (앱은 호스트에서 `bootRun` 할 때) |
| `docker compose --profile backend up -d` | `db` + `backend` |
| `docker compose --profile full up -d` | `db` + `backend` + `ai` + `frontend` |

| URL | 설명 |

## 5. 소셜 로그인 켜기

소셜 로그인(google/kakao/naver)은 각 IdP 시크릿이 있어야 동작한다. 시크릿은 **이미지에 없고 `.env` 로 주입**된다(컨테이너는 기본 프로파일이라 `application-local.yml` 을 읽지 않음).

1. client-id/secret 은 **팀 볼트**에 있다 — [1-2](#1-2-팀-볼트에서-env-받기) 대로 `.env` 를 받으면 이미 채워져 있다(항목은 `.env.example` 참고):
   ```
   GOOGLE_CLIENT_ID=...
   GOOGLE_CLIENT_SECRET=...
   KAKAO_CLIENT_ID=...
   KAKAO_CLIENT_SECRET=...
   NAVER_CLIENT_ID=...
   NAVER_CLIENT_SECRET=...
   ```
2. `.env` 반영을 위해 backend 컨테이너 재생성:
   ```bash
   docker compose --profile backend up -d --force-recreate backend
   ```
3. 로그인 호출: `POST http://localhost:8080/api/v1/auth/social/{google|kakao|naver}`
   (body: `authorizationCode` · `codeVerifier` · `redirectUri` · 신규가입 시 `ageConfirmation`)

> - `.env` 는 gitignore — **절대 커밋 금지**. 각자 로컬에만 둔다.
> - 값이 비어 있어도 기동은 정상, 해당 제공자 **로그인 시도 시에만** 실패한다.
> - **리디렉션 URI**: 실제 앱 딥링크(예: `trippilot://oauth`)는 각 IdP 콘솔에 등록돼 있어야 한다(콘솔 소유자에게 요청).
> - naver 는 PKCE 미지원(`codeVerifier` 는 더미) + authorize 에 `state` 필수. apple 은 p8 서명 + id_token JWKS 검증 구현 후 지원 예정.

## 6. 자주 쓰는 명령

```bash
docker compose --profile full logs -f          # 로그 실시간
docker compose --profile full ps               # 상태
docker compose --profile full up -d --build be # 특정 서비스만 재빌드
docker compose --profile full down             # 내리기(볼륨 보존)
docker compose --profile full down -v          # 볼륨까지 초기화(DB 리셋)
```

## 7. 이미지 발행(CI)

- `develop` 에 머지되면 GitHub Actions 가 변경된 서비스 이미지를 **GHCR 에 자동 발행**
  (`.github/workflows/{backend,ai,frontend}-ci.yml`, 경로 트리거)
- 태그: `:develop`(움직이는 최신) · `:sha-xxxx`(불변)
- 이미지: `ghcr.io/asm-trippilot/trippilot-{backend,ai,frontend}`

## 8. 트러블슈팅

- **`docker compose` 가 안 먹고 `docker-compose` 만 됨** → OrbStack 앱을 한 번 열어 CLI tools 설치 완료
- **pull 시 `denied`/`unauthorized`** → 1번 GHCR 로그인 안 됨, 또는 PAT 에 `read:packages` 누락
- **backend 가 db 연결 실패** → `db` 가 healthy 될 때까지 대기(compose `depends_on` 이 처리). 첫 기동은 40s+ 정상
- **포트 충돌(5432/8080/19006/8000)** → 로컬에서 해당 포트 쓰는 프로세스 종료
