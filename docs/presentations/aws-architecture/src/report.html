강점 01 · 다층 방어

여섯 겹의 통제로 데이터 계층을 지킵니다

TLS 종단NLB · ACM

앱으로 들어오는 입구는 HTTPS 443 하나입니다.

API 게이트웨이nginx

/api와 상태 확인만 통과시키고 나머지는 404로 막습니다. IP마다 초당 10건(순간 60건)으로 속도를 제한합니다.

파드 간 허용 목록NetworkPolicy

backend는 gateway·ai와 배포용 Job에서만, ai는 backend와 점검 Job에서만 연결을 받습니다.

컨테이너 잠금securityContext

root 실행 금지, 읽기 전용 파일시스템, 권한 상승 차단, capability 전부 제거.

보안 그룹Security Group

DB 5432와 캐시 6379는 EKS 노드에서 오는 연결만 받습니다.

격리 서브넷Data subnet

인터넷·NAT 기본 경로가 없습니다. DB는 SSL을, Redis는 TLS를 강제합니다.

한 겹이 뚫리더라도 다음 겹이 막도록 쌓았습니다. 특히 데이터 계층의 라우팅 테이블에는 인터넷·NAT로 가는 기본 경로가 없습니다. 보안 그룹을 잘못 열어도 바깥과 곧바로 이어지지 않습니다.

서비스 토큰과 JWT 서명키가 없으면 앱이 아예 기동하지 않도록 해, 인증 설정이 빠진 채 운영되는 일도 막습니다.

강점 07 · 비용에 비례하는 설계

지금은 필요한 만큼만 쓰고, 운영 규모 설정은 미리 마련했습니다

지금 아끼는 방법

  • DB·캐시에 ARM 기반 Graviton(t4g) 인스턴스
  • 개발 서버는 검증에 성공하면 0대로 축소
  • 메모리 5GiB를 요청하는 임베딩은 필요할 때만 배포
  • 알림 문구 모델은 Bedrock 서버리스, 유휴 시 추론 용량 0
  • 실측으로 자원 요청값 조정(backend CPU 500m → 200m)
  • 로그 보존 기한을 명시해 무기한 과금 방지

Conclusion

정리

  • 격리 — 데이터 계층은 인터넷 경로가 없는 격리 서브넷에 있습니다
  • 회복 — 이중화·PDB·자동 롤백으로 노드 교체와 배포 때의 중단을 줄입니다
  • 권한 — 장기 키 없이 OIDC와 Pod Identity로 필요한 권한만 줍니다
  • 보호 — 운영 DB는 백업·삭제 보호·최종 스냅숏이 기본값입니다
  • 재현 — 핵심 인프라가 코드이고 운영 반영에는 검증 게이트가 있습니다
  • 관측 — 조용한 실패까지 Slack으로 알립니다
  • 비용 — 지금 규모에 맞춰 쓰고, 운영 규모 설정은 미리 마련했습니다
