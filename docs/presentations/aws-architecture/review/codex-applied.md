# codex(gpt-6-astra) 검수 반영 기록

## 반영

| ID | 내용 | 반영 방식 |
|---|---|---|
| A01 | 무중단·분산 보장 표현 | "늘 둘 이상" → "둘 이상 띄워 둬요", PDB는 "계획된 교체", 분산은 "우선/선호", 심사 덱 제목 "중단을 줄이는 이중화와 복구" |

| A03 | 배포 게이트 예외 | 정기 릴리스 기준 + 핫픽스는 Jira 키·사유 기록 후 건너뜀(심사 8장 각주, 학생 13장) |
| A04 | 비밀값 경로 | "메모리로만" 삭제 → Secrets Manager → Kubernetes Secret 동기화 |
| A05 | 수동 배포 범위 | 서버만 수동, 웹은 main 반영 시 자동 배포(덱·다이어그램) |
| A06 | prd 즉시 전환 | "설정 하나로 바로" → "규모 설정을 미리 마련, 전환은 별도 준비·검증" |
| A07 | Bedrock 0원 | "유휴 시 추론 용량 0으로 축소"로 수정 |

| A09 | nginx 제한 | IP 기준 10r/s · burst 60, /api·상태 확인만 노출 |
| A10 | 롤링 대상 | gateway·backend·ai(API 파드)로 한정 |
| A11 | 긴 요청 보장 | "마무리될 시간을 최대 660초" |
| A12 | NetworkPolicy 예외 | 배포용·점검 Job 명시 |
| A13 | 개발 DB 격리 | "직접 영향이 번지지 않음"으로 범위 한정 |
| A14 | AI·임베딩 장애 전파 | "자원 분리 + 임베딩 정지 시 규칙 기반 추천 전환" |
| A15 | LLM 알람 범위 | "Claude·GPT 호출 실패"로 명시 |
| A16 | 알람 즉시성 | 심사 9장 제목 교체, 재시작·NotReady 10분·DB 지속 조건 표기 |
| A17 | 알람 네임스페이스 | "앱 로그·재시작 알람"으로 한정 |
| A18 | 데이터 서브넷 | "인터넷·NAT 기본 경로 없음", 심사 4장 제목 "여섯 겹의 통제" |
| A19 | OIDC·Pod Identity | "두 시간짜리 임시 출입증", "AI 파드들", 용어집 수정 |
| A20 | 개발 0대 조건 | "검증에 성공하면 0대, DB는 유지" |

| A23 | 임베딩 메모리 | 요청 5GiB(실사용 4GiB대)로 구분 |
| B01 | 논리/물리 혼동 | 다이어그램 부제에 "논리 구성도: 실제 AZ 배치 고정 아님", 데이터 메모에 "인스턴스 단일 AZ" |
| B02 | 개발 NLB·DB | NLB 카드 "개발용 NLB는 별도", 개발 네임스페이스 "별도 NLB·개발 RDS" |
