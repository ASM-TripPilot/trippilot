# 운영 배포 규칙

운영 서버(`trippilot` 네임스페이스, `api-dev.` 도메인)는 **열차(release)와 핫픽스(hotfix) 때만** 만진다. 사람이 지키기만 하면 되던 규칙이 안 지켜져서(운영 DB에서 테스트, 잦은 직배포) 워크플로가 강제한다. (TRIP-1659)

> 헷갈리는 이름: 운영이 `api-dev.`, 개발이 `dev-api.` 다. 글자 순서만 다르다 — 도메인으로 대상을 고르지 말고 워크플로의 `target` 입력으로 고른다.

## 열차 (release)

- **언제**: 앱 릴리스일 또는 주 1회 중 먼저 오는 날. 서버는 **앱 제출보다 먼저** 나가고, 이전 앱 버전과도 호환돼야 한다(옛 앱 사용자가 남는다).
- **절차**: 개발 서버에서 검증 → `release/main-*` 승격 PR(`develop` 시점을 `main` 에 머지) → 머지 → `main` 에서 `target=prod` 배포.
- **워크플로 입력**: `deploy_kind=release`, `deploy_ref=<릴리스 이름>`(앱 버전 등, 영문·숫자·`.-_` 40자 이하).
- **게이트**: 배포하려는 코드(`.github` 제외)가 **최근 72시간 안에 성공한 개발 서버 배포 런의 커밋과 같아야** 한다. 없으면 AWS 자격 증명을 받기 전에 실패한다. 승격 PR 본문의 "개발 서버 검증 런" 칸이 이제 기계 검사가 된다.
- 새 LLM 기능 이름을 도입한 승격은 **2런**이다: 1런은 입력 없이 이미지만(이미지가 그 이름을 알게 됨), 2런에 `llm_feature_models` 로 배정한다.

## 핫픽스 (hotfix)

> **지금 안 고치면 사용자가 오늘 피해를 보는가?** 예일 때만.

- 핫픽스: 5xx 가 계속된다·로그인이 안 된다·데이터가 깨진다·보안 문제·비용 폭주·외부 연동(LLM 키·한도 등)이 죽어 기능이 꺼졌다.
- 열차: 기능 추가, AI 품질·문구 개선, 성능 튜닝, 데이터(POI) 갱신. 급해 보여도 위 질문에 "아니오"면 열차에 태운다.
- **워크플로 입력**: `deploy_kind=hotfix`, `deploy_ref=TRIP-123`(Jira 키), `deploy_reason=<한 줄 사유>`(3~200자). 개발 검증은 **사후**에 한다.
- 실행 요약에 `Declared: hotfix TRIP-123 — 사유` 가 남는다.

## 운영을 파이프라인 밖에서 바꿀 때

운영 시크릿(Secrets Manager)·`kubectl`·`helm rollback` 은 워크플로를 거치지 않는다. 핫픽스 정의에 해당할 때만 하고, **그 Jira 이슈에 무엇을 왜 바꿨는지**(키 값은 빼고) 남긴다. 모델 배정은 가능하면 워크플로의 `llm_feature_models` 입력으로 한다.

## 롤백

- 코드: `helm history trippilot -n trippilot` 로 리비전을 보고 `helm rollback trippilot <리비전> -n trippilot`. 리비전은 최근 10개(`--history-max 10`)이고 이미지는 ECR 에 `sha-…` 태그로 남아 있다.
- **되돌려지지 않는 것**: DB 마이그레이션(Flyway forward-only), 시크릿(helm 밖 — Secrets Manager 의 `AWSPREVIOUS` 버전). 그래서 마이그레이션이 든 열차는 새 스키마에서 옛 코드가 돌아도 되게(expand → contract) 짠다.
- 롤백도 파이프라인 밖의 변경이다 — 위 절을 따른다.

## 개발 서버 켜고 끄기

개발 서버(`trippilot-dev`, `dev-api.`)는 **검증 때만 켠다**. RDS·로드밸런서는 계속 떠 있고 파드만 0 이다(임베딩 5Gi 가 메모리 큰 노드 1대를 잡아 월 약 $84).

- **켜기**: 워크플로 `target=dev` 배포(15~20분). 0 으로 내려 둔 파드는 배포 앞 스텝이 1 로 올린다(helm 이 직접 내린 0 을 되돌려 주지 않는다).
  - 임베딩은 재계획·대안·도우미 기억을 건드린 변경일 때만 `embedding_enabled=true`. 끄고 배포하면 노드가 한 대 덜 뜬다.
- **끄기**: `dev_sleep_after=true`(기본)면 스모크·KB·POI 적재가 **모두 성공한 뒤** 자동으로 0 으로 내린다. 실패하면 원인을 보려고 켜 둔다. QA 를 켜 둔 채 하려면 `false` 로 주고, 끝나면 수동으로 `kubectl -n trippilot-dev scale deploy --all --replicas=0`.
- 검증 점검: AI 기동 로그의 `기능별 모델 배정 N종`, `llm_cost` 의 기능별 success, 도우미 대표 호출 3건.

## 이 규칙이 안 막는 것

- 운영 DB 에 테스트 계정을 만드는 것(앱 로그인 테스트는 개발 서버에서).
- 승격 PR 안의 `.github` 변경(워크플로 사본은 main 이 따로 유지한다).
