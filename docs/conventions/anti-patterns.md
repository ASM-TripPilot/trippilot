# 안티패턴 로그 (실패·실수를 통한 학습)

> **목적**: 개발 중 테스트 실패·구현 실패·설계 오류가 나올 때마다 **근본 원인**을 파악해 "이렇게 하면 안 된다"를 한 줄로 누적한다. 동일한 시행착오를 반복하지 않기 위함.
>
> **기록 규칙**
> - 한 항목 = **규칙(하지 말 것 → 대신 할 것)** + 왜 + 근거(티켓/PR).
> - 실패가 실제로 발생했을 때만(가설 금지). 재현·검증된 것만.
> - 최신 항목을 각 영역 맨 위에 추가. 영역이 없으면 새로 만든다.
> - AI 에이전트(Claude Code)는 작업 착수 전 이 문서를 읽고, 새 실패가 나오면 여기에 한 줄 추가를 제안한다.

## DB · 스키마 · 마이그레이션

- **부모가 "삭제 후 재삽입"으로 교체되는 테이블에 `ON DELETE CASCADE` 자식을 매달지 말 것 → 수명 주기의 진짜 주인(상위 엔티티)에 매단다.** 일정은 편집·되돌리기마다 `replaceForTrip`(DELETE→INSERT)로 통째 교체되므로, `itinerary_id` FK CASCADE 로 매단 편집 이력이 **편집 한 번에 전부 지워졌다.** 게다가 재생성은 새 `itinerary_id` 를 발급해 이력이 과거와 끊긴다. FK 를 걸기 전에 "부모 행이 UPDATE 되는가, 교체되는가"를 먼저 확인할 것. E2E 가 아니면 안 드러난다(단위 테스트의 인메모리 Fake 엔 cascade 가 없다). (TRIP-310, PR #131 — 정본 §2.1 도 함께 정정)
- **`numeric(p,s)` 로 정밀도를 줄여 저장하면서, 계산값을 접지 않은 채 그대로 응답에 싣지 말 것 → 산출 시점에 저장 정밀도로 접을 것.** DB 는 쓰기에서 반올림하는데 `jpa.save()` 는 **메모리 객체를 그대로 돌려준다** — 방금 만든 응답은 `3.6205…`, 다음 조회는 `3.62` 가 되어 화면에는 "새로고침하면 값이 바뀐다"로 보인다. 예외도 로그도 없고 단위 테스트(인메모리)로는 원리적으로 안 보인다. 실 DB IT 에서 `저장 결과 shouldBe 다시 읽은 값` 을 한 줄 두면 잡힌다. (TRIP-555 `style_analysis.avg_radius_km`)
- **컬럼을 다른 테이블로 옮기면 길이 검증도 함께 옮길 것.** 편집 사유를 `change_log_entry.reason varchar(500)` 에서 `itinerary_revision.summary varchar(200)` 으로 옮기며 요청측 `@Size(max=500)` 을 그대로 둬, 201~500자 입력이 `22001` → **편집까지 롤백되고 500**. 컬럼 상한과 요청 상한은 같은 커밋에서 함께 움직여야 한다. (TRIP-310, PR #131)
- **JPA에서 같은 트랜잭션 내 "삭제 후 재삽입"(자식 컬렉션 교체)을 파생 `deleteByX`로 하지 말 것 → bulk `@Modifying @Query` delete.** 파생 `deleteByX`는 `em.remove`로 큐잉되고, Hibernate는 flush에서 **INSERT를 DELETE보다 먼저** 실행해 같은 키 재삽입 시 unique 제약 위반(`ux_trip_destination_seq` 등). bulk delete는 즉시 실행돼 옛 행이 먼저 사라진다. (TRIP-177, PR #35)
- **다중 경로로 cascade되는 FK에 `ON DELETE RESTRICT`/`NO ACTION`을 쓰지 말 것 → `DEFERRABLE INITIALLY DEFERRED`.** `account → saved_stay` 와 `account → trip → base_assignment → saved_stay` 처럼 다이아몬드로 cascade되면, 즉시 검사되는 RESTRICT/NO ACTION이 cascade 도중 참조를 발견해 **계정 하드삭제(퍼지)를 깨뜨린다.** DEFERRABLE는 커밋 시점에 검사해 참조가 이미 사라져 통과하되, 직접 삭제 가드는 유지된다. (TRIP-174, PR #29 · 로컬 PostgreSQL 재현·검증)
- **jsonb 컬럼을 수동 `ObjectMapper`로 직렬화하지 말 것 → 도메인 타입에 `@JdbcTypeCode(SqlTypes.JSON)`.** 수동 직렬화는 이중 인코딩(JSON 안에 escape된 JSON 문자열)을 만든다. `Map<String,String>`·`List<...>` 같은 도메인 타입에 직접 매핑하면 Hibernate가 처리. (TRIP-155)
- **불변식을 앱에서만 지키지 말고 DB CHECK로도 강제할 것.** 예: `coord_confirmed=true`인데 좌표 null, lat/lng 한쪽만 있는 상태가 DB에서 허용됐음 → `CHECK ((lat IS NULL)=(lng IS NULL) AND (NOT coord_confirmed OR lat IS NOT NULL))`. (TRIP-174 검수)
- **JPQL `concat`/`like` 안에 null 이 될 수 있는 파라미터를 넣지 말 것 → 빈 문자열 같은 값으로 정규화한다.** `(:q is null or r.name like concat('%', :q, '%'))` 는 **검색어 없는 호출만** 500 으로 끝난다 — Hibernate 가 null 파라미터의 타입을 `concat` 안에서 추론하지 못해 bytea 로 바인딩하고 `operator does not exist: character varying ~~ bytea` 가 난다. 평범한 `:x is null or col = :x` 는 멀쩡히 돌아서 같은 패턴이라고 착각하기 쉽다. 필터 있는 질의는 전부 통과하므로 실 DB IT 가 없으면 "검색은 되는데 목록만 안 나오는" 형태로 화면 붙일 때 발견된다. (TRIP-358, PR #229)
- **`target` 을 지정해 중간 버전까지만 올리는 테스트에서 `R__` 반복 시드를 같이 돌리지 말 것 → `repeatableSqlMigrationPrefix` 로 해석 대상에서 뺀다.** Flyway 는 target 이 무엇이든 반복 마이그레이션을 **그 집합 끝에 무조건** 붙인다. `GenerationSessionBackfillIT` 가 2.26 까지만 올리는데 `R__seed_stay.sql` 이 따라 붙어, `stay` 에 컬럼을 추가한 V2.51 을 넣는 순간 `column "address" does not exist` 로 죽었다 — 그대로 두면 그 테스트가 **"V2.26 이후로 stay 에 컬럼을 추가하지 말라"** 는 제약이 된다. 시드는 그런 테스트가 보려는 것과 무관하므로 빼는 게 맞고, 덤으로 12,782행 적재도 사라진다. (V2.51, 전체 빌드에서 실패로 드러남)
- **upsert 만 하는 생성 시드는 원본에서 사라진 행을 지우지 못한다 → 같은 스크립트에 "이번 실행이 건드리지 않은 행" 삭제를 함께 둔다.** `INSERT … ON CONFLICT DO UPDATE` 는 추가·갱신만 한다. 원본 갱신(2026-08-17 → 09-22)에서 폐업 21곳이 빠졌는데 정본에는 그대로 남았다 — 문 닫은 숙소가 계속 검색에 뜨고, 전화번호를 붙인 뒤로는 **사용자가 없는 곳에 전화를 건다.** Flyway 는 스크립트 하나를 한 트랜잭션에서 돌리고 `now()` 가 트랜잭션 시작 시각으로 고정되므로, upsert 가 `updated_at = now()` 를 쓰게 해 두면 `DELETE … WHERE updated_at < now()` 가 정확히 "이번에 없던 행"만 지운다(빈 DB 에서는 0건). **빈 DB 로는 원리적으로 못 보는 결함이라** 오래된 시각의 행을 심고 시드를 다시 태우는 IT 가 있어야 한다. (`R__seed_stay.sql`, 역검증으로 확인)
- **외부 원본에서 온 전화번호를 "0 으로 시작하고 자릿수가 맞으면 통과"로 정규화하지 말 것 → 지역번호·국번을 화이트리스트로 검증한다.** 형식 검사(`^0\d{1,3}-\d{3,4}-\d{4}$`)는 **가짜를 못 잡는다 — 가짜도 형식은 맞다.** 실측으로 셋이 샜다: `060-473-8988`(정보이용료 번호 — 누르면 사용자에게 요금이 붙는다) · `069-3564-9718`(없는 지역번호) · `02-0773-8803`(국번은 0 으로 시작하지 않는다) · `02-1644-xxxx`(지역번호가 잘못 붙은 전국대표번호 — 그대로 걸면 연결되지 않는다). 더해서 `0507-456-0364` 를 `050-7456-0364` 로 묶는 오표기도 있었다(안심번호는 국번이 4자리다). **틀린 번호를 주느니 NULL(="모름")이 낫다.** 검사는 생성기 안에만 두지 말고 DB 조회로 한 번 더 센다. (V2.51 검수 + 원본 갱신, 실측 41건)
- **생성 시드의 `ON CONFLICT DO UPDATE SET` 에 새 컬럼을 빠뜨리지 말 것 → INSERT 절과 같은 커밋에서 함께 늘린다.** 정본 행이 이미 있는 환경(DEV·로컬)에서는 시드 재실행이 **전부 충돌 경로로 간다.** INSERT 절만 고치면 마이그레이션은 컬럼을 만들고 시드는 통과하는데 **값이 영원히 NULL 로 남는다** — 빌드도 실 DB IT 도 전부 초록이다(Testcontainers 는 빈 DB 라 INSERT 경로만 탄다). 한 행만 비우고 시드를 실제로 다시 태워 되돌아오는지 보는 IT 를 함께 둔다. (V2.51 `R__seed_stay.sql`, 역검증으로 확인)
- **마이그레이션은 반드시 실제 PostgreSQL에 V1→최신 전체 체인으로 적용해 검증할 것.** 파일 단독 문법 검사로는 FK cascade·권한·제약 상호작용 버그를 못 잡는다. Testcontainers 통합테스트(`SchemaMigrationIT`)나 로컬 docker DB로 실 적용. (TRIP-174)

## 설계 · 문서

- **규칙·가드·배분을 만들었으면 그것이 실제로 무엇을 했는지 한 번 출력해 볼 것 → 통과·초록·그럴듯한 서술을 동작의 증거로 쓰지 말 것.** 이 아래 여러 항목이 같은 모양이고, 2026-09-24 하루에 세 세션에서 **다섯 번** 나왔다. 공통 구조는 이렇다 — 판정 장치를 만든 뒤 **그 장치의 출력을 안 본다**. 장치가 없는 것보다 나쁘다: 있다는 사실이 확인을 대신한다.

  | 만든 것 | 안 본 것 | 실제 |
  |---|---|---|
  | 실패율 5% 게이트 | 그 종료 코드가 닿는지 | `\| tee` 가 삼켜 가드가 무력 (#634·#636) |
  | 비입장료 제외 규칙 | 무엇이 제외됐는지 | 21건이 **전부 진짜 입장료**(`일반`의 "반"이 수강료 필터에 걸림) |
  | 키 회전 `(calls // 900) % 3` | 그 배분을 돌려 보기 | 같은 실패를 **세 번 연속 오진**(속도 제한 → 죽은 key0 → 계정 누적 소진, 전부 틀림) |
  | 위키 묶음 40건 | 응답이 온전한지 | `prop=extracts` 상한 20 — 본문 절반이 무음 유실 (#640) |
  | 조인 키를 쓰는 배선 | 픽스처가 그 키를 채우는지 | 배선을 끊어도 26건이 전부 통과 (#643·#693) |

  처방은 셋이고 전부 **몇 줄**이다: ⑴ **가드는 일부러 위반해** 빨개지는지 본다 ⑵ **필터는 걸러낸 목록을 찍어** 눈으로 훑는다(전수가 많으면 경계 구간만 — 감점·배제가 실제로 발생하는 곳) ⑶ **배분·분포는 주장 전에 돌려 본다**(`Counter((i//900) % 3 for i in range(n))` 다섯 줄이면 위 세 번의 오진이 전부 없었다). 셋 다 "출력을 본다"의 형태다. 서술을 먼저 만들면 그 서술이 관측을 대신하고, 그때부터 반박이 아니라 해석 경쟁이 된다. (2026-09-24 · 요금 수집 트랙·KB-5·/replan 배선에서 교차 확인)

- **어휘(status·enum·kind)를 늘렸으면 그 값을 읽는 도구에도 뜻을 정해 줄 것 → 모르는 값을 조용히 기본 분류로 흘리는 코드는 크게 실패하도록 바꾼다.** `work-graph.toml` 에 `status = "dropped"` 를 새로 쓰면서 `work_graph.py` 에는 안 알렸다. 그 스크립트는 `status not in NOT_OURS | DONE` 로 "우리 몫"을 고르므로 **모르는 값이 전부 남은 작업으로 흘러들어간다** — 접기로 한 노드가 `남은 우리 몫` 에 계속 잡히고, 쓰지도 않을 **Flyway 번호 경합 경고**까지 만들어 냈다(실측 19 vs 18). 오타도 같은 경로로 샌다(`droped` → 조용히 +1). 처방은 분류를 늘리는 것이 아니라 **알려진 값 집합을 선언하고 그 밖이면 종료**시키는 것이다 — 그래야 다음 사람이 어휘를 늘릴 때 반드시 마주친다. (PR #675 검수)

- **표본이 얇다고 적을 거면 결론도 같이 유보할 것 → "얇다"는 각주는 면죄부가 아니다.** 요금 실측에서 SIGHT 무료율이 **60.0%(n=55)** 로 나와 "SIGHT 는 NATURE 만큼 무료가 아니다"를 결론으로 보고했다. 표본이 얇다고 **명시까지 했는데도** 결론은 단정형이었다. 표본을 늘리니 **80.7%(n=176)** — **20%p 이동**했고 "갈렸다"던 차이가 NATURE 89.5% 와 9%p 로 좁혀졌다. 같은 판에서 ACTIVITY 도 66.7%(n=15) → 84.2%(n=38) 로 움직였다. 제안 문서 순서가 수집 순서라 앞머리 표본이 지역 편중이었던 것이다. **측정을 한 것과 그 측정이 결론을 감당하는 것은 다르다** — "n=55, 얇음"이라는 각주는 읽는 쪽에 경고를 주는 것처럼 보이지만, 실제로는 단정형 문장이 그대로 다음 결정에 실려 간다. 처방: 얇은 표본에서 나온 갈림은 **"갈렸다"가 아니라 "갈릴 수도 있다 — 확인 필요"** 로 적고, 확인 전에는 설계 근거로 넘기지 않는다. 판정 기준: **그 결론이 뒤집히면 무엇이 바뀌나**를 먼저 답해 본다 — 바뀌는 게 있으면 단정하지 말고 표본을 늘린다. (요금 출처 실측 TRIP-902, 2026-09-22)
- **openapi 에 "스키마는 끝에 덧붙인다"를 *파일 끝*으로 읽지 말 것 → `components.schemas` 절의 끝에 넣을 것.** 이 파일은 `components.schemas` **다음에** `components.responses` 가 온다. 파일 끝에 붙이면 정의가 responses 절로 들어가고 `$ref: '#/components/schemas/X'` 가 **조용히 끊긴다.** 실측(2026-08-26 U5·U6 층1~3 통합): 이렇게 끊긴 참조가 **14종** 쌓였는데 경로↔핸들러를 대조하는 `OpenApiContractIT` 도, `SwaggerDocsIT` 도, 전체 빌드도 **전부 초록**이었다 — 경로는 멀쩡하고 참조 해석은 아무도 안 봤기 때문이다. 터지는 곳은 프론트 코드 생성(orval)이다. 처방: 앵커를 `ModerationUnavailable` 같은 **responses 절 원소로 잡지 말고** schemas 절 안의 원소로 잡는다. 게이트도 함께 심었다 — `OpenApiContractIT` 가 이제 모든 `$ref` 가 풀리는지 확인한다. (U5·U6 층1~3)

(TRIP-912, PR #642)
- **벤더 API 에 "값이 없다"고 결론내기 전에 엔드포인트를 전부 훑을 것 → 한 엔드포인트의 부재는 원천의 부재가 아니다.** TourAPI `detailIntro2` 만 보고 레포츠(28)를 **"원천 결손 — 응답 자체가 빈다"** 로 적고, 관광지(12)·음식점(39)도 "요금 필드 없음"으로 판정해 예산 등급 기능을 접는 쪽으로 보고까지 올렸다. 실제로는 **`detailInfo2`(반복정보)에 레포츠 `이용요금`이 94% 채움·88% 금액 포함**으로 있었고, 관광지도 `입 장 료` 가 70% 였다. 반복정보는 `infoname`/`infotext` 쌍이라 **필드명이 고정이 아니어서** 스키마 문서를 훑어도 안 보이고, 어댑터에 메서드가 없으면 존재 자체를 잊는다. 판정을 뒤집은 비용은 POI 당 1콜짜리 스캔 800건이었다 — 기능을 접는 결정에 비하면 공짜다. 처방: **"원천에 없다"는 결론은 (엔드포인트 × 전 필드) 실측 뒤에만 쓴다.** 필드명으로 찾지 말고 **값의 모양으로 찾는다**(요금이면 `원` 이 붙은 수의 포함률) — `usetime` 같은 산문 필드에 섞여 있으면 이름으로는 안 보인다. (`probe_fee_sources.py`, 2026-09-19)
- **외부(AI·벤더) 문자열을 검증 없이 저장하지 말 것 → 저장 상한에 맞춰 자른다(거부 아님).** LLM 설명·거리 문구는 길이 보장이 없어 컬럼을 넘기면 `22001` 로 **정상 생성된 일정이 통째로 롤백되고 500** 이 나간다. 사용자가 고칠 수 있는 값이 아니므로 400 으로 되돌리는 것도 답이 아니다 — 잘라서 진행하고 잘림을 말줄임표로 드러낸다. 자를 때는 **서로게이트 페어를 끊지 말 것**(고아 서로게이트가 남아 UTF-8 인코딩에서 문자가 깨진다 — 이모지가 섞이면 실제로 발생). (TRIP-306·308, PR #129)
- **형태가 미확정인 응답 필드를 데이터 클래스로 고정하지 말 것 → 원시 노드로 받아 방어적으로 읽는다.** 부가 메타 하나(`candidates_summary`)를 타입으로 고정했더니 **명시적 `null`·문자열 등 예상 밖 형태 하나에 역직렬화가 통째로 깨져**, 정상 200 응답이 버려지고 MINIMAL 폴백으로 강등됐다. "없으면 없는 것"과 "못 읽으면 전체 실패"는 다르다. 또 **없는 값을 기본값으로 채우지 말 것** — `poolSize` 를 `0` 으로 채우면 "후보 0건"이라는 AI 판정을 백엔드가 지어내는 셈이다. (TRIP-306, PR #129)
- **키 규약이 미합의인 맵을 조용히 매칭하지 말 것 → "받았는데 하나도 안 붙었다"를 로그로 드러낸다.** `explanations` 키 규약이 어긋나면 근거가 전부 null 이 되는데, 그 상태가 "AI 가 근거를 안 줬다"와 구분되지 않는다. (TRIP-306, PR #129)
- **계약 문서만 보고 경계 어댑터를 구현하지 말 것 → 상대 팀 구현 코드를 직접 열어 확인할 것.** 계약 문서는 합의 시점 스냅숏이라 상대 구현이 앞서가면 조용히 어긋난다. AI `solve_mode` 는 실제로 4값(`OR_TOOLS/LLM/RULE_FALLBACK/MINIMAL`)인데 계약·백엔드는 3값(`FULL_AI/DETERMINISTIC/MINIMAL`), `freshness` 도 필드 구성이 완전히 달랐다. 도메인 DTO 를 그대로 직렬화한 어댑터는 **실 연동 첫 호출부터 역직렬화 실패 → 매 요청 폴백**이 됐을 것이고, 로그엔 "AI 호출 실패"만 남아 네트워크 문제로 오인된다. → **어댑터 전용 wire DTO** 로 상대 스키마를 받고 도메인으로 매핑(차이를 어댑터가 흡수). (TRIP-229, PR #119 닫고 #121로 재작업)
- **미지 enum·필드를 조용히 기본값으로 흡수하지 말 것 → 실패로 승격.** 모르는 `solve_mode` 를 기본값으로 넘기면 계약 드리프트가 정상 동작으로 위장된다. INV-4(침묵 실패 금지)는 폴백뿐 아니라 **스키마 해석**에도 적용. (TRIP-229)
- **미배선 경계 메서드가 "빈 결과"를 반환하게 두지 말 것 → 명시적 실패.** `validate` 가 빈 위반 목록을 반환하면 "문제 없음"이라는 **거짓 음성**이 사용자 확정까지 흘러간다. 아직 못 붙였으면 실패시켜 드러내는 편이 안전. (TRIP-229)
- **`@ConditionalOnProperty` 를 빈 하나에만 걸지 말 것 → 설정 클래스 전체에.** 어댑터만 조건부로 두면 비활성 모드에서도 `@Configuration` 의 다른 빈들이 생성돼 부작용이 상시 발생한다. "기능이 꺼져 있으니 무해하다"는 가정 자체가 검증 대상. (TRIP-229, PR #119)
- **공유 `RestClient.Builder` 빈을 변형(mutate)하지 말 것 → 어댑터마다 전용 빌더 생성.** `DefaultRestClientBuilder` 는 copy-on-write 가 아니라 in-place 변경이고, 여러 모듈이 같은 이름·타입 빈을 `@ConditionalOnMissingBean` 으로 공유한다. baseUrl·requestFactory·컨버터를 붙이면 **다른 모듈의 HTTP 클라이언트가 오염**된다(소셜 로그인 장애 위험). (TRIP-229, PR #119)
- **경계 전용 `HttpMessageConverter` 를 `@Bean` 으로 노출하지 말 것 → 설정 안에서 인스턴스로 만들어 해당 클라이언트에만 부착.** SB4 는 컨텍스트의 **모든** 컨버터 빈을 MVC 목록에도 주입하므로, AI 경계용 snake_case 컨버터가 **공개 API 응답을 snake_case 로** 바꿀 수 있다. (TRIP-229, PR #119)
- **SB4 의 기본 Jackson 은 3(`tools.jackson`)** — 경계 매퍼도 Jackson 3로 만들 것. Jackson 2(`com.fasterxml`) 컨버터를 붙이면 실제 통신에서 역직렬화가 깨진다. 또 빈 `JsonMapper` 는 Kotlin 모듈을 자동 등록하지 않아 데이터클래스 역직렬화가 실패하므로 `tools.jackson.module:jackson-module-kotlin` 을 명시 등록. (TRIP-229)
- **"충돌 없이 자동 병합됨"을 "합쳐도 된다"로 읽지 말 것 → 병합 결과를 실제로 빌드할 것.** git 이 말하는 것은 **겹친 줄이 없다**까지다. 한 브랜치가 바꾼 시그니처를 다른 브랜치가 부르고 있으면 서로 다른 hunk 라 **충돌 표시가 나지 않고 조용히 컴파일이 깨진다.** 실측: 브랜치 6개를 순서대로 합치자 `git merge` 는 6번 모두 성공했는데 빌드는 `KakaoPlaceLookupAdapter` 생성자 변경(타임아웃 도입) 때문에 깨졌다 — 그 파일을 건드린 두 브랜치는 **각자의 PR CI 에서는 둘 다 초록**이다(각각 develop 기준이라 상대 변경을 보지 못한다). 더 나쁜 것은 발현 시점이다: 먼저 머지한 PR 은 통과하고 **두 번째가 머지된 뒤 develop 이 깨진다.** 처방: 여러 브랜치를 쌓아 두었으면 머지 전에 스크래치 브랜치에 **머지 순서대로 합쳐 전체 빌드를 한 번 돌린다**(`git checkout -b scratch develop && git merge A B C…`). 겹치는 파일 목록은 `git diff --name-only develop..<branch>` 로 먼저 뽑아 두면 어디를 볼지 안다. (타임아웃·역지오코딩 브랜치)
- **외부 와이어 DTO 를 역직렬화하는 모듈은 Jackson 3 Kotlin 모듈을 스스로 선언할 것 — 없어도 예외가 나지 않는다.** SB4 의 `RestClient` 기본 컨버터는 Jackson 3(`tools.jackson`)인데 Kotlin 모듈이 없으면 Kotlin data class 를 **기본 생성자로 만들고 `val` 을 채우지 못한다** — 예외 없이 전 필드가 기본값이 되어 `documents=[]` 같은 빈 결과가 된다. 200 을 받고도 후보 0건이라 **"못 찾음"과 구분되지 않는다**(벤더 장애와도 구분되지 않는다). 실측: place-data 는 Jackson **2** Kotlin 모듈만 선언한 채, `itinerary-generation` 이 선언한 Jackson 3 모듈이 런타임 classpath 로 새어 든 덕에 우연히 동작하고 있었다 — 그 모듈이 의존을 빼면 카카오 검색·역지오코딩이 조용히 빈 결과가 된다. 앱 전체 테스트에서는 절대 안 드러나고, **모듈 단위 테스트**(`MockRestServiceServer` + 바닐라 `RestClient.builder()`)에서만 잡힌다. (place-data 역지오코딩)

- **AI 와이어 계약(`ai/docs/openapi.json`)에 요청 필드를 추가하면 같은 PR에서 백엔드 DTO에도 추가할 것 → backend-ci까지 초록 확인 후 머지.** 백엔드 `AiBoundaryOpenApiTest`가 요청 키의 **정확 일치**를 강제하고, 경로 필터상 ai 계약 파일 변경이 backend-ci를 트리거한다 — ai만 보고 머지하면 develop이 그 자리에서 빨간불이 된다. (TRIP-479, PR #306 — `include_explanations` 추가로 실측)
- **새 모델 세대를 붙일 때 "기존 파라미터가 그대로 먹는다"고 가정하지 말 것 → 운영 기본 설정(`C1Config()` 그대로)으로 실 호출 1회를 먼저 한다.** 같은 일이 두 번 났다: GPT-5 가 `temperature` 를 파라미터째 거부(400, TRIP-377 #208)했고, Claude 5(opus-5·sonnet-5)가 `temperature=0.0` 을 거부(400 `deprecated for this model`, TRIP-680 #472)했다 — haiku-4-5 는 받아서 모델 하나만 찔러 보면 놓친다. 둘 다 게이트웨이가 `llm_error` 로 흡수해 **응답은 200·규칙 폴백**이라 증상이 없고, 후자는 2단 폴백 실경로를 태우다 우연히 드러났다. 거부는 벤더 SDK 예외가 아니라 400 본문에만 있으므로 어댑터 테스트(fake client)로는 못 잡는다.

## 아키텍처 · 구현

- **방어를 넣기 전에 그 방어가 공격 전제를 실제로 막는지·정상 입력을 얼마나 죽이는지 재 볼 것 → 재 보지 않은 방어는 순손실일 수 있다.** 프롬프트 인젝션 감사가 "가짜 행사 주소 → 선호 점수 +0.1478" 을 지적해 `event_extraction` 의 주소도 원문 스니펫 대조(`_name_in_snippets`)에 걸었다. 둘 다 틀렸다: ①**막지 못한다** — 공격 전제가 "공격자가 스니펫을 쓴다"이므로 공격자 주소는 **그 스니펫 안에 있어** 대조를 통과한다. ②**비싸다** — 스니펫은 장소를 통칭("광안리해수욕장 일원")으로 쓰고 모델은 행정 주소("부산 수영구 광안리해수욕장")로 편다. 그 확장이 정상인데 구·시 토큰이 원문에 없어 걸린다 — 현실적 쌍 7건 중 **주소 1건만 생존**했다. 기존 테스트는 주소를 단언하지 않아 **전부 통과했다**(조용히 6/7 을 버리는 변경이 초록이었다). 처방: 방어 한 줄에도 (a)공격 시나리오를 그대로 태워 보고 (b)정상 입력 표본으로 과잉 차단율을 센다. 되돌린 근거는 `event_extraction.py` 모듈 docstring 에 재도입 금지로 남겼다. (TRIP-912, PR #642)
- **남의 모듈 `api` 를 동기 호출하기 전에 그 모듈이 나를 (간접적으로라도) 참조하는지 볼 것 → 순환이면 내 포트로 뒤집고 조립은 app 이 한다.** 일정 생성이 개인화(U5)를 부르려다 `archive → itinerary-generation → reflection → archive` 로 닫혀 **Gradle 이 즉시 막았다**(설계를 끝낸 뒤에 만나면 되돌리는 비용이 크다). 푸는 방법은 의존을 뒤집는 것이다 — 필요한 모양을 소비 모듈이 `PersonalizationPort` 로 선언하고, 그것을 실제 구현에 잇는 어댑터를 **양쪽을 다 아는 유일한 자리인 app** 에 둔다(`OutboxSubscriber` 배선과 같은 꼴). 어댑터에는 **판정을 넣지 않는다** — 규칙이 두 곳에 흩어진다. (TRIP-556)
- **날짜에서 파생되는 상태로 도메인 이벤트를 만들지 말 것 → 그 사건이 일어난 **순간을 기록하는 컬럼**을 두고 조건부 쓰기로 한 번만 발행할 것.** `TripStatus.ENDED` 는 저장되지 않고 `statusAt(today)` 가 날짜에서 파생한다 — 즉 "여행이 끝나는 순간"이 어디에도 없다. 그 상태로 폴링해 발행하면 **매 주기마다 같은 여행에 이벤트가 또 나간다**(구독자가 멱등이어도 아웃박스가 계속 부푼다). `ended_at` 을 두고 `UPDATE … WHERE ended_at IS NULL` 이 성공한 그 순간에만 발행한다 — 조건부 쓰기가 곧 멱등이고, 다중 인스턴스에서도 하나만 이긴다. 파생 상태를 저장 컬럼으로 되돌리는 선택(=`status` 를 쓰기)은 하지 않는다: 사실이 두 개가 된다. - **게이트가 항목의 내용을 전부 걸러냈을 때 그 항목을 빈 문자열로 '성공' 반환하지 말 것 → 항목을 빼고 드롭 이벤트에 세라(전량이면 폴백 사유가 실린다).** 빈 문자열은 하류에서 `null` 이 아니다 — 백엔드의 `clamp(x) ?: 기존값` 을 통과해 **이미 있던 값을 빈 값으로 덮고**, `!= null` 로 세는 매칭 경고는 울리지 않으며, 게이트웨이는 성공으로 집계해 체계적 드리프트(모델이 `#` 을 빼먹는 등)가 관측에서 사라진다. 실측(2026-09-24, 해시태그 게이트 리뷰): 초안이 전부 무효인 슬롯을 `""` 로 실었다 — 종전 문장판에서는 parse_error(폴백·Degradation 관측)였던 부류가 침묵으로 바뀌는 회귀. 빈 문자열을 "값 있음"으로 읽는 소비자가 있는지는 하류의 `?:`·`!= null` 을 먼저 찾아본다.

## Kotlin · 언어

- **Kotlin 주석(특히 KDoc `/** */`) 안에 `/api/v1/**` 같은 `/*` 시퀀스를 넣지 말 것.** Kotlin은 블록주석이 **중첩**돼서, 경로 글로브의 `/`+`*`가 중첩주석을 열고 KDoc의 `*/`가 그 중첩분만 닫아 **파일 전체가 미완결 주석**이 된다("Unclosed comment" + 뒤이어 import·참조 전부 unresolved 연쇄). 주석에선 글로브를 "(base 하위)"처럼 풀어쓰거나 백틱/코드블록으로. (PR #44 OpenApiContractIT)
- **기본값이 있는 파라미터를 시그니처 가운데에 끼우지 말 것 → 맨 뒤에 붙인다.** `NormalizedPlace`·`Poi.reconstitute` 에 새 필드를 관련 필드 옆(가독성)에 넣었더니 **위치 인자로 조립하던 어댑터·테스트가 전부** 깨졌다. 타입이 달라 컴파일이 잡아 줬을 뿐이고, 인접 필드가 같은 타입이었다면(여기선 `String?` 이 연달아 있다) 조용히 값이 한 칸씩 밀린다. 가독성을 위한 배치는 KDoc 으로, 순서는 호환성으로 정한다. (TRIP-359, PR #230)
- **"전역 에러 핸들러가 있으니 클라 입력 오류는 4xx 로 나간다"고 가정하지 말 것 → 실제로 한 번 쏴 보고 코드를 확인할 것.** `GlobalExceptionHandler` 가 도메인 예외·`@Valid`·본문 파싱을 모두 덮고 있었는데도, **스프링이 파라미터 바인딩 단계에서 던지는 예외**는 어느 갈래에도 안 걸려 `Exception` 으로 떨어졌다. 실측(2026-09-01) 셋 다 **500 `INTERNAL`**: `GET /api/v1/trips/not-a-uuid`(경로변수 타입) · `?centerLat=abc`(쿼리 타입) · 필수 쿼리 누락. 컨트롤러 **이전**에 터지는 예외라 컨트롤러를 아무리 읽어도 안 보이고, 테스트도 정상 입력만 넣으면 영영 안 밟는다. 호출자 입력 오류를 5xx 로 알리면 프론트·AI 의 재시도·폴백이 잘못된 갈래를 탄다(TRIP-249 3번 미매핑 경로 500 과 같은 형태다). → **UUID-PATH-400 으로 해소**: `MethodArgumentTypeMismatchException`·`MissingServletRequestParameterException` 두 핸들러 추가. 새 바인딩 예외(헤더 누락·`@RequestPart` 등)는 여전히 미확인이니 **새 파라미터 형태를 도입하면 그때 다시 잰다**.
- **빌더 체인 중간에서 코틀린 스코프 함수 `apply { }` 로 조건부 설정을 붙이지 말 것 → `let { builder -> ... }` 로 인자를 이름 붙여 받을 것.** `RestClient.Builder` 에는 **동명의 멤버 `apply(Consumer<Builder>)`** 가 있어서, `.apply { defaultHeader(...) }` 를 쓰면 코틀린 확장이 아니라 그 멤버가 잡힌다. 그러면 람다 안의 `this` 가 빌더가 아니게 되어 `Unresolved reference 'defaultHeader'` 가 난다(TRIP-856 실측). 여기서는 컴파일이 잡아 줬지만, **람다 안에서 쓰는 이름이 바깥 스코프에도 있으면 조용히 그쪽이 잡혀 설정이 통째로 누락된다** — 빌더는 원본을 그대로 돌려주므로 실패가 아니라 무동작으로 끝난다. 같은 함정이 `Consumer` 오버로드를 가진 다른 빌더에도 있다.
- **Spring MVC의 `RequestMappingHandlerMapping` 은 `..mvc.method.annotation` 패키지다**(`..mvc.method` 아님). 또 컨텍스트에 매핑 빈이 여럿이라 주입 시 `@Qualifier("requestMappingHandlerMapping")`로 MVC 것을 지정(actuator 매핑과 구분). (PR #44)

## 테스트

- **테스트가 리포 밖 파일(compose·Helm·배포 스크립트·`.env.example`)을 읽어 배선을 지킨다면 `inputs.files(...)` 선언과 CI `paths` 추가를 **둘 다** 할 것 → 하나만 하면 회귀가 일어난 바로 그 순간에 가드가 안 돈다.** `APPLE_CLIENT_ID` 통로 가드(TRIP-858)를 만들고도 (a) Gradle 이 그 파일들을 `:app:test` 입력으로 안 봐서 compose 에서 줄을 지워도 `UP-TO-DATE ... BUILD SUCCESSFUL in 299ms`, (b) `backend-ci.yml` 의 `paths` 에 없어서 **Helm 만 고치는 PR 은 워크플로가 트리거조차 안 됨** — 두 겹이 독립적으로 뚫려 있었다. 즉 그 가드는 "한 번 초록 찍고 끝"이었다. 일반화: **가드의 감시 대상이 빌드 시스템의 입력 그래프 밖에 있으면, 가드가 있다는 사실이 가드가 돈다는 뜻이 아니다.** 고친 뒤 실측으로 UP-TO-DATE → 실제 FAILED 로 바뀌는 것까지 확인한다. (TRIP-858, PR #676 2차 적대적 리뷰)
- **`@Bean` 이 내부 오버로드에 위임하는 구조에서, 테스트가 오버로드만 부르면 `@Bean` 본문은 아무도 안 잰다 → 인자 없는 운영 경로를 한 번은 그대로 태울 것.** `appleJwksRestTemplate(connect, read)` 만 소켓으로 검증하고 Spring 이 실제로 부르는 `fun appleJwksRestTemplate()` 에는 단언이 없어서, `@Bean` 본문을 `RestTemplate()` 으로 바꾸면 **타임아웃이 둘 다 사라지는데 전 빌드가 초록**이었다(KDoc 은 그 구멍을 닫았다고 적고 있었다). 운영 상수로 실제 소켓을 태우면 느리지만, **느린 이유가 곧 재는 내용**이다. 덧: 이 역검증을 "타임아웃 제거"로 하면 테스트가 무한히 매달려 실험 자체가 성립하지 않는다(아래 같은 규칙) — 상한 초과 고정값으로 바꾼다. (TRIP-858, PR #676 2차 적대적 리뷰)
- **Gradle 입력이 아닌 파일(`docker-compose.yml`·Helm 차트·배포 스크립트)을 흔드는 역검증은 `--rerun-tasks --no-build-cache` 로 돌릴 것 → 아니면 변이가 "무반응"으로 보인다.** 배포 통로 가드(`AppleClientIdWiringTest`)를 검증하려고 compose 에서 `APPLE_CLIENT_ID` 행을 지우고 테스트를 돌렸는데 **빨강 0** 이 나왔다. 가드가 약해서가 아니라 그 파일들이 테스트 태스크의 **선언된 입력이 아니어서** Gradle 이 입력 불변으로 보고 캐시에서 결과를 복원했기 때문이다(XML 을 지워도 캐시가 이긴다). `--rerun-tasks --no-build-cache` 로 다시 돌리자 5개 변이가 전부 해당 테스트 하나씩만 정확히 물었다. 같은 파일의 **소스 변이는 정상 반응**해서 장치가 고장난 줄도 몰랐다 — 한 회차에 소스 변이와 비입력 변이를 섞으면 이 차이가 가려진다. (TRIP-858)
- **"만료된 토큰" 픽스처를 `exp` 만 과거로 옮겨 만들지 말 것 → `iat` 도 같이 옮겨 둘 다 과거로 둘 것.** Apple id_token 검증(TRIP-858)에서 `issueTime = now - 30s` · `expirationTime = now - 600s` 로 만들었더니 **`iat > exp` 라는 형식 오류**가 되어 Spring 의 `Jwt` 생성 단계가 먼저 막았다(`expiresAt must be after issuedAt`). 테스트는 초록이었지만 정작 재려던 **만료 검증에는 한 번도 닿지 않았고**, `JwtTimestampValidator` 를 통째로 지워도 여전히 초록이었다 — 역검증(M3 무반응)으로만 드러났다. 실제 만료 토큰은 `iat`·`exp` 가 **둘 다 과거**이고 순서는 정상이다. 일반화하면 **시각 두 개가 서로 순서 제약을 갖는 픽스처는 한쪽만 옮기면 제약 위반이 되어 엉뚱한 층이 막는다** — 기준점을 하나 잡고 나머지를 그로부터 파생시킨다(`iat = exp - 600s`). (TRIP-858)
- **IT 가 준비값으로 쓰는 고정 시각을, 앱이 실 `Clock` 으로 판정하는 값에 그대로 넘기지 말 것 → 그 값만 `Instant.now()` 기준으로 잡을 것.** 스프링 컨텍스트의 `Clock` 은 실제 시스템 시계다. 다른 준비값처럼 `Instant.parse("2026-08-11T…")` 을 발화 예정 시각에 넣었더니 **보름 지난 예약**이 되어 유예 판정(INV-U6-09)에 걸렸고, `FIRED` 를 기대한 단정이 `CANCELED_LATE` 로 실패했다. 증상이 "구현이 틀렸다"처럼 보이지만 틀린 것은 테스트다 — 그리고 반대 방향(가드를 지웠는데 통과)이었으면 **조용히 지나갔을 것이다.** 시각에 대한 판정을 받는 값만 실제 지금을 기준으로 만든다. (TRIP-547 `NotificationScheduleIT`)
- **IT 에서 전역 범위 조회의 결과를 통째로 단정하지 말 것 → 이번 건으로 좁혀 물을 것.** `findDue(now, limit)` 처럼 테이블 전체를 보는 질의는 **같은 컨테이너를 공유하는 다른 테스트 메서드가 남긴 행**을 함께 가져온다. `shouldContainExactly emptyList()` 가 앞선 테스트의 예약 때문에 실패했다 — 단독 실행하면 통과하고 전체 실행에서만 깨지는 형태라 flaky 로 오독하기 쉽다. 실제 어댑터 질의는 그대로 쓰되 `any { it.id == 이번건 }` 으로 좁힌다. (TRIP-547 `NotificationScheduleIT`)
- **스모크·리허설이 픽스처를 지어내 채우면, 프로덕션의 "데이터 0건"을 초록으로 가린다 → 실 적재 경로를 쓰거나, 최소한 "이 문서는 스크립트가 만든 것"임을 출력에 드러낸다.** PlanB 리허설이 KB-1·KB-2 문서를 실행 시 생성하고 끝나면 지우도록 짰는데, 실서비스에는 그 두 collection 에 **쓰는 경로가 아예 없어** `schedule_context`·`persona_context` 가 항상 `"(검색 결과 없음)"` 이다. 스모크는 5종 전부 통과했지만 그 공백은 한 번도 드러나지 않았다 — 통과가 곧 "프로덕션에서도 된다"가 아니다. 덧: 같은 스크립트에서 픽스처(저장 장소)를 검증 대상(풀 상위)과 같은 값으로 뽑아, **KB 검색을 아예 안 해도 통과하는 단언**도 함께 나왔다. 픽스처와 기대값이 같은 출처에서 나오면 그 테스트는 아무것도 안 검사한다. (canon-auditor 감사 D5 · 커플링은 타 세션 지적, 2026-08-23) → **TRIP-512 로 해소**: 저장 장소를 벡터에 지어 넣는 대신 백엔드가 요청 봉투로 보내게 바꿨다. 리허설도 같은 봉투 경로를 타므로 픽스처가 프로덕션 공백을 가리지 않는다.

- **모드 스위치 오설정이 불변식을 끄는 자리에서는 경고 로그로 끝내지 말 것 → 기동을 막을 것.** "잘못 설정하면 기본값으로 남는다"는 대개 경고면 충분하지만(기능이 degrade 될 뿐), **오설정의 결과가 검사 자체의 무력화면 다르다.** `geocode.mode=kakao` 인데 키가 비면 카카오가 401 → 모든 판정이 `UNKNOWN` → `TripService` 는 `UNKNOWN` 을 통과시키므로(장애가 곧 차단이 되면 안 되니 옳다) **국내강제(INV-U1-12)가 통째로 꺼진 채 정상 기동한다.** 해외 목적지가 전부 허용되고 로그를 뒤지지 않으면 아무도 모른다. 기동 실패는 시끄럽고 배포 즉시 드러난다 — 조용히 꺼진 불변식보다 낫다. 판정 기준: **오설정이 "덜 동작"이면 경고, "검사가 없어짐"이면 기동 거부.** (`RegionGeocodeModeAnnouncer`)

- **`cmd > file` 로 상태를 복원하지 말 것 → 임시 파일에 받아 성공했을 때만 옮길 것.** 리다이렉트는 **명령이 실패해도 빈 파일을 남긴다.** `git show FETCH_HEAD:collect_state.json > collect_state.json || echo "::notice::상태 없음"` 는 폴백이 도는 그 순간에도 0바이트 파일을 만들어 놓고, 그걸 읽은 스크립트는 "상태 파일 손상 — 처음부터"라는 **WARNING 한 줄만 남기고 성공으로 끝난다.** "상태가 없다"와 "상태가 깨졌다"가 같은 결과로 수렴하면 5일이 지나도 아무도 모른다. - **폴백 자원(키·엔드포인트·리전)을 "소진되면 다음"으로만 전환하지 말 것 → "못 쓰겠으면 다음"도 함께 둘 것.** 사용량 기준 전환만 있으면 **죽은 자원이 뒤의 멀쩡한 자원을 통째로 가린다.** 실측(2026-08-19): TourAPI 키링이 키당 호출 수로만 넘어가는데 2번 키가 403(인증 거부)이라, 750콜 예산 중 318콜만 쓰고 3번 키(정상)는 한 번도 안 쓰인 채 6개 지역이 비었다 — 그런데 워크플로는 **성공(초록)** 이었다. 처방: 자원 단위 거부 신호(403·키 관련 에러코드)를 만나면 그 자원을 퇴출하고 다음 살아있는 자원으로 **같은 요청을 재시도**한다(재시도 상한 = 자원 수). 단 **일시 장애(타임아웃·429·5xx)는 퇴출 사유가 아니다** — 실측으로 살아있는 키도 같은 지역에서 함께 타임아웃했다. 잘못 퇴출하면 멀쩡한 자원을 잃는다. - **"처리 완료" 색인에 도장을 찍기 전에, 그 처리가 실제로 끝났는지 확인할 것.** 증분 수집의 스킵 색인은 **재시도 기회를 없애는 장치**이기도 하다 — 부분 실패한 항목까지 색인하면 다음 실행이 건너뛰어 **그 결손이 영구화된다**. 실측: 상세(영업시간) 조회가 429로 실패해도 POI 는 통과시키는데("정보 없음 ≠ 배제", 옳다) 색인까지 해서, 8,043건 중 3,840건이 영업시간 영구 빈칸으로 굳었다. 429 는 "나중에 다시 오라"는 뜻인데 우리가 그 "나중에"를 막았다. 색인 조건은 **결손 없이 끝난 것**으로 좁힌다. 단 판정 기준은 "값이 있는가"가 아니라 **"물어봤는가"** 다 — 원본에 그 필드가 아예 없어 빈 답이 오는 경우까지 재조회하면 매 실행 쿼터만 태운다("못 물어봤다" ≠ "물어봤더니 없더라").
