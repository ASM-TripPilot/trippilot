수업의 대상은 여행 서비스 TripPilot이다. 백엔드는 API를 제공하고 AI 서비스와 통신한다. 로컬에서는 kind 클러스터 안에 애플리케이션과 데이터베이스를 함께 띄운다. AWS에서는 EKS에 애플리케이션을, RDS에 PostgreSQL을 배치한다. 여기서는 어떤 명령을 실행하는지에 더해 어떤 도구가 무엇을 소유하며 어떤 결과를 다음 단계에 넘기는지 살펴본다.

  3. 03 / PLAN & APPLY인프라 구성Terraform → AWS API

DEV와 PRD는 각각 별도의 state와 AWS 리소스를 사용한다. 현재 코드는 환경마다 이미지를 다시 빌드한다. 동일 이미지 digest를 승격하는 방식은 3강의 확장 설계에서 다룬다.

수업 시간과 진행 방식

기본 수업은 각 50분, 총 150분이다. 두 번의 10분 휴식까지 포함하면 170분이다. 각 강의의 시간표는 설명과 코드 읽기, 짝 토론, 실습 결과 확인을 포함한다. 30분 수업에서는 핵심 경로와 대표 예제에 집중하고 60분 수업에서는 확장 실습까지 진행한다.

운영안강의별 시간강사의 준비
압축30분 × 3강 = 90분예제 파일을 미리 열고 실습은 결과 읽기로 대체한다.
기본50분 × 3강 = 150분도구 설치를 사전 과제로 내고 코드 읽기와 로컬 검증을 함께 진행한다.
확장60분 × 3강 = 180분Cloudflare 추가 설계, workflow 작성, 이미지 승격 설계 토론을 추가한다.
클라우드 계정 없이도 학습할 수 있다.

본문 읽기와 설계 문제에는 AWS 계정이 필요 없다. Terraform의 backend를 비활성화한 초기화와 mock provider 테스트는 AWS 리소스를 만들지 않지만 Provider 다운로드에는 네트워크가 필요하다. 실제 plan은 AWS 조회 권한이 필요하며 state 잠금을 사용할 수 있다. apply와 bootstrap은 실제 리소스를 변경하므로 강사가 지정한 실습 환경에서 진행한다.

강사는 3강 전에 예제 DEV 환경과 배포 로그를 준비하는 편이 좋다. EKS·RDS·NAT 생성과 이미지 빌드는 수업 시간보다 오래 걸릴 수 있고 생성한 리소스에는 비용이 발생한다. 50분 수업의 완료 기준은 배포의 선행 조건과 검증 결과를 설명하고 준비된 환경에서 절차를 따라갈 수 있는지다. 모든 학생이 새 AWS 계정을 처음부터 운영 상태로 만드는 것까지 요구하지는 않는다.

읽는 방법과 준비물

  • 기초 지식: Git 브랜치·커밋, 환경변수, HTTP, 컨테이너 이미지와 실행 프로세스의 차이. Kubernetes의 Pod·Service·Deployment는 3강에서 다시 짚는다.
  • 코드 읽기: 이 저장소의 해당 브랜치와 텍스트 편집기. 본문의 파일 링크는 저장소 안에서 HTML을 열었을 때 연결된다.
  • 명령 환경: 예제 명령은 Bash 기준이다. Windows에서는 WSL2의 Linux 작업 환경을 사용한다. PowerShell에 Bash의 export, 줄 끝 \, 명령 치환을 그대로 붙여 넣지 않는다.
  • 로컬 실습: Python, Terraform CLI 1.13.5. Kubernetes 실습에는 Docker·kind·kubectl·Helm·just·Bazel 및 프로젝트 언어 도구가 추가로 필요하다. 상세 설치는 로컬 배포 README에서 확인한다.
  • 교재 기능: 목차 이동, 접힌 정답 열기, 브라우저 인쇄/PDF를 사용할 수 있다. 발표 자료에는 강사 노트·읽기 모드·키보드 탐색 기능이 있다. HTML 하나에 스타일과 스크립트를 포함하므로 본문을 읽는 데 인터넷이나 웹 서버가 필요 없다.
