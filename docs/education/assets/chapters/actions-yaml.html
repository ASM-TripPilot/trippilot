Workflow 파일은 .github/workflows/ 아래의 .yml 또는 .yaml 파일이다. YAML은 들여쓰기로 구조를 구분한다. 실습에서는 한 단계마다 공백 두 칸을 쓰고 탭은 쓰지 않는다. key: value는 이름과 값, -는 목록의 항목, |는 줄바꿈을 유지한 여러 줄 문자열이다. run: | 아래의 내용은 YAML이 아니라 선택한 shell에서 실행할 스크립트가 된다.

키읽는 방법예
name화면에 표시할 이름workflow 이름과 step 이름 모두에 사용
on어떤 이벤트에 반응하는가workflow_dispatch
jobs, runs-on작업과 실행 머신validate, ubuntu-latest
steps, uses단계 목록과 재사용 actionactions/checkout@v4
withaction에 전달할 입력python-version: '3.13'
run, envshell 명령과 환경변수python -m unittest …
id, outputs다른 단계가 참조할 식별자와 결과steps.check.outputs.revision
needs, if선행 job과 실행 조건needs: validate
permissions토큰에 허용할 기능 범위contents: read

구문별 상세 정의: GitHub Workflow syntax. 다음 예제의 실행 순서는 이 교재를 위한 설명용 구성이다.

아래 파일은 AWS 자격 증명을 요청하지 않고 저장소의 부트스트랩 정책 테스트만 수행하는 완전한 연습 예제다. 우선 별도 연습 폴더의 course-checks.example.yml로 저장하고 읽는다. 원격 실행을 실습할 경우에는 저장소 내용이 있는 개인 연습용 사본에서만 .github/workflows/course-checks.yml로 등록한다. 본 프로젝트의 AWS workflow는 변경할 필요가 없다.

작성 예제 · 검증용 workflow 전체 · AWS 접근 없음
name: Course / offline checks

on:
  workflow_dispatch:
    inputs:
      make_report:
        description: 결과 요약 생성
        type: boolean
        default: true

permissions:
  contents: read

env:
  COURSE_NAME: TripPilot automation

jobs:
  validate:
    runs-on: ubuntu-latest
    timeout-minutes: 10
    outputs:
      revision: ${{ steps.check.outputs.revision }}
    steps:
      - name: Read repository
        uses: actions/checkout@v4
        with:
          persist-credentials: false
      - name: Set up Python
        uses: actions/setup-python@v5
        with:
          python-version: '3.13'
      - name: Test bootstrap policy files
        id: check
        env:
          VALIDATED_REVISION: ${{ github.sha }}
        run: |
          python -m unittest discover -s infra/bootstrap/tests -v
          printf 'revision=%s\n' "$VALIDATED_REVISION" >> "$GITHUB_OUTPUT"
          printf 'CHECK_LABEL=bootstrap-contracts\n' >> "$GITHUB_ENV"
      - name: Show same-job environment
        run: printf '%s / %s\n' "$COURSE_NAME" "$CHECK_LABEL"

  report:
    needs: validate
    if: inputs.make_report
    runs-on: ubuntu-latest
    permissions: {}
    env:
      CHECKED_REVISION: ${{ needs.validate.outputs.revision }}
    steps:
      - name: Write human-readable result
        run: |
          printf '### Offline checks passed\n' >> "$GITHUB_STEP_SUMMARY"
          printf 'Commit: `%s`\n' "$CHECKED_REVISION" >> "$GITHUB_STEP_SUMMARY"

첫 블록 on.workflow_dispatch는 수동 실행을 허용하고 make_report는 체크박스 입력을 만든다. validate는 코드와 Python을 준비한 후 테스트를 실행한다. run의 테스트가 실패하면 이후 성공 경로의 출력은 작성되지 않는다. report는 needs: validate 때문에 검증 성공 뒤에만 실행되며 체크박스가 꺼져 있으면 건너뛴다.

uses: actions/setup-python@v5의 @v5는 action 버전 참조다. Python 버전은 action의 입력인 with.python-version에서 정한다. 두 버전은 서로 다른 대상을 가리킨다. 동일한 step에 uses와 run을 함께 넣는 대신, 준비 action과 실행 명령을 별도 step으로 나눈다.

report에는 checkout이 없다. 파일을 읽지 않고 전달받은 문자열만 요약에 쓰기 때문이다. 반대로 소스를 읽는 새 job을 추가하면 그 job에서도 checkout이 필요하다. GitHub 호스팅 job 사이에 작업 폴더나 설치한 도구가 자동 공유된다고 가정하지 않는다. 문자열은 output으로 전달하고 필요한 파일은 명시적으로 artifact에 저장해 전달하는 식으로 구분한다. 이 브랜치의 state·plan·비밀값은 일반 artifact로 올리지 않는다. Job 구성 공식 설명

실제 workflow의 working-directory: backend는 해당 run 명령을 backend 폴더에서 실행한다. cd backend를 한 step에서 실행했다고 다음 step까지 현재 폴더가 유지되는 것은 아니다. 여러 step에 같은 기본 폴더가 필요하면 AI CI처럼 defaults.run.working-directory를 설정한다. 이 기본값은 run에 적용되며 action의 with.context 같은 입력을 대신하지 않는다. Shell·작업 폴더 기본값
