• Workflow, event, job, runner, step, action의 관계를 설명한다.
  • uses와 run을 구분하고 조건·의존성·출력값을 가진 YAML을 작성한다.
  • GITHUB_TOKEN, OIDC 토큰, AWS IAM Role이 맡는 역할을 구분한다.
  • 이 브랜치의 CI와 AWS 배포가 어떻게 분리되는지 설명하고 승인·검증이 보장하는 범위를 판단한다.
기본 50분주제수강생 산출물
0–6분실행 구조와 기존 CI 읽기event → job → step 연결도
6–16분YAML 문법과 완전한 기초 예제검증용 workflow 사본
16–23분context·환경변수·출력 전달변수의 생산자와 소비자 표시
23–35분실제 AWS workflow 해부plan/apply 실행 경로 비교
35–41분OIDC·Environment·동시 실행권한과 승인 시점 설명
41–47분로컬 실습오프라인 테스트 결과와 오류 원인
47–50분확인 문제세 가지 운영 오해 수정

30분 수업: 개념 4분 → 기초 YAML 7분 → 실제 배포 표 9분 → 권한·승인 5분 → 실습·문제 5분으로 진행한다. 60분 수업: 기본 과정에 잘못된 브랜치 입력 분석 5분과 plan 승인 지점 재설계 토론 5분을 더한다. 모든 실습은 기존 AWS workflow를 실행하거나 수정하지 않는 방식이다.
