수업 실습에서는 강사가 준비한 실행 로그를 읽는 것으로 대체할 수 있다. 실제 실행자는 배포할 develop의 commit SHA, 해당 코드의 앱 CI 결과, GitHub Environment 변수, AWS 계정과 리전을 먼저 기록한다. AWS deploy workflow의 검증 job은 인프라·배포 도구·Helm 검사와 backend 종료 설정의 일부 테스트를 수행한다. backend·AI·frontend 전체 테스트 성공을 자동으로 종합 확인하는 release gate는 현재 별도로 구현되어 있지 않다.

기존 앱 CI가 GHCR로 이미지를 발행했더라도 AWS workflow가 그 이미지를 가져와 배포하지는 않는다. 앱 CI 통과는 코드 품질의 증거이고 AWS workflow는 해당 실행에서 ECR용 이미지를 다시 만든다. branch가 이미 다음 commit으로 이동했다면 이전 CI의 초록색 표시를 새 commit의 검증으로 간주하면 안 된다.

UI 경로는 Actions → AWS / Terraform and EKS deploy → Run workflow이다. mode=plan이면 deploy_application=true를 선택했더라도 앱 배포는 실행하지 않는다. 반대로 앱만 바꿔 배포하는 경우에도 현재 workflow는 인프라 plan/apply를 먼저 수행한다. 앱 전용 승격 입력은 아직 없다.

실제 workflow가 적용하는 계획 · 읽기 예제

terraform plan -lock-timeout=5m \
  -var-file="../environments/$DEPLOY_ENVIRONMENT.tfvars" \
  -out="$RUNNER_TEMP/trippilot.tfplan"

# mode=apply일 때만 실행
terraform apply -lock-timeout=5m "$RUNNER_TEMP/trippilot.tfplan"

같은 workflow 실행 안에서는 저장한 plan 파일을 apply한다. 별도 plan 실행에서 나온 파일을 나중의 apply 실행이 재사용하는 것은 아니다. S3 state를 가리키는 계정·리전·환경을 바꾸면 전혀 다른 인프라를 대상으로 계획할 수 있으므로 Summary의 state 버킷 이름도 확인한다.

인프라 생성 뒤 Secrets Manager에는 backend·ai·database·shared 저장소가 생긴다. Terraform은 저장소를 만들고 앱 비밀값은 배포 도구가 처리한다. 비어 있으면 DB용 암호, backend/AI 공통 서비스 토큰, RSA JWT 서명키를 생성하고 기존 값은 유지한다. 외부 LLM·OAuth·기상 API 키를 자동으로 발급하지는 않는다. 필요한 키 이름은 runtime_secrets.py의 허용 목록을 따라 Secrets Manager에서 입력하며 값 자체를 수업 제출물·로그·Helm values에 복사하지 않는다.

DB 초기화 Job만 임시로 RDS 관리자 자격증명을 사용한다. backend 런타임 SQL은 app_user, Flyway는 app_migrate를 사용하며 앱 Pod에 관리자 암호를 넘기지 않는다. DB 초기화는 역할과 스키마를 준비하는 반복 가능한 작업이고 애플리케이션 Flyway migration과 DB 백업 복구는 서로 다른 작업이다. Secret을 수정했으면 수동 앱 배포를 다시 실행해 동기화와 Pod 교체가 일어나게 한다.

현재 Helm 배포 명령 · workflow 내부 발췌

helm upgrade --install trippilot deploy/eks/chart --namespace trippilot \
  -f "deploy/eks/chart/values-$DEPLOY_ENVIRONMENT.yaml" \
  -f "$RUNNER_TEMP/trippilot-values.json" \
  --set-string "rolloutNonce=$DEPLOY_RUN_ID" \
  --atomic --wait --timeout 20m --history-max 10

첫 -f는 replica 수·PDB 같은 환경 정책, 다음 -f는 이번 Terraform output과 이미지 tag를 사용한다. 뒤에 지정한 values가 앞의 값을 덮어쓰며 --set-string은 마지막으로 적용된다. rolloutNonce가 바뀌면 같은 이미지 tag라도 Pod template이 달라져 Secret 변경을 반영할 새 Pod를 만든다. --atomic은 Helm upgrade 자체가 실패하면 변경을 되돌리고 --wait도 활성화한다. Helm 3 upgrade 옵션.
