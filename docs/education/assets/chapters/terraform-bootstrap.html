S3 backend를 사용하려면 S3 bucket이 이미 있어야 한다. GitHub가 bucket을 만들려면 AWS 권한이 있어야 한다. 그런데 그 AWS 권한도 같은 Terraform에서 만들려 하면 최초 실행 권한이 없는 상태로 되돌아온다. 부트스트랩의 선행 의존 문제다. 시스템을 실행하기 위한 최소 기반을 시스템의 일반 배포 단계와 나눠 해결한다.

이 브랜치는 AWS 관리자가 기존 관리자 또는 SSO 세션으로 GitHub OIDC provider와 환경별 bootstrap 역할을 준비하도록 한다. 이어서 수동 AWS bootstrap (manual) workflow가 CloudFormation template을 적용한다. CloudFormation은 여기서 Terraform의 backend를 사용하지 않으므로 S3 state bucket을 먼저 만들 수 있다.

Bootstrap은 환경 전용 state bucket, 일반 배포 역할, EKS cluster/node 서비스 역할을 관리한다. 일반 Terraform은 서비스 역할을 data로 조회하며 그 신뢰 정책을 직접 수정하지 않는다. 기반 권한을 바꿀 수 있는 사람과 서비스 인프라를 배포할 수 있는 실행의 책임을 구분한 것이다. 한 리소스를 CloudFormation과 Terraform 양쪽에 동시에 선언하면 두 도구가 서로의 변경을 되돌릴 수 있으므로 소유 도구를 하나로 정한다.

강사나 AWS 관리자는 사전 작업으로 최초 인증 경로를 준비한다. 학생은 이 수업에서 bootstrap workflow를 실행하지 않고 템플릿과 정책을 읽는다. 실제 절차와 Environment 변수는 저장소의 AWS 초기 설정 가이드에 연결되어 있다. 이미 있는 계정 수준 OIDC provider를 중복 생성하지 않는 점, PRD Environment의 배포 브랜치를 제한해야 하는 점도 함께 확인한다.
