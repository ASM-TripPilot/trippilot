TripPilot AWS 전체 구성

  • VPC 안에 public·private compute·isolated data 서브넷을 둡니다.

TRIPPILOT / 04

네트워크 구역과 접근 경계

  • Public은 NLB·NAT, private compute는 EKS, isolated data는 RDS·Redis를 맡습니다.
  • NAT는 내부 앱의 외부 요청에 사용합니다. data subnet에는 인터넷 기본 경로가 없습니다.
  • DB·Redis 접근은 EKS 보안 그룹과 TLS 설정을 함께 확인합니다.
강사 노트AZ(가용 영역)는 한 리전 안의 분리된 운영 구역입니다. 각 AZ마다 세 종류의 서브넷을 만듭니다. Public이라는 이름만으로 모든 리소스가 외부에 공개되지는 않습니다. 실제 접근은 주소, 경로, 보안 그룹 설정에 달려 있습니다. RDS 5432와 Redis 6379는 EKS 클러스터 보안 그룹에서만 들어오도록 허용하며 TLS를 사용합니다. EKS 노드는 private이지만 관리 API에는 public endpoint도 있습니다.

HCL 블록과 표현식

  • resource 블록의 유형과 로컬 이름은 실제 AWS 객체의 이름과 구분합니다.

2강 · GitHub Actions

  • Workflow는 이벤트, job, step으로 배포의 실행 순서를 표현합니다.
  • TripPilot AWS 배포는 workflow_dispatch로 수동 시작합니다.
