## 5. 티켓을 어떻게 뽑을 것인가

**팀 템플릿을 그대로 따른다** (TRIP-1259 참조): 부모 "작업" 1건 + 서브태스크 N칸.
부모 본문은 `스코프 / 근거 / 선행조건 / DoD / 수용 기준(AC) / 정본 경로` 절을 갖는다.
제목은 `[FE]|[BE]|[AI]|[BE·AI] 증상 — 요약 (N칸)` 꼴.

**발행 순서**

1. **정본 정리 먼저** (티켓 아님, PR 1건) — §1 의 7건. 이걸 미루면 다음 사람이 또 중복을 만든다.
2. **P0 묶음 2건 발행**
   - `[BE·AI] 실사용 피드백 2026-10-07 — 일정 생성 품질 (N칸)`: 차선책 좌표 · HC1 면제(기존 TRIP-1247·1249 와 **중복 확인 후 그쪽에 칸 추가**) · 09:00 창
   - `[AI] 죽은 데이터 경로 되살리기 (4칸)`: 입장료 · 행사 · KB-5 · 벡터 색인
3. **P1 묶음 1건** — `[BE·AI] AI 호출 비용 상한 (3칸)`: 관측(식별자) → AI 손잡이 → BE 상한.
   **관측이 먼저다** — 상한 숫자를 지어내지 않으려면.
4. **P2 는 티켓 전에 결정 회의 1건.** 결정 없이 티켓을 만들면 "결정 대기"로 쌓인다
   (지금 열린 61건 중에도 그런 것이 있다).
5. **보안 1건 단독** — `state`·`nonce` 는 묶지 않는다. 심사·출시와 무관하게 독립적으로 닫힐 수 있다.

**발행 전 체크 3줄**

```
gh pr list --state merged --limit 15          # 방금 머지된 것과 겹치나
# Jira: project = TRIP AND statusCategory != Done AND summary ~ "<키워드>"
grep -n "<키워드>" backend/docs/design/work-graph.toml
```

세 번째가 특히 중요하다 — work-graph 노드는 Jira 티켓이 없는 경우가 많아 Jira 만 보면 중복이 난다.

## 출시 차단

**푸시를 켠다** (사용자 직접 결정). 내 권고는 "심사 빌드에서 권한 요청을 내린다"였고 **기각됐다**.
켜는 데 필요한 것을 실측했다 — `PUSH_EXPO_ACCESS_TOKEN` 은 **선택이다**(`ExpoPushAdapter.kt:55`
가 비어 있으면 Bearer 를 안 붙일 뿐), `PushModeAnnouncer` 도 토큰이 아니라 **실 발송기 주입만**
요구한다. 즉 **배포 입력 `push_mode=expo` 한 번이면 서버는 켜진다**(#994).

남은 잔여 둘 — ① **FE 수신 핸들러 0건**(`setNotificationHandler`·
`addNotificationResponseReceivedListener` 전수 0, TRIP-835): 없으면 알림이 와도 **탭이 아무 데도
안 간다**. ② 실기기 왕복 1회(TRIP-834 · `PUSH-LIVE-CHECK`, 현재 0회).
**서버만 켜고 ①을 안 하면 "알림은 오는데 눌러도 안 열리는" 상태가 된다** — 켜는 순서는 FE 먼저다.

- **1200**: 새 안 채택 · 사진 스트립 제거 + 자동 채우기 버튼 · 점선 칸은 **남김**(자동 채우기 실패
  경로의 보조) · 칩 **터치 타깃 44 + 토큰 색**(접근성은 타협 대상 아님) · 시트 높이 축소 ·
  회고 링크는 **기록 1곳 이상일 때만**
- **1201**: 배정은 **도착 시각 우선, 없으면 계획 구간** · 분류 못 한 사진 칸 **둔다**(안 두면 사진이
  조용히 사라진다) · 권한 없을 때 안내+설정 이동 · EXIF 위치는 **GPS 동의 있을 때만**
- **1203**: 누락으로 보고 버튼 추가 · **j01 컴팩트 카드와 모양 통일** · 시각은 **도착 시각으로 통일**
  (같은 방문이 09:21/20:59 로 갈려 보이는 건 사용자 눈에 버그)
