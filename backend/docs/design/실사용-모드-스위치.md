# 실사용 모드 스위치 — 환경별 값·키 발급 상태·차단 조합 (TRIP-850)

> **정본 관계**: 이 문서는 소비 뷰다. 허용 키 목록·배포 전 검증의 정본은
> `deploy/eks/runtime_secrets.py`, 각 스위치의 기본값은 `backend/app/src/main/resources/application.yml`
> **또는 해당 모드 어나운서의 `@Value` 폴백**(아래 표 주석), EKS 고정값은
> `deploy/eks/chart/templates/backend.yaml`, 투입 절차는 `docs/guides/aws-eks-deployment.md` 다.
> 표와 코드가 다르면 **코드가 이긴다** — 발견하면 이 표를 고친다.

## 왜 이 문서인가

외부 경계 스위치는 전부 기본값이 스텁·가짜·꺼짐이다. 이것은 의도다 — CI 외부호출 0 정책과
시드 없는 환경의 안전값이다. 문제는 환경별로 무엇을 켜는지가 코드 세 곳(yml·compose·차트)과
시크릿에 흩어져 있어 "아무도 안 켠 상태"와 "켜면 안 되는 상태"가 구분되지 않던 것. 이 문서가 그 표다.

## 1. 환경별 값 표

| 스위치 (env) | 기본(안전값) | 로컬 compose | CI | EKS | 실사용 값·전제 |
|---|---|---|---|---|---|
| `AI_SCHEDULE_MODE` | `fake` | `.env` 로 `http` 선택 | `fake` | **차트 고정 `http`** | AI 파드 + `SERVICE_AUTH_TOKEN` |
| `AI_REFLECTION_MODE` | `rule` | `.env` 선택 | `rule` | **차트 고정 `http`** | 환각 가드 완료(TRIP-848) |
| `AI_REMINDER_COPY_MODE` | `off` | `.env` 선택 | `off` | 시크릿 (시드 기본 `http`) | 실어댑터 완료(#546) |
| `PLACE_GEOCODE_MODE` | `stub` | `.env` 선택 | `stub` | 시크릿 (시드 기본 `stub`) | `kakao` — 카카오 로그인 REST 키 공용 |
| `WEATHER_MODE` | `fake` | `.env` 선택 | `fake` | 시크릿 (시드 기본 `fake`) | `kma` — 공공데이터포털 **Decoding** 키 |
| `STAY_CONTENT_MODE` | `stub` | compose 기본 **`db`** | `stub` | **차트 고정 `db`** | 없음 — 정본 시드 기존재 |
| `PUSH_MODE` | `off` | `.env` 선택 | `off` | 시크릿 (시드 기본 `off`) | `expo` — FE 배선 + 실기기 왕복(PUSH-LIVE-CHECK) |
| `AFFILIATE_MODE` | `fallback` | `.env` 선택 | `fallback` | 시크릿 (시드 기본 `fallback`) | `tripcom` — TRIPCOM 3종 (켜는 결정 = 사용자) |
| `SERVICE_AUTH_TOKEN` | 빈값 (발신 fail-open · 인바운드 `/internal/**` fail-closed) | `.env` | 빈값 | **첫 배포가 자동 생성·보존** + `REQUIRE=true` 고정 | AI 쪽 인바운드 검증은 별건(AI-INBOUND-AUTH) |
| `JWT_SIGNING_KEY` | 빈값 (생성+경고) | `.env` 빈값 | 빈값 | **첫 배포가 자동 생성·보존** + `REQUIRE=true` 고정 | — |

- `AI_SCHEDULE_MODE`·`AI_REFLECTION_MODE`·`PUSH_MODE` 의 기본값은 yml 에 없고 **어나운서의
  `@Value` 폴백**이 정한다(`ScheduleAgentModeAnnouncer`·`ReflectionModeAnnouncer`·`PushModeAnnouncer`).
  compose 밖에서 직접 띄울 때 실바인딩 env 는 접두어형(`TRIPPILOT_AI_SCHEDULE_MODE` 등)이다 —
  표의 짧은 이름은 compose/.env 별칭이고, compose 가 접두어형으로 이어 준다.
- EKS "시크릿" = Secrets Manager `backend` 그룹 → `trippilot-backend` K8s Secret. 비어 있는 첫 배포는
  `runtime_secrets.seed_groups` 가 시드 기본값을 채우고, **이후 값 변경은 시크릿 수정 + 재배포**다.
- `AFFILIATE_MODE`·`TRIPCOM_*` 의 EKS 배선은 이 티켓(TRIP-850)에서 추가했다 — 그 전엔 compose 에만 있었다.

## 3. 켰을 때 막히는 조합

**배포 전 검증이 죽인다** (`validate_groups` — 파드에 닿기 전에 ValueError):

- `PLACE_GEOCODE_MODE=kakao` 인데 `KAKAO_CLIENT_ID` 없음
- `WEATHER_MODE=kma` 인데 `WEATHER_API` 없음
- `AFFILIATE_MODE=tripcom` 인데 `TRIPCOM_ALLIANCE_ID`/`SID`/`AD_ID` 중 하나라도 없음
- `GOOGLE_CLIENT_SECRET` 에 값이 **차 있음** (공개 클라이언트 — invalid_client 실측)
- LLM provider 지정인데 해당 API 키 없음 · 모드 오타 · allowlist 밖 키

**기동이 막힌다** (검증을 우회해 파드까지 간 경우 — 어나운서·require):

- `JWT_REQUIRE_CONFIGURED_KEY=true` 인데 키 없음 (EKS 는 true 고정)
- `PUSH_MODE=expo` 인데 실 발송기 미배선 (`PushModeAnnouncer`)
- tripcom 인데 alliance-id·sid·ad-id 빈값 (어댑터 require)

조용히 꺼지는 것보다 시끄럽게 죽는 쪽을 고른 게 설계다 — 운영자는 이 표로 그 실패를 예상한다.

## 4. 실값 투입 (사람 몫)

AWS 콘솔에서 Secrets Manager `backend` 시크릿(JSON)을 수정하거나 put-secret 경로를 쓴다 —
절차·시크릿 이름은 `docs/guides/aws-eks-deployment.md`. **켜기 자체의 전제는 각 티켓이 진다**
(날씨 TRIP-849 완료 · 리마인드 #546 완료 · 푸시는 PUSH-LIVE-CHECK · 제휴는 배포 결정).
