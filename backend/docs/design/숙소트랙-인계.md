## 3. OTA 조사 결과 (2026-09-25)

### 트립닷컴 > 아고다 — 문턱이 다르다

| | 딥링크 | **검색·콘텐츠 API** |
|---|---|---|
| 아고다 | 셀프서브 즉시 | **4~8주 상업 협상 + 여행사 법인 + KYC + 운영 중인 플랫폼** |
| 트립닷컴 | 어필리에이트 가입 | **어필리에이트 등급에 포함**(widgets, APIs, deep link generators) |

리포 문서(`제휴링크-연동-설계.md`)가 *"아고다: 셀프서브 CID 즉시"* 라고 적은 것은 **딥링크 얘기**다.
B(콘텐츠 API)에는 안 맞는다 — 그 표는 딥링크 기준으로 쓰였다.

### 선례가 있다 — 투플(toople.co.kr)

AI 여행 계획 앱인데 우리와 포지셔닝이 겹치고, **트립닷컴으로 숙소를 처리한다**(사용자 관찰).
사업자 정보가 결정적이다:

```
사업자등록번호   566-52-01060
통신판매업 신고   2025-대전중구-0508
여행업 등록      없음
지위            통신판매중개자 — "실제 거래 책임은 판매자에게"
```

**여행업 등록 없이, 2025년 신고한 소규모 사업자가 하고 있다.** 즉 아고다의
*"registered travel company"* 는 **아고다 한정 조건**이지 일반 규칙이 아니다.

### 트리플과는 모델이 다르다 — 따라 하지 말 것

트리플은 메타서치(익스피디아·아고다·트립닷컴 등 N개 비교) + 자체 재고(야놀자 인수) 하이브리드다.
**N개를 비교하려면 같은 호텔을 N개 재고에 매핑해야 하고, 그게 우리가 TourAPI 에서 겪은 매칭 지옥이다.**

**공급사를 하나로 두면 그 문제가 통째로 사라진다** — 그쪽 호텔 ID 가 곧 우리 ID 이고, 사진·가격·
어매니티가 같은 응답에 딸려온다. 비교 기능은 공급사를 늘릴 때 고민한다.

## 4. 계약 없이 지금 할 수 있는 것 — Fake keystone

**구조가 이미 받아 준다.** 포트 문서가 *"실 벤더 단계에서 Resilience4j 서킷·Redis 캐시가 이 포트
구현을 감싼다"* 고 적고 있다 — 즉 벤더 어댑터는 **설계 이탈이 아니라 원래 그리려던 그림**이고
`DbContentAdapter`(정본 읽기)가 중간 기착지였다.

| 이미 있는 것 | 역할 |
|---|---|
| `AccommodationContentPort` | OTA 어댑터를 꽂을 자리 |
| `STAY_CONTENT_MODE` (stub·db) | `ota` 한 값만 추가 |
| `ContentResult.degraded` | OTA 실패 → 정본으로 떨어진 것을 표현 |
| `saved_stay.external_source` nullable | OTA 숙소 저장이 스키마 변경 없이 됨 |
| `SavedStay` 의 이름·좌표 사본 | OTA 조회 불가해져도 **거점으로는 계속 쓰임** |

마지막 줄이 중요하다 — canon 이 *"외부 조회 불가해져도 사용 가능"* 하라고 설계해 둬서,
**탐색 정본을 갈아도 일정 생성이 안 깨진다**(U1 `domain-entities` §2).

### 빠진 것 둘 — 여기가 실제 작업이다

1. **날짜가 없다.** 포트가 `search(region: String?)` 뿐인데 **OTA 실가격은 체크인/체크아웃이
   있어야 나온다.** 시그니처를 넓혀야 하고 이게 제일 큰 변경이다.
2. **사진 필드가 없다.** `Stay` 에 추가해야 한다.

### 정직하게 — B 의 비용

**런타임 벤더 호출로 돌아간다.** `DbContentAdapter` 주석이 정확히 그걸 피하려고 쓰였다 —
*"검색 1회 = 외부 호출 1회가 되어 쿼터가 곧 검색 가능 횟수가 되고, 벤더가 느리면 검색이 같이 느려진다."*
실가격은 원리적으로 실시간이라 피할 수 없다. 완화는 **콘텐츠는 캐시·가격은 캐시 안 함 + 서킷 +
타임아웃 + 실패 시 정본으로 degrade**.

덧: **포트 문서와 `DbContentAdapter` 주석이 서로 반대를 말한다.** B 로 가면 이 충돌을 정리해야 한다 —
어느 쪽이 종착지인지.

## 5. 사람 몫 — 이게 병목이다

1. **트립닷컴 어필리에이트 가입** (무료·셀프서브로 보임). 가입하면 **API 접근 범위가 즉시 확인된다** —
   사진·편의시설이 실제로 오는지, 호출 제한이 얼마인지. 공개 문서는 *"data feed and API"* 라고만 해서
   **가입 전엔 확정할 수 없다.** 기술 진입점: <https://connect.trip.com/>
2. **법적 구조 확인** — 통신판매중개자 지위 + 면책 고지로 가는 것(투플 방식). **법무 판단 영역**이고
   우리 통신판매업 신고 상태도 확인이 필요하다.
3. **출시 전 벽** — 어필리에이트 심사가 "운영 중인 매체"를 보는 건 그대로다. 아고다의 4~8주 협상보다는
   훨씬 낮지만 0은 아니다.

## 6. 아직 안 정해진 것 — 세션이 물어야 한다

- **카드 디자인.** 사진 없는 데이터에 사진 전제 카드를 끼우는 것이 문제의 절반이다. 지도 썸네일은
  **선례가 없어 기각**했다(2026-09-24 조사 — 지도 썸네일의 실제 용도는 로딩 플레이스홀더·성능
  최적화지 사진 대체가 아니고, 썸네일 리스트 패턴 문서가 *"대부분이 플레이스홀더면 그 패턴의 이점이
  사라진다"* 고 명시한다. 우리는 98%가 그렇게 된다). **FE·기획 합의가 필요하다.**
- **A/B 갈림길.** "전국 12,936곳을 다 보여주되 대부분 사진이 없다"(A) vs "사진 있는 숙소만 보여주되
  목록이 줄어든다"(B). **제품 결정**이다.
- **`TRIP-825` 의 남은 다섯 필드.** `address` 는 들어갔고 `imageUrl` 은 위 계약 대기다.
  나머지(SavedStay `imageUrl`·`region`·가격·`isBase`)는 노드 노트에 판단이 적혀 있다.

## 7. 갱신 경로 — 알아 둘 것

정본 시드는 **수동**이다. `backend/scripts/gen_stay_seed.py <문화_숙박업.csv>` 로 만든다.

- 원본은 [행정안전부 LOCALDATA](https://www.localdata.go.kr/) 「숙박업」. **리포에 없다.**
- 생성기 주석의 *"curl 은 403"* 은 **정정됐다**(PR #685) — UA 차단이고, 브라우저 UA 를 붙이면 200 이다.
  다만 그건 안내 페이지지 파일이 아니다. 자동화하려면 변동분 OpenAPI 를 쓴다.
- 드리프트 속도 실측: **폐업 약 19건/월 · 신규 약 103건/월.** 반년을 끌어도 죽은 항목이 1% 안쪽이다.
- `pyproj` 가 필요하다. 시드 재생성은 **폐업 제거를 동반**한다(`updated_at < now()`).

### 8.6 협업 규칙 — 두 번 겪었다

이전 세션은 숙소 트랙에 손대지 않는다.
