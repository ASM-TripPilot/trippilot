## 1. 패키지·모듈 구조 + 경계 규칙

### 1.1 Gradle 멀티모듈 (D04 모듈러 모놀리스)

```
backend/
├─ app/                     ★ 유일한 Spring Boot 애플리케이션(조립·설정·필터체인·Flyway)
├─ common/
│  ├─ core/                 도메인 이벤트 계약·트랜잭셔널 아웃박스·공통 타입(Result·에러)
│  └─ security/             JWT 검증·인증 필터·JWK 로더(LC-2)
└─ modules/
   ├─ auth/                 M1 — Account·SocialIdentity·Consent·Location·RefreshSession·Deletion
   ├─ profile/              M2 — Profile·PreferenceSet·닉네임 생성
   └─ moderation/           C3 — BannedWordDictionary·checkText (profile·후속 UGC 재사용)
```

패키지 루트: `com.trippilot.<module>` (예: `com.trippilot.auth`).

### 1.2 모듈 내부 헥사고날 레이어

```
modules/auth/
├─ domain/          엔티티·값객체·도메인 서비스·포트(interface) — 프레임워크 의존 0
├─ application/     유스케이스(서비스)·트랜잭션 경계·포트 오케스트레이션
└─ adapter/
   ├─ in/web/       컨트롤러·요청/응답 DTO·매핑 (Spring MVC)
   ├─ out/persistence/  JPA 엔티티·리포지토리 구현(도메인 포트 구현)
   └─ out/external/     SocialOAuthPort 어댑터 4종·MailDeliveryPort(후속) 등
```

### 1.3 경계 규칙 (ArchUnit/Konsist로 CI 강제 — NFR-U1-MT-01·02)

| # | 규칙 |
|---|---|
| R1 | `modules/*`는 서로 직접 참조 금지 — 상호작용은 `common/core` 이벤트 계약으로만 |
| R2 | `domain` 레이어는 Spring·JPA·Jackson 등 프레임워크 import 금지(순수 Kotlin) |
| R3 | 외부 기술 의존은 `adapter`에만 — `application`은 포트 인터페이스만 안다 |
| R4 | `app`만 `@SpringBootApplication`·컴포넌트 스캔 조립 소유 |
| R5 | 의존 방향: `app → modules → common`. 역방향(common→modules) 금지 |
| R6 | 컨트롤러에 인증 가드 누락 검출("인증 없는 핸들러 = 화이트리스트 외 금지", NFR-U1-SEC-20) |

## 2. 도메인 이벤트 카탈로그 + 트랜잭셔널 아웃박스

### 2.1 이벤트 봉투 (`common/core` 정본)

```
EventEnvelope {
  eventId: UUID           // 멱등 키 — 전 구독자 이 값 기준 중복 제거
  eventType: String       // 예 "auth.AccountCreated"
  schemaVersion: Int
  aggregateType: String   // "Account" 등
  aggregateId: String
  correlationId: String   // 요청 상관 ID(MDC)
  occurredAt: Instant
  payload: JSON
}
```

### 2.2 아웃박스 테이블 (스키마 추가 — `common/core` 마이그레이션 `V1.0`)

```sql
CREATE TABLE outbox_event (
  id            bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  event_id      uuid NOT NULL UNIQUE,
  event_type    varchar(80) NOT NULL,
  aggregate_type varchar(40) NOT NULL,
  aggregate_id  varchar(64) NOT NULL,
  correlation_id varchar(64),
  payload       jsonb NOT NULL,
  occurred_at   timestamptz NOT NULL DEFAULT now(),
  published_at  timestamptz,                 -- NULL=미발행
  attempts      int NOT NULL DEFAULT 0
);
CREATE INDEX ix_outbox_unpublished ON outbox_event (occurred_at) WHERE published_at IS NULL;
```

- **원자성**: 애그리거트 상태 변경 + `outbox_event` INSERT를 **단일 트랜잭션**(services.md §0.2). 외부 호출은 TX 밖.
- **릴레이**: Spring `@Scheduled` + ShedLock(PostgreSQL 락) 폴링 → 인프로세스 이벤트 버스·감사 파이프라인(LC-8)로 at-least-once 발행 → `published_at` 마킹.
- **멱등**: 구독자는 `eventId`로 중복 제거(계약).

### 2.3 U1 이벤트 목록 (초안 — services.md §0.2 대조 필요)

| 이벤트 | 발행 시점 | 소비자(U1) |
|---|---|---|
| `auth.AccountCreated` | 소셜 가입 완료 | 감사(LC-8) |
| `auth.AccountDeletionRequested` | 삭제 요청 | 감사 · GPS 파기 훅 · 연쇄 삭제 예약 |
| `auth.AccountDeletionCancelled` | 유예 내 철회 | 감사 |
| `auth.AccountPurged` | 유예 만료 파기 | 감사 · 연쇄 삭제 오케스트레이션(U8 완성) |
| `auth.ConsentGranted` / `auth.ConsentRevoked` | 동의·철회 | 감사 · 위치 법정 로그 |
| `auth.LocationConsentChanged` | L2/L3 변경 | GPS 파기 트리거(L3 REVOKE) |
| `auth.RefreshReuseDetected` | 회전 토큰 재사용 | 감사(즉시 알림 — SECURITY-14) |
| `profile.NicknameChanged` | 닉네임 변경 | 감사 |

> `common/core`는 U1에서 계약+릴레이 골격만 산출, 최초 실소비는 U3(StayRegistered)부터(logical-components LC-10). U1 자체 소비자는 감사·삭제연쇄 훅.

## 3. 인증/토큰 상세

### 3.1 액세스 토큰 (JWT · 무상태)

| 항목 | 값 |
|---|---|
| 알고리즘 | **RS256**(비대칭 — JWK 셋·kid 롤오버, Nimbus JOSE S-5) |
| 클레임 | `iss=trippilot`, `aud=trippilot-app`, `sub=<accountId>`, `iat`, `exp=+1h`, `jti`(UUID) |
| 헤더 | `kid`(서명 키 식별 — 롤오버) |
| PII | **미포함**(sub=accountId만, SECURITY-03) |
| 검증 | 서명·`exp`·`iss`·`aud` 무상태 검증(LC-2). DB 의존 없음 |

### 3.2 리프레시 토큰 (불투명 · 회전)

- 불투명 랜덤 토큰(JWT 아님) — 서버는 `RefreshSession.tokenHash`만 저장(원문 미저장).
- 갱신 시 회전(구 토큰 `rotated_at` 마킹 → 신 토큰 발급), 재사용 감지 시 체인 전체 revoke(INV-R2).
- 수명 90일. 클라이언트 OS 보안 저장소 보관.

### 3.3 JWK 키 관리

- JWK 셋을 Secrets Manager 보관(PD-3). **kid 롤오버**: 신 kid 추가 → 배포 → 구 kid 검증 유예(액세스 수명 1h) 후 제거.
- 기동 시 키 조회 실패 → **fail-fast**(무검증 서빙 금지, LC-6).

### 3.4 Spring Security 필터체인 7단 (tech-stack §2.3)

```
1. 상관 ID 필터(MDC 주입)
2. 요청 크기·컨텐츠 타입 가드(SECURITY-05)
3. JWT 인증 필터(Bearer 검증 · STATELESS)
4. Rate-limit 필터(공개 인증 엔드포인트 한정 · LC-3)
5. 인가: anyRequest().authenticated() + 공개 화이트리스트(API설계 §2)
6. 보안 헤더 라이터(SECURITY-04)
7. 전역 예외 변환(AuthenticationEntryPoint/AccessDeniedHandler — 일반화 메시지)
```

## 4. 에러/응답 표준

### 4.1 봉투

- **성공(2xx)**: 리소스 본문을 그대로 반환(래퍼 없음).
- **실패(4xx/5xx)**: 단일 봉투(API설계 §5).

```json
{ "error": { "code": "NICKNAME_TAKEN", "message": "...", "traceId": "...", "fields": [ ... ] } }
```

### 4.2 규칙

| 항목 | 결정 |
|---|---|
| code | 도메인 에러 코드 enum(문자열) — HTTP status와 분리(클라 분기용) |
| message | 사용자 표시용 일반 문구 — **인증·인가 실패는 원인 비노출**(SECURITY-15) |
| traceId | 상관 ID 반향(로그 대조) |
| fields | `VALIDATION_ERROR`에만 — `[{field, reason}]` |
| 검증 | `@Valid` 실패 → 전역 핸들러가 400 `VALIDATION_ERROR`로 변환. 클라(Zod)와 규칙 수치 대응표 유지 |
| 매핑 | 예외→상태 매핑은 `@RestControllerAdvice` 1곳 집중 |

전체 HTTP·code 표는 `U1-API-설계.md §5` 참조(소셜 전용 반영본).
